# Prep Lab

Браузерное приложение для подготовки к техническим собеседованиям на основе своих проектов и материалов. Один экземпляр принадлежит одному владельцу. Основные сценарии: персональный интенсив, интервью, практика, чтение материалов, повторение, импорт своей базы, разбор проектов и обсуждения. Встроенная база посвящена frontend; интенсив использует выбранные материалы любого направления.

## Архитектура

Nuxt 4, Vue 3, TypeScript strict, Pinia и Nitro; интерфейс работает с `ssr: false`.

- `app/pages/` и `app/layouts/` компонуют интерфейс.
- `app/features/` содержит пользовательские сценарии с отдельными UI, model и API; чужие features подключаются через public index.
- `app/entities/` владеет предметными компонентами и хранилищами; `app/shared/` — общими элементами.
- `domain/` содержит чистые алгоритмы и контракты без Vue, файловой системы и БД.
- `server/api/` — тонкие HTTP-входы, `server/application/` — сценарии, `server/infrastructure/` — внешние зависимости.
- `content/common/` и `content/prompts/` входят в серверную поставку; пользовательские операции их не переписывают.

Направления импортов проверяет ESLint. Создавай каталоги и абстракции только при наличии соответствующего кода. Предпочитай существующий способ решения новому механизму.

## Данные и совместимость

Личные данные хранятся в закрытом каталоге `.local/`; другой корень задаётся `FRONTEND_LAB_DATA_DIR`. Не добавляй в Git или публичную раздачу базы, credentials, снимки пользовательских источников, локальные настройки и журналы.

Сохраняй ID вопросов и материалов, алиасы путей/заголовков, неизвестные прежние отметки и исторические снимки интервью. Миграция исходных browser/JSON-сохранений однократна и оставляет исходники нетронутыми. При повреждении или отказе записи не создавать пустую замену.

Папка источника разрешается через `scripts/sources.ts allow`; произвольный серверный путь из HTTP не принимается. Пустой или недоступный снимок не означает удаление базы. Preview и личные решения отделены от активных материалов; принятие проверяет ссылки и ревизию, а запись выполняется транзакционно. Внешние файлы не переписываются.

Генерация создаёт черновик. Импорт сначала становится предложением изменений, проект активируется после отдельного принятия. Код не подтверждает личное авторство и коммерческие результаты. Конкретные критерии проектного вопроса принадлежат `Pilot.questions[].criteria`; общий текст используется только для прежних записей без этого поля.

## Подключение помощника

Данными отдельного подключения ChatGPT владеет `server/infrastructure/codex/`. Настольный вход не используется. Все сценарии разделяют один активный turn. Scoped `Codex.close()` не должен отменять чужую операцию; общий `closeCodex()` вызывается при завершении сервера.

`trustedTask` формирует только серверное приложение, сырой материал остаётся данными. Не предоставляй браузеру произвольный RPC, shell или чтение файлов. Отмена, disconnect и restart не должны автоматически повторять запрос. Общие проверки используют подготовленные ответы и временные данные; реальные входы и запросы модели требуют явного разрешения владельца.

## Запуск и проверки

Поддерживаемые версии Node.js задаёт `package.json`. Установка: `npm ci --ignore-scripts`. Разработка: `npm run dev`; production: `npm run build`, затем `npm start`. Адрес по умолчанию — `http://127.0.0.1:4173/`. Docker описан в `docs/self-hosted.md`.

`npm run check` проверяет типы, ESLint, Prettier, сборку, Node/integration-тесты, материалы и ссылки; `npm run check:all` добавляет Playwright Test. Перед браузерными тестами установи Chromium: `npx playwright install chromium`. Тесты находятся в `tests/`, фикстуры — в `tests/fixtures/`, помощники — в `tests/helpers/`.

Некоторые исторические проверки необязательного личного пакета явно пропускаются при его отсутствии; основные сценарии проверяются независимыми синтетическими данными. Не ослабляй проверку из-за отсутствия личных файлов или ограничений окружения.

После изменений выполняй проверки под затронутое поведение. Различай автоматический PASS, визуальный просмотр и реальную пользовательскую приёмку. Не выдавай чтение кода за запуск. Инструкции для пользователя находятся в `docs/user-guide.md`, для разработчика — в `docs/development.md`.

## Границы работы

Сначала получи контекст затронутой области и учитывай текущие изменения. Не откатывай чужую работу и не расширяй задачу без необходимости. Commit, push, переписывание истории, публикация, production-действия и удаление пользовательских данных требуют явного разрешения владельца.
