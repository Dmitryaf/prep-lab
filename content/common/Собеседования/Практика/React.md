## Контракт поля и композиция

Сделай `NameField` с props `value`, `onValueChange` и `children`. Родитель хранит имя и показывает приветствие внутри поля. Внешняя кнопка родителя может заменить имя. Поле должно сразу показать замену, а ввод — обновить приветствие. Значение не должно иметь двух независимых владельцев.

> [!example]- Разбор
>
> Поле передаёт value в input, а из onChange вызывает onValueChange с новой строкой. Родитель меняет state; children содержит приветствие из того же state. Полная [[Фронтенд/React/02. Props, callbacks и композиция#Контракт компонента|реализация]] используется непосредственно в тестах стенда. Проверь ввод, очистку, внешнюю замену и смену children. Внешний rerender сам по себе не должен вызывать onValueChange.

## Поиск: от списка до гонок запросов

**Формат раунда:** Написание кода
**Этап кода:** main

Реализуй управляемый компонент `UserSearch({ users, query, onQueryChange, onSelect })`. `users` — массив `{ id: string, name: string }` с уникальными ID, `query` — строка родителя. Покажи подписанное поле и список. Фильтр ищет подстроку без учёта регистра, обрезая пробелы по краям запроса. Пустой запрос показывает всех. Сохрани порядок и исходный массив; для каждого имени нужна кнопка, вызывающая `onSelect(id)`. Если совпадений нет, покажи «Ничего не найдено».

Пример: Alice, Malik, Bob и запрос ` ALI ` дают Alice, Malik; запрос `?` даёт пустой список. Родитель может изменить query извне — поле сразу показывает новое значение. В базовой задаче все данные уже переданы: сеть и задержка ввода не нужны.

**Критерии ответа:** Поле отражает query и сообщает новое значение родителю; фильтр соблюдает примеры и порядок; исходные данные не меняются; стабильные ключи, подпись поля, выбор кнопкой и пустой результат работают.
**Изучить:** [[Фронтенд/React/03. Состояние и обновления|Состояние и производные значения]], [[Фронтенд/React/08. Формы и события|Формы и события]]

> [!example]- Разбор: производный список без дополнительного состояния
>
> Фильтр вычисляется из props при рендере. Хранить его копию в state и синхронизировать эффектом не требуется.
>
> ```js
> // checked-example: react-search-base
> function filterUsers(users, query) {
>   const term = query.trim().toLowerCase();
>   return users.filter((user) => user.name.toLowerCase().includes(term));
> }
> ```
>
> ```jsx
> function UserSearch({ users, query, onQueryChange, onSelect }) {
>   const visible = filterUsers(users, query);
>   return (
>     <section>
>       <label>
>         Поиск пользователей
>         <input
>           type="search"
>           value={query}
>           onChange={(event) => onQueryChange(event.target.value)}
>         />
>       </label>
>       {visible.length === 0 && <p role="status">Ничего не найдено.</p>}
>       <ul>
>         {visible.map((user) => (
>           <li key={user.id}>
>             <button type="button" onClick={() => onSelect(user.id)}>
>               {user.name}
>             </button>
>           </li>
>         ))}
>       </ul>
>     </section>
>   );
> }
> ```
>
> Проверь пустой запрос, пробелы, регистр, отсутствие совпадений, новый массив users и изменение query родителем. Клик и Enter/Space на кнопке передают ID, а имя отображается текстом. Обычный список кнопок не обещает поведение combobox.

### Серверный поиск: задержка и поздние ответы

**Критерии ответа:** Проверяю debounce, пустой ввод, смену организации, запоздалые ответы, ошибку и освобождение ресурсов; аргументирую модель отображения прежних результатов.
**Изучить:** [[Фронтенд/React/10. Запросы и серверное состояние|Запросы и серверное состояние]], [[Фронтенд/React/05. Эффекты и внешние системы|Эффекты и очистка]], [[Фронтенд/API браузера/05. Fetch, CORS и сетевые запросы/03. AbortController и race condition в запросах|Отмена и поздние ответы]]

**Входы компонента.** `orgId` — строковый ID организации; `query` — строка, которой владеет родитель; `onQueryChange(text)` и `onSelect(id)` — callbacks. `loadUsers(orgId, term, { signal })` возвращает Promise массива `{ id: string, name: string }` с уникальными ID. Функция загрузчика имеет стабильную ссылку между обычными рендерами. Компонент показывает список в порядке API и не меняет полученный массив.

1. Покажи подписанное поле и список пользователей; выбор — настоящая кнопка, доступная через Tab и Enter/Space.
2. Добавь debounce 300 мс. Пустая после trim строка сразу очищает видимый результат и не вызывает запрос. Контракт этого упражнения скрывает прежний список при новом запросе.
3. Добавь загрузку/ошибку/пустой ответ. A начался, затем B; B завершился раньше A. Результат, ошибка и завершение A не должны менять видимое состояние B. Учитывай загрузчик, который игнорирует AbortSignal.
4. Родитель меняет query или orgId при pending-запросе. Старые пользователи не должны показываться в другой организации; внешнее изменение query должно быть видно в поле. При unmount убери таймер и отмени запрос.
5. Повтори в StrictMode, где в режиме разработки может быть дополнительный цикл «подключение → очистка ресурсов → повторное подключение». Объясни, почему корректное освобождение ресурсов важнее попытки запретить повторный effect флагом.

В этом задании список состоит из обычных кнопок. Если требуется combobox с ArrowUp/ArrowDown, активной опцией и Escape, сначала задай отдельный контракт фокуса и ARIA: одна подпись поля его не реализует. Загрузка «ещё» и сохранение старых результатов также меняют текущий контракт.

> [!example]- Разбор поиска и готовая реализация
>
> Состояние React хранит результат одной операции целиком. Эффект управляет таймером, контроллером отмены и флагом active. Функция очистки сначала запрещает применять результат, затем освобождает ресурсы. Одной отмены недостаточно: загрузчик может её проигнорировать. Результат дополнительно сопоставляется с парой orgId/term: при изменившемся вводе старый список скрывается уже во время рендера, ещё до следующего запуска эффекта.
>
> ```jsx
> // checked-example: react-search
> import { useEffect, useState } from 'react';
>
> function emptySearch(key, status) {
>   return { key, status, users: [], error: null };
> }
>
> function useUserSearch(orgId, query, loadUsers, delay = 300) {
>   const term = query.trim();
>   const key = JSON.stringify([orgId, term]);
>   const [result, setResult] = useState(() => emptySearch(null, 'idle'));
>
>   useEffect(() => {
>     if (!term) return;
>     let active = true;
>     const controller = new AbortController();
>     setResult(emptySearch(key, 'loading'));
>     const timer = setTimeout(async () => {
>       try {
>         const users = await loadUsers(orgId, term, {
>           signal: controller.signal,
>         });
>         if (active) setResult({ key, status: 'success', users, error: null });
>       } catch (error) {
>         if (active) setResult({ ...emptySearch(key, 'error'), error });
>       }
>     }, delay);
>     return () => {
>       active = false;
>       clearTimeout(timer);
>       controller.abort();
>     };
>   }, [orgId, term, key, loadUsers, delay]);
>
>   if (!term) return emptySearch(key, 'idle');
>   return result.key === key ? result : emptySearch(key, 'loading');
> }
>
> // Учебный HTTP-контракт: GET /api/users?org=...&q=... -> массив пользователей.
> async function loadUsersFromApi(orgId, term, { signal }) {
>   const params = new URLSearchParams({ org: orgId, q: term });
>   const response = await fetch(`/api/users?${params}`, { signal });
>   if (!response.ok) throw new Error(`HTTP ${response.status}`);
>   const users = await response.json();
>   if (
>     !Array.isArray(users) ||
>     !users.every(
>       (user) =>
>         user !== null &&
>         typeof user === 'object' &&
>         typeof user.id === 'string' &&
>         typeof user.name === 'string',
>     ) ||
>     new Set(users.map((user) => user.id)).size !== users.length
>   ) {
>     throw new Error('Invalid users response');
>   }
>   return users;
> }
>
> function UserSearch({
>   orgId,
>   query,
>   onQueryChange,
>   onSelect,
>   loadUsers = loadUsersFromApi,
>   delay = 300,
> }) {
>   const result = useUserSearch(orgId, query, loadUsers, delay);
>   return (
>     <section>
>       <label>
>         Поиск пользователей
>         <input
>           type="search"
>           value={query}
>           onChange={(event) => onQueryChange(event.target.value)}
>         />
>       </label>
>       {result.status === 'loading' && <p role="status">Загрузка…</p>}
>       {result.status === 'error' && (
>         <p role="alert">Не удалось загрузить пользователей.</p>
>       )}
>       {result.status === 'success' && result.users.length === 0 && (
>         <p role="status">Ничего не найдено.</p>
>       )}
>       <ul>
>         {result.users.map((user) => (
>           <li key={user.id}>
>             <button type="button" onClick={() => onSelect(user.id)}>
>               {user.name}
>             </button>
>           </li>
>         ))}
>       </ul>
>     </section>
>   );
> }
> ```
>
> Родитель передаёт query и меняет его в onQueryChange: копия `useState(initialQuery)` внутри компонента перестала бы реагировать на внешнюю смену. ID организации входит в ключ результата; одинаковое слово в другой организации не означает те же данные. Стабильный загрузчик объявляют вне компонента или используют useCallback с нужными зависимостями; заново созданная inline-функция в deps может постоянно перезапускать effect.
>
> **Проверка.** Управляй Promise A/B вручную. Проверь B → A, старый reject A при загрузке B, смену организации с тем же словом, пустой ввод до ответа, unmount до debounce и после старта запроса. В тестовом загрузчике намеренно игнорируй signal. Отдельно проверь, что debounce не запускает все промежуточные строки, текущая ошибка видна, пустой массив даёт «Ничего не найдено», имя `<img ...>` показывается текстом и кнопка выбирается клавиатурой. HTTP-адаптер отдельно проверяется на не-2xx, неверный JSON-контракт и кодирование `&`/`?` в строке поиска.
>
> Не добавляй общий `finally(() => setLoading(false))` без проверки актуальности: завершение A выключило бы загрузку B. Здесь состояние операции меняется одним защищённым действием в обработчиках успеха и ошибки. Дополнительный запрос, успевший начаться до очистки ресурсов, возможен; корректность определяется отсутствием устаревшего видимого результата, а не обещанием «ровно один запрос при любом режиме разработки».
>
> **Следующее условие.** Если во время нового поиска нужно сохранять старые результаты, убери их маскировку только после нового договора: явно обозначай их как устаревшие, запрети показ между организациями и поменяй проверки UI. Для крупных списков сначала измерь рендер; useMemo/useCallback не исправляют гонку данных.

Эффекты и очистка ресурсов: [React useEffect](https://react.dev/reference/react/useEffect), [синхронизация с внешними системами](https://react.dev/learn/synchronizing-with-effects).

**Уточнения**
- Теперь сохраняйте прежний список при обновлении в той же организации. Как отличить устаревшие данные и не показать их в другой организации?
- Ответы A и B завершились в обратном порядке, а A отклонён. Напишите проверку результата и индикатора загрузки.

## Drag: точка захвата, границы и отмена

Сделай перемещение кнопки внутри контейнера 320×200 без библиотек и без position:absolute. Положение хранится как смещение от исходного места в потоке. При захвате за правый край кнопка не должна прыгать к курсору левым углом.

Этапы: движение с сохранением точки захвата → отпускание за пределами кнопки → границы контейнера → pointercancel/lostpointercapture → управление стрелками при фокусе. При отмене сохраняется последнее положение, движение прекращается. Поддерживается один первичный указатель. Во время жеста контейнер не прокручивается и не меняет размер; у предков нет масштабирования. Для масштабируемого/прокручиваемого холста нужна другая модель преобразования координат.

> [!example]- Разбор геометрии и Pointer Events
>
> Сохраняем координаты начала жеста и исходное смещение. Новое положение — исходное плюс дельта указателя, поэтому точка захвата сохраняется. Границы измеряем при начале жеста; pointer capture доставляет дальнейшие события тому же элементу. transform сохраняет исходное место в потоке. Ограничение позиции используется и мышью, и клавиатурой.
>
> ```js
> // checked-example: drag-geometry
> function clampPosition(point, limits) {
>   return {
>     x: Math.max(limits.minX, Math.min(limits.maxX, point.x)),
>     y: Math.max(limits.minY, Math.min(limits.maxY, point.y)),
>   };
> }
> function dragPosition(start, clientX, clientY) {
>   return clampPosition({
>     x: start.x + clientX - start.clientX,
>     y: start.y + clientY - start.clientY,
>   }, start.limits);
> }
> ```
>
> ```jsx
> // checked-example: react-drag
> import { useRef, useState } from 'react';
>
> function Draggable() {
>   const stageRef = useRef(null);
>   const buttonRef = useRef(null);
>   const drag = useRef(null);
>   const [position, setPosition] = useState({ x: 0, y: 0 });
>
>   function measureLimits(current) {
>     const stage = stageRef.current.getBoundingClientRect();
>     const button = buttonRef.current.getBoundingClientRect();
>     return {
>       minX: current.x + stage.left - button.left,
>       maxX: current.x + stage.right - button.right,
>       minY: current.y + stage.top - button.top,
>       maxY: current.y + stage.bottom - button.bottom,
>     };
>   }
>   function onPointerDown(event) {
>     if (!event.isPrimary || event.button !== 0 || drag.current) return;
>     drag.current = {
>       ...position,
>       clientX: event.clientX,
>       clientY: event.clientY,
>       id: event.pointerId,
>       limits: measureLimits(position),
>     };
>     event.currentTarget.setPointerCapture(event.pointerId);
>   }
>   function onPointerMove(event) {
>     const start = drag.current;
>     if (start && start.id === event.pointerId) {
>       setPosition(dragPosition(start, event.clientX, event.clientY));
>     }
>   }
>   function finish(event) {
>     if (drag.current?.id !== event.pointerId) return;
>     drag.current = null;
>     if (event.currentTarget.hasPointerCapture(event.pointerId)) {
>       event.currentTarget.releasePointerCapture(event.pointerId);
>     }
>   }
>   function onKeyDown(event) {
>     const delta = {
>       ArrowLeft: [-10, 0],
>       ArrowRight: [10, 0],
>       ArrowUp: [0, -10],
>       ArrowDown: [0, 10],
>     }[event.key];
>     if (!delta || drag.current) return;
>     event.preventDefault();
>     const limits = measureLimits(position);
>     setPosition((previous) =>
>       clampPosition(
>         {
>           x: previous.x + delta[0],
>           y: previous.y + delta[1],
>         },
>         limits,
>       ),
>     );
>   }
>
>   return (
>     <div>
>       <div
>         ref={stageRef}
>         style={{
>           width: 320,
>           height: 200,
>           outline: '1px solid gray',
>           overflow: 'hidden',
>         }}
>       >
>         <button
>           ref={buttonRef}
>           type="button"
>           aria-label="Перемещаемая кнопка. Используйте стрелки для перемещения"
>           onPointerDown={onPointerDown}
>           onPointerMove={onPointerMove}
>           onPointerUp={finish}
>           onPointerCancel={finish}
>           onLostPointerCapture={finish}
>           onKeyDown={onKeyDown}
>           style={{
>             transform: `translate(${position.x}px, ${position.y}px)`,
>             touchAction: 'none',
>             userSelect: 'none',
>           }}
>         >
>           Перетащи меня
>         </button>
>       </div>
>       <output>
>         {Math.round(position.x)}, {Math.round(position.y)}
>       </output>
>     </div>
>   );
> }
> ```
>
> Контейнер в этом примере без padding и border, кнопка меньше него; outline не меняет измеряемую геометрию. Пример не обещает работу при произвольном изменении CSS. На pointercancel и потере capture освобождаем состояние жеста так же, как на pointerup. Глобальных listeners и таймеров нет; при удалении элемента браузер прекращает его pointer capture. touch-action:none ограничено ручкой, а не всей страницей. Ref хранит служебное состояние жеста, React-state — отображаемую позицию.
>
> **Проверка.** Захвати разные точки кнопки и смести указатель на одинаковую дельту — итоговое смещение должно совпадать. Выйди за края, отпусти и снова начни: кнопка не прыгает, движение не продолжается после отпускания. Проверь все четыре границы, отмену касания/потерю capture, повторный жест и unmount посередине. Через Tab установи фокус и стрелками дойди до границы. Математика функции проверяется отдельно, доставка Pointer Events и геометрия — в настоящем браузере; эмуляция прямоугольников не доказывает работу touch на телефоне.
>
> **Усложнения.** Если контейнер может измениться в процессе жеста, определяй, когда пересчитывать границы и что делать с уже недопустимым положением. При transform:scale у предка нужно перевести дельту экрана в локальные координаты. Для переноса между контейнерами добавляются модель данных, hit testing и контракт завершения: одно визуальное смещение не перемещает сущность между списками. Для дорогого рендера сначала снимай профиль, затем обсуждай rAF и очистку его callback.

Связанная задача: [[Собеседования/Практика/Интерфейс и интеграции#Drag & drop между двумя контейнерами|перенос между контейнерами]]. API: [pointer capture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture), [pointercancel](https://developer.mozilla.org/en-US/docs/Web/API/Element/pointercancel_event).

## Ревью компонента с запросами

**Формат раунда:** Ревью кода

**Критерии ответа:** Нахожу причины устаревшего результата и неправильного loading; воспроизвожу их управляемыми Promise и исправляю поведение без подмены сетевых отказов успехом.
**Изучить:** [[Фронтенд/React/10. Запросы и серверное состояние|Запросы и серверное состояние]], [[Фронтенд/React/05. Эффекты и внешние системы#Зависимости и замыкания|Зависимости и замыкания]], [[Фронтенд/API браузера/05. Fetch, CORS и сетевые запросы/03. AbortController и race condition в запросах|Отмена и поздние ответы]]

Сценарий: родитель меняет orgId и query; пользователи выбираются кнопками, список отображает порядок API. Ответы могут завершаться в любом порядке. Разбери код ниже, сохрани поведение и предложи минимальные исправления. Сначала назови наблюдаемые ошибки и проверки; затем отдельно обсуждай стиль и декомпозицию. Код намеренно ошибочный и не является готовым решением.

```jsx
import { useEffect, useMemo, useState } from 'react';
function BrokenUserSearch({ orgId, query, onQueryChange, onSelect }) {
  const [text, setText] = useState(query);
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(false);
  useEffect(() => {
    setTimeout(() => {
      setLoading(true);
      fetch(`/api/users?org=${orgId}&q=${text}`)
        .then(response => response.json())
        .then(setUsers)
        .finally(() => setLoading(false));
    }, 300);
  }, []);
  const rows = useMemo(() => users, []);
  return <section>
    <input value={text} onChange={event => {
      setText(event.target.value);
      onQueryChange(event.target.value);
    }} />
    {loading && <span>Загрузка</span>}
    {rows.map((user, index) => <div key={index} onClick={() => onSelect(user.id)}
      dangerouslySetInnerHTML={{ __html: user.name }} />)}
  </section>;
}
```

Усложняй ревью: родитель заменил query → пришёл HTTP 500 → старый ответ догнал новый → сменился orgId → компонент удалён до таймера → имя содержит HTML → кандидат предлагает «добавить useCallback везде». Для каждого нового условия объясни, какой конкретный участок кода меняется и почему.

> [!example]- Разбор ревью и порядок исправления
>
> | Находка | Наблюдаемый эффект | Исправление и проверка |
> | --- | --- | --- |
> | text — разовая копия query | Внешнее изменение не видно в поле | Управляемое поле из query; родитель меняет значение после первого рендера |
> | У эффекта пустой список зависимостей | Ввод и смена организации не запускают нужный запрос | Указать реальные зависимости и очистку ресурсов; проверить новую пару orgId/query |
> | Таймер не очищается | После удаления компонента или нового ввода может начаться ненужная работа | clearTimeout в функции очистки; удалить компонент до 300 мс |
> | Нет защиты от устаревших результатов | После добавления зависимостей ответ A может перезаписать B, а завершение старого запроса — убрать признак загрузки B | Флаг active, очистка ресурсов и ключ операции; управляемые порядки ответов A/B |
> | HTTP-статус и данные не проверяются, нет catch | Ошибка или неверные данные попадают в успешную ветку, rejection не обработан | Проверить response.ok, структуру и состояние ошибки |
> | rows мемоизирован с пустыми deps | Всегда остаётся первый пустой массив | Убрать ненужный memo; новые users должны появиться в UI |
> | Сырые параметры URL | Символ & меняет смысл запроса | URLSearchParams; проверить имя с & и ? |
> | HTML из имени | Пользовательские данные становятся разметкой | Текстовый JSX-вывод; строка с тегом видна текстом |

> | Индекс как key | При смене порядка и локальном состоянии строк возможна неверная идентичность | Стабильный user.id; переставить строки с состоянием/фокусом |
>
> Сначала исправь блокирующий устаревший rows, чтобы увидеть остальные симптомы; затем жизненный цикл и ошибки, безопасность и управление. Не ограничивайся тем, что после одной правки список появился. Полная исправленная реализация с тем же контрактом находится в [[Собеседования/Практика/React#Поиск: от списка до гонок запросов|разборе поиска]] — повторная копия загрузчика здесь не нужна.
>
> Индекс в key не доказывает ошибку в списке, состав и порядок которого не меняются. Обработчик, объявленный внутри map, и изменение состояния через then сами по себе не являются дефектами. Promise можно обработать корректно без переписывания на async/await. Вынос запроса в отдельный хук помогает организовать код, но корректность всё равно проверяется по поведению. React.memo/useCallback не заменяют очистку ресурсов, зависимости и защиту от устаревших данных.
>
> **Приёмка ревью.** Назови три наиболее существенных дефекта с пользовательским последствием, минимальную правку и независимую проверку для каждого. Затем примени все согласованные изменения и повтори весь сценарий, включая unmount и обратный порядок ответов. Проверь также ошибки, отмену и смену параметров, а не только успешное выполнение.

## Resize: свежий callback без повторной подписки

**Формат раунда:** Написание кода
**Этап кода:** main

Напиши `useResize(onResize)` и компонент `WindowWidth`. Хук подписывается на resize окна и вызывает `onResize(window.innerWidth)` при событии; при удалении компонента снимает слушатель. Компонент сразу показывает текущую ширину, затем обновляет число при resize. Выполнение только в браузере, SSR не требуется. Смена callback должна использовать новый callback; переподписка в базовом решении допустима.

Пример: начальная ширина 1024 → на экране «Ширина: 1024»; окно стало 800 и пришёл resize → «Ширина: 800». После удаления компонента callback больше не вызывается.

**Критерии ответа:** Начальная и обновлённая ширина видны; add/remove используют один обработчик; смена callback отражается на последующих событиях; unmount снимает подписку. Не требую запрета переподписки в базовом решении.
**Изучить:** [[Фронтенд/React/05. Эффекты и внешние системы|Подписка и очистка]], [[Фронтенд/React/03. Состояние и обновления|Обновление состояния]]

> [!example]- Разбор: эффект с парной очисткой
>
> ```jsx
> import { useEffect, useState } from 'react';
>
> function useResize(onResize) {
>   useEffect(() => {
>     const listener = () => onResize(window.innerWidth);
>     window.addEventListener('resize', listener);
>     return () => window.removeEventListener('resize', listener);
>   }, [onResize]);
> }
>
> function WindowWidth() {
>   const [width, setWidth] = useState(() => window.innerWidth);
>   useResize(setWidth);
>   return <p>Ширина: {width}</p>;
> }
> ```
>
> Setter состояния стабилен; переданный произвольный callback может меняться, поэтому входит в зависимости. Проверка: подключить A → resize → заменить на B → resize → удалить → resize. A и B получают по одному вызову, после удаления вызовов нет.

### Resize без переподписки при смене callback

Измени useResize: замена callback больше не снимает и не добавляет listener. При этом resize должен вызывать последнюю применённую функцию. Проверь последовательность A → resize → B → resize и удаление компонента. Дополнительные циклы очистки в StrictMode не должны оставлять лишние слушатели.

**Критерии ответа:** Подписка не создаётся заново при смене функции обратного вызова; ссылка в `ref` обновляется после отрисовки; очистка удаляет исходный обработчик; вместо функции A действительно вызывается B.
**Изучить:** [[Фронтенд/React/06. Refs и работа с DOM|Ref и актуальный callback]]

> [!example]- Разбор: актуальное значение отдельно от подписки
>
> ```jsx
> import { useEffect, useLayoutEffect, useRef } from 'react';
> function useResize(onResize) {
>   const latest = useRef(onResize);
>   useLayoutEffect(() => {
>     latest.current = onResize;
>   }, [onResize]);
>   useEffect(() => {
>     const listener = () => latest.current(window.innerWidth);
>     window.addEventListener('resize', listener);
>     return () => window.removeEventListener('resize', listener);
>   }, []);
> }
> ```
>
> Layout effect обновляет ссылку после commit до следующего браузерного события. Запись в ref прямо во время render могла бы опубликовать callback рендера, который React ещё не применил. Здесь браузерный контракт остаётся прежним.

## Форма: ошибка и повторная отправка

**Критерии ответа:** Проверяю отправку актуального ввода, блокировку повторного запроса, сохранение введённого при ошибке и успешную повторную попытку через наблюдаемый интерфейс.
**Изучить:** [[Фронтенд/React/08. Формы и события|Механизм, пример и ограничения]]

Сделай форму имени. Пустой ввод не отправляется. Пока save выполняется, повторный submit не запускает второй запрос. При отказе введённое имя остаётся, ошибка видна, повтор разрешён. После успеха показывается подтверждение. Для базового варианта ввод во время сохранения заблокирован.

> [!example]- Разбор
>
> [[Фронтенд/React/08. Формы и события#Отправка с сохранением ввода|SaveName]] хранит черновик и этап операции отдельно. Управляй Promise вручную: отправка → повторная отправка → отклонение Promise → проверка текста → повтор → успешное завершение Promise. Дополнительный вариант разрешает ввод во время запроса: тогда сохранённый снимок состояния и новый черновик нужно различать. Не очищай новый текст при завершении старой операции. Серверная идемпотентность остаётся отдельным контрактом.

**Уточнения**
- Разрешите ввод во время сохранения. Старый ответ не должен очистить новый черновик.
- Ответ сервера потерян после сохранения. Какие гарантии нужны API, чтобы повтор не создал вторую запись?

> [!followup]- Разрешите ввод во время сохранения. Старый ответ не должен очистить новый черновик.
>
> Разделю состояние операции и редактируемый черновик. Каждый ввод увеличивает локальную revision. При submit фиксирую отправленные name и revision; ref-блокировка по-прежнему запрещает второй запрос, но input остаётся доступным. Изменение поля не снимает pending уже идущего сохранения.
>
> При успехе запоминаю подтверждённый снимок. Сбрасывать поле или показывать «Текущий ввод сохранён» можно только при совпадении текущей revision с отправленной. Проверку выполняю по актуальному состоянию, например в чистом reducer для события saveSucceeded, а не по переменной из замыкания submit. Если revision изменилась, оставляю новый текст и показываю «Предыдущий вариант сохранён, есть несохранённые изменения». При отказе сохраняю ввод и освобождаю блокировку в finally.

Проверить также A → B → A: сравнение только строк не замечает новых правок, счётчик revision замечает. Отдельно проверяю отказ и двойной submit. Эта локальная revision описывает изменения ввода; серверная version решает другой вопрос — конкурентное редактирование записи. [Состояние и замыкание обработчика](https://react.dev/reference/react/useState).

> [!followup]- Ответ сервера потерян после сохранения. Какие гарантии нужны API, чтобы повтор не создал вторую запись?
>
> Тайм-аут означает неизвестный исход: сервер мог создать запись, а клиент не получить подтверждение. Для повторной доставки нужен устойчивый идентификатор логической операции, созданный до первого запроса. Повтор того же отправленного снимка использует прежний ключ; новый ключ на каждой попытке не защищает от дублей.
>
> Согласую API: ключ ограничен пользователем/организацией и видом команды; сервер атомарно связывает его с созданием записи и результатом. Одновременные запросы с одним ключом не создают две записи. Повтор возвращает прежний результат или статус незавершённой операции; тот же ключ с другим payload отклоняется. Проверка прав выполняется и при повторе. Клиент сохраняет ключ до подтверждения, а для восстановления после перезагрузки API позволяет узнать итог операции.
>
> Тест: сервер фиксирует создание, соединение обрывается до ответа, клиент повторяет исходный payload и ключ — в БД одна запись, её id одинаков в подтверждениях. Отдельно проверить два параллельных повтора и изменённый payload. Нужен оговорённый срок хранения ключей: после его истечения прежняя гарантия может исчезнуть, поэтому неизвестный результат сначала выясняют, а не слепо повторяют. [Пример такого контракта у Stripe](https://docs.stripe.com/api/idempotent_requests); конкретные сроки и статусы определяет наше API.

## Ревью подписки и вложенного таймера

**Критерии ответа:** Проверяю смену ключа подписки, позднее событие и вложенный таймер; после очистки старый источник не меняет интерфейс, таймеры и подписки освобождены.
**Изучить:** [[Фронтенд/React/05. Эффекты и внешние системы|Механизм, пример и ограничения]]

Найдите ошибки и отделите их от необязательной оптимизации. Добавление должно показывать новую строку, а «Всего» — количество строк. После события offline раз в секунду выводится актуальное количество; повторное offline не создаёт второй таймер, online останавливает его. При unmount всё освобождается. Начальное состояние этого упражнения — online; это демонстрация ресурсов, не проверка доступности сервера.

```jsx
import { useState, useLayoutEffect, useCallback } from 'react';

function BrokenItems() {
  const [items, setItems] = useState([]);
  const [count, setCount] = useState(0);
  useLayoutEffect(() => {
    window.addEventListener('offline', () => {
      setInterval(() => console.log(count), 1000);
    });
  });
  const onClick = useCallback(() => {
    setItems([...items, { id: count + 1, title: String(Date.now()) }]);
    setCount(count + 1);
  });
  return <>
    <button onClick={() => onClick()}>Добавить</button>
    <p>Всего: {count}</p>
    {items.map(item => { <li>{item.title}</li>; })}
  </>;
}
```

> [!example]- Разбор
>
> Сначала восстанови поведение: map с фигурными скобками не возвращает JSX, строкам нужны key и контейнер списка. Эффект без dependencies создаёт обработчик после каждого commit. Ни обработчики, ни порождённые ими интервалы не освобождаются; каждый таймер читает count своего замыкания.
>
> useCallback без dependencies не сохраняет ссылку между рендерами. Он здесь не нужен, но это не причина «замороженного count»: замыкание таймера создаётся в другом месте. useLayoutEffect не нужен для подписки, которая не измеряет расположение до отрисовки. Отдельный count дублирует длину списка.
>
> Ниже один вариант для React 19.2+: effect владеет подписками и интервалом, useEffectEvent читает актуальное количество после commit, а ID создаётся в обработчике клика. Updater массива остаётся чистым.
>
> ```jsx
> // checked-example: react-offline-review
> import { useEffect, useEffectEvent, useRef, useState } from 'react';
>
> function ItemsWithOfflineLog() {
>   const [items, setItems] = useState([]);
>   const nextId = useRef(0);
>   const onTick = useEffectEvent(() => console.log(items.length));
>
>   useEffect(() => {
>     let timer = null;
>     function stop() {
>       if (timer !== null) clearInterval(timer);
>       timer = null;
>     }
>     function start() {
>       if (timer === null) timer = setInterval(() => onTick(), 1000);
>     }
>     window.addEventListener('offline', start);
>     window.addEventListener('online', stop);
>     return () => {
>       window.removeEventListener('offline', start);
>       window.removeEventListener('online', stop);
>       stop();
>     };
>   }, []);
>
>   function addItem() {
>     const id = ++nextId.current;
>     setItems((previous) => [...previous, { id, title: `Строка ${id}` }]);
>   }
>   return (
>     <>
>       <button onClick={addItem}>Добавить</button>
>       <p>Всего: {items.length}</p>
>       <ul>
>         {items.map((item) => (
>           <li key={item.id}>{item.title}</li>
>         ))}
>       </ul>
>     </>
>   );
> }
> ```
>
> Проверки: два offline подряд; добавление строки во время работы таймера; online; unmount и новый mount; StrictMode. Должны оставаться один интервал на экземпляр, актуальное число и отсутствие действий после удаления. Счётчик ID локален экземпляру; для сохраняемых данных нужен другой контракт идентификаторов. Событие online само по себе не подтверждает доступность API.
>
> Для React без useEffectEvent выбери другой способ чтения актуального значения с явным контрактом: [[Фронтенд/React/06. Refs и работа с DOM#Подписка со свежим callback|ref после commit]]. Теория: [[Фронтенд/React/05. Эффекты и внешние системы|эффекты и очистка]].
