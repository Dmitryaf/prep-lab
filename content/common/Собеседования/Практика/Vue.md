## Реактивность и обновление DOM

### Порядок жизненного цикла и фокус

Parent содержит Child, а Child — поле ввода. Определите порядок сообщений при первом монтировании, изменении count и удалении Child через v-if. Как будет работать фокус у родителя и ребёнка? Все файлы относятся к одному примеру.

```vue
<!-- Parent.vue -->
<script setup>
import { ref, onBeforeMount, onMounted, onUpdated } from 'vue';
import Child from './Child.vue';
const visible = ref(true);
const count = ref(0);
onBeforeMount(() => console.log('parent before mount'));
onMounted(() => console.log('parent mounted'));
onUpdated(() => console.log('parent updated'));
</script>
<template>
  <button @click="count++">{{ count }}</button>
  <button @click="visible = !visible">Показать/скрыть</button>
  <Child v-if="visible" :count="count" />
</template>
```

```vue
<!-- Child.vue -->
<script setup>
import { ref, onBeforeMount, onMounted, onUpdated, onUnmounted } from 'vue';
defineProps({ count: Number });
const input = ref(null);
onBeforeMount(() => console.log('child before mount'));
onMounted(() => { console.log('child mounted'); input.value.focus(); });
onUpdated(() => console.log('child updated'));
onUnmounted(() => console.log('child unmounted'));
</script>
<template><input ref="input" :value="count" /></template>
```

Дополнительно: замените onUpdated на watch с flush: 'pre'/'post'/'sync', вызывайте nextTick после изменения состояния. Не приписывайте всем этим случаям одинаковый порядок.

> [!example]- Разбор простыми словами
>
> Первое монтирование: parent before mount → child before mount → child mounted → parent mounted. При изменении переданного count: child updated → parent updated. При скрытии ребёнка выполняются child unmounted, затем parent updated.
>
> Фокус из child mounted работает: его input уже создан. Если родитель тоже переводит фокус в своём mounted, он делает это позже ребёнка и может перехватить его. После изменения visible в уже работающем компоненте жди `await nextTick()`. Подробнее: [[Фронтенд/Vue/11. Реактивность, очередь обновлений и рендеринг|данные и DOM обновляются в разное время]].

### Асинхронный обработчик и снимок значения

Что произойдёт после двух быстрых нажатий? Сравните чтение ref в момент завершения и сохранённое значение до ожидания. Задержка и функция wait предоставлены как вход.

```vue
<script setup>
import { ref } from 'vue';
const count = ref(0);
const wait = ms => new Promise(resolve => setTimeout(resolve, ms));
async function increment() {
  const previous = count.value;
  await wait(2000);
  count.value = previous + 1;
}
</script>
<template><button @click="increment">{{ count }}</button></template>
```

Предложите исправление по выбранному контракту; обсудите ошибку, повторную отправку и удаление компонента до завершения операции.

> [!example]- Разбор — базовое решение
>
> Оба вызова до ожидания прочитают 0 и сохранят previous=0. Каждый потом запишет 1: результат двух нажатий — 1, а не 2. Это два устаревших снимка значения, не потеря реактивности ref.
>
> Для контракта «каждая завершившаяся операция прибавляет один» достаточно читать актуальное значение после ожидания:
>
> ```js
> async function increment() {
>   await wait(2000);
>   count.value += 1;
> }
> ```
>
> Продолжения выполняются последовательно: первое увидит 0 и запишет 1, второе — 1 и запишет 2. Если второй запуск нужно запрещать до завершения запроса, проверяй флаг `pending` и устанавливай его до первого `await`, а сбрасывай в `finally`. Отключения кнопки недостаточно: функцию могут вызвать программно.
>
> В реальном запросе отдельно обрабатывают отказ. Если после удаления компонента результат применять нельзя, функция очистки помечает текущую операцию неактивной, отменяет доступную операцию, а продолжение проверяет актуальность перед записью. Это не отменяет уже выполненное действие на сервере. Проверьте два вызова, отказ одного и уничтожение владельца до завершения.

**Критерии ответа:** Предсказываю потерю одного инкремента, выбираю контракт повторного действия и обсуждаю остановку владельца.

**Изучить:** [[Фронтенд/Vue/03. computed, watch и watchEffect|Объяснение и примеры]]

### Фокус сразу после v-if

Кнопка должна показать поле ввода и передать ему фокус. Почему пример не работает? Предложите исправление через момент обновления DOM; сравните со сценарием v-show.

```vue
<script setup>
import { ref } from 'vue';
const visible = ref(false);
const input = ref(null);
function showInput() {
  visible.value = true;
  input.value.focus();
}
</script>
<template>
  <button @click="showInput">Показать</button>
  <input v-if="visible" ref="input" />
</template>
```

> [!example]- Разбор простыми словами
>
> Присваивание visible меняет данные сразу, но DOM обновляется позже. Поэтому input.value ещё null. Сделай showInput асинхронной: `visible.value = true; await nextTick(); input.value?.focus();`, импортировав nextTick из vue.
>
> При v-show узел уже существует, но прежде чем фокусировать скрытое поле, тоже дождись применения видимости. Optional chaining защищает от отсутствия узла, но само по себе не ждёт его появления.

### Оптимизация дочернего компонента

Родитель содержит поле value и отдельную кнопку принудительного обновления. Child показывает переданные данные и получает обработчик изменения. Проверьте, какие изменения действительно требуют обновления Child, затем сократите ненужные обновления. Измерьте результат; не добавляйте v-memo без необходимости. Сравните стабильную функцию из setup с функцией, создаваемой внутри шаблона.

```vue
<script setup>
import { ref } from 'vue';
import Child from './Child.vue';
const value = ref('');
const revision = ref(0);
</script>
<template>
  <button @click="revision++">Обновить {{ revision }}</button>
  <p>{{ value }}</p>
  <Child :on-change="text => value = text" />
</template>
```

Child вызывает переданный onChange при вводе. Предложите также контракт через событие компонента. Подробности устройства Child в этом варианте нужно определить самостоятельно.

> [!example]- Разбор простыми словами
>
> Сначала проверь реальное обновление Child при изменении только revision. Функция в шаблоне может иметь новую ссылку; вынеси `function onChange(text) { value.value = text; }` в setup и передай `:on-change="onChange"`. Либо ребёнок делает emit('change', text), а родитель использует @change.
>
> Не добавляй v-memo до измерения. Если Child действительно использует изменившиеся данные, обновление нужно. Подробности кеширования обработчиков зависят от скомпилированного шаблона.

### Условное наблюдение и жизненный цикл

Нужно загружать данные только при enabled=true и освобождать ресурсы при уничтожении компонента. Какие проблемы создаёт регистрация наблюдения/обработчика в произвольный момент? Исправьте пример с учётом изменений enabled и остановки наблюдения.

```vue
<script setup>
import { ref, watch, onUnmounted } from 'vue';
const enabled = ref(false);
const count = ref(0);
setTimeout(() => {
  if (enabled.value) {
    watch(count, value => console.log(value));
    onUnmounted(() => console.log('stop'));
  }
}, 1000);
</script>
```

Не объясняйте ошибку «порядком хуков»: во Vue причина связана с активным экземпляром компонента и областью владения наблюдением.

> [!example]- Разбор простыми словами
>
> Регистрация внутри setTimeout происходит вне синхронного setup. У onUnmounted нет нужного активного экземпляра, а созданный позднее watcher нужно останавливать вручную.
>
> Проще создать наблюдатель сразу: `watch([enabled, count], ([active, value]) => { if (active) console.log(value); });`. Для запроса зарегистрируй очистку ресурсов в обработчике наблюдателя. Так принадлежность наблюдения компоненту известна с самого начала.

### Счётчик: входные свойства и событие ребёнка

Родитель хранит count, ребёнок отображает его и просит увеличить на единицу. Спроектируйте связь через пропс count и событие increment. Затем объясните, почему ребёнок не должен менять props.count напрямую. Вариант: тот же контракт через v-model. Реализация не предоставлена.

> [!example]- Разбор простыми словами
>
> Ребёнок читает props.count и по клику вызывает emit('increment'). Родитель передаёт `:count="count"` и обрабатывает `@increment="count++"`. Значение принадлежит родителю; ребёнок сообщает намерение, а не меняет входные данные.
>
> Для v-model договорись о modelValue и update:modelValue либо используй defineModel в поддерживаемой версии Vue. Механизм: [[Фронтенд/Vue/04. Компоненты, props, emits и slots|контракт компонента]].

### Таймер сообщения и смена значения

Сообщение нужно очищать через 7 секунд после его появления. Что произойдёт, если новое сообщение пришло до окончания таймера? Найдите проблемы и исправьте очистку ресурсов.

```vue
<script setup>
import { ref, watch } from 'vue';
const message = ref('');
watch(message, value => {
  if (!value) return;
  setTimeout(() => { message.value = ''; }, 7000);
});
</script>
<template>{{ message }}</template>
```

Проверьте повтор одинакового сообщения, очистку при остановке наблюдения и уничтожение компонента. Сначала согласуйте, считается ли одинаковая строка новым сообщением.

> [!example]- Разбор простыми словами
>
> Старый таймер может удалить уже новое сообщение. В callback watcher используй третий аргумент onCleanup: создай таймер и зарегистрируй `onCleanup(() => clearTimeout(id))`. При следующем запуске прежний таймер будет очищен; при остановке watcher — текущий.
>
> Та же строка не меняет значение ref и обычно не перезапускает watch. Если одинаковый текст означает новое сообщение, храни `{ id, text }` с новым id или отдельно перезапускай таймер в функции показа.

### Вызов обработчика во время отрисовки

Почему компонент может обновляться бесконечно? Найдите разницу между значением входного свойства и обработчиком события.

```vue
<script setup>
import { ref } from 'vue';
import CounterButton from './CounterButton.vue';
const count = ref(0);
function increment() { count.value++; }
</script>
<template><CounterButton :handler="increment()" :count="count" /></template>
```

CounterButton ожидает функцию handler и вызывает её при клике. Варианты исправления: корректная передача функции либо контракт через событие; реализация ребёнка в условии не дана.

> [!example]- Разбор простыми словами
>
> `:handler="increment()"` вызывает increment во время вычисления шаблона и передаёт его результат undefined. Изменение count провоцирует следующее обновление.
>
> Передай функцию: `:handler="increment"`. Если ребёнок испускает событие, используй `@increment="increment"`. Вызов в обработчике события и вызов при вычислении prop происходят в разные моменты.

### Потеря значения при изменении реактивного объекта

Кнопка должна увеличивать счётчик. Найдите проблемы в получении значения и записи состояния, сохранив механизм reactive.

```vue
<script setup>
import { reactive } from 'vue';
const state = reactive({ counter: 0 });
const { counter } = state;
function increment() {
  ({ counter: state.counter + 1 });
}
</script>
<template><button @click="increment">{{ counter }}</button></template>
```

Объясните разницу между созданием объекта и изменением свойства; проверьте отображение после исправления каждой ошибки отдельно.

> [!example]- Разбор простыми словами
>
> Здесь две независимые ошибки. Деструктуризация скопировала число 0, а тело increment лишь создало и отбросило новый объект.
>
> Меняй `state.counter += 1`, а в шаблоне читай `state.counter`. Если нужна отдельная переменная, возьми `const counter = toRef(state, 'counter')`. Исправление только записи оставит шаблон со старой копией числа.

## Запросы, подписки и освобождение ресурсов

### Подписка на статус друга

Выделите логику в useFriendStatus(friendId), возвращающую реактивный статус: null до ответа, затем «Онлайн»/«Офлайн». При изменении идентификатора снимите старую подписку; при уничтожении компонента снимите текущую. Контракт внешнего API:

```js
ChatAPI.subscribeToFriendStatus(id, callback);
ChatAPI.unsubscribeFromFriendStatus(id, callback);
// callback получает { isOnline: boolean }
```

friendId может меняться: не зафиксируйте случайно первоначальное число. Уточните синхронный ответ при подписке и событие от предыдущего друга.

> [!example]- Разбор простыми словами
>
> Принимай ref или функцию чтения id. В watch с immediate сбрасывай статус в null, создавай callback и подписывайся на текущий id. Callback принимает результат только пока эта подписка актуальна. В onCleanup пометь её неактуальной и отпишись с теми же id и callback.
>
> Зарегистрируй очистку ресурсов до вызова subscribe: API может ответить синхронно. При смене друга не показывай старый статус как статус нового. Базовая модель: [[Фронтенд/Vue/06. Жизненный цикл, запросы и очистка ресурсов|запросы и очистка ресурсов]].

### useFetch: реактивный адрес и состояния запроса

**Формат раунда:** Написание кода
**Этап кода:** main

Напиши `useFetch(url, request)` и компонент списка пользователей. В базовом варианте url — неизменяемая непустая строка; `request(url)` возвращает Promise массива `{ id: string, name: string }` с уникальными ID либо отклоняется. Composable возвращает `data`, `loading`, `error` и `load()`. Компонент вызывает load при подключении, показывает загрузку, ошибку с кнопкой повтора, пустой ответ либо имена. Пока запрос выполняется, повторный load ничего не запускает. При новой загрузке прежний результат скрывается.

Добавь локальное поле поиска: регистр не важен, пробелы по краям игнорируются, пустая строка показывает всех. Фильтрация не делает новый запрос. Пример ответа: Alice, Bob; ввод ` AL ` оставляет Alice. Ошибка → «Повторить» → успешный пустой ответ показывает «Ничего не найдено».

**Критерии ответа:** Различаю загрузку, ошибку и пустой ответ; загрузка запускается явно; повтор после ошибки работает; параллельный повтор заблокирован; локальный фильтр не изменяет массив и не вызывает API. Реактивный адрес и отмена — отдельный этап.
**Изучить:** [[Фронтенд/Vue/05. Composables и переиспользование логики|Composables]], [[Фронтенд/Vue/03. computed, watch и watchEffect|Производный список]], [[Фронтенд/Vue/06. Жизненный цикл, запросы и очистка ресурсов|Жизненный цикл и запросы]]

> [!example]- Разбор: загрузчик и производный список
>
> ```js
> // checked-example: vue-fetch-base
> import { ref } from 'vue';
> function useFetch(url, request) {
>   const data = ref([]);
>   const loading = ref(false);
>   const error = ref(null);
>   async function load() {
>     if (loading.value) return;
>     loading.value = true;
>     error.value = null;
>     data.value = [];
>     try {
>       data.value = await request(url);
>     } catch (cause) {
>       error.value = cause instanceof Error ? cause : new Error(String(cause));
>     } finally {
>       loading.value = false;
>     }
>   }
>   return { data, loading, error, load };
> }
> ```
>
> Экспортируй useFetch из useFetch.js. В данном компоненте request — переданная функция с согласованным контрактом; HTTP-адаптер отдельно проверяет response.ok и форму JSON.
>
> ```vue
> <script setup>
> import { computed, onMounted, ref } from 'vue';
> import { useFetch } from './useFetch.js';
> const props = defineProps({ request: { type: Function, required: true } });
> const { data, loading, error, load } = useFetch('/api/users', props.request);
> const query = ref('');
> const visible = computed(() => {
>   const term = query.value.trim().toLowerCase();

>   <label>Поиск <input v-model="query" type="search" /></label>

>   </div>

>

После unmount Promise может завершиться, но у него нет общей подписки или состояния другого компонента; отмену транспорта добавляет следующий этап.

#### Реактивный адрес и поздние ответы

Теперь useFetch принимает строку, ref или функцию чтения адреса и сам загружает данные при изменении адреса. Пустой адрес очищает результат без запроса. При смене A → B поздний успех или отказ A не должен менять data, error или loading B. `request(url, { signal })` может проигнорировать отмену. При смене адреса и unmount освободи ресурсы. Сначала согласуй этот контракт, затем реализуй его вместо базового useFetch.

**Критерии ответа:** Наблюдаю значение адреса; очистка отменяет запрос и запрещает все поздние изменения; пустой адрес сбрасывает состояние; текущая ошибка не теряется; решение работает при игнорировании signal.
**Изучить:** [[Фронтенд/Vue/03. computed, watch и watchEffect|watch и cleanup]], [[Фронтенд/API браузера/05. Fetch, CORS и сетевые запросы/03. AbortController и race condition в запросах|Отмена и гонки]]

> [!example]- Разбор: каждое наблюдение владеет своей операцией
>
> ```js
> import { ref, toValue, watch } from 'vue';
> function useFetch(address, request) {
>   const data = ref([]);
>   const loading = ref(false);
>   const error = ref(null);
>   watch(
>     () => toValue(address),
>     (url, _, onCleanup) => {
>       let active = true;
>       const controller = new AbortController();
>       onCleanup(() => {
>         active = false;
>         controller.abort();
>       });
>       data.value = [];
>       error.value = null;
>       loading.value = Boolean(url);
>       if (!url) return;
>       Promise.resolve()
>         .then(() => request(url, { signal: controller.signal }))
>         .then((value) => {
>           if (active) data.value = value;
>         })
>         .catch((cause) => {
>           if (active)
>             error.value =
>               cause instanceof Error ? cause : new Error(String(cause));
>         })
>         .finally(() => {
>           if (active) loading.value = false;
>         });
>     },
>     { immediate: true, flush: 'sync' },
>   );
>   return { data, loading, error };
> }
> ```
>
> Создавай композиционную функцию синхронно в `setup`: Vue остановит наблюдение и вызовет очистку при удалении компонента. При редких сменах адреса `flush: 'sync'` сразу делает предыдущую операцию неактуальной. Такой режим не подходит для коллекций с частыми изменениями. Проверь завершение B перед A, позднюю ошибку A, пустой адрес во время ожидания и удаление компонента. Готовый сценарий: [[Фронтенд/Инженерные основы/07. Тестирование/02. Проверка поиска с поздними ответами|стенд поиска]]. Кэш и повторы не входят в этот этап.

> <p>
>   <template v-for="part in parts" :key="part.start">

> [!followup]- Нужно искать без учёта регистра. Уточните Unicode-контракт и покажите пример, который ломает наивную реализацию.

> Нельзя считать, что преобразование регистра сохраняет длину и индексы исходной строки. Например, `'İx'.toLowerCase()` даёт `i` + комбинируемую точку + `x`. Индекс `x` в преобразованной строке равен 2, но `'İx'.slice(2, 3)` уже пуст: подсветка по этим индексам ломается.
>
> Согласуй локаль, нормализацию Unicode и смысл равенства: должны ли `é` и `e\u0301` совпадать, считается ли `ß` эквивалентом `ss`, как обрабатываются турецкие I/İ/ı/i. `toLowerCase`, locale-aware преобразование и Unicode case folding решают разные задачи.

### Поиск репозиториев GitHub

Покажите имя, число звёзд и ответвлений репозитория; имя — ссылка на репозиторий. Первоначальный поиск — Vue. Усложнения: сначала только 5 результатов и «Показать ещё» по 5; после последней порции кнопка исчезает. При новом поиске — индикатор и снова первые 5. Запрос запускается через 1 секунду после окончания ввода. Лимит из условия — 10 поисковых запросов в минуту; это ограничение упражнения.

```js

  return fetch('https://api.github.com/search/repositories?q=' + encodeURIComponent(query))
    .then(result => result.json())
    .then(data => data.items)
    .then(repos => repos.map(({ forks, full_name, stargazers_count, html_url }) => ({
      forks, name: full_name, stars: stargazers_count, url: html_url
    })));
}
```

>
> Проверь response.ok и структуру items; после ошибки сохрани возможность повторить. Пауза в 1 секунду сама по себе не обеспечивает максимум 10 запросов в минуту: для такого требования нужен отдельный учёт времени запусков. Внешний API может иметь другие лимиты — 10 здесь учебное условие.

### Первый артикул остаётся при смене маршрута

Vue Router повторно использует компонент для /pages/:article. При переходе на другой артикул отображаются первые загруженные данные. Исправьте пример, сохранив переиспользование компонента; затем обсудите вариант с ключом RouterView и его цену.

```vue
<script setup>
import { ref, onMounted } from 'vue';
import { useRoute } from 'vue-router';
const route = useRoute();
const article = ref(null);
onMounted(async () => {
  article.value = await fetch('/api/articles/' + route.params.article).then(r => r.json());
});
</script>
<template><pre>{{ article }}</pre></template>
```

> [!note]- Подсказка
> наблюдать нужный параметр, гонка ответов, ошибка и отмена. Не запускайте запрос только потому, что изменилось несвязанное поле route.

> [!example]- Разбор — базовое решение
>
> onMounted срабатывает при монтировании, а не при каждом изменении параметра переиспользуемого компонента. Наблюдаем нужный параметр и запускаем первую загрузку через immediate. Базовый вариант целиком заменяет script setup исходного примера:
>
> ```vue
> <!-- core-example: article-route -->
> <script setup>
> import { ref, watch } from 'vue';
> import { useRoute } from 'vue-router';
> const route = useRoute();
> const article = ref(null);
> const error = ref('');
> const loading = ref(false);
> watch(
>   () => route.params.article,
>   async (id, previous, onCleanup) => {
>     const controller = new AbortController();
>     let current = true;
>     onCleanup(() => {
>       current = false;
>       controller.abort();
>     });
>     article.value = null;
>     error.value = '';
>     loading.value = true;
>     try {
>       const response = await fetch(
>         '/api/articles/' + encodeURIComponent(String(id)),
>         { signal: controller.signal },
>       );
>       if (!response.ok) throw new Error('HTTP ' + response.status);
>       const value = await response.json();
>       if (current) article.value = value;
>     } catch (reason) {
>       if (current)
>         error.value =
>           reason instanceof Error ? reason.message : 'Ошибка загрузки';
>     } finally {
>       if (current) loading.value = false;
>     }
>   },
>   { immediate: true },
> );
> </script>
> <template>
>   <p v-if="loading">Загрузка</p>
>   <p v-else-if="error" role="alert">{{ error }}</p>
>   <pre v-else>{{ article }}</pre>
> </template>
> ```
>
> В этом маршруте параметр article гарантированно является одной строкой. Изменение несвязанных параметров URL не запускает запрос. Очистка ресурсов работает и при смене параметра, и при удалении компонента, если наблюдатель создан синхронно. Флаг current нужен даже вместе с отменой: тестовый транспорт или уже выполняемое продолжение может завершиться позднее. Проверка актуальности нужна в обработчиках успеха, ошибки и завершения.
>
> Сначала завершите B, потом A — остаётся B. Затем завершите A, пока B ожидается — индикатор B остаётся. Проверьте отказ B и 404. Key у RouterView тоже может пересоздать компонент, но сбросит весь локальный ввод и ресурсы; выбирайте это только при необходимости полного сброса. Проверка схемы ответа для конкретного Article добавляется на границе API отдельно.

**Критерии ответа:** Наблюдаю только article, загружаю сразу, проверяю HTTP и защищаю data/error/loading от старого запроса.

### Обработчик прокрутки и актуальные входные свойства

Компонент передаёт событие прокрутки и статус пользователя в analytics.log. Найдите утечку, повторную регистрацию и потерю реактивности; исправьте работу при смене пропсов.

> Возьми [[Фронтенд/JavaScript/05. Асинхронность/07. Debounce и throttle#Debounce|обычный debounce с cancel]]. Создай его один раз в composable, зарегистрируй `onScopeDispose(debounced.cancel)` и верни функцию. Если delay — ref, читай текущее значение при планировании нового таймера.
>
> Для меняющегося callback явно выбери getter/ref либо зафиксируй функцию на время жизни. Вызов вне активной области Vue требует явного dispose; автоматическая очистка не возникает сама.

## Контракты компонентов и проверка интерфейса

### Полиморфная кнопка: кнопка или ссылка

Создайте Vue-компонент кнопки с входным свойством as: по умолчанию кнопка, при as="a" — ссылка. Задайте TypeScript-контракт: кнопка разрешает type/disabled и запрещает href; ссылка разрешает href/target/rel и по условию запрещает type/disabled. Последние два использования должны давать ошибку проверки шаблона.

```vue
<template>
  <Button @click="submit">Отправить</Button>
  <Button as="button" type="submit">Отправить</Button>
  <Button as="a" href="https://example.com" target="_blank">Перейти</Button>
  <!-- Ошибки по контракту задачи: -->
  <Button as="button" href="https://example.com">Кнопка</Button>
  <Button as="a" type="submit">Кнопка</Button>
</template>
```

Реализация кнопки не дана. Используйте динамический компонент, определите обработку атрибутов и событий. Проверяйте через vue-tsc, а не только сборку. Запрет type у ссылки — ограничение именно этого компонента: в HTML у ссылки есть type для MIME-типа. Усложнение: доступ к корневому DOM-элементу через ссылку на компонент.

> [!example]- Разбор простыми словами
>
> Сначала опиши два варианта props: `{ as?: 'button'; href?: never; type?: ...; disabled?: boolean }` и `{ as: 'a'; href: string; type?: never; disabled?: never; target?: string; rel?: string }`. Общее содержимое идёт через slot.
>
> Рендер выбирает button или a и передаёт только подходящие атрибуты. Для кнопки по умолчанию безопаснее type='button', если отправка формы не запрошена. Проверь запрещённые комбинации через vue-tsc. Ограничение type у ссылки здесь задано условием компонента.

### Vue-обёртка над библиотекой карты

Предоставленная библиотека работает с DOM напрямую. Реализуйте компоненты IndoorMap/MapPoint с декларативными параметрами центра и точек; изменения пропсов должны обновлять карту, удалённая точка — исчезать из библиотеки.

```js
const map = new IndoorMap({ element: document.getElementById('map') });
map.setCenter(10, 10);
const point = map.addPoint(15, 15);
map.removePoint(point);
```

Требуемая форма использования:

```vue
<template>
  <MapView :center="[10, 10]">
    <MapPoint v-for="point in points" :key="point.id" :position="point.position" />
  </MapView>
</template>
```

Добавление точки [0,0] и удаление всех точек должны отражаться на карте. Обсудите provide/inject, наблюдение за входными свойствами и освобождение ресурсов. Вариант: обёртка Canvas/Rect над рисованием на canvas. Метод уничтожения карты в исходном интерфейсе не указан — сначала уточните его.

> [!example]- Разбор простыми словами
>
> MapView создаёт экземпляр библиотеки после появления DOM-контейнера и предоставляет его детям через provide. Каждый MapPoint добавляет свою точку, хранит возвращённую ссылку и удаляет её при удалении компонента. Изменение координат передаётся библиотеке через её API; если перемещения нет, удаляется старая точка и создаётся новая.
>
> Ноль — допустимая координата, поэтому проверка `if (x && y)` неверна. Создание карты и уничтожение требуют реального контракта библиотеки: отсутствующий destroy нельзя выдумать. Освобождение слушателей и экземпляра нужно уточнить до обещания отсутствия утечек.

### Карта бронирований: проверка кода

Компонент должен загрузить место по locationId, показать доступные интервалы каждого spots и отметить выбранное место. Найдите ошибки реактивности, структуры данных и работы с запросом. Функция loadLocation предоставлена извне; она возвращает Promise с объектом {name}.

```vue
<script setup>
import { ref, watchEffect } from 'vue';
import { loadLocation } from './api';
const props = defineProps({ locationId: String, spots: Array });
const location = ref({});
const selected = ref();
watchEffect(() => {
  loadLocation(props.locationId).then(value => location.value = value);
});
const availableSpotTime = props.spots.map(spot => ({
  [spot.id]: spot.timeslots.find(slot => slot.isAvailable)
}));
</script>
<template>
  <h1>Места в {{ location.name }}</h1>
  <div v-for="spot in spots" @click="selected = spot.id"
       :class="{ active: selected === spot.id }">
    {{ spot.id }}: {{ availableSpotTime[spot.id] }}
  </div>
</template>
```

Проверьте смену spots, быстрые изменения locationId, ошибку запроса и отсутствие доступного интервала. Не считайте отсутствие TypeScript-типов единственной проблемой.

> [!example]- Разбор простыми словами
>
> `props.spots.map(...)` выполняется один раз и создаёт массив объектов, а шаблон обращается к нему как к словарю по id. Сделай computed с Map по id или вычисляй доступные интервалы рядом с каждой строкой. Если нужны все интервалы, используй filter, а не find.
>
> Запрос location требует error/loading и защиты от позднего ответа. Для списка нужен key по spot.id. Выбор места оформляй доступной кнопкой или другим подходящим контролом, а не только click на div. Отсутствие интервала показывай явно, не как undefined.

### Список дел: добавить, переключить и удалить

**Формат раунда:** Написание кода
**Этап кода:** main

Реализуй список дел на Vue 3. Вход `initialData` — массив `{ id: string, text: string, isDone: boolean }` с уникальными ID. Это только начальный снимок; не изменяй массив и объекты родителя. Новое дело получает уникальный ID через переданную `makeId()`. Добавление обрезает пробелы, игнорирует пустой текст и очищает поле после успеха. Переключение меняет isDone, удаление убирает запись по id; неизвестный ID ничего не делает.

Пример: начальное «Прочитать» → ввести ` Написать ` → добавить → два дела, поле пустое. Переключить первое → выполнено. Удалить второе → осталось первое. Добавление одних пробелов не меняет список. Покажи доступные кнопки/checkbox и устойчивые ключи.

**Критерии ответа:** Все три операции соблюдают пример; строки обрезаются, пустое дело не создаётся; объекты родителя сохраняются; ID стабилен и используется как key; ввод очищается только после добавления.
**Изучить:** [[Фронтенд/Vue/02. ref, reactive и потеря реактивности|Реактивное состояние]], [[Фронтенд/Vue/07. Шаблоны, директивы, события и v-model|Список и события]], [[Фронтенд/Vue/04. Компоненты, props, emits и slots|Владение props]]

> [!example]- Разбор: локальный список и операции по ID
>
> ```js
> // checked-example: vue-todos-base
> import { ref } from 'vue';
> function useTodos(initialData, makeId) {
>   const items = ref(initialData.map((item) => ({ ...item })));
>   const text = ref('');
>   function addItem() {
>     const value = text.value.trim();
>     if (!value) return;
>     items.value.push({ id: makeId(), text: value, isDone: false });
>     text.value = '';
>   }
>   function toggleItem(id) {
>     const item = items.value.find((item) => item.id === id);
>     if (item) item.isDone = !item.isDone;
>   }
>   function deleteItem(id) {
>     items.value = items.value.filter((item) => item.id !== id);
>   }
>   return { items, text, addItem, toggleItem, deleteItem };
> }
> ```
>
> Экспортируй useTodos из useTodos.js. Здесь makeId гарантирует отсутствие коллизий с начальными и новыми ID, а приложение передаёт, например, `() => crypto.randomUUID()`.
>
> ```vue
> <script setup>
> import { useTodos } from './useTodos.js';
> const props = defineProps({ initialData: Array, makeId: Function });
> const { items, text, addItem, toggleItem, deleteItem } = useTodos(
>   props.initialData,
>   props.makeId,
> );
> </script>
> <template>
>   <form @submit.prevent="addItem">
>     <label>Новое дело <input v-model="text" /></label>
>     <button type="submit">Добавить</button>
>   </form>
>   <ul>
>     <li v-for="item in items" :key="item.id">
>       <label
>         ><input
>           type="checkbox"
>           :checked="item.isDone"
>           @change="toggleItem(item.id)"
>         />{{ item.text }}</label
>       >
>       <button type="button" @click="deleteItem(item.id)">
>         Удалить {{ item.text }}
>       </button>
>     </li>
>   </ul>
> </template>
> ```
>
> Копии записей отделяют локальный черновик от родителя. Изменение initialData после создания списка намеренно не синхронизируется: это начальный снимок, а не управляемая модель.

#### Выделение Item с контрактом событий

Вынеси строку в Item.vue. Компонент получает объект data, не меняет его и испускает toggle/delete с ID. Родитель по-прежнему владеет массивом. Проверь переключение и удаление второго элемента после удаления первого: событие должно использовать ID записи, а не прежний индекс.

**Критерии ответа:** Item не мутирует props; оба события несут ID; родитель сохраняет операции и ключи; checkbox отражает актуальное isDone.
**Изучить:** [[Фронтенд/Vue/04. Компоненты, props, emits и slots|Контракт props/emits]]

> [!example]- Разбор: события вместо изменения props
>
> ```vue
> <script setup>
> defineProps({ data: { type: Object, required: true } });

> </script>

### Лента публикаций: реклама и страницы

Проверьте Vue-компонент: загрузка posts/offers, вычисляемый список, реклама после каждых 10 публикаций, выбор размера страницы. usePostsStore/useOffersStore — предоставленные хранилища Pinia, enrichPost обогащает публикацию. Их внутренние реализации не заданы.

```vue
<script setup>
import { computed, onMounted } from 'vue';
import { usePostsStore, useOffersStore } from './stores';
import { enrichPost } from './utils';
const postsStore = usePostsStore();
const offersStore = useOffersStore();
const { posts, isLoading } = postsStore;
const { offer } = offersStore;
const emit = defineEmits(['changePagination']);
const rows = computed(() => posts.reduce((acc, post, index) => {
  if (index % 10 === 0) acc.push(offer);
  return [...acc, enrichPost(post)];
}, []));
onMounted(() => { postsStore.fetchPosts(); offersStore.fetchOffers(); });
</script>
<template>
  <p v-if="isLoading">Загрузка</p>
  <ul v-else><li v-for="post in rows">{{ post.title }} — {{ post.date }}</li></ul>
  <select @change="emit('changePagination', $event.target.value)">
    <option :value="10">10</option><option :value="20">20</option>
  </select>
</template>
```

Найдите ошибки с реактивностью Pinia, позицией рекламы, отсутствующим offer, ключами, типом значения select и ошибками запроса. Оцените стоимость копирования массива на каждом шаге reduce.

> [!example]- Разбор простыми словами
>
> Доставай реактивные поля Pinia через storeToRefs. В одном проходе сначала добавляй публикацию, затем, если `(index + 1) % 10 === 0` и offer существует, рекламу. Не копируй весь накопленный массив на каждой итерации.
>
> У строки должны быть тип и устойчивый ключ: одна и та же реклама после разных десятков имеет разные позиции и ключи. Значение select приходит строкой — преобразуй и проверь допустимый размер страницы. Обработай ошибки обоих запросов и определи, можно ли показать публикации без рекламы.

## Проектирование компонентов и состояния

### Большой компонент формы

Компонент одного экрана содержит запросы к API, проверку ввода и прав, преобразование данных и десятки полей. Разделить ответственность: интерфейс отображает данные, модель формы управляет вводом, прикладные правила проверяют допустимость действий, а модуль API обменивается данными с сервером.

> [!example]- Разбор простыми словами
>
> Оставь отображение и события в компонентах, состояние черновика и сохранения — в composable формы, чистые правила — в отдельных функциях, HTTP — в API-адаптере. Делить по каждому полю не обязательно: граница должна скрывать самостоятельное правило. См. [[Собеседования/Проектирование/Клиентское приложение#Бизнес-форма с согласованием|пошаговый разбор формы]].
>
> Пример границы: компонент полей сообщает об изменениях, composable хранит черновик и выполняет submit, чистая функция валидирует диапазон дат, API-адаптер превращает DTO. Начинаю с одной такой обязанности, а не раскладываю каждый input по отдельному файлу. Сохраняю единый сценарий: изменение → валидация → сохранение → отказ с сохранённым вводом.
>
> Проверяю, что после выделения модулей не появились две копии черновика и событие не теряет промежуточное изменение. Размер файла — сигнал для исследования, но выбранная граница должна объяснять ответственность и облегчать изменение поведения.
### Неявный общий state

Composable объявляет `ref` на уровне модуля. Два независимых экрана неожиданно разделяют значение. Объяснить причину и предложить API с явным shared или per-instance состоянием.

> [!example]- Разбор простыми словами
>
> Код модуля выполняется при его загрузке, поэтому ref вне функции один на все вызовы. Для независимых экземпляров создавай ref внутри composable. Для общего состояния используй явно названный store или фабрику, передаваемую потребителям. При SSR общий модульный state не должен смешивать данные разных запросов.

### Лишняя работа списка

Таблица на несколько тысяч строк пересчитывает тяжёлое форматирование при любом изменении фильтра. Определить, что измерять, где вычислять данные и когда нужны pagination или virtualization.

> [!example]- Разбор простыми словами
>
> Измерь отдельно вычисление данных и отрисовку DOM. Вынеси чистое производное значение в computed, убери повторное форматирование неизменных данных. Если проблема в числе строк, выбирай пагинацию или виртуализацию; computed не уменьшит DOM сам по себе. Практика: [[Фронтенд/Инженерные основы/04. Производительность/03. Практическая диагностика таблицы, ввода и памяти|таблица и задержка ввода]].

### Типизированный компонент

Опиши компонент выбора: входное значение `modelValue`, событие его обновления, список вариантов, отключённое состояние и слот для отображения варианта. Покажи, как связать тип выбранного значения с типом вариантов без лишнего усложнения.

> [!example]- Разбор простыми словами
>
> Начни с конкретного типа Option: id и label. ModelValue содержит id выбранного элемента или null, событие update:modelValue передаёт тот же тип. Slot получает option для отображения. Disabled запрещает изменение, но не скрывает текущее значение.
>
> Параметр типа нужен, если разные потребители передают значения разных типов. Он должен сохранять полезную связь между ними. Если все варианты имеют один известный тип, достаточно обычного описания свойств.

### Store или composable

Одни и те же фильтры нужны списку, счётчику и URL. Выбрать владельца состояния, способ синхронизации и защиту от циклических обновлений.

Модальные окна: [[Собеседования/Проектирование/Клиентское приложение#Слой модальных окон и всплывающих элементов|проектирование всплывающих элементов]]. Проверка загрузки, повторной попытки и сохранения: [[Собеседования/Практика/Тестирование#Форма: результат, ошибка и повтор|задача на тестирование формы]].

> [!example]- Разбор
>
> Сначала выбираю источник истины. Если фильтры должны восстанавливаться через Back/reload и передаваться ссылкой, каноническое состояние фильтра удобно читать из URL. Composable разбирает и нормализует query, предоставляет вычисляемые значения списку и счётчику, а действия меняют URL. Отдельный локальный ref нужен только для ещё не применённого текста ввода с явным правилом синхронизации.
>
> Pinia нужна, если состояние действительно разделяется независимыми областями приложения и не принадлежит только маршруту. Не делаю две встречные подписки URL→store и store→URL без сравнения нормализованных значений: они создают циклы и лишнюю историю. Для ввода обычно replace, для отдельного пользовательского перехода — push по контракту.
>
> Проверки: прямой URL, Back, reload, пустые/невалидные параметры, изменение фильтра и согласованные список/счётчик. Название store или composable само не задаёт владельца состояния.

Версия примеров — Vue 3.5; разборы не подразумевают существование неуказанных методов внешних библиотек.
