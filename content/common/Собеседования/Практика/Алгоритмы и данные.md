# Алгоритмы: практические задачи

[[Собеседования/00. Карта раздела|Карта банка]]

Расширенная практика под алгоритмический формат. Здесь оставлены разные механизмы и ограничения, а не обязательный набор из всех задач. Для обычного frontend-интервью начни с преобразования данных, обхода дерева и объяснения сложности. Банкомат, острова и LRU нужны при таком формате задания, а не как постоянный экзамен Senior.

Решайте до просмотра разбора. Исходные ошибки в коде сохранены намеренно. Если в условии не указаны среда выполнения и режим или поведение пустого входа, сначала сформулируйте нужное уточнение.

## Строки и разбор текста

### Одна вставка, удаление или замена символа

**Условие.** Проверьте, можно ли получить одну строку из другой не более чем одной вставкой, удалением или заменой символа. Примеры cat/dog → false; cat/cats → true; cat/cut → true; cat/cat → true; cat/at → true; cat/acts → false. Цель O(N), O(1) памяти.

> [!example]- Разбор
>
> Если длины отличаются больше чем на один символ, ответ false. Иду двумя указателями. При равенстве сдвигаю оба; при первом различии отмечаю использованную правку и сдвигаю оба для равных длин либо только указатель длинной строки. Второе различие означает false. Оставшийся последний символ длинной строки расходует одну правку. Одинаковые строки допустимы: «не более одной» включает ноль.
>
> Для cat/cats три совпадения и один хвост дают true; cat/acts требует больше одной правки. Время O(n), память O(1) при выбранной единице символа. В JavaScript индексирование строки работает с UTF-16 code units; если нужны Unicode code points или графемы, контракт и оценку памяти следует пересмотреть. Проверки: обе пустые, пустая/один символ, замена первого/последнего, две замены, лишний символ в середине.

### RLE-сжатие строки

**Условие.** Для строки букв A–Z верните кодирование серий: повторяющаяся буква получает число повторений, одиночная — без числа. Пример "AABBBCCXYZDDDDEEEFFF" → "A2B3C2XYZD4E3F3". Пустая строка допустима; недопустимый символ должен дать ошибку. Следите за последней серией.

Большой пример: 4×A, 3×B, 2×C, X,Y,Z, 4×D, 3×E, 3×F, 6×A, 28×B → A4B3C2XYZD4E3F3A6B28. Проверки: пустая строка, один символ, два разных, серия длиннее девяти символов, последняя серия и несколько серий.

**Критерии ответа:** Сохраняю последнюю серию, не пишу единицу для одиночной буквы, отклоняю неверный алфавит и объясняю время O(n).
**Изучить:** [[Фронтенд/JavaScript/07. Массивы и коллекции/02. Методы массивов и перебор|Перебор и накопление результата]]

> [!example]- Разбор RLE
>
> Два индекса ограничивают текущую серию: левый остаётся у её первой буквы, правый движется до другой буквы или конца строки. После записи серии левый переносится к правому. Пустой вход не заходит в цикл; последняя серия обрабатывается тем же правилом, что остальные.
>
> ```js
> // checked-example: rle
> function encodeRuns(text) {
>   if (typeof text !== 'string' || !/^[A-Z]*$/.test(text)) {
>     throw new TypeError('Expected A–Z letters');
>   }
>   const result = [];
>   let left = 0;
>   while (left < text.length) {
>     let right = left + 1;
>     while (right < text.length && text[right] === text[left]) right++;
>     const count = right - left;
>     result.push(text[left] + (count === 1 ? '' : String(count)));
>     left = right;
>   }
>   return result.join('');
> }
> ```
>
> `encodeRuns('AB')` → `'AB'`, `encodeRuns('AAAAAAAAAAAA')` → `'A12'`, `encodeRuns('')` → `''`; строчная буква вызывает ошибку. Указатели суммарно проходят n позиций: время O(n), память результата O(n). Частая ошибка — записывать серию только при появлении следующей буквы и потерять последнюю. Это кодирование не гарантирует уменьшения размера.

### Группировка анаграмм

**Условие.** Сгруппируйте строки по совпадению кратностей букв. Требуется эффективное использование времени и памяти; порядок групп и строк нужно уточнить. Отдельное уточнение — заданный порядок результата, его нельзя потерять при объединении условий.

Для решения ниже выбираем явный контракт: плотный массив строк из `a–z`, включая пустую строку; регистр, пробелы и Unicode не нормализуются. Группы идут по первому появлению своей анаграммы, строки внутри — в порядке входа; повторы сохраняются. Например, `['eat', 'tea', 'tan', 'ate', 'nat', 'bat']` даёт три группы: `['eat', 'tea', 'ate']`, `['tan', 'nat']` и `['bat']`. Вход не меняется.

> [!example]- Разбор группировки анаграмм
>
> У анаграмм одинаковый набор букв с одинаковыми кратностями. Отсортированная копия букв становится ключом: `eat` и `tea` дают `aet`, а `aab` и `abb` дают разные ключи. Map хранит группы по первому добавлению ключа.
>
> ```js
> // checked-example: anagrams
> function groupAnagrams(words) {
>   if (!Array.isArray(words)) throw new TypeError('words must be an array');
>   const groups = new Map();
>   for (const word of words) {
>     if (typeof word !== 'string' || !/^[a-z]*$/.test(word)) {
>       throw new TypeError('expected lowercase ASCII words');
>     }
>     const key = [...word].sort().join('');
>     if (!groups.has(key)) groups.set(key, []);
>     groups.get(key).push(word);
>   }
>   return [...groups.values()];
> }
> ```
>
> Для n строк максимальной длины L время O(n · L log L) с учётом сортировки; память включает результат и ключи групп, до O(n · L) символов ключей. Строки в результате переиспользуются как значения. Проверки: пустой массив → `[]`; две пустые строки дают одну группу с двумя пустыми строками; `['aab', 'abb', 'aba', 'aab']` даёт группы `['aab', 'aba', 'aab']` и `['abb']`; вход сохраняет прежний порядок. Неверный алфавит отклоняется, а не незаметно очищается.
>
> **Усложнение.** Для фиксированного алфавита из 26 букв используй массив частот как ключ, с однозначными разделителями: время O(n · (L + 26)). Для русского текста сначала договорись о регистре, `ё`, Unicode-нормализации и том, что считать символом. Сумма кодов букв не является надёжным ключом: возможны коллизии. Сортировка групп по размеру — отдельное условие, которое меняет исходный порядок.

### Самая длинная подстрока без повторов

**Этап кода:** advanced

**Условие.** Верните длину наибольшего непрерывного участка без повторяющихся символов. Цель O(N). Уточните алфавит и модель символа; пустая строка даёт 0. Не путать с подсчётом всех таких подстрок.

Для этого решения символом считаем Unicode code point: `😀a😀b` даёт 3. Составной видимый символ из нескольких code point не объединяем; нормализацию не выполняем. Вернуть нужно длину, а не саму подстроку.

**Формат раунда:** Написание кода
**Критерии ответа:** Поддерживаю окно без повторов, не сдвигаю левую границу назад на abba, различаю code point и графему; объясняю O(n).
**Изучить:** [[Фронтенд/JavaScript/07. Массивы и коллекции/03. Map, Set, WeakMap и WeakSet|Map и поиск последнего вхождения]], [[Собеседования/Темы/Алгоритмы и программирование#Когда применять два указателя и скользящее окно?|Скользящее окно]], [[Собеседования/Темы/Алгоритмы и программирование#Как оценивать время работы и дополнительную память?|Сложность алгоритма]]

> [!example]- Разбор скользящего окна
>
> Map хранит последний индекс каждого символа. Если он уже находится внутри текущего окна, переносим начало за его прошлое вхождение. Если вхождение осталось слева от окна, начало менять нельзя: поэтому нужен Math.max, а не безусловное присваивание.
>
> ```js
> // checked-example: unique-window
> function longestUnique(text) {
>   if (typeof text !== 'string') throw new TypeError('Expected a string');
>   const last = new Map();
>   let left = 0;
>   let right = 0;
>   let best = 0;
>   for (const character of text) {
>     const previous = last.get(character);
>     if (previous !== undefined) left = Math.max(left, previous + 1);
>     last.set(character, right);
>     best = Math.max(best, right - left + 1);
>     right++;
>   }
>   return best;
> }
> ```
>
> Проверки: `''` → 0, `'aaaa'` → 1, `'abba'` → 2, `'abcabcbb'` → 3, `'😀a😀b'` → 3. `for...of` считает code point, а `text[i]` дал бы кодовые единицы UTF-16. При обычной модели Map ожидаемое время O(n), память O(k), где k — число разных символов. Проверка всех подстрок не сохраняет линейную сложность.

**Уточнения**
- Как вернуть саму подстроку, не смешав индексы code point и UTF-16?
- Что потребуется для длины в видимых символах, включая emoji с соединителем?

### Нормализация пути Unix

**Условие.** Сверните повторные /, . и .. по контракту относительного/абсолютного пути. Для абсолютного пути нельзя подниматься выше /. Для относительного начальные .. может сохраниться; это нужно явно определить. Функция не обращается к файловой системе и не разрешает символьные ссылки.

> [!example]- Разбор
>
> Разбиваю путь по / и обрабатываю сегменты стеком. Пустой сегмент и . пропускаю. Для .. удаляю последний обычный сегмент; если удалить нечего, в абсолютном пути остаюсь у корня, а в относительном сохраняю .. . Уже сохранённый .. нельзя поглощать следующим .. . Остальные имена кладу в стек.
>
> Для /a//b/../c результат /a/c; для ../../a/.. результат ../.. . Пустой нормализованный относительный путь представляю как ., абсолютный — как /. Это выбранный текстовый контракт: обращений к файловой системе нет, поэтому /link/.. не обязано означать то же самое при реальном разрешении symlink. Проверки: /../../, ../.., a/../../b, скрытые имена .config и завершающий /. Время и память O(n) по длине входа.

## Массивы, поиск и размен

### Пара чисел с заданной суммой

Верни индексы двух разных элементов, сумма которых равна target. Вход — плотный массив безопасных целых чисел, target — безопасное целое. Один элемент нельзя использовать дважды, исходный массив не меняется. При отсутствии пары верни `null`. Если пар несколько, выбирай первую по правому индексу, а для него — самый ранний подходящий левый индекс. Примеры: `[2, 7, 11, 15], 9` → `[0, 1]`; `[3, 3], 6` → `[0, 1]`; `[3], 6` → `null`.

> [!example]- Разбор поиска пары
>
> Для текущего числа x ищем ранее встреченное `target - x`. Сначала ищем, потом сохраняем x — иначе число могло бы найти само себя. Map хранит первый индекс каждого значения.
>
> ```js
> // checked-example: two-sum
> function twoSum(values, target) {
>   if (!Array.isArray(values) || !Number.isSafeInteger(target)) {
>     throw new TypeError('expected an array and a safe integer target');
>   }
>   for (const value of values) {
>     if (!Number.isSafeInteger(value))
>       throw new TypeError('expected safe integers');
>   }
>   const seen = new Map();
>   for (let right = 0; right < values.length; right++) {
>     const value = values[right];
>     const left = seen.get(target - value);
>     if (left !== undefined) return [left, right];
>     if (!seen.has(value)) seen.set(value, right);
>   }
>   return null;
> }
> ```
>
> Ожидаемое время O(n), память O(n) при обычной модели Map. Проверки: пустой массив; повторяющиеся числа; отрицательные значения; `[0, 4, 0], 0` → `[0, 2]`; `[1, 1, 2], 3` → `[0, 2]`. Индекс 0 нельзя проверять через `if (left)` — это допустимый найденный индекс. Отдельно проверь неверный вход и неизменность массива.
>
> **Усложнения.** Если возвращать все пары индексов, число результатов само может быть O(n²). Если массив уже отсортирован, возможны два указателя и O(1) дополнительной памяти, но порядок выбора пары нужно согласовать заново. Сортировать исходный массив без сохранения индексов нельзя. Для дробных чисел требуется отдельный договор о точности.

### Медиана набора чисел

Реализуй `median(values)` для плотного непустого массива конечных JS-чисел. Медиана — центральное значение отсортированного набора; при чётном количестве — среднее двух центральных. `[9, 1, 3]` → `3`; `[1, 2, 10, 20]` → `6`. Массив нельзя менять; пустой вход, NaN и бесконечности отклоняются. Результат имеет обычную точность Number.

> [!example]- Разбор медианы
>
> Сортируем копию численно. Нечётная длина даёт один индекс floor(n / 2), чётная — два соседних. Сортировка без компаратора была бы строковой: например, 10 может оказаться перед 2.
>
> ```js
> // checked-example: median
> function median(values) {
>   if (!Array.isArray(values) || values.length === 0) {
>     throw new RangeError('expected a non-empty array');
>   }
>   for (const value of values) {
>     if (typeof value !== 'number' || !Number.isFinite(value)) {
>       throw new TypeError('expected finite numbers');
>     }
>   }
>   const sorted = [...values].sort((a, b) => a - b);
>   const middle = Math.floor(sorted.length / 2);
>   if (sorted.length % 2) return sorted[middle];
>   const left = sorted[middle - 1];
>   const right = sorted[middle];
>   const sum = left + right;
>   return Number.isFinite(sum) ? sum / 2 : left / 2 + right / 2;
> }
> ```
>
> Ветка с половинами предотвращает Infinity при сложении двух очень больших конечных чисел; она не превращает Number в точную десятичную арифметику. Ожидаемое время O(n log n), память O(n) для копии, плюс служебная память реализации sort. Проверки: один элемент; два элемента; отрицательные и повторяющиеся значения; уже отсортированный вход; `[Number.MAX_VALUE, Number.MAX_VALUE]`; пустой массив и NaN. Сравни вход до/после.
>
> **Усложнения.** Если нужна медиана одного большого массива без полной сортировки, обсуди Quickselect и его худший случай. Для потока значений подходят две кучи с балансировкой. Это другие контракты: приведённое решение обрабатывает уже имеющийся конечный набор и не реализует потоковую медиану.

### Непрерывный подотрезок с суммой X

**Условие.** Для массива целых чисел найдите любой непустой непрерывный отрезок с заданной суммой, либо отсутствие решения. Вход может содержать отрицательные числа. Обсудите переполнение частичных сумм и разницу с вариантом только с положительными числами.

Нужно вернуть границы подотрезка, а не только факт существования. В исходном варианте разрешены отрицательные числа.

> [!example]- Разбор
>
> Использую префиксные суммы: сумма от l до r равна prefix[r + 1] − prefix[l]. Храню в Map первую позицию каждой уже увиденной суммы; до обхода там 0 → −1. Для текущей суммы s ищу s − X. Если индекс найден, непустой отрезок начинается после него и заканчивается текущим элементом. Сначала ищу, затем записываю текущую сумму — иначе при X=0 можно ошибочно вернуть пустой отрезок.
>
> Для [2, -1, 2] и X=1 на втором элементе s=1, в Map есть 0 → −1: возвращаю [0,1]. Скользящее окно с удалением слева при слишком большой сумме здесь не подходит: отрицательное число нарушает монотонность. Ожидаемое время O(n), память O(n). Проверки: решение с индекса 0, нулевая сумма, повторные префиксы, отсутствие решения. Для JS Number проверяю безопасный диапазон сумм; при необходимости использую BigInt согласованно для значений, X и ключей.

### K ближайших к элементу отсортированного массива

Дан массив a, отсортированный по неубыванию, индекс index и K. Верните в любом порядке K чисел, ближайших по значению к a[index], **включая сам выбранный элемент**. Требуется O(K) времени.

Ограничения: 1≤N≤10⁶; −10⁹≤a[i]≤10⁹; 0≤K≤N; 0≤index<N.

```cpp
std::vector<int> find_k_closest(const std::vector<int>& a,
                               size_t index, size_t k);
// {2,3,5,7,11}, index=3, k=2 -> {5,7 }
// {4,12,15,15,24}, index=1, k=3 -> {12,15,15 }
// {2,3,5,7,11}, index=2, k=2 -> {3,5} или {5,7 }
```

Отдельное уточнение может потребовать меньший элемент при равных расстояниях. Не добавляйте это правило молча.

> [!example]- Разбор
>
> При K=0 возвращаю пустой результат. Иначе первым беру a[index], ставлю left=index−1 и right=index+1. Пока нужно ещё число, сравниваю расстояния соседей до исходного a[index], выбираю ближайшего и сдвигаю только его указатель. Если одна сторона исчерпана, беру другую. На каждой стороне расстояния не убывают, поэтому ближайший оставшийся элемент обязательно стоит у одной из границ.
>
> Дубликаты являются отдельными элементами, их не удаляю. При равных расстояниях условие допускает любую сторону; если требуется меньший элемент, выбираю левую. Время O(K), дополнительная память O(1) без результата, результат O(K). В C++ не уменьшаю size_t ниже нуля: использую безопасную проверку границы или знаковый индекс. Проверки: K=0, K=N, крайний index, одинаковые значения, равные расстояния.

### K ближайших к значению X

Дан отсортированный массив целых чисел, K и X. Верните K ближайших к X чисел **в порядке возрастания**. При равном расстоянии выбирайте меньшее число. Элементы и X не больше 10⁴; K≤N; N≤10⁶.

```text
[1,2,3,4,5], K=4, X=3  -> [1,2,3,4]
[1,2,3,4,5], K=4, X=-1 -> [1,2,3,4]
```

В отличие от предыдущего варианта, дано значение X, а не индекс: учтите стоимость его поиска.

**Сравнение с соседним вариантом:** когда дан индекс уже существующего элемента, можно начать прямо с него и получить O(K); произвольное X сначала требует поиска границы O(log N). Объясни разные ограничения, порядок результата и равные расстояния.

> [!example]- Разбор
>
> Бинарным поиском нахожу первую позицию не меньше X. Ставлю указатели по обе стороны и K раз расширяю выбранный интервал в сторону ближайшего значения. При равном расстоянии беру левое, то есть меньшее число. После K выборов возвращаю срез между итоговыми границами: он уже отсортирован; порядок самих выборов сортировкой не является.
>
> Например, [1,2,3,4,5], X=3, K=4 даёт интервал [1,2,3,4], потому что при последнем равенстве выбирается 1, а не 5. Стоимость O(log n + K), память результата O(K). Проверки: X вне диапазона, K=0, K=N, дубликаты и равные расстояния. Не обещаю O(K) для произвольного X: начальную позицию ещё нужно найти.

### Пересечение интервалов двух пользователей

**Условие.** Даны два отсортированных списка непустых интервалов присутствия пользователей в сети. Найдите интервалы, когда оба были в сети одновременно. Уточните, включаются ли границы и могут ли пересекаться интервалы внутри одного списка. Здесь нужно пересечение двух списков, а не объединение интервалов одного списка.

> [!example]- Разбор
>
> Для двух списков с непересекающимися внутри каждого интервалами держу по указателю. Пересечение текущей пары: начало max(startA,startB), конец min(endA,endB). Для полуинтервалов добавляю результат только при start < end; для замкнутых возможно start = end. Затем продвигаю интервал с меньшим концом, при равных концах можно продвинуть оба: он уже не пересечёт последующие интервалы другого списка.
>
> При внутренних перекрытиях сначала нормализую каждый список, иначе возможны повторяющиеся участки результата. Пример [1,4), [6,9) и [3,7) даёт [3,4), [6,7). Проверки: касание границ, пустой список, один интервал внутри другого, одинаковые концы. Сам проход O(n+m), память кроме результата O(1); сортировка и нормализация, если требуются, учитываются отдельно.

### Банкомат с ограниченным количеством купюр

**Условие.** Номиналы 50,100,500,1000,5000. Вход содержит количество купюр каждого номинала; выдайте сумму, предпочитая крупные купюры, и обновите остаток. При невозможности — ошибка без частичной выдачи. Уточните, требуется ли поиск любого точного размена при неудаче жадного выбора.

> [!example]- Разбор
>
> Сначала проверяю сумму и неотрицательные целые остатки. Строю план выдачи отдельно от состояния банкомата: выбираю допустимое число крупных купюр, уменьшаю остаток суммы, перехожу к следующему номиналу. Только если остаток суммы ноль, применяю весь план. При неудаче исходные количества остаются прежними.
>
> Контракт должен уточнять смысл «предпочитая крупные»: лексикографический приоритет количеств или минимальное число купюр. Если требуется гарантированный точный размен при любых номиналах/лимитах, использую ограниченный поиск с возвратом либо динамическое программирование по сумме. Нельзя переносить гарантию жадного алгоритма с одной системы номиналов на произвольную. Проверки: точная выдача, недостаток общей суммы, достаточно денег без нужного размена, ноль, повтор после отказа. При конкурентной выдаче проверка и списание должны быть одной атомарной операцией на владельце остатков; локальная функция сама этого не обеспечивает.

### Слияние и пересечение отсортированных массивов

Даны два отсортированных массива. Верните новый отсортированный массив с объединением либо пересечением элементов, не изменяя входы.

```text
a = [1,2,2,5,7,14]
b = [4,6,6,7,9,14,15]
слияние -> [1,2,2,4,5,6,6,7,7,9,14,14,15]
intersection -> [7,14]
```

При объединении повторяющихся значений возможны два правила: сложить количество вхождений из обоих списков или взять большее из двух количеств. Сначала выберите правило. При пересечении количество равно `min(n, m)`.

**Вариант — разность A без B с учётом повторений.** Входы — плотные массивы конечных чисел, отсортированные по неубыванию. Для каждого числа x оставить max(countA(x) − countB(x), 0) вхождений; результат отсортирован, входы неизменны. Это не разность множеств: для A=[1,2,2,2,5] и B=[2,2,4] результат [1,2,5], а не [1,5]. Проверять сортировку входа в этой функции не требуется — это предусловие. NaN, holes и пользовательский comparator вне контракта.

> [!example]- Разбор
>
> В слиянии сравниваю текущие элементы двух массивов, добавляю меньший и двигаю его указатель; при равенстве для указанного примера сохраняю оба вхождения. В конце добавляю хвост. Для пересечения при равенстве добавляю одно значение и двигаю оба; при неравенстве двигаю меньший. Так число одинаковых значений в пересечении равно минимуму двух количеств.
>
> Например, [2,2,2] и [2,2] дают пять двоек при слиянии и две при пересечении. Если для объединения выбран максимум кратностей, обрабатываю серии одинаковых значений и добавляю max(countA,countB), это другой контракт. Оба прохода O(n+m), входы неизменны, память — результат. Проверки: пустой массив, непересекающиеся значения, серии дубликатов и полностью одинаковые входы.

> [!example]- Два указателя для разности
>
> Указатель B пропускает значения, меньшие текущего A: они уже не смогут совпасть с этим или последующим значением A. Равные элементы погашают друг друга по одному. Если равного B нет, текущий A остаётся в результате.
>
> ~~~js
> // checked-example: sorted-multiset-difference
> function sortedDifference(a, b) {
>   const result = [];
>   let i = 0;
>   let j = 0;
>   while (i < a.length) {
>     while (j < b.length && b[j] < a[i]) j++;
>     if (j < b.length && b[j] === a[i]) {
>       i++;
>       j++;
>     } else {
>       result.push(a[i++]);
>     }
>   }
>   return result;
> }
> ~~~
>
> Инвариант: для обработанного префикса A уже принято окончательное решение, а использованный элемент B не погасит второе вхождение. Указатели только растут, поэтому время O(n + m), дополнительная память кроме результата O(1). Память результата O(k), где k ≤ n.
>
> Проверки: пустой A/B; полное погашение; больше повторений слева и справа; непересекающиеся диапазоны; отрицательные числа; сохранность входов. Если нужны уникальные элементы A, которых вообще нет в B, это другой контракт: Set удаляет повторения. [MDN: Set](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Set).

### Объединение пользователей по email

**Условие.** Пользователь имеет user_id и набор email. Пользователи с общим email принадлежат одной компоненте, включая транзитивные связи; верните объединённые группы с уникальными email. Параметры N/M произвольны. Не используйте только попарную проверку одной пары.

> [!example]- Разбор
>
> Завожу DSU по индексам пользователей и Map email → первый владелец. Для каждого email объединяю текущего пользователя с найденным владельцем; если адрес новый — запоминаю владельца. После всех объединений собираю пользователей и уникальные email по окончательному корню. Это сохраняет транзитивность: A связан с B через один адрес, B с C через другой — все трое окажутся вместе.
>
> Нормализацию email задаю отдельно: нельзя молча приводить любые части адреса или удалять точки. Пользователь без email остаётся отдельной группой. Нужно определить стабильный ID и порядок групп, если они важны потребителю. При сжатии путей и объединении по рангу время почти линейно по пользователям и вхождениям email; память линейна. Проверки: транзитивная цепочка, повтор адреса внутри пользователя, несколько независимых групп, пустые email-наборы.

### Шаговое соревнование

Выберите участников, которые присутствовали во **все** дни и набрали максимальную суммарную величину steps; верните все userIds с одинаковым максимумом и steps. Внутри одного дня участник имеет одну запись. Победителя может не быть.

```js
const statistics = [
  [{ userId: 1, steps: 1000 }, { userId: 2, steps: 1500 }],
  [{ userId: 2, steps: 1000 }],
];
// { userIds: [2], steps: 2500  }
const statistics2 = [
  [{ userId: 1, steps: 2000 }, { userId: 2, steps: 1500 }],
  [{ userId: 2, steps: 4000 }, { userId: 1, steps: 3500 }],
];
// { userIds: [1, 2], steps: 5500  }
function getChampions(statistics) { /* Ваш код */ }
```

> [!note]- Подсказка
> пустой вход; в первый день 1 участник, в следующий 10 000; O(общего числа записей) и значение N/K в оценке.

> [!example]- Решение и проверка
>
> Победитель обязан присутствовать в первый день, поэтому в Map достаточно держать участников первого дня. Для каждого сохраняем сумму и число последовательно пройденных дней. В день с индексом `day` увеличиваем сумму только у того, у кого уже учтено ровно `day` дней. Пропустивший день больше не догонит этот счётчик, даже если вернётся с огромным результатом. В конце сравниваем суммы только у прошедших все дни; при равенстве сохраняем всех лидеров.
>
> Уточнённый контракт: ID — число или строка; внутри дня ID уникальны; steps — неотрицательные безопасные целые, итоговые суммы также помещаются в безопасный диапазон Number. Пустой вход, пустой день или отсутствие подходящих участников дают `{ userIds: [], steps: 0 }`. Ноль шагов не означает отсутствие участия. Порядок победителей — порядок первого дня; числовой `1` и строковый `'1'` различаются.
>
> ```js
> // checked-example: step-champions
> function getChampions(statistics) {
>   if (statistics.length === 0) return { userIds: [], steps: 0 };
>   const totals = new Map();
>   for (const { userId, steps } of statistics[0]) {
>     totals.set(userId, { steps, days: 1 });
>   }
>   for (let day = 1; day < statistics.length; day++) {
>     for (const { userId, steps } of statistics[day]) {
>       const current = totals.get(userId);
>       if (current?.days !== day) continue;
>       current.steps += steps;
>       current.days++;
>     }
>   }
>   let maximum = 0;
>   let userIds = [];
>   for (const [userId, total] of totals) {
>     if (total.days !== statistics.length) continue;
>     if (total.steps > maximum) {
>       maximum = total.steps;
>       userIds = [userId];
>     } else if (total.steps === maximum) {
>       userIds.push(userId);
>     }
>   }
>   return { userIds, steps: maximum };
> }
> ```
>
> Если R — общее число записей, D — количество дней, K — число участников первого дня, ожидаемое время O(R + D), дополнительная память O(K) при обычной оценке доступа к Map. Если каждый день непустой, D ≤ R и время можно записать O(R). Ни сортировка, ни повторный `includes` по всем участникам не нужны. Входные записи не меняются: счётчики созданы отдельно.
>
> Проверки: оба примера; ничья с обратным порядком второго дня; участник пропустил середину и вернулся; новые участники появились позднее; все результаты нулевые; пустой вход и пустой день. **Критерии ответа:** Проверяю участие именно во все дни, сохраняю ничьи и нулевые результаты, определяю отсутствие победителя, объясняю O(R + D)/O(K) и не изменяю вход.

### Свернуть целые числа в диапазоны

Уточни дубликаты, порядок входа и отрицательные числа. Например, `[0, 1, 2, 3, 5, 8, 9]` превращается в `0-3,5,8-9`.

**Условие.** Дан список неповторяющихся целых чисел. Верните отсортированные диапазоны. Пример [1,4,5,2,3,9,8,11,0] → "0-5,8-9,11"; [1,4,3,2] → "1-4". Уточните отрицательные числа и максимальное целое.

В исходном варианте список содержит неотрицательные целые числа без повторов. Примеры: [1,4,5,2,3,9,8,11,0] → "0-5,8-9,11"; [1,4,3,2] → "1-4"; [1,4] → "1,4"; [1,2] → "1-2".

> [!example]- Разбор
>
> Копирую вход и сортирую численно, затем поддерживаю начало и конец текущей непрерывной серии. Следующее число продолжает серию, если больше конца ровно на 1; иначе записываю одиночное число или start-end и начинаю новую серию. После цикла обязательно записываю последнюю.
>
> Время O(n log n) из-за сортировки и O(n) на проход, память O(n) для копии и результата. Если вход уже отсортирован, достаточно линейного прохода. Условие обещает отсутствие повторов; для расширенного контракта их либо пропускаю, либо отвергаю. Проверки: [], [1], [1,2], [1,3], обратный порядок и последняя серия. Для отрицательных значений строка вроде -3--1 неоднозначна человеку: формат нужно согласовать, а не менять молча. Проверяю безопасный диапазон целых.

### Поиск подпоследовательности

Проверьте, встречаются ли буквы pattern в text в том же порядке, возможно с пропусками. Это не измерение расстояния редактирования между строками.

Исходные проверки для второй строки cartwheel: car, cwhl, cwhee и cartwheel → true; cwheeeel и lw → false. Нужен один проход без регулярного выражения. Уточните пустую строку, регистр и Unicode.

> [!example]- Разбор
>
> Указатель pattern двигается только при совпадении очередного символа text; text просматривается один раз. Сохраняется инвариант: уже пройденный префикс pattern найден в правильном порядке.
>
> ~~~js
> function isSubsequence(pattern, text) {
>   let index = 0;
>   for (let i = 0; i < text.length && index < pattern.length; i++) {
>     if (text[i] === pattern[index]) index++;
>   }
>   return index === pattern.length;
> }
> ~~~
>
> Это вариант с точным сравнением UTF-16 code units; для графем нужен другой договор о символах. Пустой pattern даёт true, непустой pattern и пустой text — false. Для cartwheel: cwhl проходит, lw нет, поскольку порядок обратный. Время O(text.length), дополнительная память O(1). Повторяющиеся буквы требуют отдельных позиций, поэтому cwheeeel не проходит.

> [!example]- Разбор

### Кэш LRU с ограниченной ёмкостью

**Этап кода:** advanced

**Условие.** Реализуйте get/put для кеша с ограничением числа элементов либо памяти. При переполнении удаляется элемент, который дольше всего не использовался. Уточните, что считается использованием, нулевую вместимость, обновление существующего ключа и асинхронную загрузку. Требуется эффективный поиск и смена порядка.

В этом варианте ограничиваем число ключей целым `capacity >= 0`. Успешный get и любой put обновляют давность; промах — нет. Ключи и значения любые, включая `undefined`, поэтому get возвращает `{ found: false }` либо `{ found: true, value }`. TTL, размер в байтах и загрузка по сети не входят в контракт.

**Формат раунда:** Написание кода
**Критерии ответа:** Чтение и обновление меняют порядок, удаляется самый старый ключ; различаю промах и undefined, проверяю ёмкость 0 и не обещаю сетевую дедупликацию.
**Изучить:** [[Фронтенд/JavaScript/07. Массивы и коллекции/03. Map, Set, WeakMap и WeakSet|Порядок ключей и операции Map]], [[Собеседования/Темы/Алгоритмы и программирование#Как оценивать время работы и дополнительную память?|Сложность алгоритма]]

> [!example]- Разбор LRU
>
> В Map первый ключ будет самым старым. Чтобы перенести существующий ключ в конец, удаляем его и добавляем заново: один set уже существующего ключа порядок не меняет. Поля закрыты, чтобы внешний код не нарушил ёмкость или порядок.
>
> ```js
> // checked-example: lru
> class LRUCache {
>   #capacity;
>   #entries = new Map();
>   constructor(capacity) {
>     if (!Number.isInteger(capacity) || capacity < 0) {
>       throw new RangeError('Invalid capacity');
>     }
>     this.#capacity = capacity;
>   }
>   get(key) {
>     if (!this.#entries.has(key)) return { found: false };
>     const value = this.#entries.get(key);
>     this.#entries.delete(key);
>     this.#entries.set(key, value);
>     return { found: true, value };
>   }
>   put(key, value) {
>     if (this.#capacity === 0) return;
>     this.#entries.delete(key);
>     this.#entries.set(key, value);
>     if (this.#entries.size > this.#capacity) {
>       this.#entries.delete(this.#entries.keys().next().value);
>     }
>   }
> }
> ```
>
> При ёмкости 2: `put('a', 1)`, `put('b', 2)`, `get('a')`, `put('c', 3)` удалят b. Отдельно проверь обновление a через put, промах, нулевую ёмкость и сохранённый undefined. Память O(capacity). В обычной модели хеш-таблицы операции имеют ожидаемую постоянную стоимость; JavaScript не обещает строгую O(1) для каждой операции Map. Если интервью требует собственную структуру с явной O(1), обсуди Map ключ → узел и двусвязный список, а не сортировку по времени при каждом get.
>
> Порядок ключей и поведение коллекции: [MDN: Map](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map).

### Сбор value из дерева

Дополнение: сохрани depth-first порядок и определи поведение при циклических ссылках. Сравни рекурсию и итеративный обход для глубокого дерева.

Соберите значения `value` обходом дерева в глубину в порядке узел → дети. Учтите глубокую вложенность. Входное дерево показано в примере.

**Контракт:** root — null либо узел с собственным полем value; children отсутствует, равен undefined либо является плотным массивом таких узлов. Null даёт пустой результат. Дерево не содержит повторных ссылок на узлы: и цикл, и общий ребёнок двух ветвей считаются ошибкой. Возвращаем значения в preorder: узел → его дети слева направо. Поле value не клонируется; объект в этом поле сохраняет свою ссылку. Исходник не меняется. Вход — обычные данные без getters/Proxy и конкурентного изменения.

```js
const tree = {
  value: 1,
  children: [
    { value: 2, children: [{ value: 3 }] },
    { value: 4, children: [{ value: 5 }, { value: 6 }] },
  ],
};
```

> [!example]- Обход глубокого дерева без рекурсивных вызовов
>
> ~~~js
> // checked-example: tree-values-preorder
> function getTreeValues(root) {
>   if (root === null) return [];
>   const result = [];
>   const pending = [root];
>   const seen = new Set();
>   while (pending.length > 0) {
>     const node = pending.pop();
>     if (node === null || typeof node !== 'object' || Array.isArray(node) ||
>         !Object.hasOwn(node, 'value')) {
>       throw new TypeError('Expected a node with own value');
>     }
>     if (seen.has(node)) throw new TypeError('Repeated node');
>     seen.add(node);
>     const children = node.children === undefined ? [] : node.children;
>     if (!Array.isArray(children)) throw new TypeError('Expected children array');
>     result.push(node.value);
>     for (let i = children.length - 1; i >= 0; i--) pending.push(children[i]);
>   }
>   return result;
> }
> ~~~
>
> Стек хранит ещё не обработанные узлы. Правый ребёнок кладётся раньше левого, чтобы левый был снят первым. Каждый допустимый узел добавляет ровно одно значение; seen обнаруживает повтор, а не молча пропускает его. На исходном примере ответ [1,2,3,4,5,6].
>
> Для n узлов время O(n), результат O(n), seen O(n); явный стек в худшем случае также O(n). Рекурсивная глубина не расходуется, но память остаётся конечной. Если гарантирован корректный tree и защиту от повторов снимают, это другой уровень проверки входа, который нужно назвать явно.
>
> **Вариант — по уровням.** Замените стек очередью: храните индекс головы, читайте pending[head++] и дописывайте детей в исходном порядке. На том же дереве получится [1,2,4,3,5,6]. Не вызывайте shift на каждом шаге; простой массив с растущим head хранит уже прочитанные ссылки до конца обхода, поэтому его память O(n), даже когда текущий уровень узкий.
>
> Проверки: null; лист со значением 0/undefined; несколько детей; цепочка из 20 000 узлов; цикл; общий ребёнок; неверный children; сохранность узлов и порядка. Значения могут повторяться — запрещено повторное посещение того же объекта узла, а не одинаковое value. [MDN: Set и сравнение объектов по идентичности](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Set).

> [!example]- Исходный рекурсивный вариант: найти ограничения
>
> Этот исходный код годится только для неглубокого дерева без повторных ссылок. Он не выполняет новый контракт отказа при цикле/общем ребёнке. Сравните его с итеративным решением выше; не считайте отсутствие рекурсии и защиту от циклов одной задачей.
>
> ```Js
> /*
> Есть дерево, которое лежит в переменной tree.
> Нужно написать функцию, которая будет пробегать по этому дереву и возвращать массив всех собранных value из этого дерева.
> Важно помнить о памяти и что дерево может иметь глубокую вложенность.
> */
>
>
> // Рекурсивная функция для извлечения значений из дерева
> function getTreeValues(tree) {
>   const result = []; // Массив для хранения значений
>
>   // Вспомогательная функция для обхода дерева
>   function traverse(node) {
>     if (!node) return;
>
>     // Сохраняем значение текущего узла
>     result.push(node.value);
>
>     // Если у текущего узла есть дочерние элементы, обходим их
>     if (node.children && node.children.length > 0) {
>       for (const child of node.children) {
>         traverse(child); // Рекурсивно обходим каждый дочерний узел
>       }
>     }
>   }
>
>   // Запускаем обход с корня дерева
>   traverse(tree);
>
>   return result; // Возвращаем массив собранных значений
> }
>
> console.log(getTreeValues(tree)); // [1, 2, 3, 4, 5, 6]
> ```
>

### Сумма чисел во вложенном объекте

Вариант задачи [[Собеседования/Практика/Алгоритмы и данные#Сбор value из дерева|обхода дерева]]: структура не имеет специальных полей value/children. Напишите `sumNumbers(data)`, которая суммирует числовые значения на любой из представленных глубин.

Учебный вход — конечное дерево из обычных объектов, массивов и примитивов без циклов, getters и специальных объектов. Числовые строки, null и boolean не прибавляются; NaN и Infinity игнорируются. Читаются только собственные перечисляемые строковые свойства, исходник не меняется.

```js
const data = { a: 2, b: { c: 3, d: [4, null, '5', false, { e: -1 }] }, z: 0 };
sumNumbers(data); // 8
```

> [!example]- Разбор
>
> Каждый вызов либо возвращает число, либо складывает ответы для вложенных значений. Сначала проверяем null: у него typeof тоже равен object.
>
> ```js
> // checked-example: nested-number-sum
> function sumNumbers(data) {
>   if (typeof data === 'number') return Number.isFinite(data) ? data : 0;
>   if (data === null || typeof data !== 'object') return 0;
>   let total = 0;
>   for (const value of Object.values(data)) total += sumNumbers(value);
>   return total;
> }
> ```
>
> В примере складываются 2 + 3 + 4 - 1 + 0. Строка '5' остаётся строкой. Проверь пустой объект/массив, несколько уровней, ноль, отрицательные числа и отсутствие числовых значений. Посещение значений занимает O(n); рекурсия использует стек глубиной h, дополнительно создаются массивы Object.values.
>
> «Любая вложенность» не означает бесконечную глубину: стек JavaScript ограничен. Для очень глубоких данных нужен итеративный обход с явным стеком. Циклический граф требует отдельного контракта: считать общую ссылку один раз или каждое её вхождение — разные задачи. Добавлять WeakSet молча нельзя.

## Прикладные преобразования данных

До решения уточни размер входа, порядок результата, допустимость мутации и поведение некорректных данных.

### Группировка операций

**Формат раунда:** coding
**Этап кода:** short
**Критерии ответа:** За один проход группирую только валидные операции, считаю количество и сумму; поддерживаю отрицательные суммы и ключ __proto__, не меняю вход, пустой массив даёт пустой объект.
**Изучить:** [[Фронтенд/JavaScript/07. Массивы и коллекции/01. Массив как объект и базовые операции|Обход и преобразование массива]]

Дан массив операций `{ id, category, amount, valid }`. Вернуть объект, где для каждой категории указаны количество валидных операций и сумма `amount`.

В базовом контракте category — строка, valid — boolean, amount — конечное число, включая отрицательное. Категории без валидных операций не включай. Две валидные операции категории `food` на 10 и -3 дают `{ food: { count: 2, amount: 7 } }`; пустой массив даёт пустой объект. Вход не меняй.

> [!example]- Разбор группировки операций
>
> За один проход создаём итог для категории и добавляем сумму. Берём только `valid === true`. Условие: amount — конечное число, отрицательные суммы допустимы; категории без валидных операций не нужны.
>
> ```js
> // checked-example: group-operations
> function groupOperations(operations) {
>   const totals = Object.create(null);
>   for (const { category, amount, valid } of operations) {
>     if (!valid) continue;
>     const total = (totals[category] ??= { count: 0, amount: 0 });
>     total.count++;
>     total.amount += amount;
>   }
>   return totals;
> }
> ```
>
> Две валидные операции категории `food` на 10 и -3 дадут `{ count: 2, amount: 7 }`. Объект без прототипа позволяет безопасно использовать категорию вроде `__proto__` как обычный ключ. Вход не меняется. Время O(n), дополнительная память O(k), где k — число категорий.
>
> Вариант интервью: оставь оплаченные заказы, сгруппируй по customerId, отсортируй суммы по убыванию и возьми первые N. Сортировать нужно итог из k клиентов, а не весь массив заказов: O(n + k log k). При равных суммах заранее договорись о порядке.

### Индекс по идентификатору

Преобразовать дерево узлов `{ id, children }` в `Map<id, node>`. Дерево может быть глубоким. Обсудить рекурсивный и итеративный варианты.

Для решения ниже вход — один корневой объект; id — непустая строка либо безопасное целое число, children отсутствует либо является массивом таких узлов. Число 1 и строка `'1'` — разные ключи. Повтор id, повторная ссылка на узел и цикл считаются ошибкой. Значения Map должны быть исходными объектами; вход не меняется.

**Критерии ответа:** Обхожу глубокое дерево без рекурсивного переполнения, сохраняю ссылки и вход, обнаруживаю цикл и повтор id; оцениваю O(n) времени и памяти.
**Изучить:** [[Фронтенд/JavaScript/07. Массивы и коллекции/03. Map, Set, WeakMap и WeakSet|Map для индекса и Set для посещённых узлов]]

> [!example]- Разбор индекса дерева
>
> Явный стек хранит ещё не обработанные узлы. Set посещённых объектов защищает от цикла и повторного включения одного объекта в разные ветки; Map отдельно проверяет совпадение id разных объектов. Добавляем детей в обратном порядке, чтобы обход следовал исходному порядку слева направо.
>
> ```js
> // checked-example: tree-index
> function indexTree(root) {
>   const index = new Map();
>   const visited = new Set();
>   const stack = [root];
>   while (stack.length) {
>     const node = stack.pop();
>     if (!node || typeof node !== 'object' || Array.isArray(node)) {
>       throw new TypeError('Expected a node object');
>     }
>     if (visited.has(node)) throw new Error('Cycle or Repeated node');
>     visited.add(node);
>     const validId =
>       typeof node.id === 'string'
>         ? node.id.length > 0
>         : Number.isSafeInteger(node.id);
>     if (!validId) throw new TypeError('Invalid node id');
>     if (index.has(node.id)) throw new Error('Duplicate node id');
>     index.set(node.id, node);
>     const children = node.children === undefined ? [] : node.children;
>     if (!Array.isArray(children)) throw new TypeError('Invalid children');
>     for (let i = children.length - 1; i >= 0; i--) stack.push(children[i]);
>   }
>   return index;
> }
> ```
>
> Проверки: один узел; несколько веток; цепочка из 12 000 узлов; два разных объекта с одинаковым id; ссылка узла на самого себя; сохранение `result.get(id) === node`. Не используй `stack.push(...children)` для произвольно широкой ветки: число аргументов тоже ограничено. При обычной модели Map/Set время O(n), дополнительная память O(n), включая итоговый индекс. Для графа с общими узлами нужен другой договор: повторный узел пропускать, а не считать ошибкой.

**Уточнения**
- Какой результат нужен при повторяющемся id: ошибка, первый или последний узел?
- Что изменится, если вместо дерева разрешён граф с общими поддеревьями?

### Настройки колонок

Есть список доступных колонок и сохранённые пользовательские настройки. Собрать итоговый порядок: известные сохранённые колонки, затем новые колонки по умолчанию; удалённые колонки игнорировать.

> [!example]- Разбор
>
> Создаю Map доступных колонок по устойчивому id. Иду по сохранённым настройкам: неизвестные id игнорирую, повторные не добавляю, допустимые настройки объединяю с текущими значениями по умолчанию. Затем иду по доступным колонкам в исходном порядке и добавляю ещё не использованные.
>
> Нельзя без проверки переносить произвольные сохранённые поля: ширина, видимость и сортировка имеют контракт, а обязательную колонку нельзя скрыть старым значением. Например, доступны A,B,C, сохранены B,old,B — итог B,A,C. Время O(n+m), память O(n). Проверки: пустые настройки, новая/удалённая колонка, дубликаты, неверная ширина и отсутствие мутации входов.

### Плоский список комментариев

Из вложенных комментариев получить плоский массив `{ id, parentId, depth }`, не изменяя исходные объекты.

> [!example]- Разбор
>
> Для каждого корня начинаю обход с parentId=null и depth=0. В preorder добавляю новый объект {id,parentId,depth}, затем детей с текущим id и depth+1. Чтобы сохранить порядок детей при явном стеке, кладу их в обратном порядке. Исходные узлы и массивы children не изменяю.
>
> При гарантированном дереве время O(n), память результата O(n); стек зависит от формы дерева и способа обхода. Если вход может содержать циклы или повторные id, нужен явный контракт: отказ с диагностикой, а не бесконечный обход или молчаливое слияние разных узлов. Проверки: несколько корней, лист без children, глубокая цепочка, порядок соседей и неизменность исходных объектов.

### Сравнение конфигураций

Найти добавленные, удалённые и изменённые элементы между двумя массивами конфигураций по `id`. Объяснить выбранную сложность.

> [!example]- Разбор
>
> Индексирую прежний массив по id. Обхожу новый: отсутствующий id означает добавление, существующий сравниваю по значимым полям и отмечаю использованным. Оставшиеся прежние id — удалённые. Правило сравнения полей нужно задать: новая ссылка на равный объект ещё не означает изменение, а JSON.stringify зависит от представления и не является универсальным глубоким сравнением.
>
> Если важен порядок, перенесённый элемент учитываю отдельно от изменения свойств. Повторные id отвергаю либо обрабатываю по заранее выбранному правилу. Время O(n+m) плюс стоимость сравнения данных, память O(n+m) с результатом. Проверки: только перестановка, добавление и удаление, одинаковые значения в новых объектах, изменение вложенного поля и дубликат id.

### Нормализация API-ответа

**Формат раунда:** coding
**Этап кода:** main
**Критерии ответа:** Создаю индексы заказов и пользователей за один проход, сохраняю порядок orderIds и null для отсутствующего пользователя; применяю оговорённое правило повторов, не меняю входные объекты. Объясняю O(n) времени и памяти.
**Изучить:** [[Фронтенд/JavaScript/04. Объекты и прототипы/01. Объекты и свойства|Объекты и собственные ключи]] [[Фронтенд/JavaScript/07. Массивы и коллекции/01. Массив как объект и базовые операции|Преобразование массива]]

Преобразовать массив заказов с вложенными пользователями в `{ ordersById, usersById, orderIds }`. Обсудить дубли пользователей и частичные данные.

Базовый контракт: заказ имеет `{ id, total, user }`, пользователь — `{ id, name }` либо null. Все id — непустые строки; id заказов уникальны, id пользователей могут повторяться. total — конечное число. В ordersById вместо вложенного user нужно поле userId, равное id пользователя или null. Если пользователь встречается несколько раз, последнее полное описание заменяет предыдущее. Частичных объектов пользователя в базовом входе нет. Сохрани порядок заказов в orderIds и не меняй вход.

Пример: `[{ id: 'o1', total: 10, user: { id: 'u1', name: 'Анна' } }, { id: 'o2', total: 0, user: null }]` → `{ ordersById: { o1: { id: 'o1', total: 10, userId: 'u1' }, o2: { id: 'o2', total: 0, userId: null } }, usersById: { u1: { id: 'u1', name: 'Анна' } }, orderIds: ['o1', 'o2'] }`. Пустой массив даёт два пустых индекса и пустой orderIds.

> [!example]- Разбор нормализации
>
> Индексы позволяют хранить пользователя один раз и ссылаться на него из нескольких заказов. Порядок отображения хранится отдельно, поскольку перечисление ключей объекта не заменяет порядок массива заказов.
>
> ```js
> // checked-example: normalize-orders
> function normalizeOrders(orders) {
>   const ordersById = Object.create(null);
>   const usersById = Object.create(null);
>   const orderIds = [];
>   for (const { id, total, user } of orders) {
>     ordersById[id] = { id, total, userId: user === null ? null : user.id };
>     orderIds.push(id);
>     if (user !== null) {
>       usersById[user.id] = { id: user.id, name: user.name };
>     }
>   }
>   return { ordersById, usersById, orderIds };
> }
> ```
>
> Объекты без прототипа безопасно принимают строковый id вроде __proto__. Создаются новые объекты заказов и пользователей: изменение результата не должно менять поля исходного ответа. Повторное описание пользователя заменяет запись только в usersById; все заказы продолжают ссылаться на тот же id. При обычной модели доступа к свойствам — O(n) времени и O(n) дополнительной памяти.
>
> Проверь пустой массив, несколько заказов одного пользователя, его обновлённое имя, null и сохранение порядка. Правило для частичных ответов, конфликтующих версий и неизвестных полей нужно согласовывать отдельно: молчаливый spread может стереть данные. Эта базовая функция не проверяет произвольный ответ сервера и не заменяет валидацию на границе API.

> [!example]- Критерии преобразований
>
> - уточнение контракта;
> - читаемые имена и небольшие функции;
> - отсутствие случайной мутации;
> - корректность на пустом вводе и дубликатах;
> - осознанная временная и пространственная сложность.

### Из плоского списка построить дерево

Дан массив `{ id, parentId, name }`. `parentId: null` означает корень. Родитель может идти после ребёнка. Верни массив корней с `children`, не меняя вход.

Учебные условия: идентификаторы уникальны, все родители существуют, циклов нет. Нарушение этих условий обсуди отдельно.

Пример: сначала `{ id: 2, parentId: 1, name: 'Файл' }`, затем `{ id: 1, parentId: null, name: 'Папка' }`. Результат — папка с файлом внутри.

> [!example]- Разбор двух проходов
>
> Сначала создаём все узлы и таблицу `id → узел`. Затем присоединяем каждый узел к уже существующему родителю. Поэтому порядок входа не мешает.
>
> ```js
> // checked-example: build-tree
> function buildTree(items) {
>   const byId = new Map(
>     items.map((item) => [item.id, { ...item, children: [] }]),
>   );
>   const roots = [];
>   for (const item of items) {
>     const node = byId.get(item.id);
>     if (item.parentId === null) roots.push(node);
>     else byId.get(item.parentId).children.push(node);
>   }
>   return roots;
> }
> ```
>
> При обычной модели Map — O(n) времени и O(n) памяти. Корни и дети сохраняют порядок входа. Не нужен поиск родителя через `find` для каждого узла: он может дать O(n²).
>
> Для неизвестных данных сначала проверяют уникальность id и существование родителей. Циклы требуют отдельного обхода с отметками посещения. Без этого циклическая часть может молча исчезнуть из массива корней. Не выдавай учебный вариант за валидатор произвольного API-ответа.

### Объект в плоские ключи с точками

**Формат раунда:** coding
**Этап кода:** short
**Критерии ответа:** Накопляю путь при обходе, сохраняю массивы, null и пустые объекты как конечные значения; пустой вход даёт пустой объект, вход не меняется. Не добавляю обход циклов и экранирование точек без изменения контракта.
**Изучить:** [[Фронтенд/JavaScript/04. Объекты и прототипы/01. Объекты и свойства|Собственные свойства и обход объекта]]

Преобразуй `{ user: { name: 'Анна' }, active: true }` в `{ 'user.name': 'Анна', active: true }`.

Условия: обычные JSON-объекты; массивы, null и пустые объекты сохраняются как конечные значения. Ключи не содержат точки, циклов нет.

> [!example]- Разбор flattenObject
>
> При спуске накапливаем путь. Когда встретили конечное значение, записываем его под получившимся ключом.
>
> ```js
> // checked-example: flatten-object
> function flattenObject(input) {
>   const result = Object.create(null);
>   function visit(object, prefix) {
>     for (const [key, value] of Object.entries(object)) {
>       const path = prefix ? `${prefix}.${key}` : key;
>       const nested =
>         value !== null &&
>         typeof value === 'object' &&
>         !Array.isArray(value) &&
>         Object.keys(value).length > 0;
>       if (nested) visit(value, path);
>       else result[path] = value;
>     }
>   }
>   visit(input, '');
>   return result;
> }
> ```
>
> Каждый ключ посещается один раз; создание строк путей тоже требует времени и памяти. Стек рекурсии зависит от глубины. Для очень глубокого входа используй собственный стек вместо рекурсии. Если точки разрешены в ключах, нужен другой формат пути — например, массив частей.

### Получить значение по пути

**Формат раунда:** coding
**Этап кода:** short
**Критерии ответа:** Проверяю собственное свойство на каждом шаге, сохраняю `null`, `false`, `0` и существующий `undefined`; пустой путь возвращает исходный объект, отсутствующий путь — запасное значение.
**Изучить:** [[Фронтенд/JavaScript/04. Объекты и прототипы/01. Объекты и свойства|Наличие собственного свойства]]

Реализуй `getByPath(object, 'user.name', fallback)`. Если собственного свойства нет, верни запасное значение `fallback`. Существующие `null`, `false` и `0` сохрани. Пустой путь возвращает исходный объект. Точки внутри ключей и синтаксис `items[0]` не поддерживаются; `items.0` поддерживается.

Примеры: `getByPath({ user: { name: 'Анна' } }, 'user.name', '?')` → `'Анна'`; `getByPath({}, 'user.name', '?')` → `'?'`; `getByPath({ count: 0 }, 'count', 9)` → `0`. На входе обычные данные без Proxy/getters, исходный объект не меняется.

> [!example]- Разбор доступа по пути
>
> ```js
> // checked-example: get-path
> function getByPath(object, path, fallback) {
>   if (path === '') return object;
>   let value = object;
>   for (const key of path.split('.')) {
>     if (
>       value === null ||
>       typeof value !== 'object' ||
>       !Object.hasOwn(value, key)
>     )
>       return fallback;
>     value = value[key];
>   }
>   return value;
> }
> ```
>
> Проверяем наличие свойства, а не истинность значения. Если свойство существует и равно `undefined`, функция вернёт именно `undefined`. Для обычных JSON-данных нет getters; на произвольном объекте чтение свойства может выполнить код. Время зависит от числа частей пути.

### Максимальная прибыль от одной покупки и продажи

Цены идут по дням: `[7, 1, 5, 3, 6, 4]`. Купить можно один раз, продать — в более поздний день. Верни `{ buyIndex, sellIndex, profit }`; если прибыли нет, верни `null`. Для примера ответ — индексы 1 и 4, прибыль 5.

Цены — конечные неотрицательные числа. При одинаковой максимальной прибыли сохраняем первую найденную пару. Массив не меняем.

> [!example]- Разбор одного прохода
>
> Для каждого дня продажи достаточно знать самую низкую цену до него. Сначала проверяем продажу, затем обновляем минимум — покупка должна быть раньше.
>
> ```js
> // checked-example: max-profit
> function bestTrade(prices) {
>   let minIndex = 0;
>   let best = null;
>   for (let sell = 1; sell < prices.length; sell++) {
>     const profit = prices[sell] - prices[minIndex];
>     if (profit > (best?.profit ?? 0)) {
>       best = { buyIndex: minIndex, sellIndex: sell, profit };
>     }
>     if (prices[sell] < prices[minIndex]) minIndex = sell;
>   }
>   return best;
> }
> ```
>
> Для `[5, 4, 3]`, пустого массива и одного дня результат `null`. Для `[1, 1, 3]` выбираем первую единицу. Время O(n), дополнительная память O(1).
>
> Сортировка цен уничтожит порядок дней. Перебор всех пар сохраняет смысл, но требует O(n²). Несколько покупок и продаж — другая задача, текущая формула её не решает.

## Один разрез и чётная разность сумм

**Критерии ответа:** Уточняю один непрерывный разрез и непустые части; вывожу условие через общую чётность, не решаю другую задачу о произвольных подмножествах.
**Изучить:** [[Фронтенд/JavaScript/07. Массивы и коллекции/01. Массив как объект и базовые операции|Обход массива]]

Дан массив целых безопасных для JavaScript чисел. Сколько существует позиций одного разреза, после которого остаются две непустые последовательные части и разность их сумм чётная? Элементы нельзя переставлять или распределять в произвольные подмножества. Для `[2, 3, 1]` подходят оба разреза; для `[2, 3, 2]` — ни одного. Пустой массив и один элемент дают 0.

> [!answer]- Разбор через чётность
>
> Пусть общая сумма S, а слева сумма L. Разность равна `L - (S - L) = 2L - S`. Чётность зависит только от S. Если S чётная, подходят все n−1 разрезов; иначе ни один. Это O(n) времени и O(1) памяти, а не динамическое программирование.
>
> ```js
> // checked-example: even-cut
> function countEvenCuts(values) {
>   let parity = 0;
>   for (const value of values) {
>     if (!Number.isSafeInteger(value))
>       throw new TypeError('Expected safe integers');
>     parity = (parity + Math.abs(value % 2)) % 2;
>   }
>   return values.length < 2 || parity !== 0 ? 0 : values.length - 1;
> }
> ```
>
> Считаем только чётность, поэтому не переполняем безопасный диапазон суммой многих больших значений. Отрицательные числа не меняют доказательство. Проверь `[]`, `[4]`, `[0, 0]`, `[-1, 3]`, нечётную общую сумму и вход из больших безопасных целых. Если разрешить произвольные подмножества, получится другой контракт и другой подсчёт — это нужно уточнить до решения.
