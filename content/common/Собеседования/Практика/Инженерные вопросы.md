## HTTP, браузер и транспорт

### Идемпотентность HTTP-методов

Какие из перечисленных методов идемпотентны по семантике HTTP? Выберите вариант или объясните его ограничение.

- a) DELETE
- b) GET
- c) HEAD
- d) PUT

> [!example]- Разбор после самостоятельной попытки
>
> Все четыре. Повтор такого запроса должен оставлять ресурс в том же состоянии, что и один запрос. При этом код ответа может измениться.
>
>
> Например, первый DELETE удаляет ресурс и возвращает 204, а повторный получает 404: ресурс уже удалён. Повтор PUT с теми же данными тоже сохраняет прежний результат. Сервер должен соблюдать эти правила при реализации методов.
### Что такое CORS, и зачем он нужен?

Выберите вариант или обоснуйте, почему корректного варианта нет. Возможны несколько ответов.

- a) Это метод шифрования данных в HTTP запросах.
- b) Это механизм, позволяющий серверу указать, с каких источников браузерному коду разрешено читать ответ.
- c) Это заголовок, который позволяет клиенту устанавливать соединение с сервером.
- d) Это стандарт для передачи больших объемов данных по HTTP.

> [!example]- Разбор после самостоятельной попытки
>
> Верно b. CORS позволяет серверу указать, с каких сайтов браузерному коду можно читать его ответы. Origin состоит из схемы, имени хоста и порта.
>
> Перед некоторыми запросами браузер отправляет OPTIONS — preflight. Другие запросы он может отправить сразу, но не даст JavaScript прочитать ответ без разрешения сервера. Поэтому права пользователя и защиту от CSRF сервер проверяет отдельно. [Описание CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS).
>

## SQL и согласованность

### NULL в условии AND

Для одной строки один операнд условия `column1 = 'value' AND column2 = 'value'` имеет значение `UNKNOWN` из-за NULL, а другой — TRUE или FALSE. Пройдёт ли **эта строка** фильтр WHERE?

> [!example]- Разбор после самостоятельной попытки
>
> Нет. `TRUE AND UNKNOWN` даёт UNKNOWN, `FALSE AND UNKNOWN` даёт FALSE. WHERE пропускает только TRUE.
>

### COUNT(column), COUNT(*) и NULL

Что считает `COUNT(column)` в столбце, содержащем NULL и числовой ноль? Чем результат отличается от `COUNT(*)`?

> [!example]- Разбор после самостоятельной попытки
>
> `COUNT(column)` считает строки, где column не равен NULL; числовой ноль учитывается. `COUNT(*)` считает все строки группы, включая строки с NULL.
>
>
> Для строк со значениями [NULL,0,5] COUNT(column)=2, COUNT(*)=3. После LEFT JOIN строка без пары справа всё равно существует в результате: COUNT(*) её учтёт, а COUNT(right.id) — нет, если right.id NULL. Именно поэтому при подсчёте заказов ресторана без заказов выбирают ненулевой ключ заказа.
### Сходимость реплик и согласованность в конечном счёте

Что означает согласованность в конечном счёте? Выберите вариант или объясните его ограничение.

- a) Гарантия немедленной согласованности после каждой транзакции
- b) Состояние, когда все обновления данных становятся доступными, но не обязательно сразу
- c) Способ достижения высокой доступности данных
- d) Принцип, используемый только в реляционных базах данных

> [!example]- Разбор после самостоятельной попытки
>
> Изменения доходят до разных копий данных с задержкой. Если новые записи прекратятся и обмен между узлами работает, со временем копии будут показывать одинаковые данные.
>
>
> Из предложенных вариантов b ближе к смыслу. Например, пользователь сохранил имя через один узел и сразу прочитал старое через отстающую реплику. Интерфейс может временно показать подтверждённый результат команды и статус обновления, но для требования «сразу читать свою запись» нужен соответствующий серверный маршрут/контракт. Допустимую задержку обновления нужно определить отдельно.
