## Drag & drop между двумя контейнерами

Вам предстоит реализовать простой drag & drop интерфейс с использованием чистого JavaScript (без фреймворков и библиотек). На странице должны быть два контейнера: один для элементов, которые можно перетаскивать (draggable items), и один для места, куда их можно поместить (drop zone). Пользователь должен иметь возможность захватить объект из первого контейнера и перенести его во второй.
Технические требования:
1. Можно использовать события `mousedown, mousemove, и mouseup для обработки перетаскивания.`
2. Можно использовать requestAnimationFrame для работы с анимацией
3. Можно использовать служебный класс `_absolute`, добавляющий `position: absolute` и `z-index` для элемента.
4. Можно реализовать с использованием drag and drop API
5. Элемент при перетаскивании должен "прилипать" к курсору мыши и перемещаться вместе с ним.
6. После того как элемент отпущен внутри drop zone, он должен оставаться в этой зоне.
7. Если элемент отпущен вне drop zone, он возвращается в исходное местоположение.

## Клиент переключателей возможностей

Реализуйте клиента с initialData и параметрами url/interval (миллисекунды). Он обновляет данные из endpoint и даёт getToggle(key), stop(), start(), forceUpdate(). Сохраните состояние/контракт методов при повторных start/stop и ошибке запроса.

```text
type TogglesData = Record<string, unknown>;
// исходные сигнатуры контракта
new TogglesClient(initialData, { url, interval });
toggles.getToggle(key: string): unknown;
toggles.stop();
toggles.start();
toggles.forceUpdate();
```

Уточните перекрытие запросов, отмену, неверные данные, кэш и заголовки HTTP. Сигнатуры здесь — описание API, не готовый исполняемый TS-файл.

## Клиент аналитики с очередью

События кладутся в очередь и периодически отправляются на dataUrl. sendNow() сразу отправляет накопленные события. Реализуйте очередь без потери событий, появившихся во время отправки; поведение повторных попыток и дублей уточните.

```ts
interface AnalyticsEvent {
  type: string;
  version: number;
  args: Record<string, unknown>;
  timestamp: number;
}
const analytics = new AnalyticsClient(dataUrl, interval);
// queueEvent(event: AnalyticsEvent)
// sendNow()
```

> [!note]- Подсказка
> объединение изменений, закрытие страницы, защиту личных данных, работу без сети, идемпотентность и неограниченный рост очереди.

## Кнопка загрузки изображения

Дана разметка:

```html
<main>
  <div id="image-container"></div>
  <button id="image-loading-button">Load Image</button>
</main>
```

По каждому клику загрузите изображение 500×150 с `https://random.imagecdn.app/500/150.jpg` вместо предыдущего. Пока загружается — зелёный placeholder 500×150; при ошибке — красный; при успехе — console.log о загрузке. Дополнительно обсудите гонки быстрых кликов.

> [!example]- Решение и проверка
>
> Каждый клик сразу убирает прежнюю картинку и показывает контейнер заданного размера. Сам `img` создаём отдельно: обработчики назначаем до `src`, а в DOM вставляем только после успешной загрузки. Поэтому сломанная картинка не закрывает placeholder. Действует правило последнего клика: завершения старых попыток не меняют экран и не логируют успех. Возвращаем функцию очистки для размонтирования интерфейса.
>
> ```js
> // checked-example: image-button
> function mountImageButton(
>   button,
>   container,
>   getUrl = (id) =>
>     `https://random.imagecdn.app/500/150.jpg?request=${Date.now()}-${id}`,
> ) {
>   let generation = 0;
>   let active = null;
>   let disposed = false;
>   container.style.width = '500px';
>   container.style.height = '150px';
>   container.setAttribute('role', 'status');
>
>   function detach() {
>     if (active) active.onload = active.onerror = null;
>     active = null;
>   }
>   function showError() {
>     container.replaceChildren();
>     container.style.backgroundColor = 'red';
>     container.textContent = 'Не удалось загрузить изображение';
>     container.setAttribute('aria-busy', 'false');
>   }
>   function onClick() {
>     if (disposed) return;
>     const id = ++generation;
>     detach();
>     container.replaceChildren();
>     container.style.backgroundColor = 'green';
>     container.setAttribute('aria-busy', 'true');
>     const image = document.createElement('img');
>     active = image;
>     image.width = 500;
>     image.height = 150;
>     image.alt = 'Загруженное изображение';
>     const current = () => !disposed && generation === id && active === image;
>     image.onload = () => {
>       if (!current()) return;
>       detach();
>       container.style.backgroundColor = 'transparent';
>       container.replaceChildren(image);
>       container.setAttribute('aria-busy', 'false');
>       console.log('image loaded');
>     };
>     image.onerror = () => {
>       if (!current()) return;
>       detach();
>       showError();
>     };
>     try {
>       image.src = getUrl(id);
>     } catch {
>       detach();
>       showError();
>     }
>   }
>   button.addEventListener('click', onClick);
>   return () => {
>     disposed = true;
>     generation++;
>     button.removeEventListener('click', onClick);
>     detach();
>   };
> }
> // Подключение: mountImageButton(buttonElement, containerElement).
> ```
>
> Проверки: loading имеет размер 500×150; `load` заменяет его изображением; `error` показывает красный контейнер с текстом; новая попытка после ошибки работает. Для гонки запусти A и B, заверши B раньше A: виден только B, сообщение об успехе одно. После очистки новые клики и прежние завершения не меняют интерфейс.
>
> Параметр URL задаёт новую попытку вместо использования браузерного кэша; сервер всё равно может вернуть ту же картинку. Здесь не обещается физическая отмена старой загрузки: снимаются обработчики и право менять UI. Отмена сетевых ресурсов и объектные URL потребовали бы отдельного контракта. В продукте текст `alt` должен описывать смысл конкретного изображения.

**Критерии ответа:** Ставлю обработчики до src, различаю loading/error/success, сохраняю размер placeholder, защищаю UI от старой загрузки и освобождаю обработчики.

**Изучить:** [[Фронтенд/API браузера/02. События в браузере/01. addEventListener и объект события|События и очистка обработчиков]]; [[Фронтенд/API браузера/01. DOM и работа с документом/02. Изменение DOM, атрибуты и свойства|Изменение DOM]]

## Поисковые подсказки

При вводе запрашивайте POST /suggests с term; ответ `{ suggests: [{ title: string }, ...] }`. Показывайте список под полем ввода, заменяя старый. При ошибке скройте список; пустой ввод не вызывает запрос. Если ответ пуст, единственная подсказка — введённый текст.

```html
<main>
  <input type="text" id="search-input" placeholder="Поиск по объявлениям" />
  <div id="suggests-container"></div>
</main>
```

Исходный каркас (ошибки сохраняются для обсуждения):

```js
const fetchSuggests = async term => {
  const response = await fetch('/suggests', {
    method: 'POST',
    body: { term },
  });
  if (!response.ok) { throw response; }
  return response.json();
};
const searchInput = document.getElementById('search-input');
searchInput.addEventListener('input', async event => {
  // code here
});
```

Пример: «Квартира» → «Снять квартиру», «Купить квартиру»; «Получить квартиру бесплатно» и suggests=[] → тот же введённый текст.

> [!note]- Подсказка
> задержка до прекращения вызовов, отмена, устаревший ответ, безопасная вставка title и корректная сериализация тела.

## Обёртка над DOM с цепочкой методов

Напишите функцию $, чтобы вызовы работали для **всех** узлов, подходящих под selector. Реализуйте addClass/toggleClass/removeClass/css/html и цепочку вызовов.

```js
const $node = $('.js-node');
$node.addClass('node')
  .toggleClass('item')
  .removeClass('node')
  .css({ color: 'red', paddingTop: '10px' })
  .html('<li>hello</li>');
```

Обсудите объект методов на каждый вызов против общих методов класса, пустой NodeList и безопасность html. Не подключайте jQuery для реализации самой обёртки.

> [!example]- Решение и проверка
>
> Один экземпляр обёртки хранит снимок найденных элементов. Каждый изменяющий метод проходит по всему набору и возвращает тот же экземпляр; следующий метод цепочки работает с ним. Методы класса лежат в общем prototype, поэтому их реализации не создаются заново для каждой выборки. Замыкание с объектом методов тоже может выполнить контракт, но имеет другой способ хранения методов.
>
> Условия: `className` — один корректный CSS-токен; значения стилей заданы строками с единицами, если они нужны. `css` поддерживает camelCase, kebab-case и custom properties. Выборка статическая; пустой набор допускается, неправильный CSS-selector бросает стандартную ошибку браузера. Аргумент `root` ограничивает область поиска.
>
> ```js
> // checked-example: dom-wrapper
> class DomWrapper {
>   #elements;
>   constructor(selector, root = document) {
>     this.#elements = Array.from(root.querySelectorAll(selector));
>   }
>   #each(change) {
>     for (const element of this.#elements) change(element);
>     return this;
>   }
>   addClass(name) {
>     return this.#each((element) => element.classList.add(name));
>   }
>   removeClass(name) {
>     return this.#each((element) => element.classList.remove(name));
>   }
>   toggleClass(name) {
>     return this.#each((element) => element.classList.toggle(name));
>   }
>   css(styles) {
>     return this.#each((element) => {
>       for (const [name, value] of Object.entries(styles)) {
>         if (name.includes('-')) element.style.setProperty(name, value);
>         else element.style[name] = value;
>       }
>     });
>   }
>   html(trustedMarkup) {
>     return this.#each((element) => {
>       element.innerHTML = trustedMarkup;
>     });
>   }
> }
> function $(selector, root = document) {
>   return new DomWrapper(selector, root);
> }
> ```
>
> Для N выбранных узлов add/remove/toggle/html обходят N элементов; css с K свойствами делает N×K присваиваний. Стоимость поиска, разбора HTML и дальнейшего layout зависит от DOM и содержимого; оценка обхода не означает постоянной стоимости рендеринга. Память выборки — O(N). Добавленный позже узел не войдёт в уже созданную обёртку.
>
> `html` намеренно соответствует исходному контракту и принимает только доверенную разметку. Это не санитайзер: для пользовательского текста нужен `textContent`, для разрешённого HTML — отдельно выбранная проверенная очистка. Проверь два совпавших узла, отсутствие совпадений, неизменность внешнего узла, цепочку и повторный toggle. Нельзя заменить `querySelectorAll` на `querySelector`, не изменив контракт.

**Критерии ответа:** Изменяю весь набор, возвращаю тот же объект из каждого метода, объясняю статическую выборку и общие методы, различаю доверенный HTML и пользовательский текст.

## Совместимость POST-контракта

POST endpoint с тремя обязательными параметрами используется множеством клиентов. Нужно добавить четвёртый обязательный параметр и сохранить работу существующих клиентов. Предложите переходный контракт, поэтапное включение и критерий отключения старой версии. Обсудите временно необязательный параметр или значение по умолчанию, отдельную версию и oneOf; по умолчанию подходит только при наличии осмысленного значения.
