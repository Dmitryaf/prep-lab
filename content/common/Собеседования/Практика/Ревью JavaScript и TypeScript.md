# Ревью JavaScript и TypeScript

[[Собеседования/00. Карта раздела|Карта банка]]

Нужно не найти максимальное количество замечаний, а выделить риски по влиянию и предложить проверяемое улучшение.

## 1. Запрос без обработки HTTP-ошибки

```ts
async function loadUser(id: string) {
  const response = await fetch(`/api/users/${id}`)
  return response.json() as Promise<User>
}
```

Разобрать код состояния HTTP, проверку данных во время выполнения, отмену, тип ошибки и ответственность функции.

> [!example]- Разбор простыми словами
>
> Проверь response.ok до json. Прочитай данные как unknown и проверь ожидаемые поля; as не проверяет ответ сервера. Id кодируй для сегмента URL. Отмену передавай параметром, если она нужна вызывающему сценарию. HTTP 404, сетевая ошибка и неверный JSON должны оставаться различимыми.

## 2. Последовательная загрузка

```ts
for (const id of ids) {
  result.push(await loadItem(id))
}
```

Обсудить необходимость порядка, лимит конкурентности, partial failure и размер `ids` до замены на `Promise.all`.

> [!example]- Разбор простыми словами
>
> Если запросы независимы и их немного, Promise.all(ids.map(loadItem)) сокращает общее ожидание. Если есть лимит сервера — используй пул; если один результат нужен следующему — оставь последовательность. Выбери отдельно: первый отказ прерывает общий результат или нужны все статусы.

## 3. Небезопасный публичный контракт

```ts
function updateSettings(key: string, value: any): any {
  settings[key] = value
  return settings
}
```

Предложить типобезопасный API, определить допустимые ключи и решить, нужна ли мутация.

> [!example]- Разбор простыми словами
>
> Свяжи ключ и значение: `function updateSettings<K extends keyof Settings>(key: K, value: Settings[K])`. Внутри меняй только выбранное поле либо возвращай новый объект, в зависимости от принятого владения состоянием. Данные, полученные во время работы программы, всё равно проверяй отдельно; generic защищает типизированные вызовы.

## 4. Скрытая квадратичная сложность

```ts
const rows = orders.map(order => ({
  ...order,
  user: users.find(user => user.id === order.userId),
}))
```

Оценить реальный масштаб, построить индекс и обсудить отсутствующего пользователя.

> [!example]- Разбор простыми словами
>
> Сначала построй Map из users по id, затем для каждого заказа возьми пользователя по userId. В обычной модели Map время меняется с O(orders × users) на O(orders + users), появляется память под индекс. Для отсутствующего пользователя выбери явный результат, а для повторяющихся id — правило разрешения дубля.

## 5. Ошибка narrowing

```ts
type Result = { data: User } | { error: string }

function render(result: Result) {
  return result.data.name
}
```

Исправить контракт и показать безопасное сужение. Обсудить discriminated union.

> [!example]- Разбор простыми словами
>
> Сначала проверь `'data' in result`, затем читай result.data.name; в другой ветке показывай result.error. Для расширяемого контракта удобно добавить `status: 'success' | 'error'` в разные варианты и сужать по status. Утверждение `as` только скроет проблему.

## Порядок ревью

1. Уточнить назначение и ограничения кода.
2. Сначала назвать correctness и security risks.
3. Затем обработку ошибок и крайние случаи.
4. После этого — читаемость, типизацию, тестируемость и performance.
5. Не переписывать всё без необходимости.
