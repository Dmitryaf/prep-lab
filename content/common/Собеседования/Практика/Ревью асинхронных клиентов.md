# Ревью асинхронных клиентов

[[Собеседования/00. Карта раздела|Карта банка]]

## Ревью клиента флагов: остановка и поздний ответ

**Формат раунда:** Ревью кода

Клиент хранит начальные флаги, обновляет их с заданным интервалом, предоставляет `getToggle`, `start`, `stop`, `forceUpdate`.

Найди ошибки в порядке действий, покажи воспроизводящие сценарии и исправь их. Контракт: constructor запускает периодическое обновление; повторный `start` ничего не дублирует; `stop` отменяет текущую попытку и запрещает её поздний результат. `forceUpdate` разрешён и после остановки, делает одно обновление без включения polling; одновременные вызовы объединяются. Ошибка сохраняет последние хорошие данные. Интервал отсчитывается после завершения попытки.

```js
// Учебный код с намеренными ошибками.
class TogglesClient {
  constructor(initialData, { url, interval }) {
    this.data = initialData;
    this.url = url;
    this.interval = interval;
    this.start();
  }
  getToggle(key) { return this.data[key]; }
  start() {
    this.timer = setTimeout(() => {
      this.forceUpdate().finally(() => this.start());
    }, this.interval);
  }
  stop() { clearTimeout(this.timer); }
  async forceUpdate() {
    const response = await fetch(this.url);
    this.data = await response.json();
  }
}
```

> [!example]- Разбор и исправленное решение
>
> Главная ошибка: `stop` очищает таймер, но уже начавшийся запрос позднее изменит данные и вызовет `start`. Повторные `start` создают независимые цепочки таймеров. Ручное обновление может пересечься с автоматическим, и поздний ответ затрёт свежий. HTTP 503 не отклоняет `fetch` сам по себе. Rejection из автоматического запроса остаётся необработанным.
>
> Нужны отдельные признаки работающего polling и текущей попытки. После `stop` прежняя попытка теряет право менять данные и расписание. `AbortController` экономит работу; проверка идентичности защищает даже транспорт, игнорирующий abort. Объединение параллельных обновлений выбрано явно: `forceUpdate` не обещает второй запрос после уже выполняющегося.
>
> ```js
> // checked-example: review-toggles
> class TogglesClient {
>   #data;
>   #url;
>   #interval;
>   #running = false;
>   #timer = null;
>   #flight = null;
>
>   constructor(initialData, { url, interval }) {
>     if (!Number.isFinite(interval) || interval <= 0)
>       throw Error('Invalid interval');
>     this.#data = { ...initialData };
>     this.#url = url;
>     this.#interval = interval;
>     this.start();
>   }
>   getToggle(key) {
>     return this.#data[key];
>   }
>   #clearTimer() {
>     clearTimeout(this.#timer);
>     this.#timer = null;
>   }
>   #schedule() {
>     if (!this.#running || this.#flight || this.#timer !== null) return;
>     this.#timer = setTimeout(() => {
>       this.#timer = null;
>       // Ручной вызов возвращает ошибку вызывающему; polling сохранит данные.
>       this.forceUpdate().catch(() => {});
>     }, this.#interval);
>   }
>   start() {
>     if (this.#running) return;
>     this.#running = true;
>     this.#schedule();
>   }
>   stop() {
>     this.#running = false;
>     this.#clearTimer();
>     const old = this.#flight;
>     this.#flight = null;
>     old?.controller.abort();
>   }
>   forceUpdate() {
>     if (this.#flight) return this.#flight.promise;
>     this.#clearTimer();
>     const flight = { controller: new AbortController(), promise: null };
>     this.#flight = flight;
>     flight.promise = Promise.resolve()
>       .then(async () => {
>         const response = await fetch(this.#url, {
>           signal: flight.controller.signal,
>         });
>         if (!response.ok) throw Error(`HTTP ${response.status}`);
>         const data = await response.json();
>         if (!data || typeof data !== 'object' || Array.isArray(data)) {
>           throw Error('Invalid toggle data');
>         }
>         if (this.#flight !== flight) return false;
>         this.#data = data;
>         return true;
>       })
>       .finally(() => {
>         if (this.#flight !== flight) return;
>         this.#flight = null;
>         this.#schedule();
>       });
>     return flight.promise;
>   }
> }
> ```
>
> Проверка: начни запрос A, вызови `stop`, затем `start` и запрос B. Заверши B, затем A: остаются данные B и один таймер. Отдельно проверь два `start`, общий Promise двух `forceUpdate`, HTTP/JSON-ошибку и ручное обновление остановленного клиента. Если abort проигнорирован, старый сетевой запрос может физически продолжаться, но не влияет на актуальное состояние. Это не обещание единственного физического соединения.
>
> В продукте нужны наблюдаемая ошибка/свежесть данных и политика задержек при повторных отказах. Здесь polling обрабатывает rejection, сохраняя данные; внешнее логирование не включено в минимальный контракт. Вложенные объекты флагов в этом примере считаются неизменяемыми потребителем.

**Критерии ответа:** Воспроизвожу гонку stop/in-flight, разделяю остановку расписания и актуальность результата, сохраняю данные при отказе, проверяю повторный start и ручное обновление.

## Ревью клиента аналитики: очередь во время отправки

**Формат раунда:** Ревью кода

Метод `queueEvent(event)` добавляет событие, `sendNow()` отправляет накопленное, отправка также выполняется периодически. Событие содержит `type`, `version`, `args`, `timestamp`; тело запроса — JSON-массив.

Найди потерю и дублирование событий, предложи контракт ошибки и исправь код. События — JSON-совместимые неизменяемые снимки; один batch отправляется за раз. Одновременный `sendNow` присоединяется к текущему batch; новые события остаются до следующей отправки. Ошибка возвращает batch перед более новыми событиями. Метод `close` освобождает расписание и запрещает новые операции; текущая отправка может завершиться. Долговечная очередь после перезагрузки вне этого упражнения.

```js
// Учебный код с намеренными ошибками.
class AnalyticsClient {
  constructor(url, interval) {
    this.url = url;
    this.events = [];
    setInterval(() => this.sendNow(), interval);
  }
  queueEvent(event) { this.events.push(event); }
  async sendNow() {
    if (!this.events.length) return;
    await fetch(this.url, {
      method: 'POST',
      body: JSON.stringify(this.events),
    });
    this.events = [];
  }
}
```

> [!example]- Разбор и исправленное решение
>
> Сценарий потери: A отправляется, B добавляется во время запроса, успех A очищает и B. Два параллельных `sendNow` отправляют A дважды. HTTP-ошибка считается успехом; таймер не освобождается, нет обработки rejection. Сохранение ссылки на объект позволяет чужому коду менять ещё не отправленное событие.
>
> Отделим отправляемый batch от очереди. Пока он в работе, новые события накапливаются отдельно. Успех подтверждает только batch; отказ ставит его в начало очереди. Очередь нельзя очищать целиком после `await`. Таймер запускает следующую попытку после завершения предыдущей; `close` запрещает его восстановление.
>
> ```js
> // checked-example: review-analytics
> class AnalyticsClient {
>   #events = [];
>   #url;
>   #interval;
>   #flight = null;
>   #timer = null;
>   #closed = false;
>
>   constructor(dataUrl, interval) {
>     if (!Number.isFinite(interval) || interval <= 0)
>       throw Error('Invalid interval');
>     this.#url = dataUrl;
>     this.#interval = interval;
>     this.#schedule();
>   }
>   #schedule() {
>     if (this.#closed || this.#flight || this.#timer !== null) return;
>     this.#timer = setTimeout(() => {
>       this.#timer = null;
>       this.sendNow().catch(() => {});
>     }, this.#interval);
>   }
>   queueEvent(event) {
>     if (this.#closed) throw Error('Closed');
>     // Контракт принимает только JSON-совместимое событие.
>     const snapshot = JSON.parse(JSON.stringify(event));
>     this.#events.push(snapshot);
>   }
>   sendNow() {
>     if (this.#closed) return Promise.reject(Error('Closed'));
>     if (this.#flight) return this.#flight;
>     clearTimeout(this.#timer);
>     this.#timer = null;
>     if (!this.#events.length) {
>       this.#schedule();
>       return Promise.resolve();
>     }
>     const batch = this.#events;
>     this.#events = [];
>     this.#flight = Promise.resolve()
>       .then(async () => {
>         const response = await fetch(this.#url, {
>           method: 'POST',
>           headers: { 'Content-Type': 'application/json' },
>           body: JSON.stringify(batch),
>         });
>         if (!response.ok) throw Error(`HTTP ${response.status}`);
>       })
>       .catch((error) => {
>         this.#events = batch.concat(this.#events);
>         throw error;
>       })
>       .finally(() => {
>         this.#flight = null;
>         this.#schedule();
>       });
>     return this.#flight;
>   }
>   close() {
>     this.#closed = true;
>     clearTimeout(this.#timer);
>     this.#timer = null;
>   }
> }
> ```
>
> Проверь порядок: A отправляется, приходит B, отказ A — следующая пачка содержит A,B. При успехе A следующий запрос содержит только B. Проверь HTTP 503, два `sendNow`, изменение исходного объекта, пустую очередь и `close` во время запроса. Заголовок описывает тело, а `response.ok` отделяет HTTP-успех от состоявшегося сетевого обмена.
>
> Это защита от потери внутри живого клиента, не exactly-once. Потерянный ответ после записи на сервере приведёт к повторной доставке. Для дедупликации нужен стабильный ID события/операции и согласованная обработка на сервере; одного браузерного флага недостаточно. Для production отдельно решаются предел очереди, backoff, неизлечимые 4xx, согласие на аналитику и долговечное хранение. Закрытие вкладки или `close` не гарантируют отправку остатка; нельзя обещать это с помощью одного `sendBeacon`.

**Критерии ответа:** Разделяю batch и новые события, сериализую отправку, восстанавливаю очередь при сетевом/HTTP-отказе, объясняю границу дедупликации и жизненный цикл таймера.
