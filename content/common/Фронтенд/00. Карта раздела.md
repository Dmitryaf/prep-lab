# Фронтенд

Раздел объясняет механизмы frontend-разработки и их применение. Основной стек — JavaScript, TypeScript и Vue. Для проверки себя используй [[Собеседования/00. Карта раздела|банк]], для наблюдения поведения — [[Фронтенд/Практикумы/00. Карта раздела|практикумы]]. Подробности выбирай по вопросу и конкретному пробелу.

## Как темы связаны между собой

Пользователь действует в интерфейсе. JavaScript выполняет логику; TypeScript помогает согласовать ожидания к данным. Vue связывает состояние с экраном. Проверка на границе принимает или отклоняет реальные данные. Хранилище сохраняет результат, сеть связывает устройства и серверы. Архитектура определяет, кто за какой шаг отвечает; тесты проверяют конкретное поведение.

```text
Задача пользователя → HTML/CSS и Vue → логика JS/TS → проверка → сохранение
                                        ↓                       ↓
                               ошибки и конкуренция      сеть и синхронизация
                                        ↓                       ↓
                          тесты, безопасность, запуск и восстановление
```

Карта описывает весь маршрут; подробности выбираются под вопрос. Подготовка к интервью ниже остаётся быстрым альтернативным входом.

## Порядок последовательного изучения

1. Один сценарий приложения из своего репозитория либо [[Собеседования/Проектирование/Клиентское приложение|учебный frontend-кейс]].
2. Один ввод и сохранение; незнакомые основы JS/TS/Vue читать по ссылкам из сценария.
3. Владельцы данных, хранение и совместимость старых записей.
4. Сеть, конкуренция, повтор и восстановление.
5. Архитектурные решения, безопасность, тесты и выпуск.
6. [[Собеседования/01. Основной маршрут|маршрут вопросов и практики]]: объяснить, найти, предсказать, проверить и оценить изменение.

Язык, браузер, Vue и сервер не нужно изучать как несвязанные курсы. Но конкретный способ из одного проекта не становится универсальным правилом: сравни его с задачей второго проекта и назови условия выбора.

## Применение и самостоятельная проверка

Фундамент не нужно усложнять терминами. Проверяй, можешь ли ты объяснить механизм, написать решение, найти отказ и защитить выбор:

1. **Данные.** `unknown` → проверка JSON → понятные состояния: [[Фронтенд/TypeScript/03. Объединения типов и сужение|Объединения типов и сужение]].
2. **Запросы и тесты.** Исправить гонку и объяснить проверку: [[Фронтенд/Инженерные основы/07. Тестирование/02. Проверка поиска с поздними ответами|Проверка поиска с поздними ответами]].
3. **Доступ и кэш.** Проследить вход, истечение, выход и обновление версии: [[Фронтенд/Инженерные основы/03. Безопасность frontend-приложений/01. Authentication, authorization, sessions и tokens|Authentication, authorization, sessions и tokens]], [[Фронтенд/Инженерные основы/02. HTTP, HTTPS и API/01. HTTP и HTTPS основы|HTTP и HTTPS основы]].
4. **Производительность.** Найти причину по измерению, назвать предел доказательства: [[Фронтенд/Инженерные основы/04. Производительность/01. Core Web Vitals и загрузка frontend-приложения|Core Web Vitals и загрузка frontend-приложения]], [[Фронтенд/Инженерные основы/04. Производительность/03. Практическая диагностика таблицы, ввода и памяти|Практическая диагностика таблицы, ввода и памяти]].
5. **Работающий продукт.** Разобрать инцидент и проверку восстановления: [[Собеседования/Практика/Диагностика#Инциденты клиентского приложения|Диагностика клиентского приложения]].
6. **Решения и опыт.** Назвать условия выбора и собственный вклад: [[Собеседования/Практика/Инженерные решения|Инженерные решения]]. Дополнительный стек выбирай из маршрута вакансии выше.

`P0/P1/P2` — приоритет материала, а не оценка твоего уровня. Прочитанная заметка и успешно запущенный готовый тест не доказывают самостоятельное владение темой. Учебные случаи не выдавай за собственные коммерческие истории.

## Полный учебный маршрут

HTML/CSS → JavaScript → API браузера → TypeScript → Vue → инженерные основы → архитектура. Закрепление: короткое упражнение по механизму, практикум или задача банка.

Сценарий mock-интервью определяет формат и ротацию проверок; эта карта определяет, где повторять материал. Копировать все темы сценария в учебные заметки не нужно.
