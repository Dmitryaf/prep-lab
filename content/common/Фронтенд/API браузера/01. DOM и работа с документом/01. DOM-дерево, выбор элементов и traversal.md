# DOM-дерево, выбор элементов и traversal

> [!summary]
> Браузер читает HTML и создаёт из него дерево объектов — DOM. Например, кнопка становится объектом, у которого можно изменить текст, добавить класс или зарегистрировать обработчик нажатия. Именно с этими объектами работает JavaScript.

## Зачем понимать тему

DOM нужен почти во всём браузерном JavaScript: найти кнопку, прочитать значение поля, вставить элемент, повесить обработчик, делегировать событие или измерить размер блока. На собеседовании часто проверяют не редкие методы, а умение различать узлы, элементы, коллекции и селекторы.

## Базовая модель

HTML:

```html
<ul id="list">
  <li class="item">A</li>
  <li class="item">B</li>
</ul>
```

Браузер строит дерево:

```text
document
└─ html
   └─ body
      └─ ul#list
         ├─ text node с переносом строки
         ├─ li.item
         ├─ text node с переносом строки
         └─ li.item
```

`Element` - узел-элемент вроде `ul`, `li`, `button`. `Text` - текстовый узел. Оба являются `Node`.

## Выбор элементов

```js
const list = document.querySelector('#list');
const items = document.querySelectorAll('.item');

console.log(list.tagName); // UL
console.log(items.length); // 2
```

Практическое правило:

| API | Когда использовать |
| --- | --- |
| `querySelector(selector)` | нужен первый элемент по CSS-селектору |
| `querySelectorAll(selector)` | нужен статический список элементов |
| `getElementById(id)` | нужен элемент по `id`, быстро и явно |
| `closest(selector)` | нужно найти сам элемент или ближайшего подходящего предка |
| `matches(selector)` | нужно проверить сам элемент |

`querySelectorAll()` возвращает статический `NodeList`: если потом добавить новый элемент, старый список сам не обновится.

## Traversal

Traversal — это переходы между узлами дерева. Например, от пункта списка можно перейти к самому списку через parentElement, а к следующему пункту — через nextElementSibling.

```js
const item = document.querySelector('.item');

console.log(item.parentElement.id); // list
console.log(item.nextElementSibling.textContent); // B
```

Частые свойства:

| Нужно | Свойства |
| --- | --- |
| Только элементы | `children`, `firstElementChild`, `nextElementSibling`, `parentElement` |
| Любые узлы, включая текст | `childNodes`, `firstChild`, `nextSibling`, `parentNode` |

## children vs childNodes

```html
<ul id="list">
  <li>A</li>
  <li>B</li>
</ul>
```

```js
const list = document.querySelector('#list');

console.log(list.children.length); // 2
console.log(list.childNodes.length); // обычно больше из-за переносов строк
```

`childNodes` видит текстовые узлы с пробелами и переносами. Для большинства UI-задач удобнее `children`.

## Частые ошибки

- Думать, что DOM - это исходная HTML-строка.
- Путать `Node` и `Element`.
- Использовать `childNodes`, когда нужны только элементы.
- Ожидать, что результат `querySelectorAll()` обновится после изменения DOM.
- Не проверять `null` после `querySelector()`.

## Как ответить на собеседовании за одну минуту

DOM — это дерево объектов, которое браузер создаёт из документа. Например, я могу найти кнопку через `querySelector`, поменять её текст или добавить к ней обработчик. От найденного элемента можно перейти к родителю, детям или соседям.

В дереве есть не только элементы. Между двумя тегами могут находиться текстовые узлы с пробелами и переносами строк. Поэтому `children` вернёт только элементы, а `childNodes` — ещё и эти узлы.

Если я получил список через `querySelectorAll()`, а потом добавил новую кнопку, в старом списке её не будет. Для нового набора элементов нужно выполнить запрос ещё раз.

> [!note]- Углубление: терминология DOM Standard
> DOM Standard описывает общие правила для узлов, деревьев и событий. У узла могут быть родитель и дети. Tree order — это порядок, в котором обход сначала посещает родителя, затем его потомков по порядку. На этих правилах основаны методы, которыми JavaScript читает и меняет документ.
