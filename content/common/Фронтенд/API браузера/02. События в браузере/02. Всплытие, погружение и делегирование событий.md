# Всплытие, погружение и делегирование событий

> [!summary]
> DOM-событие может пройти по цепочке предков: сначала сверху вниз на фазе capture, затем на целевом элементе, затем снизу вверх на фазе bubble. Делегирование использует эту модель, чтобы обрабатывать события дочерних элементов на общем родителе.

## Зачем понимать тему

Это один из самых частых Browser API вопросов. Он проверяет не знание редких событий, а понимание пути события, `target`, `currentTarget`, `preventDefault()` и `stopPropagation()`.

## Базовая модель

```html
<div id="outer">
  <button id="inner">Click</button>
</div>
```

Если кликнуть по `button`, событие идёт примерно так:

```text
document -> html -> body -> div -> button -> div -> body -> html -> document
 capture phase             target      bubble phase
```

Listener с `{ capture: true }` срабатывает на фазе погружения. Обычный listener срабатывает на target/bubble фазе.

```js
outer.addEventListener('click', () => {
  console.log('bubble');
});

outer.addEventListener('click', () => {
  console.log('capture');
}, { capture: true });
```

При клике по `inner` сначала сработает capture-listener, потом bubble-listener.

## Делегирование событий

Вместо listener на каждой кнопке можно поставить один listener на общий контейнер.

```js
list.addEventListener('click', (event) => {
  const button = event.target.closest('[data-action]');

  if (!button || !list.contains(button)) {
    return;
  }

  const action = button.dataset.action;
  console.log(action);
});
```

Плюсы:

- меньше listeners;
- работает для элементов, добавленных позже;
- логика списка находится в одном месте.

Минусы:

- нужно аккуратно проверять `target`;
- не все события всплывают одинаково;
- `stopPropagation()` внутри дочернего элемента может сломать делегирование.

## preventDefault и stopPropagation

`preventDefault()` отменяет действие браузера по умолчанию, если событие отменяемое.

```js
form.addEventListener('submit', (event) => {
  event.preventDefault();
  saveForm();
});
```

`stopPropagation()` останавливает дальнейшее прохождение события по цепочке.

```js
modal.addEventListener('click', (event) => {
  event.stopPropagation();
});
```

Важно: `preventDefault()` не останавливает всплытие, а `stopPropagation()` не отменяет действие по умолчанию.

## stopImmediatePropagation

`stopImmediatePropagation()` останавливает дальнейшее распространение и не даёт выполниться следующим listeners на этом же target.

Это P1/P2-деталь: в обычном коде лучше проектировать обработчики так, чтобы не требовалось "глушить" соседние listeners.

## Частые ошибки

- Считать, что `preventDefault()` останавливает всплытие.
- Считать, что `stopPropagation()` отменяет переход по ссылке или submit формы.
- В делегировании использовать `event.target` напрямую и не учитывать вложенные элементы.
- Забывать проверку `container.contains(element)` после `closest()`.
- Ставить `stopPropagation()` слишком широко и ломать внешние обработчики.

## Как ответить на собеседовании за одну минуту

Когда DOM-событие происходит на элементе, оно проходит по пути события. Сначала могут вызваться listeners предков на capture phase, затем listeners целевого элемента, затем событие обычно всплывает по предкам на bubble phase. `target` остаётся исходной целью, а `currentTarget` меняется на элемент, чей listener сейчас выполняется. Делегирование использует всплытие: ставим один listener на контейнер и по `event.target.closest()` понимаем, какой дочерний элемент вызвал событие. `preventDefault()` отменяет действие браузера по умолчанию, `stopPropagation()` останавливает дальнейшее распространение.

> [!note]- Углубление: composed path и Shadow DOM
> В Shadow DOM путь события может проходить через границы shadow tree, а `event.target` может ретаргетироваться. Для базового собеседования обычно достаточно обычной DOM-модели; `event.composedPath()` стоит упомянуть только в вопросах про Web Components.
