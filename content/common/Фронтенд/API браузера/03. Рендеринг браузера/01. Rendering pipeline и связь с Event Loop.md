# Rendering pipeline и связь с Event Loop

> [!summary]
> Рендеринг — построение изображения страницы из HTML, CSS и изменений DOM. Браузер создаёт структуры документа и стилей, определяет видимые элементы, вычисляет их размеры и положение, рисует содержимое и собирает итоговый кадр. Долгое выполнение JavaScript в основном потоке может задержать обновление экрана.

## Зачем понимать тему

Эта тема помогает объяснить, почему UI "фризится", почему чтение размеров после записи стилей может быть дорогим, почему анимации через `transform` часто дешевле, чем через `top/left`, и как `requestAnimationFrame()` связан с кадром.

## Базовая модель

Упрощённый путь первичной отрисовки:

```text
HTML -> DOM
CSS  -> CSSOM
DOM + CSSOM -> render tree
render tree -> layout -> paint -> composite
```

Это учебная модель. Реальные браузеры оптимизируют, кешируют и могут пропускать некоторые шаги, если изменение их не требует.

## DOM, CSSOM и render tree

DOM описывает структуру документа. CSSOM описывает CSS-правила и вычисленные стили. Для отображения браузеру нужно понять, какие видимые элементы есть на странице и какие стили к ним применить.

`display: none` обычно исключает элемент из render tree, потому что он не занимает место и не рисуется. `visibility: hidden` место оставляет, но элемент не виден.

## Layout, paint и composite

| Шаг | Что делает | Примеры изменений |
| --- | --- | --- |
| Layout | считает размеры и позиции | `width`, `height`, `font-size`, добавление элемента |
| Paint | рисует внешний вид в слои | `color`, `background`, `box-shadow` |
| Composite | собирает слои на экране | `transform`, `opacity` часто могут обрабатываться дешевле |

Практическое правило: изменения, влияющие на геометрию, дороже, потому что могут затронуть соседей и потом потребовать paint.

## Связь с Event Loop

JavaScript, обработчики DOM-событий, таймеры и микрозадачи выполняются в порядке, который задаёт Event Loop браузера. Долгая макрозадача или непрерывная цепочка микрозадач может задержать следующий кадр.

Подробнее про порядок task/microtask: [[Фронтенд/JavaScript/05. Асинхронность/01. Event Loop в браузере|Event Loop в браузере]].

## Forced layout

Проблемный паттерн:

```js
for (const item of items) {
  item.style.width = '200px';
  console.log(item.offsetWidth);
}
```

Код меняет стиль и тут же читает layout-свойство. Браузеру может понадобиться синхронно посчитать актуальную геометрию. Лучше группировать чтения и записи.

```js
for (const item of items) {
  item.style.width = '200px';
}
const widths = items.map((item) => item.offsetWidth);
console.log(widths);
```

Здесь сначала меняем все элементы, затем читаем их новые размеры: сохраняется смысл исходного примера. Первое чтение всё ещё может потребовать синхронный расчёт геометрии, но записи больше не чередуются с чтениями. Если нужны старые размеры, читаем их до изменения стилей — это уже другая задача.

## Частые ошибки

- Думать, что любое изменение DOM сразу синхронно рисуется на экране.
- Называть отрисовку обычной макрозадачей.
- Считать, что `paint` и `repaint` - то же самое, что layout/reflow.
- Читать layout-свойства в цикле сразу после записи стилей.
- Делать тяжёлую работу в обработчике input/click и удивляться задержкам UI.

## Как ответить на собеседовании за одну минуту

Браузер строит DOM из HTML и CSSOM из CSS, затем определяет, какие элементы нужно показать. На этапе layout вычисляет размеры и положение элементов, на этапе paint рисует их внешний вид, а на этапе composite собирает слои в итоговое изображение. Изменение размеров может потребовать нового расчёта геометрии, изменение оформления — перерисовки; изменения вроде `transform` и `opacity` часто удаётся обработать при сборке слоёв. JavaScript выполняется в основном потоке, поэтому долгая макрозадача или непрерывная очередь микрозадач задерживают отрисовку и обработку ввода.

> [!note]- Углубление: разные браузеры
> Названия внутренних стадий, слоёв и оптимизаций отличаются между движками. Для интервью полезнее объяснить причинную модель "геометрия -> рисование -> композиция", чем утверждать, что каждый браузер всегда проходит один и тот же фиксированный список шагов.
