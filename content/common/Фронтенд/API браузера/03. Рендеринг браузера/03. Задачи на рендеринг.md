# Задачи на рендеринг

## Задача 1. Почему интерфейс зависает

```js
button.addEventListener('click', () => {
  const start = Date.now();

  while (Date.now() - start < 2000) {}

  status.textContent = 'Done';
});
```

Почему текст не обновляется сразу?

> [!question]- Разбор
> Обработчик клика выполняется как макрозадача JavaScript в основном потоке. Пока цикл не закончится, браузер не может перейти к обработке следующего ввода и обновлению изображения. Изменение `textContent` произойдёт в DOM, но пользователь увидит результат только когда основной поток освободится и браузер сможет обновить кадр.

## Задача 2. Forced layout

Что потенциально плохо в коде?

```js
for (const item of items) {
  item.style.height = '40px';
  total += item.offsetHeight;
}
```

> [!question]- Разбор
> Код записывает стиль и сразу читает layout-свойство. Браузеру может понадобиться синхронно пересчитать геометрию на каждой итерации. В этом примере нужны новые размеры после установки `height`: сначала запиши стиль всем элементам, затем отдельным проходом суммируй `offsetHeight`. Перенос чтений до записей дал бы старые размеры и изменил смысл задачи. Первое чтение всё ещё может вызвать layout, но повторного чередования записи/чтения уже нет.

## Задача 3. Что выбрать для анимации

Нужно плавно двигать элемент. Что лучше попробовать первым: `left` или `transform: translateX()`?

> [!question]- Разбор
> Если элемент нужно только визуально сдвинуть, сначала попробую `transform`. Изменение `left` может заставить браузер заново рассчитывать положение, а `transform` часто позволяет переместить уже подготовленный слой. Затем сравню запись Performance: итоговая стоимость зависит от самого элемента и способа его отрисовки.
