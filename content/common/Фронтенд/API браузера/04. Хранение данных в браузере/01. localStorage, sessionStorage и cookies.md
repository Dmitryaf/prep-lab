# localStorage, sessionStorage и cookies

> [!summary]
> `localStorage`, `sessionStorage` и cookies решают разные задачи. Web Storage удобен для простых клиентских строковых данных, cookies - для данных, которые должны участвовать в HTTP-запросах, особенно в сессиях.

## Зачем понимать тему

На собеседовании часто спрашивают, где хранить токен, почему `localStorage` не подходит для больших данных, чем cookies отличаются от Web Storage и почему синхронный storage может быть проблемой.

## Web Storage

`localStorage` и `sessionStorage` имеют похожий API:

```js
localStorage.setItem('theme', 'dark');
const theme = localStorage.getItem('theme');
localStorage.removeItem('theme');
```

Ключи и значения - строки. Объекты нужно сериализовать:

```js
const settings = { theme: 'dark' };
localStorage.setItem('settings', JSON.stringify(settings));

const saved = JSON.parse(localStorage.getItem('settings'));
```

## localStorage vs sessionStorage

| Свойство | localStorage | sessionStorage |
| --- | --- | --- |
| Область | origin | origin и текущая страница/вкладка |
| Жизнь | обычно переживает закрытие браузера | обычно живёт до закрытия вкладки |
| API | синхронный | синхронный |
| Данные | строки | строки |

`storage` event может сработать в других окнах того же origin, когда storage меняется.

## Cookies

Cookies - маленькие пары `name=value`, которые браузер может автоматически отправлять на сервер с подходящими HTTP-запросами.

```http
Set-Cookie: sessionId=abc; HttpOnly; Secure; SameSite=Lax
```

Практически важные атрибуты:

| Атрибут | Зачем нужен |
| --- | --- |
| `HttpOnly` | cookie недоступна из JavaScript |
| `Secure` | отправлять только по HTTPS |
| `SameSite` | ограничивает отправку в cross-site сценариях |
| `Expires`/`Max-Age` | задаёт срок жизни |
| `Path`/`Domain` | ограничивает область отправки |

## Сравнение

| Задача | Что выбрать |
| --- | --- |
| Тема интерфейса | `localStorage` |
| Черновик формы в текущей вкладке | `sessionStorage` |
| Серверная сессия | cookie с `HttpOnly`, `Secure`, `SameSite` |
| Большие offline-данные | IndexedDB |
| Данные, которые нельзя читать JS | не `localStorage`; чаще HttpOnly cookie |

## Частые ошибки

- Хранить чувствительные токены в `localStorage` и считать это безопасным.
- Забывать, что Web Storage синхронный и может блокировать основной поток.
- Считать, что cookies и `localStorage` одинаково участвуют в запросах.
- Хранить большие массивы JSON в `localStorage`.
- Полагаться на точный размер quota как на стабильный стандарт.

## Как ответить на собеседовании за одну минуту

`localStorage` и `sessionStorage` - синхронный Web Storage для строковых данных одного origin. `localStorage` обычно переживает закрытие браузера, `sessionStorage` привязан к вкладке или странице. Cookies отличаются тем, что браузер автоматически отправляет их с HTTP-запросами, если соблюдены ограничения Domain, Path, SameSite и Secure. Для серверной сессии часто используют HttpOnly Secure cookie, потому что JavaScript не может её прочитать. Для больших структурированных данных лучше IndexedDB. Квоты и очистка зависят от браузера, поэтому нельзя строить логику на точных мегабайтах.

> [!note]- Углубление: quota и privacy
> Storage quota и правила eviction зависят от браузера, режима приватности, доступного места, политики пользователя и типа хранилища. Для интервью достаточно сказать: "есть ограничения; `setItem()` может бросить `QuotaExceededError`; нужно обрабатывать ошибку и не хранить критически единственную копию данных только в браузере".
