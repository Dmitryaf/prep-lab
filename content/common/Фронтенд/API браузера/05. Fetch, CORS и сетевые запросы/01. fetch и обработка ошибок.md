# fetch и обработка ошибок

> [!summary]
> `fetch()` делает HTTP-запрос из браузера и возвращает Promise с объектом `Response`. Важная ловушка: HTTP-статус ошибки не всегда означает rejected Promise.

## Базовая модель

```js
const response = await fetch('/api/user');
const user = await response.json();
```

`fetch()` ждёт response headers и возвращает `Response`. Тело читается отдельно: `json()`, `text()`, `blob()`, `arrayBuffer()`.

## Обработка HTTP-статусов

```js
async function loadUser() {
  const response = await fetch('/api/user');

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  return response.json();
}
```

`response.ok` равен `true` для статусов 200-299. `404` или `500` обычно дают fulfilled Promise с `Response`, поэтому статус нужно проверять вручную.

## Сетевые ошибки и ошибки парсинга

```js
try {
  const response = await fetch('/api/user');

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  const user = await response.json();
  render(user);
} catch (error) {
  showError(error);
}
```

В `catch` могут попасть разные причины:

- network-level failure;
- CORS-blocked response;
- abort;
- ошибка парсинга JSON;
- вручную брошенная ошибка из-за `!response.ok`.

Для хорошего UI эти случаи часто различают.

## POST с JSON

```js
async function createUser(user) {
  const response = await fetch('/api/users', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify(user),
  });

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  return response.json();
}
```

## credentials

По умолчанию `fetch()` отправляет credentials в same-origin запросах. Для cross-origin запроса cookies/credentials нужно включать явно и сервер должен разрешить это CORS-заголовками.

```js
fetch('https://api.example.com/me', {
  credentials: 'include',
});
```

## Частые ошибки

- Ожидать, что `fetch('/missing')` попадёт в `catch` из-за `404`.
- Читать body дважды: `Response` body - поток, его нельзя просто перечитать без специальных приёмов.
- Не различать HTTP-ошибку, сетевой отказ и ошибку разбора JSON.
- Забывать `JSON.stringify()` для JSON body.
- Считать, что `mode: 'no-cors'` "решает CORS". Такой response обычно opaque и недоступен для чтения.

## Как ответить на собеседовании за одну минуту

`fetch()` возвращает Promise, который обычно fulfilled, когда браузер получил HTTP response, даже если статус `404` или `500`. Поэтому нужно проверять `response.ok` или `response.status` вручную. В `catch` попадают сетевые ошибки, CORS-блокировки, abort, ошибки парсинга или ошибки, которые мы сами бросили. Тело ответа читается отдельным асинхронным методом вроде `response.json()`. Для cookies в cross-origin запросах нужны `credentials: 'include'` на клиенте и корректные CORS-заголовки на сервере.
