# AbortController и race condition в запросах

> [!summary]
> Представим поиск: пользователь уже ввёл cat, но поздно пришёл ответ на c и заменил свежую выдачу. Это гонка запросов. `AbortController` помогает отменить ненужный запрос, а проверка актуальности защищает экран от позднего результата.

## AbortController

```js
const controller = new AbortController();

fetch('/api/search?q=cat', {
  signal: controller.signal,
}).catch((error) => {
  if (error.name === 'AbortError') {
    return;
  }

  throw error;
});

controller.abort();
```

Отмена говорит клиентской операции, что результат больше не нужен. Она не гарантирует, что сервер "откатил" уже начатую работу.

## Race condition и устаревшие ответы

Пользователь быстро печатает:

```text
c -> ca -> cat
```

Запрос `c` может вернуться позже `cat`. Если просто рендерить каждый ответ, старые данные перетрут новые.

```js
let requestId = 0;

async function search(query) {
  const currentRequestId = ++requestId;
  const response = await fetch(`/api/search?q=${encodeURIComponent(query)}`);
  const result = await response.json();

  if (currentRequestId !== requestId) {
    return;
  }

  render(result);
}
```

## Отмена предыдущего запроса

```js
let currentController = null;

async function search(query) {
  currentController?.abort();
  const controller = new AbortController();
  currentController = controller;
  setLoading(true);

  try {
    const response = await fetch(`/api/search?q=${encodeURIComponent(query)}`, {
      signal: controller.signal,
    });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const result = await response.json();
    if (currentController === controller && !controller.signal.aborted) {
      render(result);
    }
  } catch (error) {
    if (currentController === controller && !controller.signal.aborted) {
      showError(error);
    }
  } finally {
    if (currentController === controller) {
      currentController = null;
      setLoading(false);
    }
  }
}
```

Здесь отмена освобождает ресурсы запроса, а сравнение локального `controller` с текущим защищает данные, ошибку и `loading` от устаревшего продолжения. Даже если адаптер проигнорирует сигнал или старая обработка уже началась, старый вызов не изменит состояние нового поиска. При закрытии экрана нужно отменить текущий controller и снять его как активный.

## Частые ошибки

- Думать, что `abort()` откатывает серверную операцию.
- Показывать ошибку пользователю при ожидаемом `AbortError`.
- Защищаться только debounce, хотя ответы всё равно могут прийти не по порядку.
- Не учитывать race condition между несколькими независимыми источниками данных.

## Как ответить на собеседовании за одну минуту

Когда пользователь меняет поисковый запрос, предыдущий ответ уже не нужен. Я передаю в `fetch()` сигнал от `AbortController`, а при следующем вводе вызываю `abort()`. Так клиент может прекратить ожидание и освободить ресурсы. Уже выполненную запись на сервере такая отмена не откатывает.

Кроме отмены, проверяю, какому запросу принадлежит результат. Например, запоминаю его номер и перед обновлением данных, ошибки или `loading` сравниваю с текущим. Тогда ответ на c не затрёт выдачу для cat, даже если старый запрос проигнорировал отмену или его обработка уже началась.
