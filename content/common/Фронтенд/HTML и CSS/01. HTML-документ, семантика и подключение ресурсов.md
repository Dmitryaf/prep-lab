# HTML-документ, семантика и подключение ресурсов

> [!summary]
> HTML описывает, что находится на странице: заголовок, навигация, статья, поле или кнопка. Когда смысл задан подходящими элементами, браузер и вспомогательные технологии могут правильно представить страницу пользователю. CSS отвечает за оформление, а JavaScript добавляет поведение.

## Зачем понимать тему

На собеседованиях по HTML часто проверяют не список тегов, а мышление: почему `button` лучше кликабельного `div`, когда нужен `article`, как устроить headings, зачем `label`, где подключать CSS/JS и почему семантика влияет на доступность.

## Базовая структура документа

```html
<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Профиль пользователя</title>
    <meta name="description" content="Страница профиля пользователя">
    <link rel="stylesheet" href="/styles.css">
    <script src="/app.js" defer></script>
  </head>
  <body>
    <header>...</header>
    <main>...</main>
    <footer>...</footer>
  </body>
</html>
```

Практичная модель:

- `doctype` включает современный режим рендеринга;
- `html lang` помогает screen readers, переводчикам и поисковым системам;
- `head` содержит metadata и ссылки на ресурсы;
- `body` содержит видимый/интерактивный контент;
- `viewport` нужен для нормального mobile layout;
- `defer` позволяет загрузить script без блокировки построения DOM и выполнить после парсинга документа.

## Семантические теги

Семантический тег говорит, что это за часть контента:

```html
<header>
  <nav aria-label="Основная навигация">
    <a href="/">Главная</a>
    <a href="/catalog">Каталог</a>
  </nav>
</header>

<main>
  <article>
    <h1>Как выбрать монитор</h1>
    <p>...</p>
  </article>
</main>
```

Частые ориентиры:

| Тег | Когда использовать |
|---|---|
| `main` | основной уникальный контент страницы |
| `header` | вводная область страницы или секции |
| `footer` | нижняя область страницы или секции |
| `nav` | навигационный блок |
| `article` | самостоятельный материал: статья, карточка поста, новость |
| `section` | тематическая секция с заголовком |
| `aside` | дополнительный связанный контент |
| `button` | действие |
| `a` | переход по адресу |

## `div` vs semantic elements

`div` подходит, когда нужно просто объединить элементы для оформления или раскладки. Например, обёртке для двух колонок не обязательно придавать смысл статьи или навигации.

Плохо, когда `div` заменяет нативный интерактивный элемент:

```html
<!-- Плохо -->
<div class="button" onclick="save()">Сохранить</div>

<!-- Лучше -->
<button type="button">Сохранить</button>
```

Кнопка уже получает фокус, нажимается клавиатурой и сообщает свою роль вспомогательным технологиям. У неё есть и состояние disabled. У кликабельного div всё это пришлось бы реализовывать отдельно.

## Заголовки

Заголовки задают структуру контента:

```html
<main>
  <h1>Каталог</h1>
  <section>
    <h2>Ноутбуки</h2>
  </section>
  <section>
    <h2>Мониторы</h2>
  </section>
</main>
```

Не выбирай `h3` только потому, что он визуально меньше. Внешний вид меняется CSS, структура - HTML.

## Подключение CSS и JS

```html
<link rel="stylesheet" href="/styles.css">
<script src="/app.js" defer></script>
```

CSS обычно подключают в `head`, чтобы браузер мог раньше построить CSSOM. Для обычного JS в конце `body` или с `defer` - чтобы не блокировать парсинг HTML.

> [!note]- Углубление: `async` vs `defer`
> `defer` сохраняет порядок scripts и выполняет их после парсинга документа. `async` выполняет script, как только он загрузился, порядок между async scripts не гарантируется. Для основного app bundle чаще подходит `defer`, для независимой аналитики иногда `async`.

## Частые ошибки

- Делать всю страницу из `div` и `span`.
- Использовать `a` без `href` как кнопку.
- Использовать `button` для перехода по ссылке.
- Нарушать структуру заголовков ради размера шрифта.
- Забывать `lang`, `viewport`, `title`.
- Подключать blocking script в `head` без причины.

## Как ответить на собеседовании за одну минуту

HTML задаёт смысл содержимого. Например, действие «Сохранить» я оформлю кнопкой, а переход к заказу — ссылкой. Браузер тогда даст ожидаемое поведение: кнопку можно нажать клавиатурой, а ссылку открыть в новой вкладке.

Основное содержимое помещаю в `main`, навигацию — в `nav`. Самостоятельная новость может быть `article`, тематический раздел — `section`. Для простой обёртки использую `div`. Заголовки выбираю по структуре текста, а их размер задаю CSS.

В `head` указываю кодировку, viewport, название страницы и нужные метаданные, там же подключаю стили. Основной классический скрипт обычно подключаю с `defer`, чтобы он выполнился после разбора документа.

> [!question]- Разбор
> ```html
> <nav aria-label="Основная навигация">
>   <ul>
>     <li><a href="/">Главная</a></li>
>     <li><a href="/catalog">Каталог</a></li>
>   </ul>
> </nav>
> ```
>
> Карточка новости может быть `article`, если она самостоятельна и имеет свой заголовок/ссылку. `defer` не прерывает парсинг HTML и сохраняет порядок выполнения scripts.
