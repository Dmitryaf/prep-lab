# Каскад, специфичность и наследование

> [!summary]
> Каскад (cascade) выбирает итоговое значение из подходящих CSS-правил. Нужно учитывать источник, важность, слой, вес селектора и порядок; наследование (inheritance) передаёт часть значений от родителя.

## Базовая модель

CSS отвечает на вопрос: какое значение свойства применить к элементу?

Практичный порядок:

1. Найти объявления, которые подходят к элементу.
2. Учесть источник и важность (`!important`).
3. Для правил одного источника и важности учесть слои каскада (`@layer`).
4. В одном слое сравнить специфичность — вес селектора.
5. При равных условиях побеждает более позднее правило.

Это модель обычных правил автора без анимаций, переходов и `@scope`. Наследование — отдельный механизм: для наследуемого свойства при отсутствии своего значения используется значение родителя.

## Specificity

Упрощенная модель веса:

```text
inline styles > #id > .class / [attr] / :pseudo-class > tag / ::pseudo-element
```

Пример:

```css
button {
  color: black;
}

.button {
  color: blue;
}

#save-button {
  color: red;
}
```

Для `<button id="save-button" class="button">` победит `red`.

## Слои каскада и управляемые переопределения

```css
@layer vendor, components;
@layer vendor {
  #save-button { color: red; }
}
@layer components {
  .button { color: blue; }
}
```

Для той же кнопки побеждает `blue`: у обычных правил слой `components` объявлен позже, его порядок сравнивается раньше веса селектора. Правила автора вне слоёв сильнее обычных правил внутри слоёв. Это помогает поместить сторонние стили в ранний слой, не наращивая селекторы приложения.

> [!note]- Углубление: важные правила
> Для `!important` порядок слоёв обратный: ранний слой сильнее позднего, а важные правила в слоях сильнее важных правил вне слоёв. Встроенные стили также имеют отдельное место в каскаде. Нельзя свести весь каскад к формуле «id всегда сильнее класса».

## `:is()` и `:where()`

`:is()` имеет вес самого специфичного селектора в списке аргументов. `:where()` вместе с аргументами имеет нулевой вес.

```css
:where(.theme) .button { color: blue; } /* вес: один класс */
.button { color: green; }            /* тот же вес, правило позже */
:is(.theme, #app) .button { color: red; } /* id + класс */
```

У кнопки внутри `.theme` итоговый цвет — `red`: наличие `#app` в списке `:is()` повышает вес, даже если совпала `.theme`. Если оставить только первые два правила, будет `green`. Здесь правила одного слоя и важности. `:where()` удобно для легко переопределяемых базовых стилей.

## Source order

Если specificity одинаковая, побеждает правило ниже:

```css
.button {
  color: blue;
}

.button {
  color: green;
}
```

Итог: `green`.

## Inheritance

Некоторые свойства наследуются, например `color` и `font-family`. Многие layout-свойства не наследуются: `margin`, `padding`, `border`, `display`.

```css
body {
  color: #222;
  font-family: system-ui;
}
```

Потомки получат цвет и шрифт, если не переопределят их.

## CSS variables

Пользовательские CSS-переменные участвуют в каскаде и наследовании:

```css
:root {
  --color-accent: #0b72ff;
}

.button {
  background: var(--color-accent);
}

.danger-zone {
  --color-accent: #d92d20;
}
```

Внутри `.danger-zone` кнопки получат другое значение переменной.

## Pseudo-classes и pseudo-elements

Pseudo-class описывает состояние или положение:

```css
a:hover {}
button:focus-visible {}
li:first-child {}
input:invalid {}
```

Pseudo-element стилизует часть элемента или generated content:

```css
p::first-line {}
.badge::before {
  content: '';
}
```

## `!important`

`!important` повышает важность declaration, но усложняет поддержку. Его лучше оставлять для редких случаев: utility override, интеграция со сторонними стилями, user styles, emergency fix с последующим рефакторингом.

## Частые ошибки

- Лечить любой конфликт через `!important`.
- Использовать id selectors в компонентном CSS и потом тяжело переопределять.
- Не учитывать порядок импортов CSS.
- Ожидать, что `margin` или `display` наследуются.
- Считать `:before` псевдоклассом: это старый синтаксис псевдоэлемента, современная запись — `::before`.
- Считать CSS-переменные препроцессорными переменными: они работают в каскаде во время работы страницы.

## Как ответить на собеседовании за одну минуту

Каскад выбирает значение среди подходящих правил. В обычном случае сравниваются источник и важность, слой, вес селектора и порядок объявления. Поэтому поздний слой может победить более сильный селектор из раннего слоя. `:where()` имеет нулевой вес, `:is()` берёт максимальный вес аргументов. Наследование передаёт некоторые значения от родителя. CSS-переменные тоже участвуют в каскаде и могут переопределяться в поддереве.

## Практические задачи

1. Определи итоговый цвет для элемента с id и class.
2. Исправь конфликт стилей без `!important`.
3. Сделай тему карточки через CSS variables.

> [!question]- Разбор
> Если селекторы `.card .title` и `.title` оба подходят и остальные условия каскада равны, победит `.card .title`: его вес выше. Чтобы не повышать вес бесконечно, лучше изменить структуру классов или порядок слоев/импортов, а не добавлять id или `!important`.
