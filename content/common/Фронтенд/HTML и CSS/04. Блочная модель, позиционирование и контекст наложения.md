# Блочная модель, позиционирование и контекст наложения

> [!summary]
> Чтобы понять размер и положение элемента, отделяй содержимое, внутренние отступы, рамку и внешние отступы. Position задаёт правила размещения, а z-index сравнивается внутри своего контекста наложения.

## Box model

Каждый элемент в layout занимает box:

```text
content -> padding -> border -> margin
```

```css
.card {
  width: 320px;
  padding: 16px;
  border: 1px solid #ddd;
  margin: 24px;
}
```

По умолчанию `width` задает ширину content box. С `box-sizing: border-box` ширина включает content, padding и border.

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

## Display

| Значение | Практический смысл |
|---|---|
| `block` | занимает строку, можно задавать width/height |
| `inline` | идет в строке, width/height не работают как у block |
| `inline-block` | в строке, но принимает размеры |
| `flex` | контекст flex-раскладки для дочерних элементов |
| `grid` | контекст grid-раскладки для дочерних элементов |
| `none` | элемент не участвует в layout и accessibility tree |

`display` влияет на внешний тип элемента и на layout-контекст для детей.

## Position

```css
.badge {
  position: absolute;
  top: 8px;
  right: 8px;
}
```

| Значение | Что делает |
|---|---|
| `static` | обычный поток документа |
| `relative` | остается в потоке, можно сместить; создает containing block для absolute-потомков |
| `absolute` | выходит из обычного потока, позиционируется относительно содержащего блока, часто ближайшего предка с position не static; transform тоже может создать такой блок |
| `fixed` | относительно области просмотра или предка, создающего содержащий блок, например через transform |
| `sticky` | ведет себя как relative, затем фиксируется в пределах контейнера прокрутки |

## Stacking context и z-index

`z-index` работает не как глобальная "сила", а внутри stacking context.

```css
.modal {
  position: fixed;
  z-index: 1000;
}
```

Stacking context может появиться, например, у positioned element с `z-index`, у элемента с `opacity < 1`, `transform`, `filter`, `isolation: isolate` и в других случаях.

Практичная модель:

- элементы сравниваются внутри своего stacking context;
- ребенок не может "перепрыгнуть" наружу выше соседнего stacking context только большим `z-index`;
- если `z-index` не работает, ищи родителя, который создал новый stacking context.

> [!note]- Углубление: advanced stacking
> Контексты наложения могут быть вложены друг в друга. Сначала браузер определяет место целого родительского контекста среди его соседей, а затем — порядок элементов внутри. Поэтому меню с большим z-index внутри нижнего контекста не перекроет верхний соседний контекст.

## Частые ошибки

- Не использовать `border-box` и удивляться переполнению.
- Ожидать width/height у inline элемента.
- Позиционировать absolute-элемент без positioned parent.
- Поднимать `z-index` до огромных чисел, не проверив stacking context.
- Использовать `display: none` для контента, который должен оставаться доступным screen reader.
- Путать визуальное скрытие и исключение элемента из расчёта расположения.

## Как ответить на собеседовании за одну минуту

У карточки есть содержимое, внутренние отступы, рамка и внешние отступы. Если задать ширину 200px при обычном `content-box`, padding и border добавятся снаружи этой ширины. При `border-box` они войдут в 200px, а margin всё равно останется снаружи.

`display` задаёт участие элемента в раскладке и способ размещения его детей, например Flexbox или Grid. `position` помогает выбрать способ позиционирования. Значок в углу карточки можно сделать absolute, а карточке задать relative, чтобы координаты считались от неё.

Если значок или меню не выходит поверх соседа, смотрю контексты наложения у родителей. Большой `z-index` ребёнка сравнивается внутри своего контекста. Поэтому сначала проверяю, какой предок создал этот контекст через `transform`, `opacity` или сочетание position и z-index.

- Относительно чего позиционируется `absolute`?
- Почему большой `z-index` может не помочь?
- Чем `display: none` отличается от visually hidden?

## Практические задачи

1. Посчитай итоговую ширину карточки при content-box и border-box.
2. Исправь badge в правом верхнем углу карточки.
3. Найди причину, почему tooltip не перекрывает соседний блок.

> [!question]- Разбор
> Для badge обычно нужен parent:
>
> ```css
> .card {
>   position: relative;
> }
>
> .badge {
>   position: absolute;
>   top: 8px;
>   right: 8px;
> }
> ```
>
> Если tooltip не перекрывает соседей, проверь stacking context у родителей: `transform`, `opacity`, `z-index`. Отдельно проверь обрезание через `overflow`: оно может скрыть часть tooltip, но само по себе не создаёт stacking context.
