# Адаптивная вёрстка, медиазапросы и единицы измерения

> [!summary]
> Адаптивный интерфейс остаётся удобным при изменении ширины, размера текста и способа ввода. Начинай с гибкого расположения и размеров; отдельные правила добавляй там, где содержимое перестаёт помещаться.

## Базовая модель

Начинай с гибкой верстки:

- относительные размеры там, где они уместны;
- `max-width` вместо жесткого `width`;
- Flex/Grid с `gap`;
- изображения, которые не вылезают из контейнера;
- media queries для реальных переломных точек layout.

```css
.page {
  width: min(100% - 32px, 1120px);
  margin-inline: auto;
}

img {
  max-width: 100%;
  height: auto;
}
```

## Units

| Unit | Практическое применение |
|---|---|
| `px` | borders, маленькие точные размеры, иногда icons |
| `%` | размер относительно parent |
| `em` | для font-size — относительно шрифта родителя; в остальных свойствах обычно относительно шрифта самого элемента |
| `rem` | относительно размера шрифта корневого элемента; удобно для согласованных отступов и размеров текста |
| `vw`/`vh` | viewport units, осторожно на mobile |
| `dvh`/`svh`/`lvh` | более точные viewport-варианты для mobile UI |
| `fr` | доля доступного пространства в Grid |
| `ch` | примерно ширина символа `0`, иногда для текстовых строк |

Не надо делать весь UI в одной единице. Хорошая верстка смешивает units по смыслу.

## Media queries

```css
.layout {
  display: grid;
  gap: 16px;
}

@media (width >= 768px) {
  .layout {
    grid-template-columns: 280px minmax(0, 1fr);
  }
}
```

Брейкпоинты лучше выбирать по моменту, где ломается контент, а не только по названиям устройств.

## Container queries

Container queries реагируют на размер контейнера, а не viewport:

```css
.card-list {
  container-type: inline-size;
}

@container (width >= 480px) {
  .card {
    display: grid;
    grid-template-columns: 160px 1fr;
  }
}
```

Например, одна карточка может стоять и в широкой основной области, и в узкой боковой панели при том же размере окна. Container query позволяет ей менять раскладку по месту, которое выделил родитель.

## Responsive images

```html
<img
  src="product-800.jpg"
  srcset="product-400.jpg 400w, product-800.jpg 800w, product-1200.jpg 1200w"
  sizes="(width < 768px) 100vw, 50vw"
  alt="Черный рюкзак с двумя отделениями"
>
```

`srcset` и `sizes` помогают браузеру выбрать подходящий ресурс. Для LCP-изображений lazy loading может навредить - это уже performance-контекст.

## Частые ошибки

- Делать макет с фиксированной шириной, а затем исправлять каждый размер экрана отдельным медиазапросом.
- Выбирать брейкпоинты только по устройствам.
- Использовать `100vh` на mobile и получать проблемы с адресной строкой.
- Делать текст через `vw`, который становится слишком маленьким или большим.
- Не проверять zoom и пользовательский font-size.
- Ставить `loading="lazy"` на главное LCP-изображение.

## Как ответить на собеседовании за одну минуту

Сначала делаю так, чтобы элементы могли занимать доступное место: ограничиваю ширину основного контейнера через `max-width`, использую Flexbox или Grid, не позволяю изображениям выходить за границы. Затем сужаю окно и смотрю, в какой момент содержимому становится тесно. Там добавляю медиазапрос, например перевожу две колонки в одну.

Единицы выбираю по задаче. Для текста и согласованных отступов удобен `rem`, для доли ширины контейнера — проценты, для колонок Grid — `fr`. Тонкую рамку можно оставить в пикселях.

Если карточка должна работать в разных областях одного окна, использую container query по размеру её контейнера. Проверяю также длинный текст и увеличение масштаба: интерфейс должен оставаться читаемым и управляемым.
