# Переходы, анимации и трансформации

> [!summary]
> CSS transitions подходят для простого перехода между состояниями, animations - для keyframe-сценариев, transforms - для визуального преобразования элемента без изменения document flow.

## Transitions

Transition описывает плавное изменение CSS-свойства между двумя состояниями:

```css
.button {
  background: #0b72ff;
  transition: background-color 150ms ease, transform 150ms ease;
}

.button:hover {
  background: #0756bd;
  transform: translateY(-1px);
}
```

Подходит для hover/focus/open/close состояний.

## Animations

Animation использует keyframes:

```css
@keyframes fade-in {
  from {
    opacity: 0;
  }

  to {
    opacity: 1;
  }
}

.toast {
  animation: fade-in 200ms ease;
}
```

Подходит для повторяющихся или более сложных сценариев.

## Transforms

`transform` меняет визуальное положение/масштаб/поворот, но не занимает новое место в layout.

```css
.panel {
  transform: translateX(100%);
}

.panel_open {
  transform: translateX(0);
}
```

Если нужно действительно изменить место элемента в потоке, transform не заменяет layout.

## Performance basics

Для плавных анимаций часто лучше анимировать `transform` и `opacity`, если это подходит по смыслу. Изменение `width`, `height`, `top`, `left` может затрагивать layout и paint.

Подробный разбор этапов построения и отрисовки страницы находится в [[Фронтенд/API браузера/03. Рендеринг браузера/01. Rendering pipeline и связь с Event Loop|Rendering pipeline и связь с Event Loop]].

## Reduced motion

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms;
    animation-iteration-count: 1;
    transition-duration: 0.01ms;
    scroll-behavior: auto;
  }
}
```

Пользователь может просить меньше движения. Это часть accessibility.

## Частые ошибки

- Анимировать `height: auto` напрямую и удивляться.
- Использовать `transition: all`.
- Делать важный контент доступным только через hover.
- Забывать `prefers-reduced-motion`.
- Думать, что transform меняет layout-положение для соседей.
- Добавлять `will-change` везде: это может расходовать ресурсы.

## Как ответить на собеседовании за одну минуту

Transition сглаживает изменение свойства между состояниями, animation задает keyframes, transform визуально двигает/масштабирует/вращает элемент без изменения его места в потоке. Для performance обычно лучше анимировать `transform` и `opacity`, но сначала нужно понять эффект. Для доступности учитываю `prefers-reduced-motion` и не прячу важные действия только за hover.

## Вопросы для самопроверки

- Чем transition отличается от animation?
- Почему `transition: all` плохой default?
- Что transform не меняет в layout?
- Когда нужен `prefers-reduced-motion`?
- Почему `top/left` часто дороже `transform`?
