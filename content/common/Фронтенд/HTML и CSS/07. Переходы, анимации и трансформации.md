# Переходы, анимации и трансформации

> [!summary]
> Если кнопка должна плавно сменить цвет при наведении, подойдёт transition. Если движение состоит из нескольких шагов или повторяется, его можно задать через animation и keyframes. Transform меняет видимое положение, масштаб или поворот элемента, оставляя его место в обычной раскладке прежним.

## Transitions

Transition описывает плавное изменение CSS-свойства между двумя состояниями:

```css
.button {
  background: #0b72ff;
  transition: background-color 150ms ease, transform 150ms ease;
}

.button:hover {
  background: #0756bd;
  transform: translateY(-1px);
}
```

Подходит для hover/focus/open/close состояний.

## Animations

Animation использует keyframes:

```css
@keyframes fade-in {
  from {
    opacity: 0;
  }

  to {
    opacity: 1;
  }
}

.toast {
  animation: fade-in 200ms ease;
}
```

Подходит для повторяющихся или более сложных сценариев.

## Transforms

`transform` меняет визуальное положение/масштаб/поворот, но не занимает новое место в layout.

```css
.panel {
  transform: translateX(100%);
}

.panel_open {
  transform: translateX(0);
}
```

Если нужно действительно изменить место элемента в потоке, transform не заменяет layout.

## Performance basics

Для плавных анимаций часто лучше анимировать `transform` и `opacity`, если это подходит по смыслу. Изменение `width`, `height`, `top`, `left` может затрагивать layout и paint.

Подробный разбор этапов построения и отрисовки страницы находится в [[Фронтенд/API браузера/03. Рендеринг браузера/01. Rendering pipeline и связь с Event Loop|Rendering pipeline и связь с Event Loop]].

## Reduced motion

```css
@media (prefers-reduced-motion: reduce) {
  .button,
  .toast,
  .sidebar {
    animation: none;
    transition: none;
  }
  html { scroll-behavior: auto; }
}
```

Пользователь может просить меньше движения. Размести эти правила после обычных стилей компонентов: равная специфичность и поздний порядок позволят им переопределить анимацию. Универсальный `*` может проиграть селектору класса. Изменение состояния интерфейса должно завершаться и без события `animationend`.

## Частые ошибки

- Ожидать плавный переход к `height: auto` без подходящего механизма: обычная числовая интерполяция этого не даёт; `interpolate-size` требует явного включения и проверки поддержки.
- Использовать `transition: all`.
- Делать важный контент доступным только через hover.
- Забывать `prefers-reduced-motion`.
- Думать, что transform меняет layout-положение для соседей.
- Добавлять `will-change` везде: это может расходовать ресурсы.

## Как ответить на собеседовании за одну минуту

`transition` сглаживает переход между двумя состояниями: например, цвет кнопки при наведении. Через `animation` и keyframes можно задать несколько шагов или повторять движение. А `transform` определяет само преобразование — сдвиг, масштаб или поворот.

Если сдвинуть карточку через transform, соседние элементы не займут её прежнее место: в раскладке оно остаётся за ней. Для визуального движения это удобно, и браузер часто может обойтись без нового layout. Поэтому для анимации сначала рассматриваю `transform` и `opacity`.

Учитываю `prefers-reduced-motion`: пользователь может просить меньше движения. Само действие должно завершаться и без анимации, а важные кнопки должны быть доступны не только при наведении мыши.
