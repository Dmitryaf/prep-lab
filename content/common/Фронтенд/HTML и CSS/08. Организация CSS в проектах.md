# Организация CSS в проектах

> [!summary]
> Организация CSS помогает менять один компонент, не ломая соседние. Нужно договориться об именах классов, общих стилях и способе ограничить стили компонентом.

## Главная проблема

CSS глобален по умолчанию. Если в проекте нет правил, появляются:

- конфликты имен;
- рост specificity;
- `!important`;
- сломанные стили при переносе компонента;
- дублирование spacing/colors;
- непонятно, какие стили можно удалить.

## BEM

```html
<article class="product-card product-card_featured">
  <h2 class="product-card__title">Рюкзак</h2>
  <button class="product-card__button">Купить</button>
</article>
```

```css
.product-card {}
.product-card__title {}
.product-card_featured {}
```

В БЭМ имя показывает, к какому блоку относится элемент и какой вариант оформления включён. Поэтому стили можно связать с классом, не описывая всю цепочку родителей в селекторе. За соблюдением именования следит команда; в сложных компонентах имена получаются длинными.

## CSS Modules

```css
.card {
  padding: 16px;
}
```

```js
import styles from './ProductCard.module.css';

export function ProductCard() {
  return <article className={styles.card}>...</article>;
}
```

CSS Modules при сборке создают отдельные имена классов для файла. Поэтому два компонента могут иметь свой класс button и не столкнуться именами. Общие цвета, шрифты и сброс браузерных стилей всё равно нужно организовать отдельно.

## Scoped styles in Vue

Во Vue SFC можно писать:

```vue
<style scoped>
.card {
  padding: 16px;
}
</style>
```

Vue добавляет атрибуты для ограничения селекторов компонентом. Это удобно для component styles, но не отменяет design tokens, global reset и аккуратную работу с deep selectors.

Подробнее про Vue-компоненты смотри [[Фронтенд/Vue/00. Карта раздела|Vue]].

## Sass: почему @use вместо @import

Sass обрабатывается при сборке: переменные и mixins помогают подготовить CSS. CSS variables остаются в браузере и могут менять тему без новой сборки.

```scss
// _tokens.scss
$gap: 12px;

// card.scss
@use 'tokens';
.card { padding: tokens.$gap; }
```

`@use` загружает Sass-модуль один раз за компиляцию и обращается к его именам через namespace, здесь `tokens`. Так легче понять, откуда взялось значение. Старый Sass `@import` смешивал имена в общей области и мог повторно включать CSS. Для нового Sass-кода используют модульный подход; обычный CSS `@import` — отдельная конструкция.

> [!note]- Если попросят подробнее
>
> `@forward` позволяет собрать публичный интерфейс нескольких Sass-файлов. Настройки через `@use ... with` задаются при первой загрузке модуля. Эти детали нужны при устройстве библиотеки стилей, а не для объяснения каждой карточки интерфейса.

[Документация Sass: @use](https://sass-lang.com/documentation/at-rules/use/).

## CSS-in-JS обзорно

CSS-in-JS связывает стили с компонентами: некоторые решения обрабатывают их во время работы JavaScript, другие заранее при сборке. Это позволяет хранить стили рядом с компонентом, менять их по состоянию и задавать темы. Возможная цена — дополнительная работа в браузере, настройка сборки и сложность серверного рендеринга. Для общего понимания HTML/CSS достаточно знать эти различия.

## Design tokens и CSS variables

```css
:root {
  --space-3: 12px;
  --color-text: #1f2937;
  --color-accent: #0b72ff;
}
```

Tokens помогают не размазывать случайные цвета и отступы. CSS variables удобны для темизации, потому что работают в cascade.

## CSS performance и critical CSS

P1-модель:

- CSS может блокировать first render, если stylesheet нужен для построения CSSOM;
- critical CSS - минимальные стили для первого экрана;
- неиспользуемый CSS увеличивает загрузку и parsing;
- сложные селекторы редко главная проблема, но хаотичная архитектура повышает стоимость изменений;
- layout thrashing связан с JS-чтением/записью layout, смотри Browser API.

## Частые ошибки

- Смешивать global utility, component CSS и page overrides без правил.
- Повышать specificity вместо исправления архитектуры.
- Использовать BEM и одновременно писать селекторы по DOM-глубине.
- Полагаться только на scoped styles и забыть про tokens/reset.
- Делать CSS-in-JS ответом на любую проблему CSS.
- Не удалять мертвые стили.

## Как ответить на собеседовании за одну минуту

Я хочу, чтобы изменение карточки не меняло соседнюю форму. Для этого задаю понятные границы: в БЭМ классы выражают принадлежность блоку, CSS Modules создают отдельные имена при сборке, а scoped-стили Vue ограничивают селекторы через атрибуты.

Общими оставляю базовую типографику, сброс браузерных стилей и значения цветов и отступов. Например, цвет опасного действия задаю одним токеном, чтобы все кнопки удаления менялись согласованно.

При загрузке проверяю, какие стили нужны первому экрану, и убираю неиспользуемый CSS. При конфликте сначала смотрю, какое правило победило, и исправляю границу или порядок, а не наращиваю специфичность селекторов.
