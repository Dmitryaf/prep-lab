# Примитивы и объекты

> [!summary]
> В JavaScript есть примитивные значения и объекты. Примитивы ведут себя как простые значения, а объекты передаются и сравниваются через ссылку на один и тот же объект.

## Базовая модель

Примитивы:

- `undefined`;
- `null`;
- `boolean`;
- `number`;
- `bigint`;
- `string`;
- `symbol`.

Все остальное, включая массивы, функции, даты и обычные object literals, относится к объектам.

```js
const name = 'Alex';
const user = { name: 'Alex' };
const list = [1, 2, 3];
const greet = function () {};
```

`name` хранит примитивное значение. `user`, `list` и `greet` ссылаются на объекты.

## Примитивы сравниваются по значению

```js
console.log('a' === 'a');
console.log(10 === 10);
```

Результат:

```text
true
true
```

## Объекты сравниваются по ссылке

```js
console.log({} === {});

const first = {};
const second = first;

console.log(first === second);
```

Результат:

```text
false
true
```

Две записи объекта через `{}` создают два разных объекта. `second = first` копирует ссылку на тот же объект.

## Примитивы иммутабельны

Строку нельзя изменить на месте. Операции со строкой создают новое значение.

```js
let text = 'cat';
text.toUpperCase();

console.log(text);
console.log(text.toUpperCase());
```

Результат:

```text
cat
CAT
```

## Объект можно менять через ссылку

```js
const user = { name: 'Alex' };
const sameUser = user;

sameUser.name = 'Mira';

console.log(user.name);
```

Результат:

```text
Mira
```

## Частые ошибки

- Называть массив отдельным примитивным типом.
- Ожидать, что `{}` будет равно `{}`.
- Думать, что `const` делает объект неизменяемым.
- Смешивать "копирование ссылки" и "копирование объекта".
- Объяснять примитивы только через стек, а объекты только через кучу. Для P0 важнее модель значения и ссылки.

## Как ответить на собеседовании за одну минуту

В JavaScript есть примитивы и объекты. Примитивы - это `undefined`, `null`, `boolean`, `number`, `bigint`, `string` и `symbol`; они сравниваются по значению. Объекты, массивы и функции сравниваются по ссылке. Поэтому два одинаково выглядящих объекта не равны, если это разные объекты в памяти, а две переменные могут указывать на один объект и видеть одни и те же изменения.

## Вопросы для самопроверки

- Почему `{ a: 1 } === { a: 1 }` возвращает `false`?
- Почему `const user = {}` не запрещает `user.name = 'Alex'`?
- Чем примитивное значение отличается от объекта в задачах на сравнение?

## Практические задачи

### Задача 1

```js
const a = { value: 1 };
const b = a;
const c = { value: 1 };

console.log(a === b);
console.log(a === c);
```

> [!question]- Разбор
> Вывод:
>
> ```text
> true
> false
> ```
>
> `b` хранит ссылку на тот же объект, что и `a`. `c` - новый объект.

### Задача 2

```js
let value = 'hello';
const upper = value.toUpperCase();

console.log(value);
console.log(upper);
```

> [!question]- Разбор
> Вывод:
>
> ```text
> hello
> HELLO
> ```
>
> Строка не меняется на месте. Метод возвращает новое значение.
