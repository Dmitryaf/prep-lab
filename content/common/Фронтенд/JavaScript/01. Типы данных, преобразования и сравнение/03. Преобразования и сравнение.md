# Преобразования и сравнение

> [!summary]
> JavaScript умеет явно и неявно преобразовывать значения. Для интервью важно понимать truthy/falsy, базовые преобразования и почему `===` обычно безопаснее `==`.

## Truthy и falsy

Falsy-значения:

- `false`;
- `0`;
- `-0`;
- `0n`;
- `''`;
- `null`;
- `undefined`;
- `NaN`.

Все остальные значения truthy, включая `[]`, `{}` и строку `'0'`.

```js
console.log(Boolean([]));
console.log(Boolean({}));
console.log(Boolean('0'));
console.log(Boolean(''));
```

Результат:

```text
true
true
true
false
```

## Явное преобразование

```js
console.log(Boolean(0));
console.log(String(10));
console.log(Number('42'));
console.log(Number(''));
console.log(Number('abc'));
```

Результат:

```text
false
10
42
0
NaN
```

Явное преобразование читается лучше, чем код с побочными неявными преобразованиями.

## `===`

Строгое сравнение не приводит типы.

```js
console.log(1 === '1');
console.log(null === undefined);
```

Результат:

```text
false
false
```

## `==`

Нестрогое сравнение может приводить типы.

```js
console.log(1 == '1');
console.log(null == undefined);
console.log(false == 0);
```

Результат:

```text
true
true
true
```

Практическое правило: используй `===`, а `==` оставляй только для осознанных случаев, например `value == null`, когда нужно проверить и `null`, и `undefined`.

## Частые ловушки

```js
console.log([] == false);
console.log('' == 0);
console.log([1] == 1);
```

Результат:

```text
true
true
true
```

Такие задачи проверяют не интуицию, а знание преобразований. В рабочем коде лучше избегать подобных условий.

## Частые ошибки

- Считать, что `[]` falsy.
- Использовать `==` без причины.
- Проверять `NaN` через `===`.
- Забывать, что `Number('')` дает `0`.
- Сравнивать объекты по содержимому через `===`.

## Как ответить на собеседовании за одну минуту

JavaScript преобразует значения явно через `Boolean()`, `String()`, `Number()` и неявно в условиях, операторах и при `==`. Falsy-значений мало: `false`, `0`, `-0`, `0n`, пустая строка, `null`, `undefined`, `NaN`. `===` сравнивает без приведения типов и обычно предпочтительнее. `==` сначала может привести типы, поэтому дает неожиданные результаты вроде `[] == false`. Объекты сравниваются по ссылке.

## Вопросы для самопроверки

- Почему `Boolean([])` возвращает `true`?
- Почему `1 == '1'`, но `1 !== '1'`?
- Когда допустимо использовать `value == null`?
- Почему `[] == false` лучше не писать в реальном коде?

> [!note]- Углубление: Abstract Equality Comparison
> Нестрогое сравнение `==` описано в спецификации алгоритмом Abstract Equality Comparison. Он по шагам решает, когда приводить типы, как сравнивать `null` и `undefined`, что делать с объектами и примитивами.
>
> Для P0 не нужно запоминать весь алгоритм. Достаточно понимать: `==` может менять типы перед сравнением, а `===` этого не делает.
