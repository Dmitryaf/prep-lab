# Логические операторы и особенности сравнения

> [!summary]
> В JavaScript логические операторы часто работают не как "операторы boolean", а как операторы выбора значения. На собеседованиях это связывают с truthy/falsy, `==`/`===`, `??`, `?.`, `NaN` и сравнением объектов по ссылке.

## `===`, `==` и `Object.is()`

`===` сравнивает без приведения типов. Поэтому его обычно используют в рабочем коде: условие читается предсказуемо и не зависит от скрытых преобразований.

```js
console.log(1 === '1'); // false
console.log(null === undefined); // false
```

`==` перед сравнением может приводить типы, поэтому дает ловушки:

```js
console.log(1 == '1'); // true
console.log(null == undefined); // true
console.log([] == false); // true
```

`Object.is()` похож на `===`, но иначе обрабатывает `NaN` и `-0`:

```js
console.log(NaN === NaN); // false
console.log(Object.is(NaN, NaN)); // true
console.log(Object.is(0, -0)); // false
```

## `null`, `undefined` и `NaN`

`undefined` обычно означает "значение не задано", `null` - явное "пустое значение". В приложении лучше договориться, где используется каждый вариант, и не смешивать их случайно.

```js
const user = null;
let selectedId;

console.log(user === null); // true
console.log(selectedId === undefined); // true
console.log(user == null); // true: проверяет и null, и undefined
```

`NaN` не равен самому себе, поэтому его проверяют через `Number.isNaN()` или `Object.is()`.

## Truthy/falsy

Falsy-значения: `false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN`. Все остальные значения truthy, включая `[]`, `{}` и `'0'`.

```js
console.log(Boolean([])); // true
console.log(Boolean({})); // true
console.log(Boolean('0')); // true
console.log(Boolean('')); // false
```

## `&&`, `||`, `!` и short-circuit

`!` приводит значение к boolean и инвертирует его.

```js
console.log(!'text'); // false
console.log(!!'text'); // true
```

`&&` возвращает первый falsy-операнд или последний операнд, если все truthy. `||` возвращает первый truthy-операнд или последний операнд, если все falsy.

```js
console.log('user' && 'profile'); // 'profile'
console.log(0 && 'profile'); // 0

console.log('user' || 'guest'); // 'user'
console.log(0 || 'default'); // 'default'
```

Правая часть может не вычисляться, если результат уже известен. Это называют сокращённым вычислением (short-circuit evaluation):

```js
const user = null;

user && console.log(user.name); // правая часть не выполнится
```

> [!important]
> `&&` и `||` возвращают не обязательно `boolean`, а один из операндов.

## `??` и отличие от `||`

`??` возвращает правый операнд только если слева `null` или `undefined`. Он не считает `0`, `''` и `false` отсутствующим значением.

```js
console.log(0 || 'default'); // 'default'
console.log(0 ?? 'default'); // 0

console.log('' || 'empty'); // 'empty'
console.log('' ?? 'empty'); // ''
```

Практическое правило:

- `||` - запасное значение для любого значения, преобразуемого к false;
- `??` - запасное значение только для отсутствующего значения.

## Optional chaining `?.`

`?.` безопасно останавливает чтение, если слева `null` или `undefined`.

```js
const user = null;

console.log(user?.profile?.name); // undefined
```

Это не заменяет валидацию данных. Если поле обязательно по бизнес-логике, лучше явно обработать ошибку, а не спрятать ее цепочкой `?.`.

## Сравнение объектов и массивов

Объекты, массивы и функции сравниваются по ссылке, а не по содержимому.

```js
console.log({} === {}); // false
console.log([] === []); // false

const first = {};
const second = first;
console.log(first === second); // true
```

Для сравнения содержимого нужно явно сравнивать поля, использовать стабильный ключ или специализированную функцию deep equality.

## `<`, `>`, `<=`, `>=`

Для строк сравнение идет лексикографически:

```js
console.log('apple' < 'banana'); // true
console.log('10' < '2'); // true
```

Если сравниваются разные типы, JavaScript часто приводит значения к number:

```js
console.log('10' < 2); // false
console.log('' < 1); // true, потому что Number('') === 0
```

В рабочем коде лучше заранее привести значения явно:

```js
const price = Number(input.value);

if (price > 100) {
  // ...
}
```

## Типичные ловушки

```js
console.log([] == false); // true
console.log([] === false); // false
console.log(NaN === NaN); // false
console.log(Object.is(NaN, NaN)); // true
console.log({} === {}); // false
console.log(0 || 'default'); // 'default'
console.log(0 ?? 'default'); // 0
```

Главная мысль: интервью-задачи часто проверяют не "здравый смысл", а правила coercion, truthy/falsy и ссылочную модель объектов.

## Как ответить на собеседовании за одну минуту

`===` сравнивает без приведения типов, поэтому почти всегда предпочтительнее `==`. `==` может приводить типы и давать ловушки вроде `[] == false`; осознанное исключение - `value == null`, если нужно проверить и `null`, и `undefined`. Логические `&&` и `||` используют truthy/falsy и возвращают один из операндов, а не обязательно boolean. `??` отличается от `||`: он срабатывает только на `null`/`undefined`, поэтому сохраняет `0`, `''` и `false`. Объекты и массивы сравниваются по ссылке, а `NaN` проверяют через `Number.isNaN()` или `Object.is()`.

> [!note]- Углубление: Abstract Equality Comparison
> Точные правила `==` описаны алгоритмом Abstract Equality Comparison. Для P0 не нужно запоминать весь алгоритм: достаточно понимать, что `==` может менять типы перед сравнением, а `===` этого не делает. Подробные пограничные случаи лучше разбирать на задачах, а не тащить в обычный код приложения.
