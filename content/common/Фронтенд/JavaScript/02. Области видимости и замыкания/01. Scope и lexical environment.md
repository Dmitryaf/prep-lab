# Scope и lexical environment

> [!summary]
> Scope, или область видимости, определяет, где в коде доступно имя переменной. В JavaScript область видимости в основном лексическая: она определяется тем, где функция и переменные объявлены в исходном коде.

## Зачем понимать scope

На собеседованиях задачи часто выглядят как простой `console.log`, но проверяют три вещи:

- где была объявлена переменная;
- есть ли одноименная переменная ближе к текущему коду;
- из какой области функция будет искать переменные.

Без этой модели легко перепутать lexical scope с местом вызова функции.

## Базовая модель

Область видимости можно представить как цепочку комнат.

1. JavaScript сначала ищет имя в текущей области.
2. Если не нашел, идет во внешнюю область.
3. Так продолжается до глобальной области.
4. Если имя не найдено нигде, будет `ReferenceError`.

```js
const value = 'global';

function outer() {
  const value = 'outer';

  function inner() {
    console.log(value);
  }

  inner();
}

outer();
```

Результат:

```text
outer
```

`inner` находит ближайший `value` во внешней функции `outer`.

## Lexical scope

Lexical scope означает: область видимости функции определяется местом, где функция объявлена, а не местом, где она вызвана.

```js
const name = 'global';

function printName() {
  console.log(name);
}

function run() {
  const name = 'local';
  printName();
}

run();
```

Результат:

```text
global
```

`printName` объявлена в глобальной области, поэтому она ищет `name` там, где была создана. Место вызова внутри `run` не меняет ее scope.

## Виды областей видимости

### Глобальная область

Переменные, объявленные на верхнем уровне скрипта или модуля, находятся в глобальной или модульной области.

```js
const appName = 'Interview Notes';

function printAppName() {
  console.log(appName);
}
```

### Функциональная область

Переменные внутри функции доступны внутри этой функции и во вложенных функциях.

```js
function createMessage() {
  const message = 'hello';

  function printMessage() {
    console.log(message);
  }

  printMessage();
}
```

### Блочная область

`let` и `const` ограничены блоком `{ ... }`.

```js
if (true) {
  const status = 'ready';
  console.log(status);
}

console.log(status); // ReferenceError
```

## Shadowing

Shadowing происходит, когда внутренняя переменная имеет то же имя, что и внешняя. Внутренняя переменная скрывает внешнюю внутри своей области.

```js
const count = 1;

function showCount() {
  const count = 2;
  console.log(count);
}

showCount();
console.log(count);
```

Результат:

```text
2
1
```

## Переменная и свойство объекта

Доступ к переменной и доступ к свойству объекта - разные механизмы.

```js
const user = {
  name: 'Anna',
};

console.log(user.name);
console.log(name); // ReferenceError, если переменной name нет
```

`user.name` ищет свойство `name` внутри объекта `user`. `name` без `user.` ищется как переменная по цепочке областей видимости.

## Частые ошибки

- Думать, что функция ищет переменные там, где ее вызвали.
- Путать переменную `name` и свойство `object.name`.
- Забывать, что `let` и `const` ограничены блоком.
- Считать shadowing перезаписью внешней переменной. Это другое имя в более близкой области.

## Как ответить на собеседовании за одну минуту

Scope - это область, где доступно имя переменной. JavaScript ищет переменную сначала в текущей области, затем во внешних областях до глобальной. Scope в JavaScript лексический: функция запоминает окружающую область по месту объявления, а не по месту вызова. `var` ограничен функцией или глобальной областью, `let` и `const` ограничены блоком. Если во внутренней области есть переменная с тем же именем, она скрывает внешнюю.

## Вопросы для самопроверки

- Чем lexical scope отличается от поиска переменной по месту вызова?
- Почему `printName` из примера выше выводит `global`, а не `local`?
- Что такое shadowing?
- Почему `object.name` и `name` - разные операции?
- В каком случае будет `ReferenceError`?

## Практические задачи

### Задача 1

Что выведет код?

```js
const value = 10;

function printValue() {
  console.log(value);
}

function wrapper() {
  const value = 20;
  printValue();
}

wrapper();
```

> [!question]- Разбор
> Вывод:
>
> ```text
> 10
> ```
>
> `printValue` объявлена в глобальной области. Она ищет `value` по месту своего объявления, а не по месту вызова внутри `wrapper`.

### Задача 2

Что произойдет?

```js
if (true) {
  const message = 'inside';
}

console.log(message);
```

> [!question]- Разбор
> Будет `ReferenceError`. `message` объявлена через `const` внутри блока `if` и недоступна снаружи.

### Задача 3

Что выведет код?

```js
const user = { name: 'Mira' };
const name = 'Global';

console.log(user.name);
console.log(name);
```

> [!question]- Разбор
> Вывод:
>
> ```text
> Mira
> Global
> ```
>
> `user.name` читает свойство объекта. `name` читает переменную из области видимости.

> [!note]- Углубление: терминология спецификации
> В актуальной спецификации ECMAScript области видимости описываются через Environment Records.
>
> - `Environment Record` хранит bindings: связи между именами и значениями.
> - внутренний слот `OuterEnv` указывает на внешнее окружение или `null`.
> - `LexicalEnvironment` - компонент execution context, который указывает на текущее лексическое окружение.
> - `VariableEnvironment` - отдельный компонент execution context, важный для объявлений `var` и function declarations.
>
> Это модель спецификации. Эти структуры нельзя получить напрямую из JavaScript-кода как обычные объекты.
>
> В учебных материалах часто говорят: "lexical environment состоит из environment record и ссылки на внешнее окружение". Для первого понимания это полезно, но современная спецификация точнее моделирует вложенность через Environment Record и его внутренний слот `OuterEnv`.
