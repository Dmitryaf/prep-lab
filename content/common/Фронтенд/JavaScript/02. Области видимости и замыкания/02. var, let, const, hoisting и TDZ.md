# var, let, const, hoisting и TDZ

> [!summary]
> `var`, `let` и `const` задают, где доступна переменная и можно ли присвоить ей новое значение. Они по-разному ведут себя до строки объявления: `var` можно прочитать и получить `undefined`, а чтение `let` или `const` до инициализации вызовет ошибку.

## Базовая таблица

| Возможность | `var` | `let` | `const` |
| --- | --- | --- | --- |
| Область видимости | функция или глобальная область | блок | блок |
| Повторное объявление в той же области | да | нет | нет |
| Повторное присваивание | да | да | нет |
| Нужно значение при объявлении | нет | нет | да |
| Доступ до строки объявления | `undefined` | `ReferenceError` | `ReferenceError` |

## `var`

`var` ограничен функцией, а не блоком.

```js
function run() {
  if (true) {
    var value = 10;
  }

  console.log(value);
}

run();
```

Результат:

```text
10
```

Переменная `var` создаётся заранее со значением `undefined`. Значение справа от `=` она получит, только когда выполнение дойдёт до присваивания.

```js
console.log(count);
var count = 1;
```

Результат:

```text
undefined
```

## `let` и `const`

`let` и `const` ограничены блоком.

```js
{
  let blockStatus = 'ready';
  const limit = 3;
}

console.log(blockStatus); // ReferenceError
```

`const` нужно инициализировать сразу.

```js
const size; // SyntaxError
```

`const` запрещает повторное присваивание переменной, но не делает объект неизменяемым.

```js
const user = { name: 'Nina' };
user.name = 'Mira';
```

## Hoisting без мифа о переносе строк

Hoisting - это не физическое перемещение объявлений вверх файла. Код остается на месте.

Перед выполнением кода движок подготавливает объявленные имена в этой области видимости. То, когда переменную можно прочитать и какое значение она получит, зависит от вида объявления.

- `var` создается заранее и рано получает значение `undefined`;
- `let` и `const` создаются заранее, но до инициализации находятся в TDZ;
- Function Declaration создает функцию, которую можно вызвать до строки объявления;
- Function Expression зависит от переменной, в которую ее записали.

## TDZ

TDZ, или Temporal Dead Zone, - период от начала области видимости до выполнения строки объявления `let` или `const`.

```js
console.log(value); // ReferenceError
let value = 10;
```

Имя уже относится к этой области видимости, но читать переменную до инициализации нельзя.

## Function Declaration

Function Declaration можно вызвать до строки объявления в своей области видимости.

```js
sayHi();

function sayHi() {
  console.log('Hi');
}
```

Результат:

```text
Hi
```

## Function Expression и стрелочная функция

Function Expression ведет себя как значение, записанное в переменную.

```js
sayHi(); // ReferenceError

const sayHi = function () {
  console.log('Hi');
};
```

Стрелочная функция в этом контексте тоже Function Expression, записанная в переменную.

```js
sayHi(); // ReferenceError

const sayHi = () => {
  console.log('Hi');
};
```

Подробное поведение стрелочных функций относительно `this` относится к другому блоку.

## Shadowing и блок

Внутренний блок может скрыть внешнюю переменную.

```js
const value = 'outer';

{
  const value = 'inner';
  console.log(value);
}

console.log(value);
```

Результат:

```text
inner
outer
```

## Цикл с `var`

`var` создает одну переменную на всю функцию.

```js
const callbacks = [];

for (var i = 0; i < 3; i += 1) {
  callbacks.push(function () {
    console.log(i);
  });
}

callbacks[0]();
callbacks[1]();
callbacks[2]();
```

Результат:

```text
3
3
3
```

## Цикл с `let`

В цикле с `let` каждая итерация получает отдельную переменную.

```js
const callbacks = [];

for (let i = 0; i < 3; i += 1) {
  callbacks.push(function () {
    console.log(i);
  });
}

callbacks[0]();
callbacks[1]();
callbacks[2]();
```

Результат:

```text
0
1
2
```

## Частые ошибки

- Говорить, что объявления "переносятся наверх". Лучше говорить о создании bindings до выполнения строк.
- Ожидать, что `let` до объявления даст `undefined`.
- Думать, что `const` делает объект immutable.
- Забывать, что `var` не ограничен блоком `if` или `for`.
- Путать Function Declaration и Function Expression.

## Как ответить на собеседовании за одну минуту

`var` имеет функциональную или глобальную область видимости, допускает повторное объявление и до строки объявления читается как `undefined`. `let` и `const` имеют блочную область видимости и находятся в TDZ до инициализации, поэтому доступ до объявления дает `ReferenceError`. `const` нельзя объявить без значения и нельзя переназначить. Hoisting связан с тем, что движок заранее подготавливает объявленные имена. Строки кода при этом никуда не перемещаются. Function Declaration доступна до объявления, Function Expression - нет, если переменная еще не инициализирована.

## Вопросы для самопроверки

- Почему `var` внутри `if` доступен снаружи блока?
- Что именно происходит при чтении `let` до объявления?
- Чем повторное присваивание отличается от мутации объекта?
- Почему цикл с `var` часто выводит последнее значение?
- Почему Function Expression нельзя вызвать до инициализации переменной?

## Практические задачи

### Задача 1

```js
console.log(a);
var a = 5;
```

> [!question]- Разбор
> Вывод:
>
> ```text
> undefined
> ```
>
> Переменная `a` уже существует со значением `undefined`. Присваивание `5` произойдёт только на второй строке.

### Задача 2

```js
console.log(a);
let a = 5;
```

> [!question]- Разбор
> Будет `ReferenceError`. `a` находится в TDZ до выполнения строки `let a = 5`.

### Задача 3

```js
run();

const run = function () {
  console.log('run');
};
```

> [!question]- Разбор
> Будет `ReferenceError`. `run` объявлена через `const`, поэтому до инициализации она находится в TDZ. Сама функция появится как значение только после выполнения Function Expression.

> [!note]- Углубление: что именно называют hoisting
> В спецификации не используется бытовая модель "строки объявления переместились вверх". Разные объявления обрабатываются во время подготовки области выполнения: создаются bindings, часть из них инициализируется сразу, часть остается неинициализированной до выполнения объявления.
>
> Для интервью полезно объяснять hoisting через наблюдаемое поведение:
>
> - `var` можно читать до объявления, но значение будет `undefined`;
> - `let` и `const` нельзя читать до инициализации;
> - Function Declaration можно вызвать до строки объявления;
> - Function Expression зависит от объявления переменной.

> [!note]- Углубление: Function Declaration внутри блока
> Function Declaration внутри блока имеет дополнительные нюансы, особенно в обычных scripts в браузере из-за legacy-семантики. Для P0 достаточно помнить: не стоит строить код на таких тонкостях.
>
> Практическое правило: объявляй функции на уровне функции/модуля или используй `const name = () => {}` внутри блока, если нужна блочная область видимости.
