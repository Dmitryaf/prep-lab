# Замыкания

> [!summary]
> Замыкание возникает, когда функция сохраняет доступ к переменным из внешней области после того, как внешний код уже выполнился. Функция не копирует значения, а продолжает работать с доступным ей окружающим состоянием.

## Зачем понимать замыкания

Замыкания лежат в основе callbacks, обработчиков событий, фабрик функций, приватного состояния и многих задач на порядок вывода. На собеседовании важно не только дать определение, но и объяснить, почему функция видит внешнюю переменную.

## Базовая модель

Функция создается в определенной лексической области. Если внутри функции используется внешняя переменная, функция сохраняет доступ к этой области.

```js
function createGreeter(name) {
  return function greet() {
    console.log(`Hi, ${name}`);
  };
}

const greetMira = createGreeter('Mira');
greetMira();
```

Результат:

```text
Hi, Mira
```

`createGreeter` уже завершилась, но `greet` все еще имеет доступ к `name`.

## Замыкание не копирует значение

Функция сохраняет доступ к переменной, а не к снимку ее значения.

```js
function createLogger() {
  let value = 1;

  const log = function () {
    console.log(value);
  };

  value = 2;
  return log;
}

const log = createLogger();
log();
```

Результат:

```text
2
```

Если бы замыкание копировало значение, был бы вывод `1`. На практике функция видит актуальное значение переменной из сохраненного окружения.

## Счетчик через замыкание

```js
function createCounter() {
  let count = 0;

  return function increment() {
    count += 1;
    return count;
  };
}

const counter = createCounter();

console.log(counter());
console.log(counter());
```

Результат:

```text
1
2
```

`count` недоступен напрямую снаружи, но доступен функции `increment`.

## Фабрика функций

```js
function multiplyBy(multiplier) {
  return function multiply(value) {
    return value * multiplier;
  };
}

const double = multiplyBy(2);
const triple = multiplyBy(3);

console.log(double(5));
console.log(triple(5));
```

Результат:

```text
10
15
```

Каждый вызов `multiplyBy` создает свое окружение с отдельным `multiplier`.

## Приватное состояние

Замыкание позволяет спрятать состояние внутри функции и открыть только нужные операции.

```js
function createStore() {
  let value = 0;

  return {
    get() {
      return value;
    },
    set(nextValue) {
      value = nextValue;
    },
  };
}

const store = createStore();
store.set(10);
console.log(store.get());
```

Результат:

```text
10
```

## Обработчики и callbacks

Callback может использовать переменные из внешней области.

```js
function subscribe(userId, onMessage) {
  return function handleMessage(message) {
    onMessage(userId, message);
  };
}
```

Здесь `handleMessage` сохраняет доступ к `userId` и `onMessage`.

## Замыкания в циклах

С `var` создается одна переменная на весь цикл.

```js
const callbacks = [];

for (var i = 0; i < 3; i += 1) {
  callbacks.push(function () {
    console.log(i);
  });
}

callbacks[0]();
callbacks[1]();
callbacks[2]();
```

Результат:

```text
3
3
3
```

С `let` каждая итерация получает отдельную переменную.

```js
const callbacks = [];

for (let i = 0; i < 3; i += 1) {
  callbacks.push(function () {
    console.log(i);
  });
}

callbacks[0]();
callbacks[1]();
callbacks[2]();
```

Результат:

```text
0
1
2
```

## Практическая польза

Замыкания используют для:

- функций-фабрик;
- приватного состояния;
- callbacks и обработчиков;
- memoization;
- decorators;
- currying.

Генераторы тоже могут взаимодействовать с внешним состоянием, но их подробная модель относится к отдельной теме.

## Потенциальное удержание памяти

Если долгоживущая функция сохраняет доступ к большой структуре данных, эта структура может оставаться достижимой для сборщика мусора дольше, чем ожидалось.

Подробнее о памяти и достижимости: [[Фронтенд/JavaScript/10. Память и сборка мусора/02. Достижимость и garbage collection|Достижимость и garbage collection]].

## Частые ошибки

- Говорить, что замыкание копирует значения внешних переменных.
- Ожидать, что внешний `let` или `var` станет недоступен сразу после завершения функции.
- Не замечать одну общую переменную `var` в цикле.
- Путать приватное состояние через closure с приватными полями классов.
- Использовать замыкание для хранения больших данных без понимания времени жизни callback.

## Как ответить на собеседовании за одну минуту

Замыкание - это функция вместе с доступом к окружающей лексической области, где она была создана. Если функция использует внешнюю переменную и живет дольше внешней функции, она все равно может читать и менять эту переменную. Замыкание не копирует значение, а сохраняет доступ к состоянию. Поэтому счетчики, фабрики функций, callbacks и приватное состояние часто строятся на замыканиях. В циклах важно помнить: `var` дает одну общую переменную, а `let` - отдельную переменную для каждой итерации.

## Практические задачи

### Задача 1

```js
function outer() {
  let value = 1;

  return function inner() {
    value += 1;
    return value;
  };
}

const fn = outer();

console.log(fn());
console.log(fn());
```

> [!question]- Разбор
> Вывод:
>
> ```text
> 2
> 3
> ```
>
> `inner` сохраняет доступ к переменной `value` из вызова `outer`. Между вызовами `fn` используется та же переменная.

### Задача 2

```js
function createPair() {
  let value = 0;

  return [
    function increment() {
      value += 1;
    },
    function log() {
      console.log(value);
    },
  ];
}

const [increment, log] = createPair();
increment();
increment();
log();
```

> [!question]- Разбор
> Вывод:
>
> ```text
> 2
> ```
>
> Обе возвращенные функции закрывают одну и ту же переменную `value`.

### Задача 3

```js
function createIdGenerator(prefix) {
  let id = 0;

  return function nextId() {
    id += 1;
    return `${prefix}-${id}`;
  };
}
```

> [!question]- Разбор
> Это практическое применение closure: `prefix` и `id` спрятаны внутри фабрики. Снаружи доступна только функция `nextId`, которая управляет состоянием.

> [!note]- Углубление: окружение цикла с let
> Упрощенно говорят: в цикле `for (let i = ... )` каждая итерация получает отдельную переменную `i`.
>
> На каждой итерации let создаёт отдельное лексическое окружение — набор привязок имён к значениям. Поэтому функции, созданные на разных итерациях, замыкаются на разные привязки, а не на одну общую переменную.
