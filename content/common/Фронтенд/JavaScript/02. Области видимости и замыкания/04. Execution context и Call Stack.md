# Execution context и Call Stack

> [!summary]
> Контекст выполнения хранит сведения о выполняющемся коде. Стек вызовов, или Call Stack, показывает, какая функция работает сейчас и куда вернётся управление после её завершения.

## Зачем нужна эта модель

Для задач на scope обычно достаточно цепочки областей видимости. Но Call Stack помогает объяснить:

- какой код выполняется прямо сейчас;
- почему функции возвращаются в обратном порядке;
- почему рекурсия может упасть с ошибкой переполнения стека;
- как текущее выполнение связано с поиском переменных.

## Execution context

Execution context можно понимать как запись о текущем выполнении кода: что сейчас исполняется и какие окружения используются для поиска имен.

Когда вызывается функция, для ее выполнения создается новый контекст. Когда функция завершается, этот контекст удаляется из стека вызовов.

## Call Stack

Call Stack - стек вызовов функций. Он работает по принципу LIFO: last in, first out.

```js
function first() {
  second();
}

function second() {
  third();
}

function third() {
  console.log('done');
}

first();
```

Упрощенно:

```text
push first
push second
push third
pop third
pop second
pop first
```

Последняя вызванная функция завершается первой.

## Связь со scope

Call Stack показывает, какая функция сейчас выполняется. Scope показывает, где эта функция ищет переменные.

Важно не путать:

- место вызова функции влияет на порядок выполнения;
- место объявления функции влияет на lexical scope.

```js
const value = 'global';

function printValue() {
  console.log(value);
}

function run() {
  const value = 'local';
  printValue();
}

run();
```

`run` будет в Call Stack во время вызова `printValue`, но `printValue` все равно ищет `value` по месту своего объявления.

## Рекурсия и переполнение стека

```js
function repeat() {
  repeat();
}

repeat();
```

Каждый вызов добавляет в стек новую запись о выполнении функции. Если функция продолжает вызывать себя, эти записи накапливаются, стек достигает лимита и возникает ошибка переполнения.

## Call Stack и heap

Call Stack хранит сведения об активных вызовах функций. Heap, или куча, — область памяти для объектов и других динамических данных. У них разные задачи: завершение вызова не означает, что все созданные им объекты сразу исчезнут.

Подробнее: [[Фронтенд/JavaScript/10. Память и сборка мусора/01. Stack, heap и ссылки|Stack, heap и ссылки]].

## Связь с Event Loop

Event Loop использует Call Stack как индикатор, занят ли сейчас основной поток выполнением синхронного кода. Но подробный разбор задач, микрозадач и отрисовки находится в [[Фронтенд/JavaScript/05. Асинхронность/01. Event Loop в браузере|Event Loop в браузере]].

## Частые ошибки

- Путать Call Stack со scope chain.
- Думать, что место вызова меняет lexical scope функции.
- Объяснять heap и Call Stack как одну и ту же структуру.
- Забывать базовый принцип LIFO.
- Считать, что рекурсия безопасна без условия остановки.

## Как ответить на собеседовании за одну минуту

Execution context - это модель текущего выполнения кода. При вызове функции создается новый контекст, который попадает в Call Stack. Call Stack работает по принципу LIFO: последняя вызванная функция завершается первой. После завершения функции ее контекст убирается из стека. Call Stack отвечает за порядок активных вызовов, а lexical scope - за поиск переменных. При бесконечной рекурсии стек растет до переполнения.

- Чем Call Stack отличается от scope chain?
- Почему бесконечная рекурсия приводит к переполнению стека?
- Чем Call Stack отличается от heap?

> [!note]- Углубление: компоненты execution context в спецификации
> В спецификации execution context содержит несколько компонентов, включая `LexicalEnvironment`, `VariableEnvironment` и `PrivateEnvironment`.
>
> Для P1 достаточно понимать идею: текущий контекст указывает на окружения, которые используются для разрешения имен. Детальная структура нужна редко и не должна заменять простую модель Call Stack и lexical scope.
