# Потеря контекста

> [!summary]
> Потеря контекста происходит, когда функция, которую мы привыкли вызывать как метод объекта, вызывается без этого объекта слева от точки. Метод не хранит постоянную связь с объектом.

## Зачем это понимать

В frontend-коде методы часто передают в callback: в таймеры, обработчики событий, промисы, array methods, UI-библиотеки. Если передать метод как обычную функцию, он может потерять объект, из которого читает данные.

## Метод не привязан к объекту навсегда

```js
'use strict';

const user = {
  name: 'Alex',
  showName() {
    console.log(this.name);
  },
};

user.showName(); // Alex

const showName = user.showName;
showName(); // TypeError: Cannot read properties of undefined
```

В первом вызове есть объект слева от точки: `user.showName()`.

Во втором вызове переменная `showName` хранит только функцию. Вызов выглядит как `showName()`, поэтому в strict mode `this === undefined`.

## Передача метода как callback

```js
'use strict';

const user = {
  name: 'Alex',
  showName() {
    console.log(this.name);
  },
};

user.showName(); // Alex

const showName = user.showName;
showName(); // TypeError

setTimeout(user.showName, 0); // объект user не сохраняется как this

setTimeout(() => {
  user.showName();
}, 0); // Alex
```

`setTimeout(user.showName, 0)` получает ссылку на функцию. Сам объект `user` уже не участвует в будущем вызове.

`setTimeout(() => { user.showName(); }, 0)` передает wrapper-функцию. Когда wrapper выполнится, он заново вызовет метод как `user.showName()`, поэтому `this` будет `user`.

Точный `this` внутри callback от `setTimeout` зависит от среды выполнения. Для понимания потери контекста здесь важно другое: это уже не вызов `user.showName()`, поэтому `this` не будет надежно равен `user`.

Здесь важен только факт отложенного callback. Подробный порядок выполнения таймеров разбирается в [[Фронтенд/JavaScript/05. Асинхронность/01. Event Loop в браузере|Event Loop в браузере]].

## Поведение callback зависит от API

Нельзя говорить, что любой callback всегда получает один и тот же `this`. API сам решает, как вызвать переданную функцию.

Например, `setTimeout` не сохраняет объект метода. Array methods могут принимать отдельный `thisArg`. DOM `addEventListener()` для обычной listener-функции устанавливает `this` в текущий target. Поэтому для задач нужно смотреть на конкретный API.

## Деструктуризация метода

```js
'use strict';

const user = {
  name: 'Alex',
  showName() {
    console.log(this.name);
  },
};

const { showName } = user;
showName(); // TypeError
```

Деструктуризация извлекает значение свойства. Значением является функция, а не связка "объект + функция".

## Вложенная обычная функция внутри метода

```js
'use strict';

const user = {
  name: 'Alex',
  showName() {
    function inner() {
      console.log(this.name);
    }

    inner();
  },
};

user.showName(); // TypeError
```

Внешний метод вызван правильно, но `inner()` вызвана как самостоятельная функция. У нее свой вызов и свой `this`.

## Исправление через стрелочную функцию

```js
const user = {
  name: 'Alex',
  showName() {
    const inner = () => {
      console.log(this.name);
    };

    inner();
  },
};

user.showName(); // Alex
```

Стрелочная функция не создает собственный `this`. Она использует `this` из `showName`, где он равен `user`.

## Исправление через wrapper-функцию

```js
setTimeout(() => {
  user.showName();
}, 0);
```

Wrapper полезен, когда нужно сохранить не только объект, но и понятный момент вызова: "когда callback выполнится, вызови метод у этого объекта".

## Исправление через bind

```js
const boundShowName = user.showName.bind(user);

boundShowName(); // Alex
setTimeout(boundShowName, 0); // Alex
```

`bind()` создает новую функцию, в которой `this` заранее связан с `user`. Подробнее: [[Фронтенд/JavaScript/03. Контекст this/03. call, apply и bind|call, apply и bind]].

## P1: addEventListener

В DOM есть важное практическое исключение: для обычной listener-функции, переданной в `addEventListener()`, `this === event.currentTarget`.

```js
button.addEventListener('click', function (event) {
  console.log(this === event.currentTarget); // true
});
```

Стрелочная listener-функция собственного `this` не получает:

```js
button.addEventListener('click', (event) => {
  console.log(this); // this взят из внешнего контекста
});
```

Подробный разбор DOM events, propagation и listener options относится к будущему Browser API блоку.

## Типичные production-сценарии

- Передали метод сервиса в callback без `bind()`.
- Деструктурировали метод из объекта и вызвали отдельно.
- Передали метод класса как handler в UI-компонент, но метод класса не был привязан к экземпляру.
- Внутри метода создали обычную функцию и ожидали, что она увидит тот же `this`.
- Использовали стрелку как метод object literal и ожидали `this === object`.

## Краткий мост к методам классов

Методы классов тоже не становятся автоматически привязанными к экземпляру.

```js
'use strict';

class User {
  constructor(name) {
    this.name = name;
  }

  showName() {
    console.log(this.name);
  }
}

const user = new User('Alex');
const showName = user.showName;

showName(); // TypeError
```

Подробный разбор классов лучше держать в отдельном блоке.

## Частые ошибки

- Передавать `user.showName` вместо `() => user.showName()`.
- Считать, что деструктуризация метода сохраняет `this`.
- Обобщать поведение одного callback API на все callback API.
- Исправлять все через `bind()`, даже когда wrapper-функция читается понятнее.
- Забывать, что стрелка сохраняет внешний `this`, а не объект вокруг записи.

## Как ответить на собеседовании за одну минуту

Потеря контекста происходит, когда метод вызывают уже не как `obj.method()`, а как самостоятельную функцию. Метод - это значение свойства, обычно просто функция. Если ее присвоить в переменную, деструктурировать или передать callback, объект слева от точки исчезает. Исправить можно wrapper-функцией, которая снова вызывает `obj.method()`, через `bind(obj)` или стрелкой внутри метода, если нужно сохранить внешний `this`.
