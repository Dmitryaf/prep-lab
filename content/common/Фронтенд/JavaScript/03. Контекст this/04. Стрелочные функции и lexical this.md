# Стрелочные функции и lexical this

> [!summary]
> У стрелочной функции нет собственного `this`. Она использует `this` окружающего контекста, то есть того места, где стрелка была создана.

## Зачем это понимать

Стрелочные функции часто используют в callback и внутри методов. Они удобны, когда нужно сохранить внешний `this`, но опасны как методы object literal: стрелка не получает объект слева от точки как свой `this`.

## Базовая модель

Обычная функция получает `this` при вызове.

Стрелочная функция не получает собственный `this` при вызове. Когда внутри стрелки написано `this`, это значение берется из внешнего контекста.

```js
const user = {
  name: 'Alex',
  showName() {
    const inner = () => {
      console.log(this.name);
    };

    inner();
  },
};

user.showName(); // Alex
```

`showName()` - обычный метод, поэтому внутри него `this === user`. Стрелка `inner` использует этот же `this`.

## Отличие от обычной функции

```js
'use strict';

const user = {
  name: 'Alex',
  regular() {
    function inner() {
      console.log(this);
    }

    inner();
  },
  arrow() {
    const inner = () => {
      console.log(this.name);
    };

    inner();
  },
};

user.regular(); // undefined
user.arrow(); // Alex
```

Обычная `inner` вызвана самостоятельно. Стрелочная `inner` берет `this` из метода `arrow`.

## Стрелка как callback

```js
const user = {
  name: 'Alex',
  showLater() {
    setTimeout(() => {
      console.log(this.name);
    }, 0);
  },
};

user.showLater(); // Alex
```

Стрелка удобна здесь не потому, что `setTimeout` как-то специально сохраняет объект, а потому что стрелка использует `this` из `showLater()`.

## Ловушка: стрелка как свойство object literal

```js
const user = {
  name: 'Alex',
  showName: () => {
    console.log(this.name);
  },
};

user.showName(); // зависит от внешнего this; обычно не Alex
```

Стрелка не получает `user` как `this`. Объектный литерал не создает новый `this` для функции. `this` внутри стрелки берется из окружающего контекста, где был создан объект `user`.

В ES-модуле на верхнем уровне `this` равен `undefined`, поэтому такой код обычно приведет к ошибке при чтении `this.name`. В обычном скрипте браузера в нестрогом режиме внешний `this` может быть `window`, и результат будет зависеть от свойства `window.name`. Для учебных задач лучше не оставлять это неоднозначным.

Правильнее написать обычный метод:

```js
const user = {
  name: 'Alex',
  showName() {
    console.log(this.name);
  },
};

user.showName(); // Alex
```

## call, apply и bind не назначают стрелке новый this

```js
const context = { name: 'Alex' };

const showName = () => {
  console.log(this);
};

showName.call(context); // this не станет context
```

`call()`, `apply()` и `bind()` могут передавать аргументы стрелочной функции, но не могут заменить ее `this`.

## arguments

У обычной функции есть собственный `arguments`.

```js
function regular() {
  console.log(arguments.length);
}

regular(1, 2); // 2
```

У стрелочной функции собственного `arguments` нет. Используй rest parameters:

```js
const arrow = (...args) => {
  console.log(args.length);
};

arrow(1, 2); // 2
```

## Стрелка не является конструктором

Стрелочную функцию нельзя вызвать через `new`.

```js
const User = (name) => {
  this.name = name;
};

// new User('Alex'); // TypeError
```

У стрелочной функции также нет собственного свойства `prototype`, которое используется обычными функциями-конструкторами.

## Стрелочные поля классов

В классах часто встречаются стрелочные поля:

```js
class User {
  name = 'Alex';

  showName = () => {
    console.log(this.name);
  };
}
```

Это смежная тема: стрелочное поле создается для экземпляра и сохраняет `this` контекста инициализации экземпляра. Подробный разбор классов лучше держать в отдельном блоке.

## Частые ошибки

- Использовать стрелку как метод object literal и ждать `this === object`.
- Пытаться заменить `this` стрелки через `call()`, `apply()` или `bind()`.
- Использовать `arguments` внутри стрелки.
- Писать стрелку там, где нужен конструктор.
- Думать, что стрелка всегда "чинит this"; она только берет внешний `this`.

## Как ответить на собеседовании за одну минуту

У стрелочной функции нет собственного `this`. Она использует `this` окружающего контекста. Поэтому стрелка удобна внутри метода или callback, когда нужно сохранить `this` внешнего метода. Но стрелка, записанная как свойство object literal, не становится методом с `this` равным объекту. `call()`, `apply()` и `bind()` не могут назначить стрелке новый `this`. Еще у стрелок нет собственного `arguments`, их нельзя использовать как конструкторы, и у них нет собственного `prototype`.

```js
  },

```

2. Исправь метод:

```js
const user = {

    console.log(this.name);
  },

```

```js

  console.log(arguments.length);
```
