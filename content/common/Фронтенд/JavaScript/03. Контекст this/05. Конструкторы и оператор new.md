# Конструкторы и оператор new

> [!summary]
> При вызове функции с `new` JavaScript создает новый объект и вызывает конструктор с этим объектом в качестве `this`. Цель этой заметки - понять связь `new` и `this`, а не всю механику прототипов.

## Что такое функция-конструктор

Функция-конструктор - обычная функция, которую вызывают через `new`, чтобы создать и настроить новый объект.

По соглашению имена конструкторов пишут с заглавной буквы:

```js
function User(name) {
  this.name = name;
}

const user = new User('Alex');

console.log(user.name); // Alex
```

Внутри `User` значение `this` - новый объект, который создается оператором `new`.

## Практичная модель new

Когда выполняется `new Constructor(...)`:

1. Создается новый объект.
2. Новый объект связывается с `Constructor.prototype`.
3. Конструктор вызывается с новым объектом в качестве `this`.
4. Если конструктор явно вернул объект, используется он. Иначе возвращается созданный объект.

Подробную механику прототипов лучше изучать отдельно: [[Фронтенд/JavaScript/04. Объекты и прототипы/02. Прототип и цепочка прототипов|Прототип и цепочка прототипов]].

## Возврат созданного объекта

```js
function User(name) {
  this.name = name;
}

const user = new User('Alex');

console.log(user); // User { name: 'Alex' }
```

Конструктор ничего явно не возвращает, поэтому результатом `new User('Alex')` становится созданный объект.

## Явный возврат другого объекта

```js
function User(name) {
  this.name = name;

  return {
    name: 'Maria',
  };
}

const user = new User('Alex');

console.log(user.name); // Maria
```

Если конструктор явно возвращает объект, результатом `new` будет этот объект, а не изначально созданный.

## Явный возврат примитива игнорируется

```js
function User(name) {
  this.name = name;

  return 'Maria';
}

const user = new User('Alex');

console.log(user.name); // Alex
```

Примитивный return из конструктора игнорируется. Возвращается созданный объект.

## Стрелочная функция не является конструктором

```js
const User = (name) => {
  this.name = name;
};

// new User('Alex'); // TypeError
```

У стрелочной функции нет собственного `this`, и ее нельзя использовать с `new`.

## Ошибка вызова конструктора без new

```js
'use strict';

function User(name) {
  this.name = name;
}

// User('Alex'); // TypeError
```

Без `new` это обычный самостоятельный вызов функции. В strict mode `this === undefined`, поэтому запись `this.name` приводит к ошибке.

В нестрогом режиме такой вызов может случайно записать свойство в глобальный объект. Это одна из причин, почему конструкторы вызывают только через `new`.

## Краткий мост к классам

Классы используют похожую идею: `new User()` создает экземпляр и вызывает `constructor` с этим экземпляром как `this`.

```js
class User {
  constructor(name) {
    this.name = name;
  }
}

const user = new User('Alex');
```

Но классы, наследование, `super`, поля классов и статические методы - отдельный блок. Здесь важно только то, что `new` задает `this` для конструктора.

## Частые ошибки

- Вызвать функцию-конструктор без `new`.
- Ожидать, что стрелочная функция сможет быть конструктором.
- Считать, что явный return примитива заменит созданный объект.
- Углубляться в цепочку прототипов, когда вопрос только про `this`.
- Называть любую функцию с заглавной буквы конструктором, даже если ее не вызывают через `new`.

## Как ответить на собеседовании за одну минуту

`new` вызывает функцию в режиме конструктора. Сначала создается новый объект, он связывается с `Constructor.prototype`, затем конструктор выполняется с этим объектом как `this`. Обычно этот объект и возвращается. Если конструктор явно вернул другой объект, результатом будет он; если вернул примитив, такой return игнорируется. Стрелочные функции нельзя вызывать через `new`, потому что они не являются конструкторами и не имеют собственного `this`.

> [!note]- Углубление: new и явный return из конструктора
> Практическое правило: object return заменяет созданный объект, primitive return - нет.
>
> ```js
> function ReturnsObject() {
>   this.value = 1;
>   return { value: 2 };
> }
>
> function ReturnsPrimitive() {
>   this.value = 1;
>   return 2;
> }
>
> console.log(new ReturnsObject().value); // 2
> console.log(new ReturnsPrimitive().value); // 1
> ```
>
> В спецификации это связано с тем, как `Construct` обрабатывает результат вызова конструктора. Для P0 достаточно помнить наблюдаемое поведение.

```js

```

'use strict';
