# Прототип и цепочка прототипов

> [!summary]
> Если JavaScript не находит свойство в самом объекте, он ищет его в прототипе, затем в прототипе прототипа и так далее до `null`.

## Базовая модель

```js
const animal = {
  eats: true,
};

const rabbit = Object.create(animal);
rabbit.jumps = true;

console.log(rabbit.jumps);
console.log(rabbit.eats);
```

Результат:

```text
true
true
```

`jumps` - собственное свойство `rabbit`. `eats` найдено в прототипе `animal`.

## Поиск свойства

Упрощенно:

```text
rabbit -> animal -> Object.prototype -> null
```

Поиск идет снизу вверх. Если свойство не найдено нигде, результат чтения - `undefined`.

## Shadowing свойства

Если добавить свойство с тем же именем в сам объект, оно скроет свойство прототипа.

```js
const proto = { role: 'guest' };
const user = Object.create(proto);

console.log(user.role);

user.role = 'admin';

console.log(user.role);
console.log(proto.role);
```

Результат:

```text
guest
admin
guest
```

Чтение унаследованного свойства не делает его собственным. Собственное свойство появилось только после присваивания `user.role = 'admin'`.

## `Object.create()`

`Object.create(proto)` создает объект с указанным прототипом.

```js
const dictionary = Object.create(null);
dictionary.name = 'value';

console.log(Object.getPrototypeOf(dictionary));
```

Результат:

```text
null
```

Объекты без прототипа полезны редко, но показывают, что прототип может быть `null`.

## `Object.getPrototypeOf()`

```js
const proto = {};
const obj = Object.create(proto);

console.log(Object.getPrototypeOf(obj) === proto);
```

Результат:

```text
true
```

## `Object.setPrototypeOf()`

`Object.setPrototypeOf(obj, proto)` меняет прототип существующего объекта. Это возможно, но в обычном коде лучше создавать объект с нужным прототипом сразу: изменение прототипа после создания может быть медленным и усложняет понимание кода.

## `__proto__`

`__proto__` часто встречается в старых примерах, но это legacy accessor. Для чтения прототипа используй `Object.getPrototypeOf()`, для создания объекта с прототипом - `Object.create()`.

## Частые ошибки

- Говорить, что у каждого объекта есть собственное свойство `__proto__`.
- Думать, что чтение унаследованного свойства делает его собственным.
- Путать прототип объекта и свойство `.prototype` функции.
- Менять прототипы встроенных объектов.

## Как ответить на собеседовании за одну минуту

У объекта может быть внутренний прототип. Когда мы читаем свойство, JavaScript сначала ищет его в самом объекте, затем в прототипе и дальше по цепочке до `null`. Собственные свойства проверяют через `Object.hasOwn()`, наличие в цепочке - через `in`. `Object.create(proto)` создает объект с нужным прототипом, `Object.getPrototypeOf()` читает прототип, а `Object.setPrototypeOf()` меняет его, но обычно это не рекомендуют делать в горячем коде.

> [!note]- Углубление: терминология спецификации
> В спецификации внутренний прототип обычного объекта представлен внутренним слотом `Prototype`. Доступ к свойствам описывается через внутренние методы вроде `Get` и `GetPrototypeOf`.
>
> В P0 не нужно пересказывать алгоритмы. Достаточно понимать цепочку поиска свойств и отличие собственного свойства от унаследованного.
