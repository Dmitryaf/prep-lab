# Promise — базовая модель и цепочки

> [!summary]
> Promise представляет результат асинхронной операции: сейчас результата может ещё не быть, но позже Promise станет fulfilled или rejected. Цепочки `.then()`, `.catch()` и `.finally()` позволяют передавать значения и ошибки дальше без вложенных callbacks.

## Сначала главное

Запрос ещё выполняется, но код уже должен знать, как получить его результат. Promise хранит это ожидание: затем будет либо значение, либо ошибка. `then` продолжает успешную работу, `catch` обрабатывает ошибку.

Для первого чтения пройди «Базовая модель», «Как результат обработчика влияет на цепочку», «Распространение ошибок» и «finally». Остальные примеры помогают разобрать конкретное уточнение. Ключевой вопрос: что текущий обработчик **вернул или выбросил**? Это определяет следующий шаг.

## Зачем понимать Promise

Promise — основа современного асинхронного JavaScript:

- `fetch()` возвращает Promise;
- `async / await` построен поверх Promise;
- Promise callbacks выполняются через microtask queue;
- большинство задач на порядок выполнения использует `.then()`, `.catch()` и timers.

## Базовая модель

Promise может быть в одном из трёх состояний:

| Состояние | Что значит |
|---|---|
| `pending` | операция ещё не завершилась |
| `fulfilled` | операция завершилась успешно |
| `rejected` | операция завершилась с ошибкой |

`settled` — общий термин для `fulfilled` и `rejected`. Если Promise settled, его состояние уже не изменится.

```js
const promise = new Promise((resolve, reject) => {
  if (Math.random() > 0.5) {
    resolve('ok');
  } else {
    reject(new Error('failed'));
  }
});
```

## Executor выполняется синхронно

Функция, которую передают в `new Promise(...)`, называется executor. Она выполняется сразу, синхронно.

```js
console.log('A');

const promise = new Promise((resolve) => {
  console.log('B');
  resolve('done');
});

console.log('C');
```

Результат:

```text
A
B
C
```

Executor выполняется синхронно. Обработчики `.then()`, `.catch()` и `.finally()` запускаются позже, через очередь микрозадач.

## Callbacks выполняются асинхронно

Даже если Promise уже fulfilled, callback `.then()` не вызывается сразу. Он попадает в microtask queue.

```js
console.log('A');

Promise.resolve('B').then((value) => {
  console.log(value);
});

console.log('C');
```

Результат:

```text
A
C
B
```

Подробнее: [[Фронтенд/JavaScript/05. Асинхронность/01. Event Loop в браузере#Microtask Queue|Event Loop в браузере]].

## then возвращает новый Promise

Каждый вызов `.then()` возвращает новый Promise. Поэтому можно строить цепочки.

```js
const resultPromise = Promise.resolve(1)
  .then((value) => value + 1)
  .then((value) => value * 2);

resultPromise.then((value) => {
  console.log(value);
});
```

Результат:

```text
4
```

Важная мысль: следующий `.then()` ждёт результат предыдущего обработчика.

## Как результат обработчика влияет на цепочку

### Возвращено обычное значение

Возвращённое значение передаётся следующему успешному обработчику `.then()`. Например, `return 2` позволит следующему шагу получить `2`.

```js
Promise.resolve(10)
  .then((value) => value + 5)
  .then((value) => {
    console.log(value);
  });
```

Результат:

```text
15
```

### Нет return

Если обработчик завершился без `return`, его результат — `undefined`. Именно это значение получит следующий `.then()`.

```js
Promise.resolve(10)
  .then((value) => {
    value + 5;
  })
  .then((value) => {
    console.log(value);
  });
```

Результат:

```text
undefined
```

### Возвращён другой Promise

Если обработчик возвращает Promise, следующий шаг цепочки дождётся его результата.

```js
Promise.resolve(10)
  .then((value) => {
    return new Promise((resolve) => {
      setTimeout(() => {
        resolve(value * 2);
      }, 100);
    });
  })
  .then((value) => {
    console.log(value);
  });
```

Результат:

```text
20
```

### Обработчик выбрасывает ошибку

Если обработчик `.then()` выбросил ошибку, следующий Promise отклонится. Дальше цепочка будет искать обработчик этой ошибки.

```js
Promise.resolve('start')
  .then(() => {
    throw new Error('broken');
  })
  .catch((error) => {
    console.log(error.message);
  });
```

Результат:

```text
broken
```

## Передача значений

```js
Promise.resolve(2)
  .then((value) => value + 1)
  .then((value) => value * 3)
  .then((value) => {
    console.log(value);
  });
```

Результат:

```text
9
```

Каждый обработчик получает результат предыдущего обработчика.

## Распространение ошибок

Ошибка пропускает `.then()` без обработчика ошибки и попадает в ближайший `.catch()`.

```js
Promise.resolve()
  .then(() => {
    throw new Error('A');
  })
  .then(() => {
    console.log('B');
  })
  .catch((error) => {
    console.log(error.message);
  });
```

Результат:

```text
A
```

`B` не выводится, потому что цепочка перешла в rejected-состояние.

## catch может восстановить цепочку

Если `.catch()` вернул обычное значение, ошибка считается обработанной. Следующий `.then()` получит это значение и продолжит успешную ветку.

```js
Promise.reject(new Error('failed'))
  .catch((error) => {
    console.log(error.message);
    return 'fallback';
  })
  .then((value) => {
    console.log(value);
  });
```

Результат:

```text
failed
fallback
```

Чтобы пробросить ошибку дальше, нужно снова выбросить её или вернуть rejected Promise.

```js
Promise.reject(new Error('failed'))
  .catch((error) => {
    console.log('log:', error.message);
    throw error;
  })
  .catch((error) => {
    console.log('handle:', error.message);
  });
```

Результат:

```text
log: failed
handle: failed
```

## finally

`.finally()` вызывается и после успеха, и после ошибки. Например, в нём можно убрать индикатор загрузки или освободить ресурсы.

```js
Promise.resolve('data')
  .finally(() => {
    console.log('cleanup');
  })
  .then((value) => {
    console.log(value);
  });
```

Результат:

```text
cleanup
data
```

Обычно `.finally()` не меняет значение цепочки:

```js
Promise.resolve('A')
  .finally(() => 'B')
  .then((value) => {
    console.log(value);
  });
```

Результат:

```text
A
```

Но если внутри `.finally()` выбросить ошибку или вернуть rejected Promise, цепочка станет rejected.

```js
Promise.resolve('A')
  .finally(() => {
    throw new Error('cleanup failed');
  })
  .catch((error) => {
    console.log(error.message);
  });
```

Результат:

```text
cleanup failed
```

## Углубление

> [!info]- Resolved vs fulfilled
> В обычной подготовке часто говорят “Promise resolved” как “Promise успешно завершился”. Это разговорное упрощение.
>
> Точнее:
>
> - `fulfilled` — Promise уже успешно завершён с конкретным значением;
> - `resolved` — Promise “зафиксирован” на результате: возможно, он принят с другим Promise и ждёт его состояние.
>
> ```js
> const inner = new Promise((resolve) => {
>   setTimeout(() => resolve('done'), 100);
> });
>
> const outer = new Promise((resolve) => {
>   resolve(inner);
>   resolve('ignored');
> });
> ```
>
> `outer` уже resolved: его результат зафиксирован на `inner`, поэтому второй `resolve` игнорируется. При этом `outer` пока pending и станет fulfilled со значением `done` после завершения `inner`. `Promise.resolve(inner)` здесь не подходит для демонстрации: он вернул бы тот же объект `inner`.

> [!info]- Thenable
> Thenable — объект с методом `.then()`. `Promise.resolve()` умеет принимать thenable и “усваивать” его результат.
>
> ```js
> const thenable = {
>   then(resolve) {
>     resolve('value');
>   },
> };
>
> Promise.resolve(thenable).then((value) => {
>   console.log(value);
> });
> ```
>
> Результат:
>
> ```text
> value
> ```
>
> На P0-уровне достаточно знать, что Promise может работать не только с настоящими Promise, но и с promise-like объектами.

## Частые ошибки

### Ошибка 1. Забыть return внутри then

```js
fetchUser()
  .then((user) => {
    fetchPosts(user.id);
  })
  .then((posts) => {
    console.log(posts);
  });
```

Второй `.then()` получит `undefined`, потому что первый обработчик не вернул Promise.

Правильно:

```js
fetchUser()
  .then((user) => {
    return fetchPosts(user.id);
  })
  .then((posts) => {
    console.log(posts);
  });
```

### Ошибка 2. Передать результат вызова вместо callback

```js
Promise.resolve('value').then(console.log('done'));
```

`console.log('done')` выполнится сразу, а в `.then()` попадёт `undefined`.

Правильно:

```js
Promise.resolve('value').then(() => {
  console.log('done');
});
```

### Ошибка 3. Думать, что catch всегда пробрасывает ошибку

`.catch()` восстанавливает цепочку, если возвращает обычное значение. Для повторного проброса нужно `throw error`.

### Ошибка 4. Создавать лишнюю обёртку над Promise

```js
function loadUser() {
  return new Promise((resolve, reject) => {
    fetch('/user').then(resolve).catch(reject);
  });
}
```

Чаще достаточно вернуть существующий Promise:

```js
function loadUser() {
  return fetch('/user');
}
```

### Ошибка 5. Считать, что Promise сам запускает параллельный поток

Функция внутри `new Promise()` выполняется сразу в текущем потоке. Отдельную работу запускает используемый API: например, сетевой запрос или Worker. Сам Promise только позволяет получить её результат.

## Как ответить на собеседовании за одну минуту

Promise — объект, который представляет будущий результат операции. Он начинается в состоянии `pending`, затем один раз переходит в `fulfilled` или `rejected`; оба состояния вместе называют `settled`.

Функция, переданная в `new Promise()`, запускается сразу. Обработчики `.then()`, `.catch()` и `.finally()` выполняются позже, через очередь микрозадач.

Каждый `.then()` возвращает новый Promise. Следующий шаг получает то, что вернул обработчик: обычное значение, `undefined` при отсутствии `return` или результат другого Promise после его завершения. Если обработчик выбросил ошибку, цепочка переходит к её обработке.

`.catch()` может обработать ошибку и восстановить цепочку, а `.finally()` обычно нужен для очистки.

## Практические задачи

### Задача 1. Executor и then

```js
console.log('A');

new Promise((resolve) => {
  console.log('B');
  resolve();
}).then(() => {
  console.log('C');
});

console.log('D');
```

> [!question]- Разбор
> Результат:
>
> ```text
> A
> B
> D
> C
> ```
>
> Executor выполняется синхронно, поэтому `B` выводится до `D`. Callback `.then()` попадает в microtask queue и выполняется после завершения текущей task.

### Задача 2. Потерянный return

```js
Promise.resolve(1)
  .then((value) => {
    value + 1;
  })
  .then((value) => {
    console.log(value);
  });
```

> [!question]- Разбор
> Результат:
>
> ```text
> undefined
> ```
>
> Первый обработчик ничего не возвращает. Его результат — `undefined`, он и передаётся дальше по цепочке.

### Задача 3. Восстановление после ошибки

```js
Promise.reject(new Error('A'))
  .catch((error) => {
    console.log(error.message);
    return 'B';
  })
  .then((value) => {
    console.log(value);
  });
```

> [!question]- Разбор
> Результат:
>
> ```text
> A
> B
> ```
>
> `.catch()` обработал rejected Promise и вернул обычное значение. После этого цепочка стала fulfilled.

### Задача 4. finally

```js
Promise.resolve('A')
  .finally(() => {
    console.log('B');
    return 'C';
  })
  .then((value) => {
    console.log(value);
  });
```

> [!question]- Разбор
> Результат:
>
> ```text
> B
> A
> ```
>
> `.finally()` выполняется, но обычное возвращаемое значение из него не заменяет результат цепочки.
