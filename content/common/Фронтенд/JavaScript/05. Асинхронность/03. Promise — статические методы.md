# Promise — статические методы

> [!summary]
> Статические методы Promise помогают создавать завершённые Promise и координировать несколько асинхронных операций. Для собеседования важнее всего понимать стратегию ожидания: ждать все, ждать все результаты, ждать первый settled или первый fulfilled.

## Выбор на простом примере

Для страницы нужны профиль и права — выбирай all: без одного результата страницу не собрать. Для независимых виджетов допустим частичный успех — allSettled. Нужен самый быстрый успешный источник — any. Нужен первый результат любого вида, например соревнование с тайм-аутом, — race.

Сначала прочитай сводную таблицу и один нужный метод. Затем проверь: что будет при пустом входе и ошибке? Ни один из этих методов сам не отменяет остальные операции.

## Зачем понимать статические методы Promise

На практике часто нужно:

- запустить несколько независимых запросов одновременно;
- дождаться всех обязательных данных;
- собрать частичные результаты;
- ограничить ожидание тайм-аутом;
- выбрать первый успешный источник;
- понять, почему `Promise.all()` не отменяет уже запущенные операции.

## Создание завершённых Promise

### Promise.resolve()

`Promise.resolve(value)` возвращает Promise, который будет fulfilled переданным значением. Callback `.then()` всё равно выполнится асинхронно через microtask queue.

```js
console.log('A');

Promise.resolve('B').then((value) => {
  console.log(value);
});

console.log('C');
```

Результат:

```text
A
C
B
```

Если передать в `Promise.resolve()` существующий Promise, он не оборачивается в “лишний слой”:

```js
const originalPromise = Promise.resolve(10);
const resultPromise = Promise.resolve(originalPromise);

console.log(originalPromise === resultPromise);
```

Результат:

```text
true
```

### Promise.reject()

`Promise.reject(reason)` возвращает rejected Promise.

```js
Promise.reject(new Error('failed')).catch((error) => {
  console.log(error.message);
});
```

Результат:

```text
failed
```

Для rejected Promise лучше использовать `Error`, а не строку: так сохраняются message и stack.

## Promise.all()

`Promise.all(iterable)` ждёт успешного завершения всех переданных операций и возвращает массив результатов.

```js
const userPromise = Promise.resolve('user');
const postsPromise = Promise.resolve('posts');

Promise.all([userPromise, postsPromise]).then((result) => {
  console.log(result);
});
```

Результат:

```text
['user', 'posts']
```

### Порядок результатов

Порядок результатов соответствует порядку входных элементов, а не порядку завершения.

```js
const slowPromise = new Promise((resolve) => {
  setTimeout(() => resolve('slow'), 100);
});

const fastPromise = new Promise((resolve) => {
  setTimeout(() => resolve('fast'), 10);
});

Promise.all([slowPromise, fastPromise]).then((result) => {
  console.log(result);
});
```

Результат:

```text
['slow', 'fast']
```

### Fail-fast поведение

Если один Promise rejected, итоговый Promise от `Promise.all()` rejected с первой причиной ошибки.

```js
Promise.all([
  Promise.resolve('A'),
  Promise.reject(new Error('B')),
  Promise.resolve('C'),
]).catch((error) => {
  console.log(error.message);
});
```

Результат:

```text
B
```

> [!important]
> `Promise.all()` не отменяет остальные уже запущенные операции. Он только перестаёт ждать успешный общий результат. Полноценный разбор отмены через `AbortController` есть в [[Фронтенд/JavaScript/05. Асинхронность/06. Паттерны асинхронного кода|Паттерны асинхронного кода]].

## Promise.allSettled()

`Promise.allSettled(iterable)` ждёт завершения всех операций независимо от результата.

```js
Promise.allSettled([
  Promise.resolve('A'),
  Promise.reject(new Error('B')),
]).then((results) => {
  console.log(results);
});
```

Результат:

```text
[
  { status: 'fulfilled', value: 'A' },
  { status: 'rejected', reason: Error: B }
]
```

Используй `Promise.allSettled()`, когда частичный результат лучше, чем полный отказ.

## Promise.race()

`Promise.race(iterable)` завершается так же, как первый settled Promise: fulfilled или rejected.

```js
const slowPromise = new Promise((resolve) => {
  setTimeout(() => resolve('slow'), 100);
});

const fastPromise = new Promise((resolve) => {
  setTimeout(() => resolve('fast'), 10);
});

Promise.race([slowPromise, fastPromise]).then((value) => {
  console.log(value);
});
```

Результат:

```text
fast
```

Первая ошибка тоже “побеждает”:

```js
Promise.race([
  new Promise((resolve) => setTimeout(() => resolve('A'), 100)),
  Promise.reject(new Error('B')),
]).catch((error) => {
  console.log(error.message);
});
```

Результат:

```text
B
```

`Promise.race()` часто используют для тайм-аутов, но сам по себе он не отменяет проигравшую операцию.

## Promise.any()

`Promise.any(iterable)` ждёт первый fulfilled Promise. Rejected Promise игнорируются, пока есть шанс на успешный результат.

```js
Promise.any([
  Promise.reject(new Error('A')),
  Promise.resolve('B'),
  Promise.resolve('C'),
]).then((value) => {
  console.log(value);
});
```

Результат:

```text
B
```

Если все Promise rejected, итоговый Promise rejected с `AggregateError`.

```js
Promise.any([
  Promise.reject(new Error('A')),
  Promise.reject(new Error('B')),
]).catch((error) => {
  console.log(error instanceof AggregateError);
  console.log(error.errors.length);
});
```

Результат:

```text
true
2
```

## race() и any()

| Метод | Что ждёт | Как относится к ошибке |
|---|---|---|
| `Promise.race()` | первый settled Promise | первая ошибка сразу отклоняет итоговый Promise |
| `Promise.any()` | первый fulfilled Promise | ошибки игнорируются, пока не отклонятся все Promise |

```js
Promise.race([
  Promise.reject(new Error('failed')),
  Promise.resolve('ok'),
]).catch((error) => {
  console.log(error.message);
});

Promise.any([
  Promise.reject(new Error('failed')),
  Promise.resolve('ok'),
]).then((value) => {
  console.log(value);
});
```

Результат:

```text
failed
ok
```

## Последовательный и одновременный запуск

### Последовательное выполнение

Нужно, когда вторая операция зависит от результата первой.

```js
const user = await loadUser();
const posts = await loadPosts(user.id);
```

### Одновременное выполнение независимых операций

Если операции независимы, их можно запустить одновременно через `Promise.all()`.

```js
const [user, settings] = await Promise.all([
  loadUser(),
  loadSettings(),
]);
```

### Ошибка с лишними await внутри Promise.all()

```js
const [user, settings] = await Promise.all([
  await loadUser(),
  await loadSettings(),
]);
```

Так писать не стоит. Первый `await` приостанавливает выполнение до завершения `loadUser()`, и преимущество одновременного запуска теряется.

Правильно:

```js
const [user, settings] = await Promise.all([
  loadUser(),
  loadSettings(),
]);
```

## Слишком много операций одновременно

```js
await Promise.all(urls.map((url) => fetch(url)));
```

Для маленького массива это нормально. Для тысяч URL такой код может перегрузить сеть, API или браузер. В таких случаях нужен concurrency limiter: запускать не больше N операций одновременно. Базовый паттерн разобран в [[Фронтенд/JavaScript/05. Асинхронность/06. Паттерны асинхронного кода|Паттерны асинхронного кода]].

## Сводная таблица

| Задача | Метод |
|---|---|
| Получить fulfilled Promise из значения | `Promise.resolve()` |
| Получить rejected Promise | `Promise.reject()` |
| Дождаться всех обязательных операций | `Promise.all()` |
| Получить все результаты, включая ошибки | `Promise.allSettled()` |
| Взять первый settled результат | `Promise.race()` |
| Взять первый успешный результат | `Promise.any()` |
| Ошибка одного обязательного запроса должна ломать всё | `Promise.all()` |
| Ошибка одного источника допустима, нужен первый успех | `Promise.any()` |
| Нужен тайм-аут ожидания | `Promise.race()` плюс отдельная отмена при необходимости |

## Углубление

> [!info]- Пустой iterable
> Поведение с пустым iterable полезно знать как edge case, но это не главная P0-модель.
>
> ```js
> Promise.all([]).then((value) => console.log(value));
> Promise.allSettled([]).then((value) => console.log(value));
> Promise.any([]).catch((error) => console.log(error instanceof AggregateError));
> const racePromise = Promise.race([]);
> ```
>
> - `Promise.all([])` fulfilled с пустым массивом;
> - `Promise.allSettled([])` fulfilled с пустым массивом;
> - `Promise.any([])` rejected с `AggregateError`;
> - `Promise.race([])` остаётся pending.

## Частые ошибки

### Ошибка 1. Считать, что Promise.all отменяет остальные операции

`Promise.all()` fail-fast, но это не механизм отмены.

### Ошибка 2. Использовать Promise.all, когда допустим частичный результат

Если часть данных может не загрузиться, часто лучше `Promise.allSettled()`.

### Ошибка 3. Путать race и any

`race()` реагирует на первый settled результат. `any()` ждёт первый fulfilled результат.

### Ошибка 4. Делать тайм-аут без отмены запроса

`Promise.race()` может перестать ждать запрос, но сам запрос продолжит выполняться, если его явно не отменить.

### Ошибка 5. Выполнять независимые операции последовательно

```js
const user = await loadUser();
const settings = await loadSettings();
```

Если операции независимы, лучше:

```js
const [user, settings] = await Promise.all([
  loadUser(),
  loadSettings(),
]);
```

### Ошибка 6. Запускать слишком много операций одновременно

`Promise.all(bigArray.map(fetch))` может быть слишком агрессивным. Нужен лимит параллельности.

## Как ответить на собеседовании за одну минуту

Статические методы Promise помогают координировать несколько асинхронных операций. `Promise.resolve(value)` принимает обычное значение или следует состоянию переданного Promise; `Promise.reject(reason)` создаёт отклонённый Promise. `Promise.all()` ждёт все операции и fail-fast отклоняется при первой ошибке, но не отменяет остальные операции. `Promise.allSettled()` ждёт все результаты и возвращает статусы. `Promise.race()` берёт первый settled результат — успех или ошибку. `Promise.any()` берёт первый fulfilled результат, а если все завершились ошибкой, отклоняется с `AggregateError`. Для независимых операций обычно используют `Promise.all()`, но без лишних `await` внутри массива.

## Практические задачи

### Задача 1. Порядок результатов

```js
const slowPromise = new Promise((resolve) => {
  setTimeout(() => resolve('A'), 100);
});

const fastPromise = new Promise((resolve) => {
  setTimeout(() => resolve('B'), 10);
});

Promise.all([slowPromise, fastPromise]).then((result) => {
  console.log(result);
});
```

> [!question]- Разбор
> Результат:
>
> ```text
> ['A', 'B']
> ```
>
> `fastPromise` завершается раньше, но `Promise.all()` сохраняет порядок входного массива.

### Задача 2. Ошибка в Promise.all

```js
Promise.all([
  Promise.resolve('A'),
  Promise.reject(new Error('B')),
  Promise.resolve('C'),
])
  .then((result) => {
    console.log(result);
  })
  .catch((error) => {
    console.log(error.message);
  });
```

> [!question]- Разбор
> Результат:
>
> ```text
> B
> ```
>
> `Promise.all()` отклоняется при первой ошибке. `.then()` не выполнится, управление перейдёт в `.catch()`.

### Задача 3. race или any

```js
Promise.race([
  Promise.reject(new Error('A')),
  new Promise((resolve) => setTimeout(() => resolve('B'), 10)),
]).catch((error) => {
  console.log(error.message);
});

Promise.any([
  Promise.reject(new Error('C')),
  new Promise((resolve) => setTimeout(() => resolve('D'), 10)),
]).then((value) => {
  console.log(value);
});
```

> [!question]- Разбор
> Результат:
>
> ```text
> A
> D
> ```
>
> `race()` завершается первым settled Promise, поэтому первая ошибка побеждает. `any()` ждёт первый fulfilled Promise, поэтому игнорирует первую ошибку и выводит `D`.

### Задача 4. Лишний await

```js
async function run() {
  const first = await loadFirst();
  const second = await loadSecond();

  return [first, second];
}
```

> [!question]- Разбор
> Если `loadFirst()` и `loadSecond()` независимы, код запускает их последовательно. Второй запрос начнётся только после завершения первого. Лучше:
>
> ```js
> async function run() {
>   return Promise.all([
>     loadFirst(),
>     loadSecond(),
>   ]);
> }
> ```
