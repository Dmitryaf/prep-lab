# async-await

> [!summary]
> `async / await` — синтаксис поверх Promise. Он позволяет писать асинхронный код похожим на синхронный, но не отменяет правила Promise, microtask queue и обработки ошибок.

## Сначала один выбор: операции зависят друг от друга?

Если второй запрос использует результат первого, жди их последовательно. Если профиль и настройки независимы, запусти оба и дождись через Promise.all. `await` приостанавливает текущую async-функцию, а не весь браузер; тяжёлый синхронный цикл от добавления async легче не станет.

Для первого чтения достаточно разделов про возвращаемый Promise, код до await, try/catch и последовательный/одновременный запуск. Затем проверь ловушку forEach(async).

## Зачем понимать async-await

На собеседованиях часто проверяют:

- что `async`-функция всегда возвращает Promise;
- что код до первого `await` выполняется синхронно;
- что продолжение после `await` выполняется асинхронно;
- как обрабатывать ошибки через `try / catch / finally`;
- когда операции запускать последовательно, а когда одновременно;
- почему `forEach(async () => ...)` почти всегда не то, что нужно.

## async-функция всегда возвращает Promise

Если `async`-функция возвращает обычное значение, оно становится значением успешно выполненного Promise.

```js
async function getValue() {
  return 10;
}

getValue().then((value) => {
  console.log(value);
});
```

Результат:

```text
10
```

Если внутри `async`-функции выброшена ошибка, возвращённый Promise станет rejected.

```js
async function fail() {
  throw new Error('failed');
}

fail().catch((error) => {
  console.log(error.message);
});
```

Результат:

```text
failed
```

## Код до первого await выполняется синхронно

```js
async function run() {
  console.log('B');
  await Promise.resolve();
  console.log('C');
}

console.log('A');
run();
console.log('D');
```

Результат:

```text
A
B
D
C
```

`B` выводится синхронно во время вызова `run()`. На `await` функция приостанавливается, а продолжение `C` попадает в microtask queue.

## await ждёт Promise

`await promise` приостанавливает выполнение текущей `async`-функции до завершения Promise. При fulfilled результатом выражения `await` будет fulfillment value.

```js
async function run() {
  const value = await Promise.resolve('A');
  console.log(value);
}

run();
```

Результат:

```text
A
```

Если Promise rejected, `await` выбросит ошибку в месте ожидания.

```js
async function run() {
  try {
    await Promise.reject(new Error('A'));
  } catch (error) {
    console.log(error.message);
  }
}

run();
```

Результат:

```text
A
```

## await обычного значения

`await` умеет ждать не только Promise. Обычное значение будет приведено к уже fulfilled Promise, а продолжение всё равно произойдёт асинхронно.

```js
async function run() {
  console.log('A');
  await 10;
  console.log('B');
}

run();
console.log('C');
```

Результат:

```text
A
C
B
```

## try / catch / finally

`try / catch` с `await` позволяет обрабатывать rejected Promise как обычную ошибку.

```js
async function loadUser() {
  try {
    const response = await fetch('/api/user');
    return await response.json();
  } catch (error) {
    console.log('Request failed:', error.message);
    return null;
  } finally {
    console.log('cleanup');
  }
}
```

`finally` выполнится и при успехе, и при ошибке. Если нужно только залогировать ошибку, но оставить её для вызывающего кода, ошибку нужно пробросить повторно.

```js
async function loadUser() {
  try {
    return await fetchUser();
  } catch (error) {
    console.log('Failed:', error.message);
    throw error;
  }
}
```

## Последовательное выполнение зависимых операций

Если вторая операция зависит от результата первой, последовательный `await` оправдан.

```js
async function loadUserPosts() {
  const user = await loadUser();
  const posts = await loadPosts(user.id);

  return { user, posts };
}
```

## Одновременное выполнение независимых операций

Если операции независимы, запускай их одновременно через `Promise.all()`.

```js
async function loadPage() {
  const [user, settings] = await Promise.all([
    loadUser(),
    loadSettings(),
  ]);

  return { user, settings };
}
```

Подробный разбор методов: [[Фронтенд/JavaScript/05. Асинхронность/03. Promise — статические методы|Promise — статические методы]].

## Частая ошибка: последовательные независимые запросы

```js
async function loadPage() {
  const user = await loadUser();
  const settings = await loadSettings();

  return { user, settings };
}
```

Если `loadUser()` и `loadSettings()` независимы, второй запрос начнётся только после первого. Это медленнее.

Правильно:

```js
async function loadPage() {
  const [user, settings] = await Promise.all([
    loadUser(),
    loadSettings(),
  ]);

  return { user, settings };
}
```

## Частая ошибка: forEach(async () => ...)

`forEach()` не ждёт async callbacks.

```js
async function saveAll(items) {
  items.forEach(async (item) => {
    await saveItem(item);
  });

  console.log('done');
}
```

`done` выведется раньше, чем все `saveItem()` завершатся.

Если нужно выполнять последовательно:

```js
async function saveAll(items) {
  for (const item of items) {
    await saveItem(item);
  }

  console.log('done');
}
```

Если можно выполнять одновременно:

```js
async function saveAll(items) {
  await Promise.all(
    items.map((item) => saveItem(item))
  );

  console.log('done');
}
```

## fetch и HTTP-статусы

`fetch()` обычно не отклоняет Promise только потому, что сервер вернул HTTP-статус `404` или `500`. Promise fulfilled с объектом `Response`, а статус нужно проверить вручную.

```js
async function loadJson(url) {
  const response = await fetch(url);

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  return response.json();
}
```

Promise от `fetch()` rejected, например, при сетевой ошибке или некорректной схеме URL.

## Частые ошибки

### Ошибка 1. Думать, что async-функция возвращает обычное значение

```js
async function getUser() {
  return { name: 'Ann' };
}

const user = getUser();
console.log(user.name);
```

`user` — Promise, а не объект пользователя.

### Ошибка 2. Забыть await

```js
async function run() {
  const response = fetch('/api/user');
  const data = await response.json();
}
```

`response` здесь Promise. Нужно:

```js
async function run() {
  const response = await fetch('/api/user');
  const data = await response.json();
}
```

### Ошибка 3. Ловить ошибку и случайно её проглатывать

Если `.catch` или `catch` возвращает обычное значение, вызывающий код увидит успешный результат. Для повторного проброса нужен `throw`.

### Ошибка 4. Запускать независимые операции последовательно

Если операции не зависят друг от друга, используй `Promise.all()`.

### Ошибка 5. Использовать forEach с async callback

`forEach()` не возвращает Promise, который можно корректно `await`.

## Как ответить на собеседовании за одну минуту

`async / await` — синтаксис поверх Promise. Любая `async`-функция всегда возвращает Promise: обычный `return` становится fulfilled value, а выброшенная ошибка — rejected Promise. Код внутри `async`-функции до первого `await` выполняется синхронно. На `await` функция приостанавливается, а продолжение после ожидания выполняется позже через microtask queue. Ошибки rejected Promise можно ловить через `try / catch`, а независимые операции лучше запускать одновременно через `Promise.all()`. Важно помнить, что `forEach(async () => ...)` не ждёт callbacks, а `fetch()` не считает HTTP 404 или 500 сетевой ошибкой сам по себе.

## Практические задачи

### Задача 1. Возвращаемое значение

```js
async function getNumber() {
  return 5;
}

console.log(getNumber());

getNumber().then((value) => {
  console.log(value);
});
```

> [!question]- Разбор
> Первый `console.log` выведет Promise, а второй — значение `5`. `async`-функция всегда возвращает Promise.

### Задача 2. Порядок выполнения

```js
async function run() {
  console.log('A');
  await Promise.resolve();
  console.log('B');
}

console.log('C');
run();
console.log('D');
```

> [!question]- Разбор
> Результат:
>
> ```text
> C
> A
> D
> B
> ```
>
> `C`, `A`, `D` выполняются в текущей task. Продолжение после `await` попадает в microtask queue и выводит `B` после завершения синхронного кода.

### Задача 3. Ошибка и повторный проброс

```js
async function run() {
  try {
    throw new Error('A');
  } catch (error) {
    console.log(error.message);
    throw error;
  }
}

run().catch((error) => {
  console.log('B');
});
```

> [!question]- Разбор
> Результат:
>
> ```text
> A
> B
> ```
>
> `catch` внутри `run()` ловит ошибку и выводит `A`, затем повторно выбрасывает её. Возвращённый `run()` Promise становится rejected, внешний `.catch()` выводит `B`.

### Задача 4. forEach

```js
async function run(items) {
  items.forEach(async (item) => {
    await saveItem(item);
  });

  console.log('done');
}
```

> [!question]- Разбор
> `done` может выполниться до завершения `saveItem()`. `forEach()` не собирает Promise из async callbacks и не ждёт их. Для последовательного выполнения нужен `for...of`, для одновременного — `Promise.all(items.map(...))`.
