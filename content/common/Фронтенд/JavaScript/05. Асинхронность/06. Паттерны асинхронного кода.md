# Паттерны асинхронного кода

> [!summary]
> P1-заметка про практические проблемы асинхронного кода: отмену запросов, race condition, устаревшие ответы, лимит параллельности, дедупликацию и retry.

## AbortController

`AbortController` позволяет передать сигнал отмены в API, которые его поддерживают, например `fetch()`.

```js
const controller = new AbortController();

fetch('/api/user', { signal: controller.signal })
  .catch((error) => {
    if (error.name === 'AbortError') {
      return;
    }

    throw error;
  });

controller.abort();
```

Отмена не "откатывает" уже выполненную работу на сервере. Она сообщает клиентской операции, что результат больше не нужен.

## Race condition и устаревший ответ

Проблема: пользователь быстро меняет фильтр, второй запрос стартует позже, но первый отвечает последним и перетирает актуальные данные.

```js
let requestId = 0;

async function loadUser(id) {
  const currentRequestId = ++requestId;
  const response = await fetch(`/api/users/${id}`);
  const user = await response.json();

  if (currentRequestId !== requestId) {
    return;
  }

  render(user);
}
```

Здесь старый ответ игнорируется.

## Лимит параллельности

`Promise.all(items.map(request))` запускает всё сразу. Для большого списка нужен лимит.

```js
async function runWithLimit(items, limit, worker) {
  if (!Number.isInteger(limit) || limit < 1) {
    throw new RangeError('limit должен быть положительным целым числом');
  }
  const results = [];
  let index = 0;
  let failed = false;

  async function runNext() {
    while (!failed && index < items.length) {
      const currentIndex = index++;
      try {
        results[currentIndex] = await worker(items[currentIndex]);
      } catch (error) {
        failed = true;
        throw error;
      }
    }
  }

  await Promise.all(Array.from({ length: Math.min(limit, items.length) }, runNext));
  return results;
}
```

Контракт: результат сохраняет порядок входа, пустой список даёт `[]`, некорректный лимит отклоняет Promise. При первой ошибке прекращаем запуск новых элементов и отклоняем общий Promise; уже начатые операции продолжаются. Это не отмена запросов. Для отмены нужно отдельно передавать сигнал в `worker`.

## Дедупликация запросов

Если один и тот же запрос уже выполняется, можно вернуть тот же Promise.

```js
const pending = new Map();

function fetchOnce(key, load) {
  if (pending.has(key)) {
    return pending.get(key);
  }

  const promise = Promise.resolve().then(load).finally(() => {
    pending.delete(key);
  });

  pending.set(key, promise);
  return promise;
}
```

## Retry и exponential backoff

Retry полезен для временных сетевых ошибок, но опасен для неидемпотентных операций.

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function retry(operation, attempts = 3) {
  if (!Number.isInteger(attempts) || attempts < 1) {
    throw new RangeError('attempts должен быть положительным целым числом');
  }
  let delay = 200;

  for (let attempt = 1; attempt <= attempts; attempt += 1) {
    try {
      return await operation();
    } catch (error) {
      if (attempt === attempts) {
        throw error;
      }

      await wait(delay);
      delay *= 2;
    }
  }
}
```

Это учебный механизм задержки, который повторяет любую переданную ошибку. Перед применением выбери, какие ошибки допустимо повторять, учти отмену и нагрузку на сервер. Ошибки прав или проверки данных обычно не исправляются повтором; для записей нужен контракт идемпотентности. Случайный разброс задержки (jitter) помогает не отправить все повторы одновременно, но сам по себе не делает запись безопасной.

## Batching

Batching объединяет несколько операций в одну пачку: например, собрать изменения за короткий интервал и отправить одним запросом. Это снижает накладные расходы, но увеличивает задержку отдельной операции.

## Частые ошибки

- Не отличать отмену запроса от игнорирования устаревшего результата.
- Запускать тысячи запросов через один `Promise.all()`.
- Делать retry для операции, которую нельзя безопасно повторять.
- Не очищать `Map` с pending-запросами после завершения.
