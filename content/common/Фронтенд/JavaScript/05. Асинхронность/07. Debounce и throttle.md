# Debounce и throttle

> [!summary]
> Debounce откладывает вызов до паузы в событиях. Throttle ограничивает частоту вызовов.

## Debounce

Debounce полезен для поиска по вводу: пока пользователь печатает, запрос не отправляется.

```js
// checked-example: debounce
function debounce(fn, delay) {
  let timerId;

  function debounced(...args) {
    clearTimeout(timerId);

    timerId = setTimeout(() => {
      timerId = undefined;
      fn.apply(this, args);
    }, delay);
  }
  debounced.cancel = () => {
    clearTimeout(timerId);
    timerId = undefined;
  };
  return debounced;
}
```

При вызовах на 0, 100 и 200 мс с задержкой 300 мс действие произойдёт примерно на 500 мс. Стрелочная функция таймера сохраняет `this` текущего вызова; `apply` передаёт его исходной функции. `debounced.cancel()` удаляет отложенный вызов при закрытии компонента.

Debounce уменьшает количество запросов, но уже отправленный старый запрос всё равно может завершиться позже нового. Для этого нужна [[Фронтенд/API браузера/05. Fetch, CORS и сетевые запросы/03. AbortController и race condition в запросах|защита от старого ответа]].

## Throttle

Throttle полезен для scroll/resize: функция вызывается не чаще одного раза за интервал.

```js
// checked-example: throttle
function throttle(fn, interval) {
  let lastCall = -Infinity;

  return function throttled(...args) {
    const now = performance.now();

    if (now - lastCall < interval) {
      return;
    }

    lastCall = now;
    fn.apply(this, args);
  };
}
```

Это leading-вариант: первый вызов проходит сразу, промежуточные пропускаются, последнего отложенного вызова нет. `performance.now()` измеряет прошедшее время и не зависит от перевода системных часов.

> [!note]- Если попросят подробнее: trailing и flush
>
> Trailing сохраняет последние аргументы и выполняет их по окончании интервала. Это важно, если нужно обработать последнее положение после остановки событий. `flush` у debounce выполняет ожидающий вызов немедленно. Сначала зафиксируй, какие вызовы должны состояться на временной шкале, затем добавляй код: поведение на границах интервала важнее названия функции.

## Throttle с первым и последним вызовом

Контракт: первый вызов выполняется сразу; внутри интервала сохраняются последние аргументы и `this`. В конце интервала выполняется один отложенный вызов, только если после первого пришли новые события. Между реальными выполнениями проходит не меньше `interval`. `cancel()` удаляет ожидание и разрешает следующий вызов сразу. Возвращаемое значение исходной функции наружу не передаётся.

```js
// checked-example: throttle-leading-trailing
function throttleTrailing(fn, interval) {
  if (!Number.isFinite(interval) || interval <= 0) {
    throw new RangeError('interval must be positive');
  }
  let lastRun = -Infinity;
  let timer;
  let pending;
  const invoke = () => {
    const { receiver, args } = pending;
    pending = undefined;
    lastRun = performance.now();
    fn.apply(receiver, args);
  };
  function throttled(...args) {
    pending = { receiver: this, args };
    const remaining = interval - (performance.now() - lastRun);
    if (remaining <= 0) {
      clearTimeout(timer);
      timer = undefined;
      invoke();
    } else if (timer === undefined) {
      timer = setTimeout(() => {
        timer = undefined;
        invoke();
      }, remaining);
    }
  }
  throttled.cancel = () => {
    clearTimeout(timer);
    timer = pending = undefined;
    lastRun = -Infinity;
  };
  return throttled;
}
```

При `interval = 100` вызовы `A@0`, `B@20`, `C@70`, `D@130` дают `A@0`, `C@100`, `D@200`. Один `A@0` не повторяется на 100 мс. Новый вызов точно на границе заменяет ожидающие аргументы, если callback таймера ещё не выполнялся; если таймер уже выполнился, начинается следующий интервал. Таймер не гарантирует точное время: занятый поток сдвинет выполнение, поэтому отсчёт идёт от фактического вызова. Проверь также разные получатели `this`, отмену и исключение из `fn`.

## Как выбрать

| Сценарий | Паттерн |
| --- | --- |
| поиск после остановки ввода | debounce |
| сохранение черновика после паузы | debounce |
| обработка scroll | throttle |
| обработка resize | throttle |

## Частые ошибки

- Путать debounce и throttle.
- Терять `this` и аргументы исходной функции.
- Не отменять timer при уничтожении компонента.
- Делать сетевой запрос на каждое событие ввода.

## Как ответить на собеседовании за одну минуту

Debounce вызывает функцию только после паузы: каждый новый вызов сбрасывает таймер. Throttle разрешает вызов не чаще заданного интервала. Debounce чаще используют для search input, throttle - для частых событий вроде scroll и resize.
