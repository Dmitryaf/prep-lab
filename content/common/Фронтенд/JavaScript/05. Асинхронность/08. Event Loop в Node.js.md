# Event Loop в Node.js

> [!summary]
> Node.js Event Loop отличается от браузерного: у него есть фазы libuv, отдельные очереди для timers, poll, check и особое поведение `process.nextTick()`.

## Зачем отдельная заметка

Event Loop браузера и Event Loop Node.js нельзя смешивать в одном ответе. На frontend-собеседовании обычно достаточно браузера, но middle+ вопросы иногда затрагивают Node.js.

## Упрощенная модель фаз

Часто выделяют фазы:

- timers;
- pending callbacks;
- idle/prepare;
- poll;
- check;
- close callbacks.

Обработчики `setTimeout()` выполняются в фазе timers, `setImmediate()` — в check. Обработчики ввода-вывода обычно связаны с poll.

Начиная с libuv 1.45 (Node.js 20), таймеры обрабатываются после poll. Диаграмма фаз не означает, что `setTimeout(0)` всегда выполнится раньше `setImmediate`: важен контекст планирования.

## `process.nextTick()`

`process.nextTick()` не является обычной фазой Event Loop. Его callbacks выполняются после текущей операции до перехода к следующей фазе. Если бесконечно добавлять `nextTick`, можно задержать I/O.

Сравнение с Promise зависит от точки запуска. На верхнем уровне CommonJS сначала выполняется очередь `nextTick`, затем микрозадачи Promise и `queueMicrotask`. Верхний уровень ES-модуля уже исполняется в обработке микрозадач, поэтому порядок другой:

```js
console.log('sync');
process.nextTick(() => console.log('nextTick'));
Promise.resolve().then(() => console.log('promise'));
queueMicrotask(() => console.log('microtask'));
```

Для файла `.cjs`: `sync → nextTick → promise → microtask`. Для `.mjs`: `sync → promise → microtask → nextTick`. Перед ответом о порядке нужно уточнить формат модуля; правило «nextTick всегда раньше Promise» неверно.

Для переносимого откладывания короткой работы обычно подходит `queueMicrotask`. Она также не уступает управление I/O: длинную работу нельзя превращать в бесконечную цепочку микрозадач.

См. [порядок nextTick и queueMicrotask в Node.js](https://nodejs.org/api/process.html#when-to-use-queuemicrotask-vs-processnexttick).

## `setImmediate()`

`setImmediate()` добавляет обработчик в фазу check. Его порядок относительно `setTimeout(..., 0)` зависит от места вызова: например, важно, запланированы ли они внутри обработчика ввода-вывода.

## Backpressure в streams

Backpressure возникает, когда источник данных пишет быстрее, чем получатель успевает обрабатывать. В Node.js streams это решают через механизм потока данных: `write()` может вернуть `false`, а `drain` сообщает, когда можно продолжать. Для цепочек streams часто используют `pipeline()`.

## Частые ошибки

- Переносить браузерную модель tasks/microtasks на Node.js без оговорок.
- Считать `process.nextTick()` обычной microtask.
- Гарантировать один порядок `setTimeout(0)` и `setImmediate()` во всех контекстах.
- Игнорировать backpressure при работе с большими потоками данных.

## Как ответить на собеседовании за одну минуту

В Node.js Event Loop построен вокруг фаз libuv: timers, poll, check и других. `setTimeout()` относится к timers, `setImmediate()` - к check. `process.nextTick()` выполняется до перехода Event Loop к следующей фазе и может задержать I/O, если злоупотреблять им. Node.js Event Loop не нужно смешивать с браузерной моделью отрисовки и очередей задач.
