# Статические, приватные элементы и аксессоры

> [!summary]
> Классы поддерживают элементы уровня класса, приватные поля и accessor properties. Эти возможности полезны, но не меняют базовую прототипную модель.

## Static

```js
class User {
  static role = 'user';

  static createGuest() {
    return new User('Guest');
  }

  constructor(name) {
    this.name = name;
  }
}

console.log(User.role);
console.log(User.createGuest().name);
```

Статические элементы доступны на классе, а не на экземпляре.

## Приватные поля

```js
class Counter {
  #value = 0;

  increment() {
    this.#value += 1;
  }

  getValue() {
    return this.#value;
  }
}
```

`#value` доступен только внутри тела класса. Это не просто соглашение по имени.

## Getters и setters

```js
class User {
  constructor(firstName, lastName) {
    this.firstName = firstName;
    this.lastName = lastName;
  }

  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  }

  set fullName(value) {
    const [firstName, lastName] = value.split(' ');
    this.firstName = firstName;
    this.lastName = lastName;
  }
}
```

Accessor выглядит как свойство, но при чтении или записи вызывает функцию.

## Частые ошибки

- Читать static-метод с экземпляра.
- Думать, что приватное поле можно прочитать через строковый ключ.
- Использовать getter с тяжелыми побочными эффектами.
- Путать приватные поля `#field` и соглашение `_field`.

## Как ответить на собеседовании за одну минуту

`static`-методы и поля принадлежат самому классу, а не экземплярам. Приватные поля с `#` доступны только внутри класса и дают реальную языковую приватность. Getters и setters позволяют обращаться к вычисляемому или контролируемому значению как к свойству, но под капотом вызываются функции.

> [!note]- Углубление: private names
> Приватные элементы классов не являются обычными string-свойствами. Они используют отдельную модель private names, поэтому `obj['#value']` не получает доступ к приватному полю.
