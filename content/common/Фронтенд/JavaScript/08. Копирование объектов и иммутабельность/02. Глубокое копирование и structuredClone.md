# Глубокое копирование и structuredClone

> [!summary]
> Глубокое копирование создает новые объекты для вложенных структур. В браузерах и современных средах выполнения для многих случаев подходит `structuredClone()`.

## Что такое deep copy

```js
const state = {
  user: {
    name: 'Alex',
  },
};

const copy = structuredClone(state);
copy.user.name = 'Mira';

console.log(state.user.name);
```

Результат:

```text
Alex
```

Вложенный объект тоже скопирован.

## JSON-подход

```js
const copy = JSON.parse(JSON.stringify(value));
```

Этот подход прост, но теряет часть данных:

- функции;
- `undefined`;
- `Symbol`;
- `Date` превращается в строку;
- `Map` и `Set` не сохраняются как коллекции;
- циклические ссылки ломают сериализацию.

## `structuredClone()`

`structuredClone()` поддерживает многие встроенные типы лучше JSON-подхода, включая `Date`, `Map`, `Set` и циклические ссылки. Но функции не клонируются.

```js
const original = {
  date: new Date('2026-01-01'),
  tags: new Set(['js']),
};

const copy = structuredClone(original);

console.log(copy.date instanceof Date);
console.log(copy.tags instanceof Set);
```

Результат:

```text
true
true
```

## Когда deep copy не нужен

Для frontend-state чаще нужен не полный deep clone, а иммутабельное обновление только изменяемой ветки.

```js
const nextState = {
  ...state,
  user: {
    ...state.user,
    name: 'Mira',
  },
};
```

Так проще сохранить неизменные части по ссылке.

## Частые ошибки

- Использовать JSON-copy для данных с `Date`, `Map`, `Set` или `undefined`.
- Делать deep clone всего состояния при каждом изменении.
- Ожидать, что `structuredClone()` скопирует функции.
- Клонировать, когда достаточно иммутабельно обновить одну ветку.

## Как ответить на собеседовании за одну минуту

Deep copy создает новые объекты для вложенных структур, поэтому изменение копии не меняет оригинал. JSON-подход прост, но теряет типы и не работает с циклическими ссылками. `structuredClone()` подходит для многих современных случаев и умеет копировать больше встроенных типов, но не функции. Во frontend-state часто лучше не deep clone всего дерева, а создать новые объекты только на пути изменения.
