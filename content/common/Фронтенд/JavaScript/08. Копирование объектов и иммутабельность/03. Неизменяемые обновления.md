# Неизменяемые обновления

> [!summary]
> Иммутабельное обновление не меняет старый объект, а создает новый объект или массив для измененной части данных.

## Зачем это во frontend

Во frontend-приложениях состояние часто сравнивают по ссылке. Если мутировать старый объект, система может не заметить изменение или сложнее будет отлаживать историю состояния.

## Обновление объекта

```js
const user = {
  name: 'Alex',
  age: 30,
};

const nextUser = {
  ...user,
  age: 31,
};
```

`user` не изменился, `nextUser` - новый объект.

## Обновление вложенного объекта

```js
const state = {
  user: {
    profile: {
      name: 'Alex',
    },
  },
};

const nextState = {
  ...state,
  user: {
    ...state.user,
    profile: {
      ...state.user.profile,
      name: 'Mira',
    },
  },
};
```

Новые объекты создаются на пути к изменению. Неизменные ветки можно оставить по ссылке.

## Обновление массива

```js
const items = [
  { id: 1, done: false },
  { id: 2, done: false },
];

const nextItems = items.map((item) =>
  item.id === 2 ? { ...item, done: true } : item
);
```

## `Object.freeze()`

`Object.freeze(obj)` запрещает менять верхний уровень объекта.

```js
const user = Object.freeze({ name: 'Alex' });
user.name = 'Mira'; // ошибка в strict mode или тихое игнорирование в non-strict
```

`Object.freeze()` действует только на сам объект. Его вложенные объекты остаются изменяемыми, пока их не заморозят отдельно.

## Частые ошибки

- Делать shallow copy верхнего уровня, а затем мутировать вложенный объект.
- Использовать мутирующие методы массива в состоянии: `push`, `splice`, `sort`.
- Deep clone всего состояния без причины.
- Думать, что `Object.freeze()` делает глубокую заморозку.

## Как ответить на собеседовании за одну минуту

Иммутабельное обновление значит, что старый объект или массив не меняется. Вместо этого создают новую структуру для измененной части. Для объекта используют spread, для массива - `map`, `filter`, `slice`, spread и другие немутирующие подходы. При вложенности нужно копировать каждый уровень на пути изменения. Это важно во frontend, потому что изменения часто отслеживают через сравнение ссылок.
