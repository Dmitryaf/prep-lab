# ES Modules, export и import

> [!summary]
> ES Modules помогают разбивать код на файлы с явными зависимостями: один файл экспортирует значения, другой импортирует их.

## Зачем нужны модули

- разделять код по ответственности;
- явно показывать зависимости;
- переиспользовать функции и классы;
- помогать сборщикам анализировать неиспользуемый код.

## Named export

```js
// math.js
export const sum = (a, b) => a + b;

export function multiply(a, b) {
  return a * b;
}
```

```js
// app.js
import { sum, multiply } from './math.js';

console.log(sum(2, 3));
console.log(multiply(2, 3));
```

## Переименование

```js
import { sum as add } from './math.js';

console.log(add(2, 3));
```

## Default export

```js
// logger.js
export default function log(message) {
  console.log(message);
}
```

```js
// app.js
import log from './logger.js';

log('ready');
```

Default export удобно использовать, когда у модуля есть одно главное значение. Named exports обычно проще рефакторить и автодополнять.

## Re-export

```js
export { sum, multiply } from './math.js';
export { default as log } from './logger.js';
```

Так часто делают публичный входной файл модуля.

## Частые ошибки

- Импортировать named export как default или наоборот.
- Забывать фигурные скобки для named import.
- Делать слишком большой `index.js`, который скрывает настоящие зависимости.
- Использовать default export там, где модуль экспортирует набор равноправных функций.

## Как ответить на собеседовании за одну минуту

ES Modules дают статическую систему импортов и экспортов. Named export импортируется в фигурных скобках, default export импортируется без них. Экспорты можно переименовывать и реэкспортировать через промежуточный файл. Модули помогают явно описывать зависимости и дают сборщикам основу для tree shaking.
