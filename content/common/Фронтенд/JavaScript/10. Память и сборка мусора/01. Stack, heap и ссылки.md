# Stack, heap и ссылки

> [!summary]
> Stack и heap - полезная учебная модель: Call Stack хранит активные вызовы, а объекты живут отдельно и доступны через ссылки.

## Зачем это frontend-разработчику

Память важна для понимания:

- почему объекты меняются через разные переменные;
- почему замыкание может удерживать данные;
- почему обработчики и таймеры нужно очищать;
- как искать утечки в долгоживущих страницах.

## Практичная модель

Call Stack отвечает за активные вызовы функций. Когда функция вызывается, появляется frame; когда завершается - frame убирается.

Объекты, массивы и функции живут в памяти отдельно, а переменные хранят ссылки на них.

```js
const user = { name: 'Alex' };
const sameUser = user;

sameUser.name = 'Mira';

console.log(user.name);
```

Результат:

```text
Mira
```

## Упрощение

Не стоит выдавать модель "примитивы в stack, объекты в heap" за полное описание движка. Для собеседования полезнее сказать: примитивы ведут себя как значения, объекты доступны через ссылки, а детали размещения зависят от реализации.

## Частые ошибки

- Объяснять все поведение JS только физическим stack/heap.
- Путать Call Stack и heap.
- Забывать, что ссылка на объект может жить дольше функции, которая ее создала.
