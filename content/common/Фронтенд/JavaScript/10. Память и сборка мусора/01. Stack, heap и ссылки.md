# Stack, heap и ссылки

> [!summary]
> Call Stack помогает понять порядок вызовов функций, а ссылки — почему разные переменные могут обращаться к одному объекту.

## Зачем это frontend-разработчику

Память важна для понимания:

- почему объекты меняются через разные переменные;
- почему замыкание может удерживать данные;
- почему обработчики и таймеры нужно очищать;
- как искать утечки в долгоживущих страницах.

## Практичная модель

Call Stack хранит сведения о вызовах функций. При вызове в стек добавляется запись, а при завершении функции эта запись убирается.

Объекты, массивы и функции живут в памяти отдельно, а переменные хранят ссылки на них.

```js
const user = { name: 'Alex' };
const sameUser = user;

sameUser.name = 'Mira';

console.log(user.name);
```

Результат:

```text
Mira
```

## Упрощение

Примитивы передаются как значения, а при передаче объекта копируется ссылка на него. Поэтому `user` и `sameUser` в примере меняют один и тот же объект. Где именно движок хранит значения и ссылки, зависит от его реализации; правило «все примитивы в stack, все объекты в heap» слишком упрощает эту картину.

## Частые ошибки

- Объяснять все поведение JS только физическим stack/heap.
- Путать Call Stack и heap.
- Забывать, что ссылка на объект может жить дольше функции, которая ее создала.
