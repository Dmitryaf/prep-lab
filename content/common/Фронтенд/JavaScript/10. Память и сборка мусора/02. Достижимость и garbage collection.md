# Достижимость и garbage collection

> [!summary]
> Сборщик мусора освобождает память объектов, которые больше недостижимы из корней программы. На практике важно понимать достижимость, сильные и слабые ссылки.

## Достижимость

Объект остаётся в памяти, пока программа может до него добраться. Например, его хранит глобальная переменная, использует выполняющаяся функция или удерживает обработчик активного таймера. Такие связи и определяют достижимость.

```js
let user = { name: 'Alex' };
user = null;
```

Если других ссылок нет, объект может быть собран GC.

## Mark-and-sweep

Упрощенная идея:

1. GC начинает с корней.
2. Помечает все достижимые объекты.
3. Непомеченные объекты считает мусором.
4. Освобождает память позже, когда решит среда выполнения.

Это модель, а не обещание точного времени очистки.

## Сильные и слабые ссылки

Обычная ссылка сильная: она удерживает объект достижимым.

Ключ объекта в `WeakMap` и объект в `WeakSet` удерживаются слабой ссылкой. Если сильных ссылок на объект больше нет, он может быть собран.

```js
const meta = new WeakMap();
let node = {};

meta.set(node, { selected: true });
node = null;
```

Когда объект больше нигде не достижим, запись может исчезнуть.

## Частые ошибки

- Ожидать, что GC выполнится сразу после `obj = null`.
- Думать, что циклическая ссылка сама по себе всегда утечка.
- Пытаться итерировать `WeakMap`.
- Использовать `Map` для metadata объектов, которые должны свободно удаляться.

## Как ответить на собеседовании за одну минуту

Сборщик мусора может освободить объект, до которого программа больше не может добраться. Например, после `user = null` объект доступен для очистки, если других сильных ссылок на него нет. В модели mark-and-sweep сборщик сначала помечает доступные объекты, а затем освобождает остальные. Слабая связь в `WeakMap` или `WeakSet` сама по себе не удерживает объект. Когда именно произойдёт очистка, решает движок.
