# Currying, partial application, memoization и decorators

> [!summary]
> Эти паттерны используют функции и замыкания, чтобы заранее сохранить аргументы, кешировать результат или обернуть поведение.

## Currying

Currying превращает функцию от нескольких аргументов в цепочку функций по одному аргументу.

```js
const add = (a) => (b) => a + b;

console.log(add(2)(3));
```

### Функция curry с известным числом аргументов

Для функции из трёх аргументов разрешим `f(1)(2)(3)`, `f(1, 2)(3)` и `f(1)(2, 3)`. Цепочка завершается, когда собрано `arity` аргументов; пустой вызов ничего не добавляет. В отличие от `sum(...)()`, отдельного сигнала завершения нет. Используем `this` последнего вызова цепочки; при необходимости постоянного получателя сначала вызывай `fn.bind(owner)`. Лишние аргументы отбрасываются по этому контракту.

```js
// checked-example: curry-arity
function curry(fn, arity = fn.length) {
  if (!Number.isInteger(arity) || arity < 0) {
    throw new RangeError('arity must be a non-negative integer');
  }
  const collect = (saved) => function (...args) {
    const all = [...saved, ...args];
    return all.length >= arity
      ? fn.apply(this, all.slice(0, arity))
      : collect(all);
  };
  return collect([]);
}
const add3 = curry((a, b, c) => a + b + c);
const withOne = add3(1);
console.log(withOne(2)(3), withOne(5, 6)); // 6, 12
```

На каждом шаге создаётся новый массив, поэтому две цепочки от `withOne` не меняют аргументы друг друга. Число нужных аргументов задаёт `arity`. Обычно его можно взять из `fn.length`, но rest-параметр и параметры после первого значения по умолчанию туда не входят. В таких случаях передай `arity` явно: по одному rest-параметру нельзя понять, сколько аргументов нужно ждать.

## Partial application

Partial application заранее фиксирует часть аргументов.

```js
const multiply = (a, b) => a * b;
const double = (value) => multiply(2, value);

console.log(double(5));
```

## Memoization

Мемоизация позволяет повторно использовать результат, если аргумент не изменился. В этом примере функция принимает один примитивный аргумент и всегда возвращает для него один и тот же результат: он не зависит от `this`, времени или внешних изменений. Наличие записи проверяет `has`, поэтому результаты `0`, `false` и `undefined` тоже сохраняются в кэше.

```js
function memoize(fn) {
  const cache = new Map();

  return function memoized(value) {
    if (cache.has(value)) {
      return cache.get(value);
    }

    const result = fn(value);
    cache.set(value, result);
    return result;
  };
}
```

## Decorator function

Декоратор возвращает новую функцию, которая вызывает исходную и добавляет к ней поведение. Например, `once` запоминает результат первого вызова без синхронной ошибки, передав ему текущий `this` и аргументы. Следующие вызовы возвращают сохранённый результат. Если функция выбросила ошибку, можно попробовать снова. Если она вернула Promise, сохраняется именно этот Promise — даже если позже он отклонится.

```js
function once(fn) {
  let called = false;
  let result;

  return function wrapped(...args) {
    if (!called) {
      result = fn.apply(this, args);
      called = true;
    }

    return result;
  };
}
```

## Частые ошибки

- Путать currying и partial application.
- Делать memoization без ограничения размера cache.
- Использовать объект как cache для сложных ключей вместо `Map`.
- Писать decorator, который теряет `this` и аргументы.

## Как ответить на собеседовании за одну минуту

Currying разбивает вызов на цепочку функций, partial application фиксирует часть аргументов, memoization кеширует результаты, а decorator возвращает обертку вокруг функции. Все эти паттерны часто опираются на замыкания: внутренняя функция сохраняет доступ к аргументам, cache или флагам.
