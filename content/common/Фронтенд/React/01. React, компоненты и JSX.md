# React, компоненты и JSX

[[Фронтенд/React/00. Карта раздела|Карта React]]

Экран показывает список документов и число непрочитанных. Когда данные меняются, вручную искать DOM-узлы и обновлять каждый счётчик неудобно. Поэтому компонент описывает, что должно быть на экране при текущих данных, а React вызывает его и вносит нужные изменения в DOM.

## От данных к разметке

```jsx
function DocumentList({ documents, onOpen }) {
  const unread = documents.filter(document => !document.read).length;
  return <section>
    <h2>Документы: непрочитанных {unread}</h2>
    {documents.length === 0 ? <p>Документов нет</p> :
      <ul>{documents.map(document => <li key={document.id}>
        <button onClick={() => onOpen(document.id)}>{document.title}</button>
      </li>)}</ul>}
  </section>;
}
```

Для двух документов, один из которых прочитан, заголовок покажет 1, список — две кнопки. Клик передаёт родителю id. Компонент ничего не сохраняет сам: documents и onOpen приходят через props. Условия и обход — обычные выражения JavaScript. После нового массива React вычислит новый результат.

JSX — синтаксис описания элементов, преобразуемый сборщиком. Это не HTML-строка. `{document.title}` отображает строку как текст; `<b>` внутри строки не становится тегом. `dangerouslySetInnerHTML` обходит эту защиту и требует отдельного решения о доверии к HTML.

## Отличия от HTML

Имена собственных компонентов начинаются с заглавной буквы. `className` задаёт CSS-класс, `htmlFor` связывает label с id поля. Теги закрываются; соседние корневые узлы объединяют через Fragment `<>...</>`. Обработчику передают функцию: `onClick={save}`, а `onClick={save()}` вызвал бы save при рендере.

`0 && <p>Есть документы</p>` оставит на экране число 0. Для счётчика пиши `count > 0 && ...`. Если нужно скрыть строку и сохранить её состояние, это другой контракт, чем условно удалить компонент из дерева; см. [[Фронтенд/React/04. Рендер и идентичность|идентичность]].

## Чистота и запуск

Рендер вычисляет JSX. Запрос, подписка или изменение внешнего массива в теле компонента нарушают эту модель: React может повторить или отбросить вычисление. Пользовательское действие выполняется в обработчике, внешняя связь — в эффекте. Массив props нельзя сортировать на месте: используй копию либо `toSorted` в подходящей среде.

В браузерном приложении `createRoot` из `react-dom/client` подключает дерево компонентов к DOM-контейнеру. Стенд запускается через Vite; при использовании SSR подключением приложения управляет фреймворк. Готовый запуск: [[Фронтенд/React/14. Тестирование и практикум|практикум]].

## Проверка себя

Почему запрос нельзя запускать в DocumentList перед return? Что изменится, если вместо функции в onClick сразу вызвать onOpen? Где хранится состояние выбранного документа?

> [!question]- Разбор
>
> React может повторно вызвать компонент, даже если пользователь ничего нового не сделал. Поэтому запрос в теле DocumentList запускался бы при таких вызовах, а `onClick={onOpen()}` открыл бы документ сразу во время рендера. Выбранный документ хранится у родителя или в другом общем источнике: DocumentList только показывает список и сообщает о выборе.
