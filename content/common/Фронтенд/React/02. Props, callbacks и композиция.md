# Props, callbacks и композиция

[[Фронтенд/React/00. Карта раздела|Карта React]]

Редактор имени должен показывать значение, сообщать о вводе и позволять родителю разместить подсказку. Если поле и родитель независимо хранят имя, внешнее изменение документа может оставить на экране старую копию. Сначала выбираем владельца: родитель хранит значение, поле показывает его и сообщает о действиях.

## Контракт компонента

```tsx
// checked-example: react-composition
import { useState, type ReactNode } from 'react';

type NameFieldProps = {
  value: string;
  onValueChange: (value: string) => void;
  children?: ReactNode;
};

export function NameField({ value, onValueChange, children }: NameFieldProps) {
  return <section>
    <label>Имя
      <input value={value} onChange={event => onValueChange(event.target.value)} />
    </label>
    {children}
  </section>;
}

export function NameEditor() {
  const [name, setName] = useState('Анна');
  return <NameField value={name} onValueChange={setName}>
    <p>Привет, {name || 'гость'}!</p>
  </NameField>;
}
```

При вводе «Ирина» поле вызывает callback с новой строкой. Родитель меняет state и передаёт новые props; поле и приветствие показывают «Ирина». Если родитель заменит значение извне, поле тоже обновится: второй копии имени внутри него нет. `onValueChange` — обычный prop-функция; это выбранное нами имя, не специальное событие React.

Props доступны только для чтения. Изменение объекта из props затронуло бы данные владельца без согласованного обновления. Для редактирования либо сообщай о действии, либо создавай отдельный черновик с явными правилами сохранения, отмены и смены документа.

## children и передача разметки

`children` — prop для вложенного содержимого. В примере родитель выбирает приветствие, а поле определяет место вставки. Можно объявить отдельные props `header: ReactNode` и `footer: ReactNode`, если областей несколько. `ReactNode` описывает отображаемое содержимое: элементы, строки, числа, пустые значения и другие допустимые узлы.

Если дочерний компонент должен передать данные обратно в функцию построения разметки, используй render prop:

```tsx
type User = { id: string; name: string };
type UserListProps = {
  users: User[];
  renderItem: (user: User) => ReactNode;
};
function UserList({ users, renderItem }: UserListProps) {
  return <ul>{users.map(user => <li key={user.id}>{renderItem(user)}</li>)}</ul>;
}
// Использование: <UserList users={users} renderItem={user => <b>{user.name}</b>} />
```

Список владеет обходом и ключами, родитель — содержимым строки. Обычный `UserRow` с props проще, если вариативность разметки не нужна. Render prop не является компонентом: Hooks внутри переданной функции вызывать нельзя; при необходимости вынеси компонент.

## Если знаком Vue

Callback prop решает задачу уведомления родителя, для которой во Vue обычно используют emits. `children` и props с JSX позволяют задавать содержимое, render prop — передавать данные в это содержимое. Это сходные задачи, но React не воспроизводит механизм slots или синтаксис `v-model`.

## Проверка себя

Родитель сменил имя с «Анна» на «Олег». Почему `useState(value)` внутри поля не обеспечивает последующую синхронизацию? Где разместить состояние, если имя одновременно показывают поле и заголовок страницы?

> [!question]- Разбор
>
> Начальное значение useState используется при создании состояния; новый prop не переинициализирует его. Убери ненужную копию и передавай value/callback. Для общего значения выбери ближайшего общего владельца. Если нужен независимый черновик, сначала определи, когда его сохранять и сбрасывать.
