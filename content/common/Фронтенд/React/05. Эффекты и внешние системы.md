# Эффекты и внешние системы

[[Фронтенд/React/00. Карта раздела|Карта React]]

Компонент подключается к таймеру или подписке. Эта связь существует вне вычисления JSX: её нужно создать для текущих условий и убрать, когда условия изменились. Effect описывает именно эту синхронизацию.

## Создать ресурс и убрать его

```jsx
import { useEffect, useState } from 'react';

function Timer() {
  const [seconds, setSeconds] = useState(0);
  useEffect(() => {
    const id = setInterval(() => setSeconds(n => n + 1), 1000);
    return () => clearInterval(id);
  }, []);
  return <output>{seconds}</output>;
}
```

При подключении создаётся интервал, а при удалении компонента функция очистки его останавливает. Функциональная форма обновления состояния позволяет вычислять новое значение из актуального предыдущего, не захватывая устаревшее seconds.

Зависимости эффекта описывают использованные реактивные значения, например props и state. При их изменении React сначала выполняет прежнюю функцию очистки, затем повторное подключение. Удаление зависимости ради прекращения повторов может оставить устаревшее значение — исправляй причину, а не отключай проверку.

## Почему эффект сработал дважды

В разработке StrictMode помогает обнаружить отсутствие очистки дополнительным циклом подключения и очистки ресурсов. Правильная реакция — проверить симметрию создания и освобождения ресурса. Флаг «уже выполняли», скрывающий повтор, не исправляет оставшийся слушатель.

## Что не нужно переносить в effect

Полное имя из firstName/lastName вычисляется при рендере. Отправка заказа после клика принадлежит обработчику. Если связать отправку с эффектом «изменился cart», станет неясно, какое действие инициировало запись, и возникнет риск повторной отправки.

```jsx
const fullName = `${firstName} ${lastName}`;
// Лишняя схема: useEffect(() => setFullName(...), [firstName, lastName]).
```

Новый fullName появляется в том же рендере. Отдельный state и effect дали бы сначала старое значение и ещё один цикл обновления. Аналогия с Vue computed относится к задаче производного значения, но не требует useMemo.

## Зависимости и замыкания

React сравнивает элементы dependencies через Object.is. Новый объект или функция в каждом рендере могут перезапускать связь. Если объект нужен только setup, создай его внутри эффекта из примитивных зависимостей. Не удаляй реальные зависимости, чтобы получить «один вызов»: callback может замкнуть устаревшие props/state.

Пустой массив означает отсутствие реактивных зависимостей, а не универсальную гарантию «ровно один запрос». При повторном mount эффект создаётся вновь. Для условного ресурса всегда вызывай hook, а внутри setup делай `if (!enabled) return`; при изменении enabled прежняя очистка всё равно выполнится.

## Свежее значение без новой подписки

В React 19.2+ useEffectEvent отделяет часть логики эффекта, которая должна читать последние применённые значения, от реактивных условий подключения. Например, roomId требует переподключения, а смена темы уведомления — нет. Effect Event не включают в dependencies и не используют как обычный onClick или способ спрятать необходимую зависимость.

Для проекта без этого API остаются пересоздание подписки по зависимости или [[Фронтенд/React/06. Refs и работа с DOM#Подписка со свежим callback|ref после commit]]. Эти способы выбирают по контракту, а не смешивают в одном примере без причины.

## Проверка себя

Подписка зависит от documentId. Что должно произойти при его смене и при удалении компонента? Нужен ли эффект для подсчёта количества выбранных строк?

> [!question]- Разбор
>
> Функция очистки освобождает прежнюю подписку, а повторный запуск эффекта создаёт новую. При удалении компонента освобождается последняя подписка. Количество выбранных строк вычисляют при рендере. Эффект нужен, только если требуется согласовать компонент с внешней системой.
