# Refs и работа с DOM

[[Фронтенд/React/00. Карта раздела|Карта React]]

После открытия редактора нужно поставить фокус в поле. Само поле React описывает через JSX, но focus — команда браузеру. Ref связывает декларативный компонент с созданным DOM-узлом или другим значением, не участвующим в отображении.

## Что хранить в ref

Ref сохраняет значение между рендерами, но изменение `.current` не запрашивает новый рендер. Он подходит для DOM-элемента, идентификатора таймера или текущего callback внешнего слушателя. Видимое состояние формы хранится в state.

Не меняй ref во время рендера ради передачи «последних props»: рендер может не попасть на экран. Обновляй его после commit.

## Когда нужен useLayoutEffect

Обычный useEffect подходит для большинства внешних связей. useLayoutEffect выполняется до перерисовки экрана браузером и может её задержать. Он нужен, например, чтобы измерить подсказку и скорректировать её положение без видимого скачка.

Не запоминай правило «useEffect всегда строго после paint»: порядок зависит от ситуации. Важнее то, что тяжёлая работа в useLayoutEffect блокирует показ кадра. Эффекты не выполняются при серверном рендеринге.

## Подписка со свежим callback

Задача: окно уже слушает resize, родитель передал новую функцию, пересоздавать подписку не нужно. Для обычного браузерного resize можно хранить последнюю применённую функцию в ref:

```jsx
// checked-example: react-resize
import { useEffect, useLayoutEffect, useRef } from 'react';

function useResize(onResize) {
  const latest = useRef(onResize);
  useLayoutEffect(() => {
    latest.current = onResize;
  }, [onResize]);
  useEffect(() => {
    const listener = () => latest.current();
    window.addEventListener('resize', listener);
    return () => window.removeEventListener('resize', listener);
  }, []);
}
```

При изменении callback обновляется ref, а listener остаётся прежним. При unmount удаляется именно установленная функция. Это пример для браузерного компонента; измерять ширину при SSR нельзя.

Для простого компонента пересоздание недорогого слушателя с `[onResize]` часто понятнее. Усложнение ref оправдано условием задачи, а не самим наличием callback.

## Фокус и условный DOM

```jsx
function SearchField() {
  const inputRef = useRef(null);
  return <>
    <label>Поиск<input ref={inputRef} /></label>
    <button onClick={() => inputRef.current?.focus()}>Перейти к поиску</button>
  </>;
}
```

После commit ref.current указывает на input; после удаления узла становится null. Нажатие кнопки переводит фокус, но не меняет видимое значение поля. Если тем же кликом сначала выполнить setOpen(true), нового условного input ещё может не быть в DOM — синхронное чтение ref после setter не решает эту задачу. Фокусируй узел после его подключения через соответствующий effect или callback ref.

В TypeScript используй `useRef<HTMLInputElement>(null)`. Не читай размеры из ref во время рендера. Для стороннего виджета эффект создаёт экземпляр и в функции очистки вызывает его метод destroy; точный контракт зависит от виджета.

## Портал и модальное окно

`createPortal(content, container)` размещает DOM в другом контейнере, сохраняя принадлежность React-дереву: Context и распространение React-событий следуют этому дереву. Это помогает вывести окно из обрезающего контейнера, но само по себе не реализует dialog, удержание/возврат фокуса, Escape и недоступность фона.

React 19 позволяет передавать ref функциональному компоненту как prop; в коде React 18 встречается forwardRef. useImperativeHandle ограничивает доступный родителю интерфейс, например до focus. Предпочитай обычные props, когда imperative API не нужен.

## Проверка себя

Почему ref не подходит для текста счётчика на экране? Как проверить, что после смены callback resize вызывает новую функцию, а после удаления компонента — никого?

> [!question]- Разбор
>
> Изменение current не вызывает render. Для подписки: mount A → resize → rerender B → resize → unmount → resize. Проверяй именно вызванные функции и отсутствие оставшегося эффекта; StrictMode не должен создавать дубликаты активной подписки.
