# Custom hooks

[[Фронтенд/React/00. Карта раздела|Карта React]]

Двум панелям нужен счётчик с одинаковыми правилами. Копировать обработчики неудобно, но общий глобальный счётчик тоже не нужен. Custom hook переиспользует логику, а каждый вызов получает своё состояние.

## От функции к hook

```tsx
import { useState } from 'react';

function useCounter(initial = 0) {
  const [count, setCount] = useState(initial);
  const increment = () => setCount(value => value + 1);
  const reset = () => setCount(initial);
  return { count, increment, reset };
}

function TwoCounters() {
  const left = useCounter();
  const right = useCounter(10);
  return <>
    <button onClick={left.increment}>Левый: {left.count}</button>
    <button onClick={right.increment}>Правый: {right.count}</button>
  </>;
}
```

Клик по левой кнопке меняет 0 на 1; справа остаётся 10. Hook не создаёт отдельный компонент: его state принадлежит вызывающему компоненту. Изменение initial впоследствии не переинициализирует count, но reset из нового рендера использует новое initial — это часть контракта, которую стоит назвать явно.

## Правила Hooks

`useState`, `useEffect` и другие обычные Hooks вызывают на верхнем уровне компонента или custom hook. Нельзя помещать их в условие, цикл, обработчик или после условного раннего return. Стабильный порядок вызовов позволяет React сопоставить состояние между рендерами. Условие подписки располагают внутри эффекта, сохраняя сам вызов hook.

Имя собственного хука начинается с `use` и заглавной буквы дальше. Чистая функция форматирования, не вызывающая Hooks, остаётся обычной функцией. ESLint rules-of-hooks и exhaustive-deps помогают обнаружить нарушения. Разбирай причину предупреждения: порядок вызова Hooks или зависимости эффекта.

У API `use` есть отдельные правила: его разрешено вызывать условно, но это не распространяется на useState/useEffect. Для первого прохода достаточно обычных Hooks; контекст применения use разобран в [[Фронтенд/React/13. Ошибки, Suspense и серверный рендеринг|Suspense]].

## Контракт внешней связи

Для поиска hook получает orgId, строку и загрузчик, возвращает состояние операции и освобождает ресурсы. Важно описать, кто владеет кэшем, что происходит при смене входов и как показывается ошибка. [[Собеседования/Практика/React#Поиск: от списка до гонок запросов|useUserSearch]] показывает полный пример.

Два вызова такого hook не делят результаты автоматически. Для общего кэша нужен отдельный источник. Если hook возвращает функцию, её стабильность нужна только при соответствующем контракте потребителя; useCallback не требуется вокруг каждой функции.

## Если знаком Vue

Composables тоже объединяют логику. Однако React-hook выполняется при каждом рендере, и его замыкания относятся к этому рендеру. Нельзя переносить предположение «setup был вызван однажды» или ставить React Hooks в произвольные ветви.

## Проверка себя

Два компонента вызвали useCounter. Почему значения не общие? Как сделать общее значение без модульной переменной? Почему `if (enabled) useEffect(...)` нарушает правила?

> [!question]- Разбор
>
> Каждый вызов получает отдельное состояние. Подними состояние к общему владельцу и передай props либо Context. Для условной подписки всегда вызывай useEffect, а внутри эффекта проверь enabled и верни функцию очистки созданного ресурса.
