# Запросы и серверное состояние

[[Фронтенд/React/00. Карта раздела|Карта React]]

Пользователь ищет «Ан», затем «Анна». Второй ответ пришёл первым, старый — последним. Если каждый ответ безусловно записывает данные, экран показывает неправильный результат. Компонент должен знать, какой операции принадлежит ответ.

## Запрос: отмена и актуальность

Отмена и запрет устаревшей записи решают разные задачи. AbortController пытается остановить поддерживающую отмену операцию. Проверка актуальности защищает состояние от старых success, catch и finally, даже если загрузчик игнорирует signal.

```jsx
// Фрагмент компонента; load — стабильная функция, query — строка из props/state.
useEffect(() => {
  let active = true;
  const controller = new AbortController();
  setResult({ status: 'loading', data: [], error: null });
  async function run() {
    try {
      const data = await load(query, { signal: controller.signal });
      if (active) setResult({ status: 'success', data, error: null });
    } catch (error) {
      if (active) setResult({ status: 'error', data: [], error });
    }
  }
  void run();
  return () => { active = false; controller.abort(); };
}, [query, load]);
```

Функция эффекта не объявлена async: React должен получить функцию очистки ресурсов, а не Promise. При смене запроса прежняя функция очистки запрещает применять его результат. Этот короткий фрагмент показывает защиту от позднего завершения, но не скрывает старые данные до следующего запуска эффекта. Полный [[Собеседования/Практика/React#Поиск: от списка до гонок запросов|пример поиска]] дополнительно связывает результат с парой orgId/term и скрывает несоответствующий результат уже при рендере. Именно полный пример выполняется в стенде.

## Состояние операции и граница API

Различай idle, loading, success с пустым массивом, success с данными и error. При нескольких boolean легко получить одновременно ошибку, успех и загрузку. Объект с status фиксирует один основной этап; для фонового обновления отдельно договорись о сохранении прежних данных.

fetch не отклоняет Promise только из-за HTTP 404/500: проверь response.ok. TypeScript не проверит JSON — на входе нужна проверка во время выполнения. Сообщение технической ошибки и понятный текст пользователю могут различаться. API в примерах — учебный контракт, действующий сервер не требуется.

## Где заканчивается ручной effect

Для одного примера effect показывает механизм. В приложении запрос может принадлежать loader маршрута или библиотеке серверного состояния. Кэш должен различать данные по всем параметрам: например, `['users', orgId, term]`. Одинаковый term в другой организации не даёт права использовать прежний список.

TanStack Query помогает задавать ключи запросов, кэшировать данные и обновлять их после изменений на сервере. Начни с одного сценария: два потребителя одного ключа → данные устарели → повторная загрузка → смена организации. Настройки `staleTime`, `retry` и `refetch` определяют поведение. В базовом стенде библиотека не нужна: там показан ручной механизм.

## Запись и optimistic update

Пользователь поменял имя. После подтверждения сервером обнови соответствующий кэш или пометь нужные записи кэша как устаревшие. Оптимистичное обновление показывает предполагаемый результат заранее, но требует состояния ожидания и восстановления при ошибке. При параллельных изменениях нельзя безусловно вернуть старый снимок состояния: он может стереть более позднюю успешную правку.

useOptimistic в React 19 помогает представить временное состояние внутри Action; серверный запрос, обработку отказа и источник подтверждённых данных всё равно проектируешь сам. Отмена запроса не доказывает, что сервер не выполнил запись. Для неизвестного результата нужна сверка с сервером и, где применимо, идемпотентность.

## Проверка себя

Ответ B уже показан. Затем A завершился ошибкой. Какие участки кода могут испортить экран? Что меняется при переключении orgId с тем же query?

> [!question]- Разбор
>
> Старые success/catch/finally не имеют права менять текущие данные, ошибку или загрузку. Ключ включает orgId; старый список скрывается до нового эффекта. Контролируемый Promise и загрузчик, игнорирующий signal, позволяют проверить это без случайных задержек.
