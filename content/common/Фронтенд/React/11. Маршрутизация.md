# Маршрутизация

[[Фронтенд/React/00. Карта раздела|Карта React]]

Документ должен открываться по ссылке, сохранять фильтр после обновления страницы и корректно реагировать на Back. Локального state выбранной панели недостаточно: адрес становится источником навигационного состояния.

## Маршрут и вложенный экран

В примере используется React Router 7 в Declarative Mode: маршруты задаются компонентами. Эта ветка поддерживает импорты из react-router-dom. Загрузчики и действия маршрутов относятся к другим режимам, которые разобраны ниже.

```tsx
// checked-example: react-router
import { BrowserRouter, Link, Outlet, Route, Routes, useParams, useSearchParams } from 'react-router-dom';

function Layout() {
  return <><nav><Link to="/documents?q=план">Документы</Link></nav><Outlet /></>;
}
function Documents() {
  const [params, setParams] = useSearchParams();
  const query = params.get('q') ?? '';
  return <>
    <label>Фильтр<input value={query} onChange={event => {
      const next = new URLSearchParams(params);
      if (event.target.value) next.set('q', event.target.value); else next.delete('q');
      setParams(next, { replace: true });
    }} /></label>
    <Link to="/documents/42">Открыть документ 42</Link>
  </>;
}
function Document() {
  const { id } = useParams();
  return <h2>Документ {id}</h2>;
}
export function AppRoutes() {
  return <Routes><Route path="/" element={<Layout />}>
    <Route index element={<p>Выберите документы</p>} />
    <Route path="documents" element={<Documents />} />
    <Route path="documents/:id" element={<Document />} />
    <Route path="*" element={<p>Страница не найдена</p>} />
  </Route></Routes>;
}
export function RouterApp() {
  return <BrowserRouter><AppRoutes /></BrowserRouter>;
}
```

Адрес `/documents?q=план` заполнит поле строкой «план». Ввод изменяет URL с replace, чтобы история не росла на каждую букву. Клик по документу создаёт переход; Back возвращает URL списка. `Outlet` — место вложенного маршрута. Значение id из адреса остаётся недоверенным вводом; формат и права проверяются отдельно.

## Загрузка данных и ошибки

В Data Mode `createBrowserRouter` и RouterProvider соединяют маршрут с loader/action. Loader получает params и Request, чей signal можно передать fetch; экран читает результат через useLoaderData. Это позволяет связать загрузку с переходом и использовать состояние навигации и границу ошибки маршрута. Не добавляй второй effect с тем же запросом без причины.

Framework Mode добавляет соглашения и средства сборки, серверного исполнения и типизации. Declarative Mode из примера не предоставляет те же data APIs только из-за наличия Routes. Выбор режима делается для приложения целиком, а не случайно для одного hook.

При прямом открытии вложенного URL сервер SPA должен возвращать точку входа приложения; это настройка размещения. Маршрут «страница не найдена» в браузере не исправляет серверный 404 до загрузки JavaScript.

## Доступ, черновик и фокус

Перенаправление на login улучшает интерфейс, но защищать данные обязан сервер. При переходе с грязной формы нужны согласованные правила сохранения/отмены и предупреждения; произвольный unmount не сохраняет черновик. После навигации проверь заголовок страницы и перевод фокуса, особенно при управлении клавиатурой.

## Проверка себя

Почему query не стоит копировать в useState без правил синхронизации? Где будет ошибка, если прямой `/documents/42` не открывается, а переход по Link работает?

> [!question]- Разбор
>
> Вторая копия расходится с URL при возврате назад или внешнем переходе. URL должен оставаться источником выбранного фильтра либо иметь явную модель черновика. Ошибка прямого открытия может быть в настройке возврата страницы приложения сервером, а не в сопоставлении маршрута React.
