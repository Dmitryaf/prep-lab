# Производительность

[[Фронтенд/React/00. Карта раздела|Карта React]]

Ввод в поиске задерживается. Причиной может быть дорогой расчёт, повторный рендер большого дерева или работа браузера с DOM. Сначала воспроизводим задержку и измеряем её; выбираем оптимизацию после локализации причины.

## Context и мемоизация

Context передаёт значение потомкам без цепочки props. Например, текущую тему можно читать в разных компонентах. Это способ доставки значения, а не готовый кэш запросов.

Когда значение provider меняется по `Object.is`, потребители этого контекста получают обновление. Поэтому один большой объект с темой, формой и часто меняющимся таймером может вызвать лишнюю работу. Сначала раздели данные по назначению.

| Инструмент | Что сохраняет | Когда помогает |
| --- | --- | --- |
| `memo` | возможность пропустить рендер при тех же props | дорогой дочерний компонент часто получает те же props |
| `useMemo` | результат вычисления | измеримо дорогой расчёт или нужная стабильность ссылки |
| `useCallback` | ссылку на функцию | стабильная ссылка нужна потребителю |

`memo` не блокирует обновление собственного state и используемого Context. Объект или функция, созданные заново, могут нарушить сравнение props. Но сама inline-функция не является ошибкой: сначала измерь, есть ли проблема.

Практический порядок: воспроизвести торможение → посмотреть React Profiler и браузерный Performance → локализовать дорогую работу → изменить одно место → сравнить. Если тормозит layout или огромный DOM, одной мемоизации вычисления недостаточно.

> [!note]- Если попросят подробнее
>
> Мемоизация — оптимизация, а не условие правильности. Не прячь побочные действия в useMemo и не строй логику на вечном сохранении его результата. Наличие React Compiler зависит от настройки проекта: не предполагай автоматическую оптимизацию только по номеру версии React.

## Срочный ввод и дорогой список

```jsx
const [query, setQuery] = useState('');
const deferredQuery = useDeferredValue(query);
const isStale = query !== deferredQuery;
// <input value={query} onChange={e => setQuery(e.target.value)} />
// <section aria-busy={isStale}><SlowList query={deferredQuery} /></section>
// SlowList должен уметь пропустить работу при прежнем query, например через memo.
```

Поле обновляется срочно; дорогой результат может догнать его позже. Старый результат нужно обозначить, если он влияет на решение пользователя. useDeferredValue не задаёт задержку 300 мс и сам по себе не уменьшает число запросов. Debounce управляет частотой запуска работы; deferred value — приоритетом отображения.

useTransition позволяет пометить обновление как несрочное и получить isPending. Нельзя делать обновление управляемого текстового input transition: ввод должен отзываться сразу. Transition не переносит тяжёлый синхронный JavaScript в Worker и не исправляет гонку ответов API.

## Измерения и большие списки

React Profiler показывает работу компонентов; Performance браузера — JavaScript, layout, paint и длинные задачи. Если проблема в тысячах DOM-узлов, проверь виртуализацию или пагинацию. Если тормозит вычисление, уменьшай алгоритмическую работу, мемоизируй при подходящих входах или выноси вычисление в Worker по необходимости.

Сравнивай один сценарий на одинаковых данных и устройстве. Dev StrictMode и диагностические инструменты меняют стоимость; число вызовов компонента не заменяет замер задержки ввода. Общая методика: [[Фронтенд/Инженерные основы/04. Производительность/00. Карта раздела|производительность]].

## React Compiler

Compiler оптимизирует компоненты и значения во время сборки при соответствующей настройке. Он не включается автоматически из-за использования React 19. В стенде этой базы Compiler не подключён. Разбирай ручную мемоизацию как механизм и способ чтения существующего кода; не добавляй её повсеместно и не удаляй вслепую при миграции на Compiler.

## Проверка себя

Почему memo не остановил обновление от Context? Уменьшит ли useDeferredValue число fetch при каждом символе? Как различить дорогой render и layout?

> [!question]- Разбор
>
> Context обновляет своих потребителей. Deferred value не является сетевым debounce. Сопоставь React Profiler с браузерной записью: оптимизация вычисления не лечит дорогую геометрию DOM. Вывод подтверждается повторным измерением того же сценария.
