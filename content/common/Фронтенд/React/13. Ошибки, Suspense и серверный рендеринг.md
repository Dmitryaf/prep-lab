# Ошибки, Suspense и серверный рендеринг

[[Фронтенд/React/00. Карта раздела|Карта React]]

Один виджет упал, другой ещё загружается, а страница уже пришла с сервера. Это разные состояния: ошибка рендера, ожидание ресурса и подключение React к HTML. Для каждого нужен свой механизм.

## Что ловит Error Boundary

Error Boundary позволяет показать запасной интерфейс, если дочерний компонент упал во время рендера. Удобно отделить сбой виджета от всего экрана и отправить диагностическую информацию.

Граница не заменяет обработку обычного отказа fetch и ошибки обработчика клика. Такие ошибки обрабатывают там, где запущено действие, и показывают в состоянии интерфейса. Граница также не ловит собственную ошибку. Полный список ограничений см. в [документации Error Boundary](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary).

## Suspense и lazy

```jsx
import { lazy, Suspense } from 'react';
const Report = lazy(() => import('./Report.js'));
// Report.js должен экспортировать компонент по умолчанию.
function ReportPage() {
  return <Suspense fallback={<p role="status">Загружаем отчёт…</p>}>
    <Report />
  </Suspense>;
}
```

Пока код `Report` не загружен, `Suspense` показывает запасное содержимое. Объявляй `lazy` снаружи компонента, чтобы не создавать новый тип при каждой отрисовке. Ошибку загрузки через `import` обрабатывает `Error Boundary`.

Обычный fetch внутри useEffect не активирует Suspense. Для ожидания данных нужна поддерживающая Suspense интеграция или предусмотренное средой чтение стабильного Promise через use. Не создавай новый fetch-Promise при каждом рендере. Граница определяет, какую часть интерфейса можно временно заменить; слишком широкая граница может спрятать весь экран.

## Гидратация: сервер и первый рендер клиента

Клиент должен начать с разметки, соответствующей серверному HTML. Для расследования mismatch:

1. Найди первый отличающийся узел по сообщению и стеку.
2. Сравни данные и условия рендера на сервере и клиенте.
3. Проверь текущую дату, случайные значения, locale/timezone, чтение browser storage и невалидную вложенность HTML.
4. Передай одинаковые начальные данные; действительно клиентское состояние считай после подключения.
5. Повтори холодную загрузку и переход внутри приложения.

Например, сервер рисует тему по умолчанию, а первый клиентский рендер сразу читает другую из localStorage. Нужно согласовать исходную тему или применить клиентскую после гидратации, учитывая возможный визуальный переход. Подавление предупреждения не исправляет причину.

SSR не означает Server Components: это разные механизмы. Особенности Next.js изучай по целевой вакансии.

## SSR, Server Components и Next.js

SSR формирует HTML для первоначального показа; интерактивная часть затем подключается через гидратацию. Server Components задают другую границу: их код выполняется на сервере или при сборке, а результат передаётся клиентскому дереву. В Server Component нельзя использовать клиентские state/effect Hooks. Клиентские компоненты могут участвовать в серверном формировании HTML, поэтому слово «клиентский» не означает автоматически «HTML появится только после загрузки JavaScript».

`'use client'` обозначает границу модулей в поддерживающей RSC среде. Это не универсальная настройка обычного Vite SPA. `'use server'` относится к Server Functions, а не является способом объявить любой компонент серверным. Границы сериализации props, выполнения и доступа к данным определяет фреймворк.

Next.js изучай отдельным углублением после этой модели: маршруты, источники данных, кэширование, серверные операции и ошибки. Общие CSR/SSR/SSG остаются в инженерных основах, чтобы не дублировать объяснение для Vue и React.

## Проверка себя

Покажет ли Suspense запасное содержимое от fetch в useEffect? Перехватит ли Error Boundary отказ обычного обработчика отправки? Почему localStorage нельзя читать при первом рендере сервера?

> [!question]- Разбор
>
> Effect-fetch не сообщает Suspense об ожидании. Ожидаемую ошибку действия обрабатывает само действие. Сервер не имеет browser storage, а отличающийся первый клиентский результат нарушает согласованность гидратации. Нужны одинаковые исходные данные и явное применение клиентского состояния.
