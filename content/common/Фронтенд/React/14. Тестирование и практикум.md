# Тестирование и практикум

[[Фронтенд/React/00. Карта раздела|Карта React]]

Тест должен отличить работающий интерфейс от похожей реализации с ошибкой. Если старый запрос завершился последним, проверяем имя на экране и состояние загрузки; одного вызова setter или успешной компиляции недостаточно.

## Как тестировать компонент

Проверяй то, что видит и делает пользователь: поле по label, кнопку по роли и имени, результат ввода и ошибки. Для запроса важны pending, success, empty, error и поздний ответ. Для подписки — смена callback и unmount.

Управляемый Promise позволяет завершить A после B без случайных задержек. Таймер debounce удобно проверять управляемыми часами. DOM-тесты подходят для формы и состояния; настоящее положение элементов, pointer capture и производительность проверяют в браузере.

При ручных вызовах, вызывающих обновления React, нужно дождаться применения изменений; тестовые библиотеки часто оборачивают взаимодействия в `act`. Само наличие act не делает проверку правильной: утверждение должно наблюдать результат. См. [React act](https://react.dev/reference/react/act).

## Запуск стенда

[Скачай самостоятельный React-стенд](/labs/react-behavior.zip), распакуй ZIP и открой терминал в папке `react-behavior`. Нужен Node.js 22.22.3+ или 24.15+; первая установка требует доступа к npm.

```sh
npm ci --ignore-scripts
npm test
npm run typecheck
npm run build
npm run dev
```

Последняя команда запускает локальную страницу; открой адрес, который напечатает Vite. Сервер слушает только 127.0.0.1. Сетевого API нет: ответы поиска и ошибки управляются вручную на странице. Загрузчик специально игнорирует AbortSignal, чтобы проверить защиту от устаревших данных независимо от отмены.

Версии закреплены в package.json и lockfile: React/React DOM 19.3.1, React Router 7.18.4, TypeScript 5.9.3, Vitest 4.1.11. Router-пример использует Declarative Mode; в тестах его оборачивает MemoryRouter. Compiler, Next.js, RSC-сервер и библиотеки кэша в стенд не подключены.

## Что проверяется

| Сценарий | Наблюдение | Где смотреть |
| --- | --- | --- |
| Поле и children | Ввод меняет приветствие, внешний value обновляет поле | `tests/composition.test.tsx` |
| Поиск | Старые success/reject не меняют новый результат или pending | `tests/behavior.test.tsx` |
| Смена организации и пустой ввод | Прежние пользователи скрываются, ненужная работа отменяется | `tests/behavior.test.tsx` |
| Форма | Ошибка сохраняет ввод, повтор возможен, пустое имя не отправляется | `tests/behavior.test.tsx` |
| Перестановка | Черновик остаётся у своего id | `src/DraftRows.tsx`, тест поведения |
| Подписка | Новый callback используется без новой подписки, unmount освобождает ресурс | `tests/behavior.test.tsx` |
| URL | Входной query заполняет поле, Back восстанавливает изменённый фильтр | `tests/behavior.test.tsx` |

Исходники в `src/examples` входят в архив вместе с тестами и не требуют внешних заметок. Тесты и страница используют одни компоненты. Сначала сформулируй контракт и попробуй реализовать его в собственной копии, затем сравни с поставляемым решением. README описывает ручные сценарии и контрольную поломку защиты от поздних ответов.

## Как прочитать один тест

В тесте гонки сначала создаются два управляемых Promise. После смены входа B завершается первым: проверяется B в DOM. Затем завершается A: проверяется, что B остался. Отдельный тест отклоняет A, пока B ещё pending; так обнаруживается старый catch/finally, который выключает загрузку.

Не заменяй это ожиданием случайных 500 мс. Виртуальное время нужно для debounce, а управляемые Promise — для порядка ответов. Используй запросы по label/role, чтобы тесты читались как действия пользователя. Проверка вызова onSelect уместна для выходного контракта компонента, но не заменяет проверку видимого результата загрузки.

## Границы проверки

Vitest монтирует компоненты в jsdom, а не в настоящем браузерном движке. Это проверяет React-переходы и DOM-состояние, но не геометрию, pointer capture, визуальные скачки и производительность. Drag остаётся отдельным браузерным сценарием существующей карточки; его геометрия дополнительно проверяется общим скриптом примеров.

На странице стенда вручную проверь Tab/Enter, видимость фокуса, длинный ввод, ошибку формы и обратный порядок ответов. Для resize используй кнопку вызова события либо изменение размера окна; после отключения новые вызовы не должны добавляться. SSR/RSC и Actions здесь объясняются, но не являются проверенными интеграциями стенда. Успех готового теста также не подтверждает самостоятельное освоение темы.
