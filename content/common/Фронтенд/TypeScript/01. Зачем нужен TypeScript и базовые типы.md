# Зачем нужен TypeScript и базовые типы

> [!summary]
> TypeScript находит несовместимые значения до запуска программы. Он помогает описать, что принимает функция и что возвращает. Реальный ответ сервера всё равно нужно проверять во время выполнения.

## Зачем понимать тему

На middle-собеседовании TypeScript обычно проверяют не вопросом "какой синтаксис у массива", а через ситуации: почему тип не защищает от плохого ответа API, когда нужна аннотация, чем опасен `any`, почему `strictNullChecks` меняет качество кода.

## Базовая модель

TypeScript проверяет код до выполнения программы:

```text
ts-код -> type checking -> js-код -> runtime в браузере/Node.js
```

Типы помогают редактору и компилятору проверить предположения о коде. После компиляции обычные аннотации типов, `interface`, `type`, `Pick`, `Omit` и похожие конструкции стираются: JavaScript не получает из них объекты или автоматические проверки.

Если код упадет из-за `JSON.parse`, плохого ответа сервера или `undefined`, TypeScript предотвратит это только тогда, когда ты правильно описал и проверил границу данных.

## Type inference и annotations

Inference - это вывод типа из контекста.

```ts
const userName = 'Ada'; // литеральный тип 'Ada'
let editableName = 'Ada'; // string: переменную можно изменить
const roles = ['admin', 'editor']; // string[]

function sum(a: number, b: number) {
  return a + b; // number
}
```

Аннотации нужны там, где TypeScript не знает контракт или где ты хочешь зафиксировать публичное обещание:

```ts
type User = {
  id: string;
  name: string;
};

async function loadUser(id: string): Promise<User> {
  const response = await fetch(`/api/users/${id}`);
  return response.json() as Promise<User>;
}
```

> [!important]
> Последний пример описывает ожидаемый контракт, но не валидирует JSON. Для внешних данных смотри [[Фронтенд/TypeScript/07. API, unknown и проверка данных|API, unknown и проверка данных]].

## Базовые типы

```ts
const title: string = 'Profile';
const retryCount: number = 3;
const isLoading: boolean = false;
const empty: null = null;
let missing: undefined = undefined;
```

Для массивов чаще используют `T[]`, для generic-стиля - `Array<T>`:

```ts
const ids: string[] = ['u1', 'u2'];
const matrix: Array<number[]> = [[1, 2], [3, 4]];
```

Tuple фиксирует длину и типы позиций:

```ts
const point: [number, number] = [10, 20];
const result: [status: 'ok' | 'error', message: string] = ['ok', 'Saved'];
```

Object shape описывает свойства:

```ts
type Product = {
  id: string;
  title: string;
  price: number;
  discount?: number;
};
```

`discount?: number` означает, что свойства может не быть. При чтении TypeScript заставит учитывать `undefined`.

## Literal types

Литеральный тип ограничивает значение конкретной строкой, числом или boolean:

```ts
type ButtonVariant = 'primary' | 'secondary' | 'danger';

function renderButton(variant: ButtonVariant) {}

renderButton('primary');
renderButton('warning'); // error
```

Это лучше `string`, когда набор значений заранее известен.

## `any`, `unknown` и `never`

`any` отключает проверку:

```ts
function parse(data: any) {
  return data.user.profile.name.toUpperCase();
}
```

`unknown` заставляет проверить значение:

```ts
function parseName(data: unknown): string | null {
  if (
    typeof data === 'object' &&
    data !== null &&
    'name' in data &&
    typeof data.name === 'string'
  ) {
    return data.name;
  }

  return null;
}
```

`never` означает значение, которого не должно существовать: функция всегда бросает ошибку, бесконечный цикл или исчерпанный union.

```ts
function fail(message: string): never {
  throw new Error(message);
}
```

## Частые ошибки

- Думать, что TypeScript проверит ответ сервера сам.
- Ставить `any`, чтобы "быстрее починить", и терять пользу типизации дальше по цепочке.
- Аннотировать каждую локальную переменную, хотя inference уже дает точный тип.
- Использовать `String`, `Number`, `Boolean` вместо `string`, `number`, `boolean`.
- Забывать, что optional property при чтении может быть `undefined`.

## Как ответить на собеседовании за одну минуту

TypeScript добавляет статическую типизацию к JavaScript: проверяет код до запуска и помогает описывать функции, объекты, модули и API. Во время работы программы эта система типов уже не выполняется, поэтому данные извне нужно проверять отдельно. Обычно компилятор сам выводит типы локальных значений, а типы публичных границ полезно указывать явно. Вместо `any` для неизвестных данных используют `unknown` и уточняют тип реальными проверками.
