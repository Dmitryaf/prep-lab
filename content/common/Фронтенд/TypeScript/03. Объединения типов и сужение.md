# Объединения типов и сужение

> [!summary]
> Значение может быть одним из нескольких вариантов: например, успешным ответом или ошибкой. Сначала проверяем, какой вариант получили, затем используем доступные в нём поля. TypeScript отслеживает эту проверку.

## Базовая модель

Если тип `string | number`, TypeScript разрешит только операции, которые безопасны для обоих вариантов. Чтобы вызвать строковый метод, нужно сузить тип:

```ts
function formatId(id: string | number): string {
  if (typeof id === 'string') {
    return id.toUpperCase();
  }

  return id.toFixed(0);
}
```

## Основные способы narrowing

```ts
if (typeof value === 'string') {}
if (value instanceof Error) {}
if ('email' in user) {}
if (status === 'success') {}
```

User-defined type predicate:

```ts
type User = {
  id: string;
  name: string;
};

function isUser(value: unknown): value is User {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value && typeof value.id === 'string' &&
    'name' in value && typeof value.name === 'string'
  );
}
```

`value is User` — обещание компилятору. Оно не доказывает правильность самой проверки: наличие ключей ещё не гарантирует типы полей.

```ts
isUser({ id: '1', name: 'Анна' }); // true
isUser({ id: 42, name: null }); // false
isUser(null); // false
```

## Discriminated union

Лучший паттерн для UI-состояний и ответов API - общий discriminant:

```ts
type LoadState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: string };

function renderUsers(state: LoadState<string[]>): string {
  switch (state.status) {
    case 'idle':
      return 'No request yet';
    case 'loading':
      return 'Loading';
    case 'success':
      return state.data.join(', ');
    case 'error':
      return state.error;
  }
}
```

## Exhaustiveness checking через `never`

```ts
function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${String(value)}`);
}

function renderState(state: LoadState<string[]>): string {
  switch (state.status) {
    case 'idle':
      return 'Idle';
    case 'loading':
      return 'Loading';
    case 'success':
      return state.data.join(', ');
    case 'error':
      return state.error;
    default:
      return assertNever(state);
  }
}
```

Если добавить новый статус и забыть обработать его, TypeScript подсветит ошибку в `assertNever`.

## Intersection types

Intersection `&` означает "значение должно удовлетворять всем частям":

```ts
type User = { id: string; name: string };
type WithPermissions = { permissions: string[] };

type Admin = User & WithPermissions;
```

Для объектных shape это удобно. Для несовместимых primitive literals можно случайно получить `never`.

## Частые ошибки

- Пытаться пользоваться полем union-варианта до проверки.
- Делать discriminant необязательным.
- Использовать `as` вместо нормального narrowing.
- Писать type guard, который проверяет не все поля, но обещает TypeScript полную модель.
- Забывать exhaustiveness в `switch`.

## Как ответить на собеседовании за одну минуту

Union говорит, что значение может быть одним из вариантов. TypeScript разрешает только общие безопасные операции, поэтому нужен narrowing через `typeof`, `in`, `instanceof`, сравнение literal-поля или type predicate. Для сложных состояний я использую discriminated union с общим полем вроде `status` или `type`, а исчерпываемость проверяю через `never`.
