# Объединения типов и сужение

> [!summary]
> Значение может быть одним из нескольких вариантов: например, успешным ответом или ошибкой. Сначала проверяем, какой вариант получили, затем используем доступные в нём поля. TypeScript отслеживает эту проверку.

## Базовая модель

Если тип `string | number`, TypeScript разрешит только операции, которые безопасны для обоих вариантов. Чтобы вызвать строковый метод, нужно сузить тип:

```ts
function formatId(id: string | number): string {
  if (typeof id === 'string') {
    return id.toUpperCase();
  }

  return id.toFixed(0);
}
```

## Основные способы сужения типа

**ID вопроса:** Основные способы narrowing

```ts
if (typeof value === 'string') {}
if (value instanceof Error) {}
if ('email' in user) {}
if (status === 'success') {}
```

Функция проверки типа с результатом `value is User`:

```ts
type User = {
  id: string;
  name: string;
};

function isUser(value: unknown): value is User {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value && typeof value.id === 'string' &&
    'name' in value && typeof value.name === 'string'
  );
}
```

`value is User` — обещание компилятору. Оно не доказывает правильность самой проверки: наличие ключей ещё не гарантирует типы полей.

```ts
isUser({ id: '1', name: 'Анна' }); // true
isUser({ id: 42, name: null }); // false
isUser(null); // false
```

## Варианты с общим отличительным полем

**ID вопроса:** Discriminated union

Для состояний интерфейса и ответов API удобно задать общее поле, значение которого отличает один вариант от другого:

```ts
type LoadState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: string };

function renderUsers(state: LoadState<string[]>): string {
  switch (state.status) {
    case 'idle':
      return 'No request yet';
    case 'loading':
      return 'Loading';
    case 'success':
      return state.data.join(', ');
    case 'error':
      return state.error;
  }
}
```

## Проверка всех вариантов через `never`

**ID вопроса:** Exhaustiveness checking через `never`

```ts
function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${String(value)}`);
}

function renderState(state: LoadState<string[]>): string {
  switch (state.status) {
    case 'idle':
      return 'Idle';
    case 'loading':
      return 'Loading';
    case 'success':
      return state.data.join(', ');
    case 'error':
      return state.error;
    default:
      return assertNever(state);
  }
}
```

Если добавить новый статус и забыть обработать его, TypeScript подсветит ошибку в `assertNever`.

## Пересечение типов

**ID вопроса:** Intersection types

Пересечение `&` означает, что значение должно соответствовать всем перечисленным типам:

```ts
type User = { id: string; name: string };
type WithPermissions = { permissions: string[] };

type Admin = User & WithPermissions;
```

Пересечение удобно для объединения свойств объектных типов. Пересечение несовместимых конкретных значений, например разных строк, даёт `never`.

## Частые ошибки

- Читать поле одного варианта объединения до проверки типа.
- Делать общее отличительное поле необязательным.
- Использовать `as` вместо проверки и сужения типа.
- Объявлять результат функции как `value is User`, не проверив все нужные поля.
- Забывать проверить все варианты в `switch`.

## Как ответить на собеседовании за одну минуту

Объединение типов означает, что значение может быть одним из нескольких вариантов. Чтобы использовать поля конкретного варианта, я сначала проверяю тип или значение: через `typeof`, `in`, `instanceof` либо отдельную функцию проверки. Для состояний интерфейса удобно общее поле, например `status`: по его значению TypeScript определяет, какие поля доступны. С помощью `never` можно проверить, что в `switch` обработаны все варианты.

## Практические задачи

1. Сделай `LoadState<T>` для загрузки списка товаров.
2. Напиши функцию отображения с `switch` и `assertNever`.
3. Исправь функцию, где `value as User` используется без проверки.
