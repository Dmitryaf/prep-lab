# Обобщённые типы и ограничения

> [!summary]
> Generics сохраняют связь между входом и выходом: из массива пользователей функция возвращает пользователя, из массива чисел — число. Это одна реализация с точным типом для каждого вызова.
> Это «==переменная для типа данных==». Вместо того чтобы жестко указывать конкретный тип (`string`, `number`), вы создаете шаблон с буквой (обычно `<T>`). Этот шаблон подставляет нужный тип в момент, когда вы вызываете функцию или создаете объект

## Базовая модель

Без generic легко потерять информацию:

```ts
function first(items: unknown[]) {
  return items[0];
}
```

С generic TypeScript связывает элемент массива с результатом:

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}

const name = first(['Ada', 'Linus']); // string | undefined
```

## Generic constraints

Constraint ограничивает допустимые типы:

```ts
function getId<T extends { id: string }>(entity: T): string {
  return entity.id;
}
```

`T` сохраняет весь тип объекта, а constraint гарантирует наличие `id`.

## Generic helper

```ts
function groupBy<T, K>(
  items: T[],
  getKey: (item: T) => K,
): Map<K, T[]> {
  const groups = new Map<K, T[]>();
  for (const item of items) {
    const key = getKey(item);
    const group = groups.get(key);
    if (group) group.push(item);
    else groups.set(key, [item]);
  }
  return groups;
}
```

`T` связывает массив и элементы групп; `K` связывает функцию выбора ключа и ключи результата. `Map` принимает и строки вроде `__proto__` без столкновения со свойствами прототипа обычного объекта.

```ts
const groups = groupBy(['toString', '__proto__', 'toString'], (word) => word);
groups.get('toString'); // ['toString', 'toString']
groups.get('missing'); // undefined
```

Не обещаем `Record<K, T[]>`: вход может не содержать ни одного элемента для конкретного ключа. Даже при известном наборе ключей отсутствие группы нужно учитывать.

## Defaults

```ts
type ApiResponse<TData, TMeta = unknown> = {
  data: TData;
  meta: TMeta;
};
```

Default полезен, когда второй тип часто не важен, но лучше не ставить `any` по умолчанию без причины.

## Частые ошибки

- Делать generic там, где подойдет обычный тип.
- Писать `<T extends any>`: это почти всегда шум.
- Терять связь типов через `unknown` или `any`.
- Слишком усложнять helper, когда проще принять явно типизированную функцию.
- Считать параметр обобщённого типа значением, переданным функции во время выполнения. После компиляции этого параметра типа в JavaScript нет.

## Как ответить на собеседовании за одну минуту

Generics позволяют описать функцию, тип или компонент так, чтобы сохранить связь между входом и выходом. Например, `first<T>(items: T[]): T | undefined` возвращает элемент того же типа, что лежит в массиве. Constraints через `extends` задают минимальные требования к `T`, например наличие `id`, но не стирают остальные поля.
