# Вспомогательные типы и операторы типов

> [!summary]
> Вспомогательные типы (utility types) и операции над типами позволяют строить новый тип из существующего, не копируя структуру вручную.

## Зачем это нужно

Есть полная модель пользователя, но карточке нужны только id и имя, а форме редактирования — необязательные поля. Если переписать все типы вручную, они начнут расходиться. Utility types позволяют выразить правило: «возьми эти поля» или «сделай поля необязательными».

Сначала разберись с `keyof` и `T[K]`, затем с Pick/Partial. Mapped и conditional types в конце объясняют, как такие преобразования устроены внутри.

## `keyof`

`keyof T` получает union ключей:

```ts
type User = {
  id: string;
  name: string;
  role: 'admin' | 'user';
};

type UserKey = keyof User; // 'id' | 'name' | 'role'
```

## Indexed access

`T[K]` получает тип свойства:

```ts
type UserRole = User['role']; // 'admin' | 'user'
type UserValue = User[keyof User]; // string: строковые литералы уже входят в string
```

## `typeof` в типах

`typeof` в type position берет тип значения:

```ts
const routes = {
  home: '/',
  profile: '/profile',
} as const;

type RouteName = keyof typeof routes; // 'home' | 'profile'
type RoutePath = typeof routes[RouteName]; // '/' | '/profile'
```

## `as const`

`as const` делает литералы максимально узкими и readonly:

```ts
const statuses = ['idle', 'loading', 'success', 'error'] as const;
type Status = typeof statuses[number];
```

## `satisfies`

`satisfies` проверяет соответствие типу, сохраняя выведенный тип выражения вместо замены его аннотацией. Насколько он узкий, зависит от выражения и контекста:

```ts
const labels = {
  idle: 'No request',
  loading: 'Loading',
  success: 'Loaded',
  error: 'Failed',
} satisfies Record<Status, string>;
```

Если забыть ключ, TypeScript покажет ошибку. Здесь `labels.idle` имеет тип `string`, а не литерал `'No request'`: свойства изменяемого объекта расширяются до строкового типа. `satisfies` проверяет соответствие, но не заменяет `as const`.

```ts
const exactLabels = {
  idle: 'No request',
  loading: 'Loading',
  success: 'Loaded',
  error: 'Failed',
} as const satisfies Record<Status, string>;
// exactLabels.idle: 'No request'; свойства readonly на уровне типов
```

Utility types и `readonly` работают при проверке типов. Они не проверяют JSON и не замораживают объекты во время выполнения.

## Основные utility types

### `Partial<T>`

Делает все свойства типа необязательными.

```ts
type UserPatch = Partial<User>;
```

Где встречается: update-формы, PATCH-запросы, частичные настройки.

### `Required<T>`

Делает все свойства обязательными.

```ts
type DraftUser = {
  id?: string;
  name?: string;
};

type CompleteUser = Required<DraftUser>;
```

Где встречается: нормализация черновика в модель, проверка полноты объекта после валидации.

### `Pick<T, K>`

Оставляет только выбранные ключи.

```ts
type UserPreview = Pick<User, 'id' | 'name'>;
```

Где встречается: карточки, списки, DTO для короткого представления.

### `Omit<T, K>`

Исключает выбранные ключи.

```ts
type UserWithoutRole = Omit<User, 'role'>;
```

Где встречается: формы создания без server-generated полей, публичные модели без служебных данных.

### `Record<K, T>`

Описывает объект-словарь: ключи `K`, значения `T`.

```ts
type UsersById = Record<string, User>;
type StatusLabels = Record<Status, string>;
```

Где встречается: мапы по id, словари переводов, конфиги по набору статусов.

### `Readonly<T>`

Делает свойства readonly на уровне типов.

```ts
type ReadonlyUser = Readonly<User>;
```

Это не глубокая защита от изменений во время выполнения: объект всё ещё обычный JavaScript-объект.

### `ReturnType<T>`

Берет тип возвращаемого значения функции.

```ts
function createUser() {
  return { id: 'u1', name: 'Ada' };
}

type CreatedUser = ReturnType<typeof createUser>;
```

Где встречается: тип результата factory/helper-функции без ручного дублирования.

### `Parameters<T>`

Берет tuple типов параметров функции.

```ts
type Handler = (id: string, force?: boolean) => Promise<User>;
type HandlerArgs = Parameters<Handler>; // [id: string, force?: boolean]
```

Где встречается: wrappers, decorators, proxy-функции, проброс аргументов.

### `Awaited<T>`

Достает resolved value из Promise-like типа.

```ts
type HandlerResult = ReturnType<Handler>; // Promise<User>
type LoadedUser = Awaited<HandlerResult>; // User
```

Где встречается: async helpers, типизация результатов загрузки, тестовые утилиты.

## Mapped и conditional types

Mapped type перебирает ключи:

```ts
type Nullable<T> = {
  [K in keyof T]: T[K] | null;
};
```

Conditional type выбирает тип по условию:

```ts
type UnwrapPromise<T> = T extends Promise<infer Value> ? Value : T;
```

Читай `[K in keyof T]: T[K] | null` так: «для каждого ключа оставь прежний тип значения и разреши null». А `infer Value` в следующем примере означает «выведи, какое значение находится внутри Promise».

Например, `UnwrapPromise<Promise<number>>` даёт number, `UnwrapPromise<string>` оставляет string. Это один уровень извлечения. Практика с проверкой ошибочных вариантов: [[Собеседования/Практика/TypeScript#Построить utility type по шагам|utility types]] и [[Собеседования/Практика/TypeScript#Ключи по строковому шаблону|строковые шаблоны]].

> [!note]- Углубление: distributive conditional types
> Conditional type распределяется по union, если слева стоит "голый" type parameter: `T extends U ? X : Y`. Это полезно для `Exclude`/`Extract`, но может неожиданно усложнить результат. Для P0 достаточно понимать эффект распределения и уметь распознать его в utility type.

## Частые ошибки

- Дублировать `UserPreview` вручную вместо `Pick<User, ...>`.
- Использовать `as const`, когда потом объект должен свободно изменяться.
- Путать оператор для значения `typeof value` и оператор на уровне типа `typeof value`.
- Применять `ReturnType` к перегруженным функциям, не понимая выбранную сигнатуру.
- Делать глубоко рекурсивные вспомогательные типы в P0-коде без реальной необходимости.

## Как ответить на собеседовании за одну минуту

`keyof` получает ключи типа, `T[K]` — тип свойства, `typeof` в типах — тип существующего значения. `Pick`, `Omit`, `Partial` и другие вспомогательные типы собирают производную модель. `as const` сохраняет литеральные значения и задаёт `readonly`, а `satisfies` проверяет соответствие, не заменяя выведенный тип аннотацией. Проверку JSON эти операции не выполняют.
