# Vue 3, SFC и script setup

> [!summary]
> Vue связывает данные с интерфейсом: компонент описывает, что показать, а Vue обновляет DOM при изменении использованных данных. SFC объединяет шаблон, логику и стили одного компонента; script setup упрощает запись его логики.

## Зачем нужен Vue

Vue берет на себя связку:

```text
state -> template/render -> DOM update
```

Разработчик описывает состояние, шаблон и реакции на события, а Vue синхронизирует UI с данными.

## Component-based UI

Компонент объединяет всё, что относится к одной части интерфейса, например к карточке пользователя:

- входные данные через props;
- локальное состояние;
- события наружу;
- шаблон;
- стили;
- переиспользуемую логику через composables.

## SFC

Однофайловый компонент Vue (SFC) обычно состоит из трех частей:

```vue
<script setup lang="ts">
import { ref } from 'vue';

const count = ref(0);
</script>

<template>
  <button @click="count += 1">{{ count }}</button>
</template>

<style scoped>
button {
  padding: 8px 12px;
}
</style>
```

В шаблоне Vue сам читает значение ref, поэтому здесь достаточно `count`. В JavaScript для обращения к этому значению нужен `count.value`.

## `<script setup>`

`<script setup>` позволяет короче записать код компонента на Composition API. Переменные верхнего уровня сразу доступны в шаблоне. defineProps и defineEmits можно использовать без импорта: их обрабатывает компилятор Vue при сборке.

```vue
<script setup lang="ts">
type Props = {
  title: string;
};

defineProps<Props>();
</script>

<template>
  <h1>{{ title }}</h1>
</template>
```

## Options API

Options API поддерживается в Vue 3 и подходит для компонентов, где удобно группировать код по опциям:

```js
export default {
  data() {
    return { count: 0 };
  },
  computed: {
    double() {
      return this.count * 2;
    },
  },
};
```

Options API группирует код по опциям, Composition API — по связанной логике. Composition API особенно удобен при выделении composables и работе с TypeScript; переход на Vue 3 не требует переписывать исправный Options API.

## Частые ошибки

- Объяснять Vue как "магический DOM". Лучше говорить про реактивное состояние и render/update.
- Считать, что Composition API нужен только для больших проектов.
- Путать `<script setup>` с отдельной возможностью среды выполнения: этот синтаксис обрабатывает компилятор.
- Писать business logic прямо в template.
- Дублировать DOM/Event Loop объяснения вместо ссылок на JS/Browser API.

## Как ответить на собеседовании за одну минуту

Vue помогает строить интерфейс из компонентов. В компоненте я описываю данные, разметку и обработчики действий. Когда используемые данные меняются, Vue обновляет соответствующий DOM.

В SFC шаблон, логика и стили лежат в одном файле. Composition API позволяет группировать связанную логику и выносить её в composables, а script setup сокращает запись. Options API тоже поддерживается: исправный компонент на нём не нужно переписывать только ради Vue 3.
