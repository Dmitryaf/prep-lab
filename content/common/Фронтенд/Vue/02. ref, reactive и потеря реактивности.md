# ref, reactive и потеря реактивности

> [!summary]
> Vue запоминает, какие данные читает интерфейс, и обновляет его при изменении этих данных. `ref` хранит значение в `.value`; `reactive` позволяет отслеживать свойства объекта. Главное — не потерять связь при копировании значения или замене объекта.

## Базовая модель

Когда компонент рендерится, Vue запоминает, какие реактивные значения были прочитаны. Когда эти значения меняются, Vue планирует обновление компонента.

```text
read reactive value -> track dependency
write reactive value -> trigger update
```

## Как Proxy участвует в реактивности

`Proxy` перехватывает операции над объектом. Vue использует обработчик `get`, чтобы заметить чтение свойства, а `set` — чтобы узнать о его изменении. При чтении во время работы шаблона, `computed` или наблюдения Vue сохраняет зависимость от конкретного объекта и свойства. Позднее изменение этого свойства уведомляет зависимые вычисления. Изменения DOM планируются в очереди Vue.

Proxy перехватывает обращения к объекту, а Vue хранит зависимости и запускает обновления компонентов. `Reflect.get` и `Reflect.set` выполняют обычное чтение и запись внутри перехватчиков.

```ts
import { reactive, watchEffect } from 'vue';

const original = { count: 0 };
const state = reactive(original);

watchEffect(() => {
  console.log(state.count);
});

state.count += 1; // изменение через прокси запускает зависимое наблюдение
console.log(state === original); // false
```

Первый запуск наблюдения читает `state.count`, поэтому Vue запоминает зависимость. Запись через `state` уведомляет это наблюдение. Прямая запись `original.count` обходит прокси и сама не запускает обновление. Для реактивной работы используй `state`.

Подробнее о самих перехватчиках: [[Фронтенд/JavaScript/12. Proxy и Reflect/01. Proxy traps и Reflect|Proxy и Reflect]].

## `ref`

`ref` подходит для примитивных значений и состояния, которое заменяется целиком:

```ts
import { ref } from 'vue';

const count = ref(0);
count.value += 1;
```

В шаблоне `.value` не нужен:

```vue
<button>{{ count }}</button>
```

## `reactive`

`reactive` подходит для объектного состояния:

```ts
import { reactive } from 'vue';

const form = reactive({
  name: '',
  email: '',
});

form.name = 'Ada';
```

## Как выбрать между ref и reactive

**ID вопроса:** ref vs reactive

| Ситуация | Чаще выбрать |
|---|---|
| примитивное значение | `ref` |
| значение нужно полностью заменить | `ref` |
| объект формы с несколькими полями | `reactive` или набор `ref`, по стилю |
| возвращать состояние из композиционной функции | часто объект из `ref` |
| деструктурировать свойства | `toRef`/`toRefs` или отдельные `ref` |

## Потеря реактивности

При деструктуризации примитивного свойства `reactive` получается текущее значение, а не связь с исходным свойством:

```ts
const state = reactive({ count: 0 });
const { count } = state;

state.count += 1;
console.log(count); // старое значение
```

Исправление:

```ts
import { toRefs } from 'vue';

const state = reactive({ count: 0 });
const { count } = toRefs(state);
```

Если деструктурировано вложенное объектное значение, оно может остаться реактивным прокси. Но замена этого свойства в исходном объекте не заменит уже полученную локальную ссылку.

Отдельный случай — `const { foo } = defineProps(...)` в `<script setup>` Vue 3.5+: компилятор поддерживает реактивные обращения к таким props в том же блоке. Это не общее правило JavaScript-деструктуризации. Для наблюдения передавай getter `watch(() => foo, ...)`, а не готовое значение `watch(foo, ...)`. [Vue: reactive props destructure](https://vuejs.org/guide/components/props.html#reactive-props-destructure).

## P1-инструменты

- `toRef` - ref на одно свойство объекта.
- `toRefs` — ref-обёртки для перечисляемых свойств, существующих на момент вызова; для отдельного необязательного свойства используй `toRef`.
- `readonly` - защищает от записи через выданный API.
- `shallowRef` - отслеживает замену `.value`, но не глубокие изменения внутри объекта.
- `customRef` - управление отслеживанием и уведомлением об изменениях, например для задержки обновления.

> [!note]- Углубление: Proxy и ограничения
> Vue 3 использует Proxy для `reactive`, поэтому многие ограничения Vue 2 с добавлением новых свойств ушли. Но деструктуризация, копирование значения и передача обычного примитива всё ещё могут разорвать реактивную связь. Подробнее о Proxy смотри [[Фронтенд/JavaScript/12. Proxy и Reflect/01. Proxy traps и Reflect|Proxy traps и Reflect]].

## Частые ошибки

- Говорить, что `ref` и `reactive` полностью взаимозаменяемы.
- Забывать `.value` в коде компонента.
- Деструктурировать `reactive` без `toRefs`.
- Класть весь большой набор данных, который заменяется целиком в глубокий `reactive`, когда достаточно `shallowRef`.
- Изменять состояние только для чтения внутри потребителя.

## Как ответить на собеседовании за одну минуту

ref хранит значение в `.value`. Он удобен для строки поиска, счётчика или ответа сервера, который заменяется целиком. reactive делает реактивными свойства объекта, например поля формы.

При деструктуризации числового или строкового свойства reactive в переменную попадает только текущее значение. Если нужна связь с полем, использую toRef или toRefs. Значение ref можно целиком заменить через `.value`, сохранив сам ref.

1. Выбери `ref` или `reactive` для поисковой строки, формы регистрации и большого неизменяемого ответа.
2. Исправь потерю реактивности после деструктуризации.
3. Объясни, почему `const value = count.value` не обновляется.

> [!question]- Разбор
> Поисковая строка обычно `ref('')`; форма может быть `reactive({ ... })`; большой неизменяемый ответ можно держать в `shallowRef`, если важна только замена всего объекта.
>
> ```ts
> const state = reactive({ name: 'Ada' });
> const { name } = toRefs(state);
> ```
