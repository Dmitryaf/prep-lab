# ref, reactive и потеря реактивности

> [!summary]
> Vue запоминает, какие данные читает интерфейс, и обновляет его при изменении этих данных. `ref` хранит значение в `.value`; `reactive` позволяет отслеживать свойства объекта. Главное — не потерять связь при копировании значения или замене объекта.

## Базовая модель

Когда компонент рендерится, Vue запоминает, какие реактивные значения были прочитаны. Когда эти значения меняются, Vue планирует обновление компонента.

```text
read reactive value -> track dependency
write reactive value -> trigger update
```

## `ref`

`ref` подходит для primitives и часто удобен для replaceable state:

```ts
import { ref } from 'vue';

const count = ref(0);
count.value += 1;
```

В template `.value` не нужен:

```vue
<button>{{ count }}</button>
```

## `reactive`

`reactive` подходит для объектного состояния:

```ts
import { reactive } from 'vue';

const form = reactive({
  name: '',
  email: '',
});

form.name = 'Ada';
```

## ref vs reactive

| Ситуация | Чаще выбрать |
|---|---|
| primitive value | `ref` |
| значение нужно полностью заменить | `ref` |
| объект формы с несколькими полями | `reactive` или набор `ref`, по стилю |
| возвращать состояние из composable | часто объект из `ref` |
| деструктурировать свойства | `toRef`/`toRefs` или отдельные `ref` |

## Потеря реактивности

При деструктуризации примитивного свойства `reactive` получается текущее значение, а не связь с исходным свойством:

```ts
const state = reactive({ count: 0 });
const { count } = state;

state.count += 1;
console.log(count); // старое значение
```

Исправление:

```ts
import { toRefs } from 'vue';

const state = reactive({ count: 0 });
const { count } = toRefs(state);
```

Если деструктурировано вложенное объектное значение, оно может остаться реактивным proxy. Но замена этого свойства в исходном объекте не заменит уже полученную локальную ссылку.

Отдельный случай — `const { foo } = defineProps(...)` в `<script setup>` Vue 3.5+: компилятор поддерживает реактивные обращения к таким props в том же блоке. Это не общее правило JavaScript-деструктуризации. Для наблюдения передавай getter `watch(() => foo, ...)`, а не готовое значение `watch(foo, ...)`. [Vue: reactive props destructure](https://vuejs.org/guide/components/props.html#reactive-props-destructure).

## P1-инструменты

- `toRef` - ref на одно свойство объекта.
- `toRefs` - ref-обертки для всех свойств.
- `readonly` - защищает от записи через выданный API.
- `shallowRef` - отслеживает замену `.value`, но не глубокие изменения внутри объекта.
- `customRef` - ручной контроль tracking/triggering, например debounce.

> [!note]- Углубление: Proxy и ограничения
> Vue 3 использует Proxy для `reactive`, поэтому многие ограничения Vue 2 с добавлением новых свойств ушли. Но destructuring, копирование значения и передача plain primitive все еще могут разорвать реактивную связь. Подробнее о Proxy смотри [[Фронтенд/JavaScript/12. Proxy и Reflect/01. Proxy traps и Reflect|Proxy traps и Reflect]].

## Частые ошибки

- Говорить, что `ref` и `reactive` полностью взаимозаменяемы.
- Забывать `.value` в script.
- Деструктурировать `reactive` без `toRefs`.
- Класть весь большой набор данных, который заменяется целиком в глубокий `reactive`, когда достаточно `shallowRef`.
- Мутировать readonly-state внутри потребителя.

## Как ответить на собеседовании за одну минуту

Vue отслеживает чтение и запись реактивных значений. `ref` оборачивает значение в объект с `.value`, хорош для primitives и заменяемого state. `reactive` делает proxy объекта и удобен для связанных полей. Главное отличие на практике - деструктуризация и замена: `reactive` легко потерять при destructuring, поэтому нужны `toRef`/`toRefs`, а `ref` проще полностью заменить.
