# computed, watch и watchEffect

> [!summary]
> Если из имени и фамилии нужно получить полное имя — это computed. Если при изменении имени нужно отправить запрос — watch. WatchEffect сам замечает реактивные значения, прочитанные во время его синхронного выполнения.

## `computed`

Используй `computed`, когда значение можно вывести из другого состояния:

```ts
const firstName = ref('Ada');
const lastName = ref('Lovelace');

const fullName = computed(() => `${firstName.value} ${lastName.value}`);
```

`computed` кешируется и пересчитывается, когда меняются зависимости.

## `watch`

`watch` подходит для побочных эффектов:

```ts
watch(searchQuery, async (query, previousQuery) => {
  if (query === previousQuery) {
    return;
  }

  await loadResults(query);
});
```

Побочный эффект - запрос, запись в storage, ручная интеграция с внешним API, аналитика.

## `watchEffect`

`watchEffect` запускается сразу и сам собирает зависимости, которые были прочитаны синхронно:

```ts
watchEffect(() => {
  document.title = `Search: ${searchQuery.value}`;
});
```

Он удобен для простых эффектов, но менее явен, чем `watch`.

## Cleanup

Для защиты от гонок запросов и освобождения подписок нужна очистка ресурсов:

```ts
// В setup; запрос возвращает JSON, его схема здесь опущена.
const searchQuery = ref('');
const results = ref<unknown>(null);
const error = ref('');

watch(searchQuery, async (query, _oldQuery, onCleanup) => {
  const controller = new AbortController();
  let active = true;
  onCleanup(() => {
    active = false;
    controller.abort();
  });
  error.value = '';

  try {
    const response = await fetch(`/api/search?q=${encodeURIComponent(query)}`, {
      signal: controller.signal,
    });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const data: unknown = await response.json();
    if (active) results.value = data;
  } catch (cause) {
    if (active) error.value = cause instanceof Error ? cause.message : 'Ошибка поиска';
  }
});
```

Очистка ресурсов отменяет прежний запрос и запрещает применять его результат или ошибку после того, как запуск наблюдателя устарел. Она не откатывает уже выполненную сервером запись. Пример про поиск; правила показа старых результатов при новой загрузке определяются отдельно для интерфейса. `ref` и `watch` импортируются из `vue`.

## watch не хуже computed

`computed` и `watch` решают разные задачи:

- нужно значение для template или другого кода - `computed`;
- когда нужно реагировать на конкретное изменение: запрос при смене `userId`, сохранение формы при изменении определённых полей, сравнение `oldValue/newValue` - `watch`;
- когда эффект зависит сразу от нескольких реактивных значений и проще автоматически собрать зависимости, чем перечислять их вручную - `watchEffect`.
Ещё важный нюанс: `watchEffect` запускается сразу при создании, а обычный `watch` по умолчанию ждёт первого изменения source

## P1: flush timing

По умолчанию watcher callback вызывается после обновления родителя и до DOM-обновления самого компонента. Для доступа к обновленному DOM используют `flush: 'post'` или `nextTick`.

> [!note]- Углубление: scheduler
> Vue группирует обычные watcher callbacks и обновления компонентов: несколько синхронных присваиваний не обязательно дают столько же отдельных рендеров. `flush: 'sync'` запускает callback без такого пакетирования, поэтому не нужен для обычного поиска.

Форма ежедневной записи должна различать реакцию на ввод, отложенное сохранение черновика и явное сохранение записи. Само наличие `watch` не определяет, какое из этих действий произошло. Начни со сценария сохранения в исходниках проекта и проследи, где меняется каждое состояние.

## Частые ошибки

- Использовать `watch`, чтобы вычислить значение, которое должно быть `computed`.
- Делать async `computed`.
- Запускать запросы без очистки ресурсов и получать устаревший ответ поверх нового.
- Считать `watchEffect` всегда лучше, потому что он короче.
- Мутировать источник внутри watcher так, что получается цикл.

## Как ответить на собеседовании за одну минуту

`computed` - для кешируемого производного значения без побочных действий. `watch` - для побочных действий при изменении конкретного источника, особенно когда нужны старое значение, отложенный запуск или очистка ресурсов. `watchEffect` запускает эффект сразу и сам собирает зависимости, но менее явно показывает, что именно отслеживается. Для API-запросов в наблюдателе важно отменять или игнорировать устаревшие запросы.
