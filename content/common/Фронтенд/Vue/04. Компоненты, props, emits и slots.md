# Компоненты, props, emits и slots

> [!summary]
> Родитель передаёт ребёнку данные через props. Ребёнок сообщает о действиях через emits. Slots позволяют родителю задать часть разметки ребёнка, например содержимое кнопки или строки списка.

## Props

```vue
<script setup lang="ts">
type Props = {
  title: string;
  disabled?: boolean;
};

const props = withDefaults(defineProps<Props>(), {
  disabled: false,
});
</script>
```

Props не стоит мутировать внутри ребенка. Если нужно изменить значение, отправь событие или сделай локальную копию с понятным правилом синхронизации.

## Emits

```vue
<script setup lang="ts">
const emit = defineEmits<{
  save: [id: string];
  cancel: [];
}>();

function onSave() {
  emit('save', 'u1');
}
</script>
```

## `v-model`

В Vue 3 `v-model` на компоненте обычно раскрывается в prop `modelValue` и событие `update:modelValue`.

```vue
<script setup lang="ts">
defineProps<{
  modelValue: string;
}>();

const emit = defineEmits<{
  'update:modelValue': [value: string];
}>();
</script>

<template>
  <input
    :value="modelValue"
    @input="emit('update:modelValue', ($event.target as HTMLInputElement).value)"
  >
</template>
```

## Slots

Slot дает родителю контроль над частью разметки:

```vue
<template>
  <section>
    <header>
      <slot name="header" />
    </header>
    <slot />
  </section>
</template>
```

Scoped slot передаёт данные в функцию разметки, которую задал родитель. Дочерний список выбирает пользователя и вызывает слот:

```vue
<!-- В UserList.vue; users получен через props -->
<ul>
  <li v-for="user in users" :key="user.id">
    <slot name="item" :user="user">{{ user.name }}</slot>
  </li>
</ul>
```

Родитель определяет содержимое строки и получает `user` как параметр слота:

```vue
<UserList :users="users">
  <template #item="{ user }">
    <strong>{{ user.name }}</strong>
  </template>
</UserList>
```

Обычный prop передаёт значение компоненту с готовой разметкой. Scoped slot передаёт компоненту способ построить разметку из его данных. Он не записывает `user` в состояние родителя и не заменяет событие `select`.

## provide/inject базово

provide/inject позволяет передать значение вложенным компонентам, не прокидывая prop через каждый промежуточный уровень. Так форма может передать полям общий контекст, а раздел интерфейса — тему. Pinia удобнее рассматривать отдельно, когда данные должны использовать разные экраны приложения.

В родительском компоненте:

```ts
const theme = ref('light');
provide('theme', readonly(theme));
```

В дочернем компоненте:

```ts
const theme = inject<Readonly<Ref<string>>>('theme');
if (!theme) throw new Error('Провайдер темы не найден');
```

`ref`, `readonly`, `provide`, `inject` и тип `Ref` импортируются из `vue`. В большом приложении общий `InjectionKey` с `Symbol` связывает типы провайдера и потребителя.

## Частые ошибки

- Мутировать prop в дочернем компоненте.
- Делать Pinia store для каждого локального значения.
- Использовать provide/inject для неявной бизнес-логики, которую трудно отследить.
- Не типизировать emits.
- Путать slots с props: props - данные, slots - разметка.

## Как ответить на собеседовании за одну минуту

Родитель передаёт ребёнку данные через props, а ребёнок сообщает о действии через emit. Например, карточка получает пользователя и отправляет событие select. Если родитель должен сам определить содержимое карточки, использую slot.

v-model связывает значение поля с родителем через modelValue и update:modelValue. Сам prop ребёнок не меняет. Для зависимостей внутри большого поддерева, например контекста формы, подходит provide/inject.
