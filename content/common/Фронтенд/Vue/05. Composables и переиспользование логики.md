# Composables и переиспользование логики

> [!summary]
> Composable - функция, которая использует Composition API и возвращает состояние/методы для переиспользования логики между компонентами.

## Базовая модель

Если два компонента повторяют загрузку, подписку, работу с формой или URL-state, логику можно вынести:

```ts
import { ref } from 'vue';

export function useToggle(initialValue = false) {
  const isOpen = ref(initialValue);

  function open() {
    isOpen.value = true;
  }

  function close() {
    isOpen.value = false;
  }

  return { isOpen, open, close };
}
```

## Composable с запросами и очисткой

В [[Фронтенд/Инженерные основы/07. Тестирование/02. Проверка поиска с поздними ответами|Проверка поиска с поздними ответами]] есть полный `useLatestSearch`: он принимает реактивный ввод и функцию загрузки, возвращает результат, ошибку и признак загрузки. Сетевая функция отдельно проверяет HTTP и JSON.

Использование в `<script setup>` компонента (пути импорта зависят от проекта):

```ts
const query = ref('');
const { results, error, isLoading } = useLatestSearch(query, searchUsers);
```

Такое разделение позволяет проверять гонку запросов без сервера. Оно оправдано конкретным повторяемым поведением, а не желанием построить универсальную обёртку над всеми запросами. `watch` создаётся синхронно внутри текущей области Vue; при её остановке запрос отменяется, а позднее завершение больше не меняет состояние.

Важное правило: старый `finally` не должен выключать загрузку нового запроса. Защита актуальности нужна для результата, ошибки и индикатора, а не только для результата.

## Что возвращать

Обычно composable возвращает обычный объект со ссылками `ref` и функциями:

```ts
return { data, error, isLoading, refetch };
```

Так потребитель может удобно деструктурировать без потери реактивности, потому что сами поля - refs.

## Effect scope

Синхронно созданные в `setup` наблюдатели останавливаются вместе с компонентом. Внешние подписки и запросы сами от этого не исчезают: для них нужна очистка. Вне компонента можно создать `effectScope`, затем явно остановить его; `onScopeDispose` привязывает освобождение ресурсов к текущей области.

## Частые ошибки

- Возвращать объект `reactive` и затем деструктурировать его, теряя реактивность полей.
- Прятать слишком много правил конкретной задачи в общей композиционной функции.
- Не освобождать ресурсы подписок, таймеров и запросов.
- Принимать plain value вместо `Ref`, когда composable должен реагировать на изменения.
- Создавать общее изменяемое состояние на уровне модуля без явного намерения.

## Как ответить на собеседовании за одну минуту

Composable — функция на Composition API для переиспользования логики. Она принимает реактивные источники, возвращает состояние и методы, привязывает очистку к области Vue. Объект из `ref` удобно деструктурировать, сохраняя реактивность. Для запросов нужны обработка ошибки, признак загрузки, отмена и защита от позднего завершения.
