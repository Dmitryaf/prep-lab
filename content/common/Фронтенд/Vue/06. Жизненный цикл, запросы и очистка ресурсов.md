# Жизненный цикл, запросы и очистка ресурсов

> [!summary]
> Хуки жизненного цикла привязывают работу к существованию компонента: доступ к DOM после монтажа, подписки, запросы и освобождение ресурсов. Реакцию на изменение данных чаще описывают через `computed` и `watch`.

## Основные hooks

```ts
onMounted(() => {
  // DOM уже создан, можно читать template refs
});

onUpdated(() => {
  // компонент обновил DOM; использовать осторожно
});

onUnmounted(() => {
  // снять подписки, таймеры, внешние ресурсы
});
```

В `<script setup>` код верхнего уровня выполняется во время setup компонента.

## Запрос при изменении ввода

Жизненный цикл определяет, когда начать и прекратить внешнюю работу. Реакцию на изменение ввода удобнее описать через `watch`, а загрузку — вынести в функцию.

`fetch` не отклоняет Promise из-за HTTP 500. Проверяй `response.ok` и структуру JSON; приведение `as User[]` этого не делает. Готовый адаптер и реализация: [[Фронтенд/Инженерные основы/07. Тестирование/02. Проверка поиска с поздними ответами|Проверка поиска с поздними ответами]].

## Race condition

Гонка запросов: пользователь вводит A, затем B; ответ A приходит позже и затирает B. Одной отмены недостаточно: старый `catch` или `finally` тоже может изменить состояние нового запроса.

Основной приём внутри наблюдателя:

```ts
watch(searchQuery, async (query, _oldQuery, onCleanup) => {
  const controller = new AbortController();
  let active = true;
  onCleanup(() => {
    active = false;
    controller.abort();
  });
  const isCurrent = () => active && searchQuery.value === query;
  isLoading.value = true;
  error.value = null;

  try {
    // searchUsers проверяет HTTP-статус и JSON; см. связанный стенд.
    const users = await searchUsers(query, controller.signal);
    if (isCurrent()) results.value = users;
  } catch {
    if (isCurrent()) error.value = 'Не удалось выполнить поиск';
  } finally {
    if (isCurrent()) isLoading.value = false;
  }
});
```

Это фрагмент механизма. Полный вариант с импортами, пустым вводом, запуском и тестами находится в [[Фронтенд/Инженерные основы/07. Тестирование/02. Проверка поиска с поздними ответами|Проверка поиска с поздними ответами]]. При синхронном создании `watch` в `setup` остановка компонента вызывает очистку наблюдателя.

## Очистка ресурсов

**ID вопроса:** Cleanup

При завершении работы нужно освободить ресурсы:

- `addEventListener`;
- `setInterval`/`setTimeout`;
- WebSocket/subscriptions;
- AbortController;
- сторонних виджетов;
- наблюдатели, созданные вне обычной области компонента.

## Частые ошибки

- Делать запрос без признака загрузки и обработки ошибки.
- Не отменять устаревшие запросы.
- Менять состояние внутри `onUpdated` и получать бесконечные обновления.
- Читать ссылки на DOM до `onMounted`.
- Забывать removeEventListener.

## Как ответить на собеседовании за одну минуту

Хуки жизненного цикла позволяют выполнить работу в нужный момент существования компонента. После onMounted можно обращаться к созданному DOM, а при удалении компонента нужно остановить его подписки, таймеры и другие ресурсы.

Если действие зависит от изменения данных, использую watch или watchEffect. Например, при смене строки поиска запускаю новый запрос, показываю загрузку и ошибку. Прежний запрос отменяю и проверяю актуальность перед каждым изменением состояния, включая catch и finally.

> [!question]- Разбор
> Для поиска используй `watch(query, callback)` и создавай новый `AbortController` на каждый запуск. В `onCleanup` помечай запуск неактуальным и вызывай `abort()`. В `try`, `catch` и `finally` меняй состояние только у актуального запуска.
