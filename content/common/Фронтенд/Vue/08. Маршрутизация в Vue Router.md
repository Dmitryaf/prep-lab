# Маршрутизация в Vue Router

> [!summary]
> Vue Router выбирает компонент по URL. Например, адрес `/users/42` открывает карточку пользователя 42. Маршрутизатор также позволяет переходить между экранами, проверять условия перехода и загружать код страницы только при необходимости.

## Базовая настройка

```ts
import { createRouter, createWebHistory } from 'vue-router';

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: () => import('./pages/HomePage.vue') },
    { path: '/users/:id', component: () => import('./pages/UserPage.vue') },
  ],
});
```

В приложении:

```vue
<RouterLink to="/users/1">User</RouterLink>
<RouterView />
```

## Composition API

```ts
const route = useRoute();
const router = useRouter();

const userId = computed(() => String(route.params.id));

function goHome() {
  router.push('/');
}
```

`route` реактивен, поэтому данные по параметру обычно грузят через `watch`.

## Guards

```ts
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !authStore.isAuthenticated) {
    return '/login';
  }
});
```

Guards управляют переходами: например, перенаправляют на вход и предупреждают об уходе с изменённой формы. Они не защищают API: сервер проверяет сессию и права для каждого запроса. Загрузку можно связать с маршрутом, но не стоит превращать глобальный guard в место всей бизнес-логики.

## Lazy loading routes

Dynamic import разбивает приложение на chunks:

```ts
{
  path: '/settings',
  component: () => import('./pages/SettingsPage.vue'),
}
```

Это связано со скоростью загрузки и разбиением кода на отдельные файлы, подробнее смотри [[Фронтенд/Инженерные основы/04. Производительность/01. Core Web Vitals и загрузка frontend-приложения|Core Web Vitals и загрузка frontend-приложения]].

## Частые ошибки

- Считать route params обычными constants и не реагировать на их изменение.
- Загружать тяжёлые данные в общей проверке, которая выполняется при каждом переходе.
- Не обрабатывать loading/error при смене route.
- Хранить временное состояние маршрута в Pinia без необходимости.
- Забывать lazy loading для крупных страниц.

## Как ответить на собеседовании за одну минуту

Vue Router выбирает экран по URL и показывает его в RouterView. Для перехода использую RouterLink или router.push. useRoute даёт текущие параметры и query, а useRouter — методы управления переходами.

При смене `/users/1` на `/users/2` компонент может остаться тем же, поэтому нужно наблюдать за id и загрузить другого пользователя. Guards позволяют проверить условия перехода. Код крупных страниц можно загружать через dynamic import, чтобы не включать его целиком в первоначальную загрузку.

## Практические задачи

1. Спроектируй routes для списка и карточки пользователя.
2. Напиши проверку входа перед переходом на закрытый маршрут.
3. Объясни загрузку данных при изменении `route.params.id`.
