# Маршрутизация в Vue Router

> [!summary]
> Vue Router связывает URL с компонентами. Для middle-собеседования важно понимать routes, dynamic params, navigation, guards и lazy loading.

## Базовая настройка

```ts
import { createRouter, createWebHistory } from 'vue-router';

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: () => import('./pages/HomePage.vue') },
    { path: '/users/:id', component: () => import('./pages/UserPage.vue') },
  ],
});
```

В приложении:

```vue
<RouterLink to="/users/1">User</RouterLink>
<RouterView />
```

## Composition API

```ts
const route = useRoute();
const router = useRouter();

const userId = computed(() => String(route.params.id));

function goHome() {
  router.push('/');
}
```

`route` реактивен, поэтому данные по параметру обычно грузят через `watch`.

## Guards

```ts
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !authStore.isAuthenticated) {
    return '/login';
  }
});
```

Guards полезны для auth, access checks, loading данных на уровне маршрута. Но не стоит превращать guards в место всей бизнес-логики.

## Lazy loading routes

Dynamic import разбивает приложение на chunks:

```ts
{
  path: '/settings',
  component: () => import('./pages/SettingsPage.vue'),
}
```

Это связано со скоростью загрузки и разбиением кода на отдельные файлы, подробнее смотри [[Фронтенд/Инженерные основы/04. Производительность/01. Core Web Vitals и загрузка frontend-приложения|Core Web Vitals и загрузка frontend-приложения]].

## Частые ошибки

- Считать route params обычными constants и не реагировать на их изменение.
- Делать глобальный guard с тяжелыми запросами на каждый переход.
- Не обрабатывать loading/error при смене route.
- Хранить временное состояние маршрута в Pinia без необходимости.
- Забывать lazy loading для крупных страниц.

## Как ответить на собеседовании за одну минуту

Vue Router сопоставляет URL и компоненты, рендерит текущий route через `RouterView`, а навигацию делает через `RouterLink` или `router.push`. В Composition API я использую `useRoute` для текущих params/query и `useRouter` для действий. Route params реактивны, поэтому при смене id нужно перезагрузить данные. Guards нужны для контроля переходов, а lazy routes помогают code splitting.

2. Напиши guard для protected route.
3. Объясни загрузку данных при изменении `route.params.id`.
