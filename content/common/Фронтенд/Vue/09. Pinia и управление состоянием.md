# Pinia и управление состоянием

> [!summary]
> Pinia хранит данные, которые нужны нескольким частям приложения. Например, список и счётчик могут читать общие фильтры. Локальное состояние одного поля не обязательно переносить в store.

## Когда нужен store

Pinia полезна, когда состояние:

- используется в нескольких независимых ветках UI;
- должно переживать переходы между страницами;
- относится к домену приложения: пользователь, корзина, права;
- требует общих actions и derived values.

Не нужно выносить в Pinia каждую модалку, поле формы или hover-state.

## Setup store

```ts
import { computed, ref } from 'vue';
import { defineStore } from 'pinia';

type CartItem = { id: string; price: number; count: number };

export const useCartStore = defineStore('cart', () => {
  const items = ref<CartItem[]>([]);
  const totalPrice = computed(() =>
    items.value.reduce((sum, item) => sum + item.price * item.count, 0),
  );

  function addItem(item: CartItem) {
    items.value.push(item);
  }

  return { items, totalPrice, addItem };
});
```

## Использование

```ts
const cartStore = useCartStore();
cartStore.addItem({ id: 'book', price: 100, count: 1 });
```

Если деструктурируешь state/getters, используй `storeToRefs`:

```ts
import { storeToRefs } from 'pinia';

const { items, totalPrice } = storeToRefs(cartStore);
const { addItem } = cartStore;
```

## Архитектура stores

Разделяй stores по доменным областям, а не по типам полей:

- `useAuthStore`;
- `useCartStore`;
- `useProductsStore`;
- `useUiStore`, если UI-state действительно общий.

## Store не равен сохранённым данным

Делить store полезно по независимым причинам изменения. Если операции должны вместе поддерживать одно правило, механическое разбиение по количеству строк может только усложнить связи.

## Частые ошибки

- Объединять несвязанные состояния без понятного владельца и правил изменения. Границы store выбирай по связанности данных и операций.
- Выносить локальную форму в Pinia без необходимости.
- Деструктурировать store напрямую и терять реактивность state.
- Делать actions без обработки loading/error.
- Дублировать server cache без стратегии invalidation.

## Как ответить на собеседовании за одну минуту

Pinia нужна для разделяемого состояния, которое используется в разных частях приложения или переживает route transitions. Store содержит state, getters/computed и actions. Я не выношу туда все подряд: локальное состояние остается в компоненте или composable. При destructuring state использую `storeToRefs`, а методы можно брать напрямую.

## Практические задачи

1. Спроектируй store для auth.
2. Реши, где хранить состояние формы checkout.
3. Исправь потерю реактивности при destructuring store.

> [!question]- Разбор
> Auth store обычно содержит `user`, `token/session`, `isAuthenticated`, actions `login`, `logout`, `loadMe`. Состояние checkout формы лучше держать локально, если оно не нужно между страницами; если checkout многошаговый и переживает route transitions, можно вынести в store.
