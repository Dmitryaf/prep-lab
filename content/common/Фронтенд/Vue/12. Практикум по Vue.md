# Практикум по Vue

> [!summary]
> Задачи покрывают типичные middle/middle+ вопросы: реактивность, computed/watch, props/emits, composables, гонки запросов, Pinia и производительность списков.

## Задача 1. Порядок обновления состояния

В компоненте изменили `count.value += 1` и сразу читают DOM. Почему DOM может быть старым?

> [!question]- Разбор
> Vue группирует изменения и обновляет DOM асинхронно. Для чтения обновленного DOM используй `await nextTick()` или watcher с подходящим flush timing.

## Задача 2. Выбрать ref или reactive

Выбери инструмент для поискового запроса, формы и большого набора данных, заменяемого целиком.

> [!question]- Разбор
> Поисковый запрос - `ref('')`. Форма - `reactive({ ... })` или набор refs, если поля активно передаются по отдельности. Большой набор данных, заменяемый целиком - часто `shallowRef`, если важна замена целиком.

## Задача 3. Заменить watch на computed

```ts
const fullName = ref('');

watch([firstName, lastName], () => {
  fullName.value = `${firstName.value} ${lastName.value}`;
});
```

> [!question]- Разбор
> ```ts
> const fullName = computed(() => `${firstName.value} ${lastName.value}`);
> ```

## Задача 4. Типизировать props/emits

Компонент принимает `user` и emit-ит `select`.

> [!question]- Разбор
> ```ts
> type User = {
>   id: string;
>   name: string;
> };
>
> defineProps<{
>   user: User;
> }>();
>
> const emit = defineEmits<{
>   select: [user: User];
> }>();
> ```

## Задача 5. Вынести composable

Есть три компонента, которые повторяют loading/error/data для запроса.

> [!question]- Разбор
> Вынеси `useAsyncData` или доменный `useProducts`. Composable должен возвращать реактивные значения ref и действие `load/refetch`, обрабатывать ошибку и освобождать ресурсы, если запрос зависит от реактивного источника.

## Задача 6. Предотвратить race condition

Поиск отправляет запрос на каждый ввод, старый ответ иногда перезаписывает новый.

> [!question]- Разбор
> Используй debounce и `AbortController` или счетчик request id. В Vue удобно делать abort в `onCleanup` watcher.

## Задача 7. Исправить потерю реактивности

```ts
const store = useCartStore();
const { items } = store;
```

> [!question]- Разбор
> ```ts
> const store = useCartStore();
> const { items } = storeToRefs(store);
> const { addItem } = store;
> ```

## Задача 8. Спроектировать Pinia store

Опиши store для auth.

> [!question]- Разбор
> State: `user`, `isLoading`, `error`. Getter/computed: `isAuthenticated`. Actions: `login`, `logout`, `loadMe`. Не смешивай auth, products и UI-modal state в одном store.

## Задача 9. Оптимизация списка

Список из 10 000 товаров тормозит при вводе фильтра.

> [!question]- Разбор
> Сначала измерить. Затем: отложить обработку частого ввода через debounce, вычислять отфильтрованный список через computed, загружать данные порциями или отображать только видимые строки, стабильные `key`, не рендерить невидимые элементы, проверить тяжелые дочерние компоненты и лишние props.
