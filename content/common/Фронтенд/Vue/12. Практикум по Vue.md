# Практикум по Vue

> [!summary]
> Задачи покрывают типичные middle/middle+ вопросы: реактивность, computed/watch, props/emits, composables, гонки запросов, Pinia и производительность списков.

## Задача 1. Порядок обновления состояния

В компоненте изменили `count.value += 1` и сразу читают DOM. Почему DOM может быть старым?

> [!question]- Разбор
> Vue группирует изменения и обновляет DOM асинхронно. Для чтения обновленного DOM используй `await nextTick()` или watcher с подходящим flush timing.

## Задача 2. Выбрать ref или reactive

Выбери инструмент для поискового запроса, формы и большого набора данных, заменяемого целиком.

> [!question]- Разбор
> Для строки поиска подойдёт ref. Поля формы можно собрать в reactive или оставить отдельными refs, если они передаются по одному. Если большой ответ сервера всегда заменяется целиком, удобно использовать shallowRef: Vue будет отслеживать замену всего значения без глубокой обработки его полей.

## Задача 3. Заменить watch на computed

```ts
const fullName = ref('');

watch([firstName, lastName], () => {
  fullName.value = `${firstName.value} ${lastName.value}`;
});
```

> [!question]- Разбор
> ```ts
> const fullName = computed(() => `${firstName.value} ${lastName.value}`);
> ```

## Задача 4. Типизировать props/emits

Компонент принимает `user` и emit-ит `select`.

> [!question]- Разбор
> ```ts
> type User = {
>   id: string;
>   name: string;
> };
>
> defineProps<{
>   user: User;
> }>();
>
> const emit = defineEmits<{
>   select: [user: User];
> }>();
> ```

## Задача 5. Вынести composable

Есть три компонента, которые повторяют loading/error/data для запроса.

> [!question]- Разбор
> Вынеси `useAsyncData` или доменный `useProducts`. Composable должен возвращать реактивные значения ref и действие `load/refetch`, обрабатывать ошибку и освобождать ресурсы, если запрос зависит от реактивного источника.

## Задача 6. Предотвратить race condition

Поиск отправляет запрос на каждый ввод, старый ответ иногда перезаписывает новый.

> [!question]- Разбор
> Debounce уменьшает число запросов, но не защищает от позднего ответа уже запущенного запроса. На каждый запуск создай `AbortController` и признак актуальности либо request id. В `onCleanup` отмени старую работу; перед изменением результата, ошибки и loading проверь, что ответ относится к текущему вводу. Полный механизм: [[Фронтенд/Vue/06. Жизненный цикл, запросы и очистка ресурсов|запросы и очистка ресурсов]].

## Задача 7. Исправить потерю реактивности

```ts
const store = useCartStore();
const { items } = store;
```

> [!question]- Разбор
> ```ts
> const store = useCartStore();
> const { items } = storeToRefs(store);
> const { addItem } = store;
> ```

## Задача 8. Спроектировать Pinia store

Опиши store для auth.

> [!question]- Разбор
> В state храни пользователя, признак загрузки и ошибку. По наличию действующей сессии вычисляй isAuthenticated. В actions размести вход, выход и загрузку текущего пользователя: login, logout и loadMe. Товары и состояние модальных окон решают другие задачи, поэтому их лучше не смешивать с auth.

## Задача 9. Оптимизация списка

Список из 10 000 товаров тормозит при вводе фильтра.

> [!question]- Разбор
> Сначала измерь, что тормозит: фильтрация или отображение тысяч строк. Если проблема в DOM, используй загрузку порциями или виртуализацию. Стабильные key сохранят связь строк с товарами.
>
> Если дорого стоит вычисление фильтра, проверь алгоритм и computed; debounce может уменьшить число запусков при частом вводе. Затем посмотри на тяжёлые дочерние компоненты и props, из-за которых они обновляются. Сравни задержку после изменения с исходным сценарием.
