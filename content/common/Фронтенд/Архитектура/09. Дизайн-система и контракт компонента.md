# Дизайн-система и контракт компонента

Общий компонент полезен, если разные экраны могут пользоваться им без знания внутренних деталей. Дизайн-система добавляет согласованные правила поведения и оформления, документацию, проверки и процесс изменения этих договорённостей.

## От задачи к границам

Учебный случай: несколько продуктов используют окно подтверждения. Общее — открытие, заголовок, фокус, закрытие и оформление. Правило «можно ли удалить бронирование» принадлежит продукту и проверяется сервером. Не помещай его в общий Modal.

```text
токены оформления → общие элементы → составные компоненты → экран продукта
цвет/отступ          Button/Input     Modal/FormField      отмена бронирования
```

Токен — именованное решение оформления, например цвет опасного действия. Если все экраны используют один смысловой токен, изменение темы не требует поиска случайных значений цвета. При объединении похожих элементов учитывай их назначение и поведение.

## Договориться о поведении до реализации

Для Modal назови входы: `open`, заголовок, содержимое и доступные действия. Событие закрытия означает запрос на изменение состояния; владелец решает, можно ли закрыть форму с несохранённым вводом. Не храни две независимые истины `props.open` и внутреннее `isOpen` без правил согласования.

| Состояние | Ожидаемое поведение |
|---|---|
| Открытие | Понятное имя окна и начальный фокус внутри |
| Tab / Shift+Tab | Фокус остаётся в модальном окне |
| Escape | Запрос закрытия; договорённость о несохранённой форме задана явно |
| Закрытие | Фокус возвращается к инициатору либо логичному следующему элементу |
| Сохранение идёт | Видно состояние ожидания, повторное действие контролируется |
| Ошибка | Ввод остаётся; сообщение можно обнаружить и прочитать |

Это контракт для настоящего модального поведения. `aria-modal="true"` само не реализует блокировку фона и клавиатуру. Для своего компонента нужно выполнить обе части. [WAI: modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

## Storybook: состояния компонента отдельно от экрана

Чтобы увидеть ошибку Select, не обязательно каждый раз открывать весь продукт и ждать сбоя сервера. Storybook позволяет показать компонент в изоляции. Story — описанный пример состояния; args задают входы. Для Select полезны примеры с пустым списком, выбранным значением, загрузкой, ошибкой и disabled.

Учебный пример: story «Ошибка загрузки» передаёт Select пустой options и сообщение об ошибке. Читатель сразу видит это состояние, меняет args и понимает контракт.

Storybook помогает обсуждать поведение и повторять состояния. Для проверки выбора клавиатурой нужны действия и assertions; для интеграции с реальным API — отдельный сценарий. Скриншот фиксирует внешний вид; отправку формы проверяют отдельным сценарием.

## Как менять общий компонент

Допустим, раньше `close` отправлял только событие, теперь нужен `reason: 'escape' | 'button' | 'backdrop'`. Сначала найди потребителей, опиши старый и новый контракт, выбери совместимый переход или новую major-версию. Возможность адаптировать прежний контракт важнее красивого API в одном месте.

Минимальный путь выпуска: примеры состояний → тесты поведения → проверка клавиатуры → проверка нескольких реальных потребителей → описание изменения → обновление потребителей. Проверь переходы фокуса с клавиатуры и работу обновлённого компонента на существующих экранах.

## Где прекращать обобщение

Если для ещё одного экрана нужны пять взаимосвязанных флагов, остановись и назови концепцию. Возможно, нужен отдельный составной компонент поверх общих элементов. SOLID здесь означает понятные причины изменения и заменяемый контракт, а не обязательные классы и десятки интерфейсов. Простая функция или Vue-компонент могут давать нужную границу.

## Задание

Общий Select должен работать с тысячами вариантов, поиском, клавиатурой и ошибкой загрузки. Уточни, кто владеет выбранным ID, запросом, отображаемой подписью и загрузкой. Затем добавляется требование: выбранного элемента нет на текущей странице результатов.

> [!question]- Разбор
> Значение выбора нельзя отождествлять с текущим списком результатов. Нужны устойчивый ID и способ получить подпись выбранного элемента. Поиск и загрузка имеют отдельные состояния; поздний ответ не заменяет актуальный список. Сначала реши, действительно ли нужен свой сложный виджет или достаточно готового доступного элемента. Проверь выбор, очистку, disabled, ошибку, клавиатуру и восстановление подписи.

## Связь с собственным опытом

Краткий ответ: «Сначала фиксирую поведение и владельца состояния, потом API. Общий компонент должен оставаться предсказуемым для потребителей. Изменение проверяю на сценариях, клавиатуре и совместимости, а не только по скриншоту».
