# От URL до первого ответа

> [!summary]
> После ввода адреса браузеру нужно найти сервер, установить соединение, отправить запрос и получить ответ. Кэш и уже открытое соединение могут сократить этот путь. Получение HTML — только начало загрузки страницы.

## Зачем понимать тему

Эта модель помогает объяснить медленную загрузку страницы, работу кэша и CDN, защищённое соединение HTTPS, ограничения CORS, передачу cookie и начало построения страницы. На собеседовании важно последовательно описать основные этапы и связь между ними.

## Базовая модель

```text
URL
-> DNS: домен -> IP
-> TCP: надёжное соединение
-> TLS: защищённый канал для HTTPS
-> HTTP request
-> HTTP response
-> браузер начинает обработку HTML и ресурсов
```

## URL

URL описывает, где находится ресурс и как к нему обратиться.

```text
https://example.com:443/products?id=10#reviews
scheme  host        port path      query  fragment
```

Фрагмент после `#` не отправляется на сервер в HTTP-запросе. Он используется браузером на клиенте.

## DNS, TCP и TLS

DNS нужен, чтобы найти IP-адрес для домена. После этого браузер может установить соединение с сервером.

TCP отвечает за надёжную доставку байтов между клиентом и сервером. TLS используется в HTTPS: поверх TCP создаётся защищённый канал, в котором HTTP-сообщения передаются шифрованно.

> [!note]- Углубление: что видно при HTTPS
> HTTPS шифрует HTTP-сообщение: path, query, headers, cookies и body. Но не делает невидимым сам факт соединения, IP-адрес, порт, объём трафика и часть сетевых метаданных. Имя домена тоже может быть видно на разных уровнях, например через DNS или SNI, если не используются дополнительные механизмы защиты.

## CDN и caches

CDN — сеть серверов, расположенных в разных регионах. Эти серверы сохраняют копии файлов сайта: JavaScript, CSS, изображений и шрифтов.

Например, основной сервер сайта находится в США, а пользователь — в Германии. Если нужный файл есть на сервере CDN в Европе, пользователь может получить его оттуда. Обычно это быстрее, чем передавать файл из США. Основной сервер при этом получает меньше запросов, потому что часть файлов отдаёт CDN.

Кэш — сохранённая копия данных, которую можно использовать повторно. Он может находиться на разных уровнях:

- кэш браузера — файлы сохраняются на устройстве пользователя;
- общий кэш — копиями пользуются разные посетители; так может работать CDN или обратный прокси-сервер, принимающий запросы перед основным сервером;
- кэш, которым управляет код приложения, — например, через Service Worker; подробнее в [[Фронтенд/API браузера/07. Service Workers и Background Sync/01. Service Workers, Cache API и Background Sync|Service Workers, Cache API и Background Sync]].

## Где начинается Browser API

После получения HTML браузер разбирает документ, загружает файлы страницы и строит DOM — дерево документа, CSSOM — представление стилей, а затем дерево отображаемых элементов. Этапы построения и отрисовки страницы разобраны в [[Фронтенд/API браузера/03. Рендеринг браузера/01. Rendering pipeline и связь с Event Loop|Rendering pipeline и связь с Event Loop]].

## Частые ошибки

- Описывать "ввод URL" как один HTTP-запрос без DNS/TCP/TLS.
- Говорить, что HTTPS скрывает вообще всё.
- Смешивать CDN, кэш браузера и кэш, которым управляет Service Worker.
- Уходить в подробности обмена служебными сообщениями TCP/TLS до объяснения общей последовательности загрузки.

## Как ответить на собеседовании за одну минуту

Браузер разбирает URL: определяет протокол, имя сервера, путь и параметры запроса. Если IP-адрес сервера ещё неизвестен, браузер получает его через DNS. Затем устанавливает соединение с сервером — в этой базовой модели TCP. Для HTTPS стороны согласуют параметры TLS и создают защищённый канал. Браузер отправляет HTTP-запрос и получает ответ. Если это HTML, браузер начинает разбирать документ, загружать CSS, JavaScript и изображения и строить страницу.

## Практическая задача

Страница медленно открывается у пользователей из другой страны. Какие уровни проверить?

> [!question]- Разбор
> Сначала определить, где тратится время: на поиск IP-адреса, установление соединения, ожидание ответа или передачу файлов. Это видно в инструментах разработчика на вкладке Network. Затем проверить задержку до основного сервера, наличие CDN, заголовки кэширования, размеры и сжатие HTML, JavaScript и CSS, а также файлы, без которых браузер не может начать отображение. Если файлы уже получены, а страница всё ещё медленная, отдельно исследовать выполнение JavaScript и построение страницы.
