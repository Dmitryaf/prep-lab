# Bundlers, Vite, Webpack, Babel и TypeScript

> [!summary]
> Инструменты разработки превращают исходный код проекта в код, который удобно разрабатывать, проверять и отдавать браузеру. Для интервью важно понимать роли инструментов, а не помнить все настройки.

## Bundler

Сборщик (bundler) начинает с входных файлов, проходит по импортам и формирует граф зависимостей. На выходе — файлы для браузера.

```text
src/main.js
-> imports
-> dependency graph
-> JS/CSS/assets chunks
```

Он может разделять код на части (code splitting), удалять неиспользуемые экспорты (tree shaking), уменьшать размер кода (minification), обрабатывать CSS и ресурсы, подставлять переменные окружения.

## Dev server vs production build

Сервер разработки нужен для быстрой обратной связи: запуска, обновления модулей и показа ошибок.

Сборка для выпуска готовит файлы для пользователей: уменьшает код, добавляет хеши в имена, делит код и учитывает целевые браузеры.

## Vite и Webpack

| Инструмент | Практичная модель |
| --- | --- |
| Vite | в разработке использует ESM и преобразование модулей; сборщик зависит от версии: в Vite 7 — Rollup, в Vite 8 — Rolldown |
| Webpack | строит граф зависимостей и собирает файлы; загрузчики и плагины расширяют обработку |

Vite часто проще и быстрее для современных проектов. Webpack остаётся важен в больших существующих кодовых базах и сложных кастомных конфигурациях.

## Babel и TypeScript

Babel преобразует синтаксис с помощью плагинов и наборов настроек. Компилятор TypeScript проверяет типы и может выпускать JavaScript.

В современных frontend-сборках часто:

- TypeScript проверяет типы;
- быстрый преобразователь удаляет типы и преобразует синтаксис;
- сборщик проходит граф зависимостей и выпускает файлы.

## Linting и formatting

Линтер ищет потенциальные ошибки и нарушения правил: неиспользуемые переменные, неправильное применение API, опасные импорты.

Форматирование приводит код к единому виду: пробелы, переносы, кавычки. Prettier не должен заменять ESLint по смыслу.

## Частые ошибки

- Путать bundling и transpilation.
- Думать, что TypeScript всегда делает production build.
- Не различать сервер разработки и готовую сборку для выпуска.
- Считать tree shaking магией, которая удалит любой неиспользуемый код.
- Хранить секреты в переменных окружения клиентской сборки: их значения могут попасть в доступный пользователю JavaScript.

## Как ответить на собеседовании за одну минуту

Сборщик проходит зависимости и выпускает JS, CSS и ресурсы для браузера. Сервер разработки ускоряет обратную связь, сборка для выпуска готовит файлы пользователю. Babel преобразует синтаксис, TypeScript проверяет типы; само удаление типов сборщиком не означает успешную проверку. Линтер ищет ошибки и нарушения правил, форматирование задаёт единый стиль. Детали Vite зависят от версии.

## Практическая задача

В production bundle попала большая библиотека, используемая только на одном route. Что сделать?

> [!question]- Разбор
> Проверить bundle analyzer, вынести route/feature в dynamic import, убедиться, что library не импортируется в общий entry/shared module, проверить tree shaking и side effects. После изменения измерить initial JS и route loading.
