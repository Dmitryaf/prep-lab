# Module Federation и Nx на одном сценарии

Сценарий: личный кабинет содержит оболочку, каталог услуг и биллинг. Команды хотят менять их независимо. Сначала уточни, нужна ли независимая поставка: если все части выпускаются вместе, обычные модули могут быть проще.

## Три разных вопроса

| Механизм | На какой вопрос отвечает |
|---|---|
| Монорепозиторий | Где хранится связанный код? |
| Nx | Как увидеть зависимости проектов, запускать и кешировать задачи? |
| Module Federation | Как одна сборка загружает предоставленный другой сборкой модуль? |

Код можно хранить в монорепозитории, запускать задачи через Nx и загружать отдельные части через Module Federation. Но каждое решение решает свою задачу. Микрофронтенд выделяет часть продукта, которую команда может развивать и выпускать отдельно; Federation помогает подключить её код к другим сборкам.

## Путь загрузки

```text
оболочка → описание remote → загрузка контейнера → доступ к exposed-модулю
        → получение нужных chunks/shared-зависимостей → запуск модуля
```

Оболочка (host) загружает удалённую сборку (remote). У них должны быть согласованы имена, адреса и контракт модуля. В Webpack каждой сборке требуется собственный `output.uniqueName`. Это отличается от имени контейнера в конфигурации Module Federation. [Webpack: Module Federation](https://webpack.js.org/concepts/module-federation/).

Пример контракта независимого виджета, а не конфигурации Webpack:

```ts
type BillingContext = {
  tenantId: string;
  onNavigate: (path: string) => void;
};
type MountBilling = (
  element: HTMLElement,
  context: BillingContext,
) => { unmount(): void };
```

Оболочка отвечает за место и маршрут; модуль освобождает подписки и DOM при `unmount`. Идентификатор организации не даёт права доступа: сервер проверяет запросы отдельно. Передача props, событий и небольшого контекста обычно делает границу понятнее, чем общий изменяемый store без владельца.

## Что может сломаться

| Симптом | Проверяемая причина | Поведение пользователя |
|---|---|---|
| Не загрузился remote | Адрес, статус, политика браузера, доступность файла | Ошибка отдельного раздела и повтор |
| Entry доступен, chunk отсутствует | Несогласованные версии/пути ресурсов | Понятное восстановление, запись версии |
| После обновления ошибка API компонента | Несовместимый контракт host/remote | Отмена выпуска или совместимый адаптер |
| Растут обработчики при переходах | Не вызывается корректный unmount | Исправить жизненный цикл |

`shared` задаёт правила совместного использования пакетов. `singleton` ограничивает выбор одним экземпляром в области обмена, но не превращает несовместимые версии в совместимые. Версии, `requiredVersion` и реакция на несоответствие требуют явного решения. [ModuleFederationPlugin](https://webpack.js.org/plugins/module-federation-plugin/).

## Независимый выпуск имеет цену

Если remote всегда берётся с одного изменяемого URL, новая версия может попасть к старому host без его нового релиза. Нужны версия контракта, проверка поддерживаемых сочетаний, совместимая поставка и управляемый откат. Не удаляй старые chunks, пока их могут запрашивать открытые страницы. CSS, routing, авторизация и ошибки также пересекают границу сборок.

## Nx: что именно кешируется

Граф зависимостей: `shell → ui`, `billing → ui`, `catalog → ui`. Изменение общего `ui` может затронуть всех потребителей. Изменение только биллинга не обязано пересобирать всё.

Nx определяет затронутые проекты по изменённым файлам и графу зависимостей. В CI важно правильно задать сравниваемые base/head. Кэш задачи переиспользует результат при совпадении учитываемых входов; выходные файлы тоже должны быть описаны. Если влияющая на сборку настройка не входит в ключ, можно получить неподходящий артефакт. [Affected](https://nx.dev/docs/features/ci-features/affected), [cache task results](https://nx.dev/docs/features/cache-task-results).

Для сборки можно повторно использовать сохранённые выходные файлы. С деплоем это не работает так же: его задача — изменить внешнюю систему, поэтому пропуск запуска может оставить старую версию приложения. Аналогично, сохранённый результат теста внешнего сервиса относится к прошлому запуску; доступность сервиса сейчас проверяют новым запросом.

## Задание с изменением условия

Ты обновил `ui` и выпустил только remote биллинга. Старый host падает при открытии раздела. Назови первый шаг диагностики, временное восстановление и защиту перед следующим выпуском. Затем remote становится недоступен полностью.

> [!question]- Разбор
> Зафиксируй фактические версии host/remote, ошибку и запросы ресурсов. Отдели загрузку от несовместимого контракта. Откат удалённого модуля требует доступности файлов прежней версии и совместимых данных. Добавь проверку сочетаний и изоляцию ошибки раздела. Если удалённый модуль недоступен, оболочка должна продолжать работать в заранее определённых границах; отсутствие биллинга нельзя показывать как нулевую задолженность.

## Связь с опытом

Краткий ответ: «Nx помогает запускать задачи связанных проектов и повторно использовать их результаты. Module Federation позволяет оболочке загрузить модуль другой сборки. Например, команда биллинга может выпустить свою часть отдельно, но новый модуль должен работать со старой оболочкой. Поэтому проверяем совместимость версий и заранее решаем, что покажем, если модуль не загрузится».
