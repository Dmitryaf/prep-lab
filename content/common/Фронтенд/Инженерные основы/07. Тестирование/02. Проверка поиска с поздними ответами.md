# Проверка поиска с поздними ответами

> [!summary]
> Проверяем правило: только актуальный запрос может менять результат, ошибку и индикатор загрузки. Отмена экономит работу, а проверка актуальности защищает состояние даже при загрузчике, который игнорирует отмену.

## Условия задачи

Учебный поиск пользователей: ввод `alpha` запускает A, затем `beta` запускает B. Сервер вправе ответить в любом порядке. При пустом вводе очищаем результат; при новом запросе также очищаем старые результаты и ошибку. Это выбранное поведение интерфейса, а не обязательное правило всех поисков.

```text
ввод alpha → A начался
ввод beta  → A отменён, B начался
A завершился → состояние B не меняется
B завершился → показываем результат или ошибку B, загрузка выключается
```

## Запустить пример

[Скачай исходники и тесты request-lifecycle](/labs/request-lifecycle.zip). Распакуй архив и открой терминал в папке `request-lifecycle`. Это автономный стенд без сервера и браузерного приложения. Нужен Node.js 22.22.3+ или 24.15+; первая установка требует доступа к npm. Версии и дерево зависимостей закреплены в package.json и package-lock.json.

```sh
npm ci --ignore-scripts
npm run typecheck
npm test
```

README содержит условия самостоятельной попытки и способ воспроизвести дефект: отключить проверку актуальности, увидеть ожидаемый отказ тестов и восстановить защиту.

`useLatestSearch.ts` владеет состоянием и актуальностью запросов. `searchUsers.ts` отвечает за HTTP и проверку JSON. Тесты управляют завершением Promise вручную: никакой зависимости от скорости настоящей сети или `setTimeout(1000)`.

## На что смотреть в реализации

1. `watch` создаётся синхронно в `setup` или внутри `effectScope().run()`. При остановке области Vue вызывает очистку наблюдателя.
2. У каждого запуска собственные `AbortController` и флаг `active`. Очистка сначала делает запуск неактуальным, затем отменяет его.
3. Перед изменением любого состояния после `await` проверяем актуальность. Это касается и `catch`, и `finally`.
4. Сравнение с текущим вводом закрывает промежуток до следующего запуска `watch`: ввод уже изменился, но очистка ещё не выполнилась.
5. HTTP-адаптер проверяет `response.ok`, кодирует строку поиска и принимает JSON как `unknown`. Тип функции сам по себе не проверяет ответ сервера.

Отдельный `AbortError` в старом запросе не нужно показывать: старый запуск уже неактуален. Ошибку текущего загрузчика показываем как обычную ошибку. В реальном продукте текст ошибки согласуют с интерфейсом, а технические подробности отправляют в журнал.

Результаты хранятся в `shallowRef`: пример заменяет массив целиком, не меняет его элементы на месте. Если потребитель должен редактировать вложенные поля реактивно, это отдельное требование к модели состояния.

## Почему такие тесты полезны

| Проверка | Какая ошибка обнаружится |
| --- | --- |
| B завершился, затем A | старые результаты перезаписали новые |
| A отклонён при отмене, B ещё ждёт | `finally` A выключил индикатор B |
| A завершился ошибкой после начала B | ошибка старого поиска появилась в новом |
| Ошибка текущего запроса, затем новый ввод | зависшая ошибка или неверная загрузка |
| Пустой ввод | лишний запрос или возврат старого результата |
| Остановка области | обновление состояния после ухода со страницы |
| HTTP 500 и неверные поля JSON | ошибка сервера принята как корректные данные |

`effectScope` позволяет проверить настоящие наблюдатели Vue без монтажа DOM. Это проверка логики composable и её связи с Vue. Она не проверяет, что пользователь видит сообщение на экране. Для компонента отдельно проверяем ввод, состояние загрузки и сообщение; для e2e — переходы, реальный сервер и восстановление после отказа.

## Практика

1. Убери проверку в `finally`. Какой тест должен упасть и почему?
2. Замени проверку актуальности одной отменой. Какой тест покажет проблему?
3. Измени правило: сохранять старые результаты во время нового поиска. Обнови проверку поведения, не только строку реализации.

> [!question]- Разбор
> В первом случае упадёт проверка загрузки B после отмены A. Во втором — поздний успех A, потому что тестовый загрузчик намеренно игнорирует сигнал. В третьем нужно сначала получить A, начать B и проверить, что A остаётся видимым вместе с индикатором загрузки; затем проверить замену на B. Обсуди, как отличить старые результаты от актуальных в интерфейсе.

## Как объяснить на собеседовании

Я проверяю управляемые порядки завершения запросов. Старый ответ, ошибка и `finally` не должны менять состояние нового поиска. Отмена нужна, но не заменяет проверку актуальности. На сетевой границе проверяю статус и структуру данных, а отображение и настоящий сервер проверяю на других уровнях.
