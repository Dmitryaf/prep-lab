# CSR, SSR, SSG, hydration и SEO

> [!summary]
> CSR, SSR и SSG описывают, где появляется HTML: в браузере, на сервере на каждый запрос или заранее во время build. Hydration подключает интерактивность к HTML, который уже пришёл с сервера.

## CSR, SSR и SSG

| Подход | Где создаётся HTML | Плюсы | Минусы |
| --- | --- | --- | --- |
| CSR | в браузере после загрузки JavaScript | простая раздача файлов, интерактивный интерфейс | исходный HTML почти без содержимого, больше работы при первой загрузке |
| SSR | на сервере при запросе | готовый HTML с содержимым, полезный для поисковой индексации | нагрузка на сервер, ожидание ответа, подключение обработчиков в браузере |
| SSG | заранее на build | быстрый static hosting, cache/CDN | сложнее для часто меняющихся персональных данных |

## Hydration

При гидратации Vue или другой фреймворк запускает приложение в браузере и связывает его с уже полученным HTML. Например, кнопка видна сразу из серверной разметки, а после гидратации реагирует на нажатие. Для этого первый клиентский результат должен соответствовать тому, что отрисовал сервер.

Проблемы:

- hydration mismatch: HTML сервера не совпал с первым render клиента;
- большой JS всё равно нужен для интерактивности;
- страница может выглядеть готовой, но ещё не реагировать на ввод.

## SEO basics для frontend

Минимум, который должен понимать frontend-разработчик:

- уникальные `title` и `meta description`;
- semantic HTML и правильная структура заголовков;
- canonical URL для дублей;
- доступный HTML для важного контента;
- корректные status codes и redirects;
- `robots.txt` и sitemap на уровне продукта;
- performance и mobile friendliness;
- Open Graph/social tags, если важен sharing.

## Страница товара не появляется в поиске: что проверить

Сначала убедись, что по прямому URL сервер возвращает правильный статус и содержимое именно этого товара. Затем проверь, не запрещены ли обход или индексация, куда указывает canonical и доступен ли URL через ссылки и sitemap.

- `robots.txt` управляет обходом, но сам по себе не гарантирует удаление URL из индекса.
- `noindex` управляет индексацией; поисковый робот должен иметь возможность получить эту инструкцию.
- Sitemap помогает обнаружить URL, но не гарантирует индексацию.
- Canonical сообщает предпочтительный URL среди похожих страниц; это сигнал, а не замена исправлению дублей.
- Структурированные данные schema.org описывают сущность, например товар и предложение. Они должны соответствовать видимому содержимому. Они могут помочь расширенному представлению результата, но не гарантируют его.

После этих проверок открой отчёт конкретного URL в Search Console. Он поможет выяснить, обнаружил ли поисковик страницу, удалось ли её обработать и почему она могла не попасть в индекс.

[Google: robots.txt](https://developers.google.com/search/docs/crawling-indexing/robots/intro), [структурированные данные](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data).

## Когда выбирать

| Сценарий | Подход |
| --- | --- |
| внутренняя административная панель | CSR часто достаточно |
| marketing/landing/blog/docs | SSG часто хорошо подходит |
| e-commerce/category/product pages | SSR/SSG/ISR-подобные подходы часто полезны |
| сильно персонализированный кабинет | CSR или SSR с осторожностью |

## Частые ошибки

- Считать SSR автоматическим SEO-решением.
- Забывать про hydration cost.
- Генерировать одинаковые title/description на всех routes.
- Полагаться только на обновление метаданных только в браузере для важных SEO страниц.
- Не проверять, что crawler получает нужный HTML/status.

## Как ответить на собеседовании за одну минуту

При CSR браузер сначала получает файлы приложения, затем JavaScript строит интерфейс. Для внутреннего кабинета этого часто достаточно. SSR формирует HTML на сервере при запросе, а SSG — заранее во время сборки, например для документации. Готовый HTML позволяет раньше показать содержимое; клиентский код затем подключает интерактивность через гидратацию. Для поиска также нужны корректные статусы, доступные ссылки, метаданные и понятная структура страницы.

## Практическая задача

Каталог товаров должен индексироваться поиском, но цены и остатки часто меняются. Что выбрать?

> [!question]- Разбор
> Часто выбирают SSR или гибрид: сервер отдаёт индексируемый HTML с актуальными или достаточно свежими данными, кэширование через CDN настраивается осторожно, интерактивность подключается при гидратации. Для статичных частей можно использовать SSG, но для цен/остатков нужно обновление кэша или новый запрос во время работы страницы. При оформлении заказа сервер заново проверяет цену и наличие: показанное значение могло устареть.
