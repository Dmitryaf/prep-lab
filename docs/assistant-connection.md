# Подключение помощника

Помощник позволяет обсуждать материалы, готовить заметки и разбирать проекты. База, интервью и повторение доступны без подключения.

Встроенное подключение работает через ваш аккаунт ChatGPT и Codex CLI. API-ключ не нужен. Запросы используют лимиты вашего плана; доступ к выбранной модели зависит от аккаунта. Состояние подключения видно в разделе «Промпты» и в «Своих материалах» → «Настройки помощника».

## Если приложение запущено без Docker

Нужен установленный Codex CLI, доступный командой `codex`. Для текущей версии приложения используется CLI 0.158.0. Из папки проекта выполните:

```sh
node --experimental-strip-types server/infrastructure/codex/cli.ts login
```

Откройте выданную ссылку в браузере на том же компьютере и завершите вход. Проверить подключение:

```sh
node --experimental-strip-types server/infrastructure/codex/cli.ts status
```

Вход и просмотр состояния не отправляют тестовых вопросов модели. Настольный вход Codex остаётся отдельным.

Если вы задали `FRONTEND_LAB_DATA_DIR`, у помощника входа и сервера должен быть один и тот же каталог. На локальном Node-экземпляре можно включить кнопку входа в интерфейсе через `FRONTEND_LAB_LOCAL_LOGIN=1`; этот режим подходит, когда браузер и сервер работают на одном компьютере.

## Если приложение запущено в Docker

В образ уже включён Codex CLI. Для первого входа нужен компьютер с браузером, Node.js из [поддерживаемого диапазона](self-hosted.md#без-docker) и установленными зависимостями проекта:

```sh
npm ci --ignore-scripts
node --experimental-strip-types server/infrastructure/codex/cli.ts login
```

После входа помощник сохранит закрытый файл `.local/instance/assistant/credentials.json` (либо в вашем `FRONTEND_LAB_DATA_DIR`). Передайте подключение в постоянный том контейнера. На PowerShell:

```powershell
docker compose stop frontend-lab
Get-Content -Raw -LiteralPath '.local/instance/assistant/credentials.json' | docker compose run --rm --no-deps -T frontend-lab node --experimental-strip-types /app/admin/server/infrastructure/codex/cli.ts import-stdin
docker compose up -d frontend-lab
```

В POSIX shell вместо pipeline можно использовать перенаправление:

```sh
docker compose stop frontend-lab
docker compose run --rm --no-deps -T frontend-lab node --experimental-strip-types /app/admin/server/infrastructure/codex/cli.ts import-stdin < .local/instance/assistant/credentials.json
docker compose up -d frontend-lab
```

Для удалённого сервера сначала передайте файл по защищённому каналу, например SSH/SCP, а импорт выполните на сервере. Не добавляйте файл подключения в Git и не отправляйте его в переписку. После переноса используйте сессию на одном экземпляре, чтобы два сервера не обновляли её одновременно.

## Дальнейшая работа

Проверьте состояние подключения в «Промптах» или в «Своих материалах» → «Настройки помощника».

В обсуждении вопроса или темы перед отправкой можно просмотреть задание. Анализ папки запускается кнопкой «Начать анализ» в «Своих материалах»: помощник последовательно исследует файлы и собирает разбор проекта либо предложения для базы. Ход анализа виден на странице, его можно остановить. Результат добавляется в базу после отдельного принятия.

При необходимости сессию можно обновить на этой же странице. Она также обновляется перед следующим запросом, когда срок действия близок к завершению. Если нужен другой исполняемый файл CLI, задайте `CODEX_COMMAND` полным путём; на Windows это путь к `.exe`.

История обсуждений остаётся в вашем экземпляре. Отмена, закрытие страницы и перезапуск не запускают запрос повторно. После прерванного соединения обновите обсуждение или задание, чтобы увидеть сохранённый результат.
