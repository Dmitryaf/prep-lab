# Разработка

Нужен Node.js из поддерживаемых веток: 22 начиная с 22.22.3, 24 начиная с 24.15.0 либо 26 и новее. Точное ограничение `engines` и команды находятся в [package.json](../package.json).

## Запуск

Из корня репозитория:

```sh
npm ci --ignore-scripts
npm run dev
```

Откройте [http://127.0.0.1:4173/](http://127.0.0.1:4173/). Изменения интерфейса обновляются в режиме разработки автоматически.

Для запуска собранной версии:

```sh
npm run build
npm start
```

`build` создаёт сервер Nitro и клиентские файлы в `.output/`; `start` по умолчанию использует тот же адрес и порт. Настройки постоянных данных и размещения описаны в [руководстве по развёртыванию](self-hosted.md).

При `build` и старте `dev` учебные исходники из `exercises/` упаковываются в `public/labs/`. Отдельная команда — `npm run labs:package`. В архивы попадает только явный список учебных файлов из `scripts/package-labs.ts`; установка зависимостей практикумов для сборки платформы не нужна. Сгенерированные архивы не коммитятся.

Для проверки самих практикумов выполните команды из `exercises/request-lifecycle/README.md` и `exercises/react-behavior/README.md` в распакованных архивах. Это отдельные проекты со своими lockfile и проверками. Корневой `check:all` проверяет упаковку, ссылки, браузерный стенд и примеры решений из Markdown, но не устанавливает зависимости этих проектов.

## Проверки

Перед первым запуском браузерных тестов установите Chromium для Playwright:

```sh
npx playwright install chromium
```

```sh
npm run check
npm run check:all
```

`check` проверяет строгие типы, ESLint, форматирование Prettier, сборку, тесты Node.js, интеграционные сценарии и целостность учебных данных. `check:all` дополнительно запускает браузерные сценарии Playwright Test. Обычные проверки используют подготовленные ответы и не обращаются к модели.

Для исправления форматирования используйте `npm run format`, для автоматических исправлений ESLint — `npm run lint:fix`.

## Устройство

### Импорты

Для импортов между каталогами используются алиасы:

| Алиас        | Каталог     |
| ------------ | ----------- |
| `#ui/*`      | `app/*`     |
| `#domain/*`  | `domain/*`  |
| `#server/*`  | `server/*`  |
| `#scripts/*` | `scripts/*` |
| `#tests/*`   | `tests/*`   |

Например: `import { canonicalNotePath } from "#domain/knowledge/path.ts"`. Соседние модули можно подключать через `./`. Расширения `.ts` и `.vue` сохраняются; чужие features подключаются через их `index.ts`.

Алиасы заданы в `package.json#imports`. Nuxt читает эту же таблицу и передаёт её TypeScript; Node использует её напрямую при запуске тестов и команд. ESLint проверяет архитектурные границы и запрещает импорты через `../../`. Пути к файлам данных и настройки отдельных проектов в `exercises/` от этих алиасов не зависят.

### Каталоги

`app/` содержит страницы и оболочку Nuxt, сценарии в `features/`, сущности в `entities/` и общий интерфейс в `shared/`. Внутри сценариев UI, состояние и API разделены по обязанностям. `domain/` хранит чистую предметную логику и контракты без Vue и ввода-вывода. В `server/` HTTP-входы находятся в `api/`, серверные сценарии — в `application/`, работа с файлами, SQLite и подключением ChatGPT — в `infrastructure/`. Общие материалы и встроенные промпты из `content/` включаются в серверную сборку. Направления импортов проверяет ESLint.

Пользовательские сценарии описаны в [руководстве пользователя](user-guide.md), импорт и обновление материалов — в [руководстве по источникам](sources.md).
