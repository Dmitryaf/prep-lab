# Архитектура и разработка Prep Lab

## Runtime

Nuxt 4, Vue 3, TypeScript strict, Pinia и Nitro. `nuxt.config.ts` задаёт `ssr: false`: интерфейс выполняется в браузере, HTTP и постоянные данные обслуживает Node-сервер. Сборка находится в `.output/`.

| Область                               | Ответственность                                                            |
| ------------------------------------- | -------------------------------------------------------------------------- |
| `app/pages/`, `app/layouts/`          | Маршруты и композиция                                                      |
| `app/features/`                       | Интенсив, интервью, повторение, материалы, источники, обсуждения и проекты |
| `app/entities/`, `app/shared/`        | Сущности и общие UI/модели                                                 |
| `domain/`                             | Чистые алгоритмы и контракты интервью, знаний, импорта, проектов, промптов |
| `server/api/`                         | Тонкие HTTP-входы                                                          |
| `server/application/`                 | Сценарии и управление заданиями                                            |
| `server/infrastructure/`              | SQLite, файлы, источники, безопасный HTTP и подключение помощника          |
| `content/common/`, `content/prompts/` | Встроенные материалы и промпты, включаемые в серверную поставку            |

Алиасы `#ui/*`, `#domain/*`, `#server/*`, `#scripts/*`, `#tests/*` заданы в `package.json#imports` и передаются Nuxt. Чужая feature подключается через public index. ESLint проверяет направления зависимостей; общая инфраструктура не импортирует UI.

## Данные и команды

Личное состояние хранится в закрытом data directory. SQLite adapters находятся в `server/infrastructure/storage/`; встроенная база не переписывается пользовательским импортом. Сохраняются ID, алиасы и прежний прогресс. Однократные миграции оставляют исходники; ошибка записи или чтения не разрешает создавать пустую замену.

Источник проходит чтение, нормализацию, preview и явное принятие с проверкой ссылок/ревизии. Анализ сохраняет задания и результаты; незавершённая операция после restart остаётся прерванной. Generation создаёт черновик.

Интенсив работает с полным каталогом принятых материалов и проектов без фильтрации Vue/React. `domain/intensive/` собирает занятия и дополнения, `server/application/intensive/` управляет черновиком и принятием, а `server/infrastructure/intensive/` сохраняет снимки и прогресс с собственной ревизией. Данные интенсива не меняют историю интервью и список повторения. Оценки и заметки о затруднениях привязаны к ID вопроса; первый и повторный ответы хранятся отдельно. Рассказы принадлежат ID проекта. Необязательные поля совместимы с прежними сохранениями версии 1. Редактор принятой программы сохраняет скрытые занятия и их прогресс, а контекст кода, карты и теории читается из текущего принятого каталога отдельным запросом без замены снимка занятия. Задание для внешнего помощника формируется локально; его ответ задаёт порядок существующих занятий и проходит проверку перед просмотром и принятием.

Адаптер в `server/infrastructure/codex/` владеет отдельным подключением и сериализацией активного turn. Сервер формирует доверенное задание; содержимое источников остаётся данными. Произвольный RPC, shell или файловый доступ через браузер не предоставляются.

## Запуск

Поддерживаемый Node.js: `^22.22.3 || ^24.15.0 || >=26.0.0`.

```sh
npm ci --ignore-scripts
npm run dev
npm run build
npm start
```

Адрес по умолчанию — `http://127.0.0.1:4173/`. `/api/health` сообщает идентичность workspace и `autoClose: false`. Скрипты `dev.ts` и `start.ts` управляют запуском; Docker описан в [self-hosted](self-hosted.md).

Голосовой ввод реализован в `app/features/voice-input/`: MediaRecorder записывает аудио, Web Audio переводит его в моно PCM16 WAV с частотой 16 kHz. `domain/speech/wav.ts` кодирует и проверяет формат. `/api/speech` сообщает готовность движка по GET и принимает WAV по POST. Адаптер `server/infrastructure/speech/` ограничивает размер, длительность и параллелизм, проверяет Origin, запускает локальный `whisper-cli` без shell и отменяет его при разрыве соединения. Пути к движку и модели задаются только серверным окружением; HTTP не принимает файловые пути. Установка и переменные окружения описаны в [voice-input.md](voice-input.md).

## Проверки

```sh
npm run check
npx playwright install chromium
npm run check:all
```

`check` выполняет typecheck, lint, формат, сборку, Node/integration-тесты и валидацию материалов/ссылок. `check:all` добавляет Playwright. Обычные проверки используют подготовленные ответы и временные данные. Реальные model requests и входы не входят в автоматическую проверку.

`labs:package` упаковывает разрешённые файлы из `exercises/` в `public/labs/` при build/dev. Проверки практикумов выполняются в самих проектах; корневой check не устанавливает их зависимости.
