# Установка и обновление

Frontend Lab можно запустить на своём компьютере или сервере. Для каждого владельца используется отдельный экземпляр со своими материалами и настройками.

## На своём компьютере

Нужны Docker с Linux-контейнерами и Docker Compose. В папке проекта выполните:

```sh
docker compose up -d --build
```

Откройте [http://127.0.0.1:4173](http://127.0.0.1:4173). Посмотреть состояние и журнал:

```sh
docker compose ps
docker compose logs --tail=100 frontend-lab
```

Остановка сохраняет данные:

```sh
docker compose down
```

Материалы, настройки и подключение ChatGPT хранятся в постоянном томе Docker. Не используйте `docker compose down -v`, если хотите их сохранить. При обновлении сохраняйте имя папки или Compose-проекта: другое имя подключит отдельный том.

Если ранее вы запускали Node-версию, её данные из `.local` автоматически в Docker не переносятся.

## Другой порт

Скопируйте `.env.example` в `.env` и задайте порт и соответствующий ему адрес, например:

```dotenv
FRONTEND_LAB_PORT=4180
FRONTEND_LAB_ORIGIN=http://127.0.0.1:4180
```

Затем снова выполните `docker compose up -d --build` и откройте указанный адрес.

## На сервере

По умолчанию Docker открывает порт только на `127.0.0.1`. Для удалённой работы настройте SSH-туннель либо обратный прокси с HTTPS и ограничением доступа владельцу. Внутренних аккаунтов Frontend Lab нет: доступ к адресу приложения означает доступ к его материалам и операциям.

Для внешнего адреса задайте `FRONTEND_LAB_ORIGIN=https://lab.example.com`. Прокси должен сохранять исходный `Host` и поддерживать потоковые ответы. Не открывайте экземпляр с личными данными для всех посетителей.

## Папки источников

Для обычного импорта достаточно загрузки Markdown или ZIP через браузер. Если нужно читать папку сервера, добавьте в файл `compose.override.yaml` рядом с `compose.yaml`:

```yaml
services:
  frontend-lab:
    volumes:
      - type: bind
        source: /absolute/path/to/knowledge
        target: /sources/personal
        read_only: true
```

Подключите папку и разрешите её приложению:

```sh
docker compose up -d
docker compose exec frontend-lab node --experimental-strip-types /app/admin/scripts/sources.ts allow personal "Моя база" /sources/personal
```

Compose автоматически использует `compose.override.yaml` и при последующих запусках. На Windows в `source` укажите путь, доступный Docker Desktop. Для анализа в «Своих материалах» выберите «Путь к папке» и укажите `/sources/personal`. Для импорта готовых Markdown-заметок откройте «Импорт готовых материалов», выберите «Разрешённая папка сервера» и её название. Исходные файлы не меняются. Символические ссылки и junction не поддерживаются.

## Резервная копия и обновление

Перед обновлением остановите сервер и сохраните постоянный том целиком. В нём есть личные материалы и данные подключения ChatGPT, поэтому копия должна оставаться закрытой.

Пример для Docker: заранее создайте закрытую папку резервных копий, доступную пользователю контейнера, и укажите её абсолютный путь:

```sh
docker compose stop frontend-lab
docker compose run --rm --no-deps --volume /absolute/backup:/backup --entrypoint tar frontend-lab -C /data -czf /backup/frontend-lab-data.tar.gz .
docker compose start frontend-lab
```

Убедитесь, что копия создана. Получите новую версию исходников и пересоберите приложение:

```sh
docker compose up -d --build
```

При восстановлении используйте отдельный пустой том и остановленный сервер. Не распаковывайте копию поверх работающей базы.

## Без Docker

Нужен Node.js 22.22.3+ в ветке 22, 24.15+ в ветке 24 или 26+. Из папки проекта:

```sh
npm ci --ignore-scripts
npm run build
npm start
```

Откройте [http://127.0.0.1:4173](http://127.0.0.1:4173). Данные сохраняются в `.local`; другой каталог можно задать через `FRONTEND_LAB_DATA_DIR`. При переносе на сервер сохраняйте весь каталог и собирайте приложение на целевой системе.

Для разработки с обновлением страницы при изменении кода используйте [руководство разработчика](development.md).
