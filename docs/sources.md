# Свои материалы

## Анализ папок и файлов

На странице «Свои материалы» выберите **«Разобрать проекты»** или **«Дополнить базу знаний»**. Укажите абсолютный путь к папке; связанные репозитории можно указать по одному в строке. Вместо пути доступны загрузка файлов, выбор папки и ZIP. Описание проекта, своей работы и пожелания необязательны. Кнопка «Начать анализ» запускает подключённого помощника; подключение доступно в «Настройках помощника» на этой же странице.

Проект исследуется по частям, затем помощник собирает общий разбор: назначение, основные сценарии, устройство, технологии, решения, вопросы и ссылки на код. Результат можно прочитать перед добавлением. Принятый проект открывается с визуальной картой: «Сценарии», «Устройство», «Технологии». В «Устройстве» показаны крупные части по ответственности — например, доставка ответов или локальные данные. Выбор блока открывает его назначение, взаимодействия и связанные разборы. В разделе «Код» кнопка «Показать код» открывает сохранённый фрагмент с подсветкой и номерами строк. Его можно скопировать без номеров. Прежние проекты тоже получают карту из сохранённых данных.

Для учебных материалов помощник находит связанные темы в текущей базе и сравнивает их содержимое. Результат разделяет новые темы, дополнения, повторы и противоречия. Отметьте нужные изменения и нажмите «Принять выбранные изменения». Доработки сохраняются в личной базе с прежними идентификаторами вопросов и прогрессом. Исходные файлы не переписываются.

У подключённой папки есть «Проверить обновления»: неизменённые части анализа проекта используются повторно. Если файлы не изменились, модель не вызывается; для материалов также учитываются изменения базы. Задание сохраняется при закрытии страницы. После остановки сервера незавершённое задание остаётся прерванным и самостоятельно не запускается.

Поддерживаются текстовые материалы Markdown/MDX/TXT, а для проектов — исходники и конфигурация. PDF и другие неподдерживаемые форматы перечисляются среди пропущенных. Служебные каталоги, зависимости, скрытые файлы и файлы с секретами исключаются. Лимиты одного подключения: 8 папок, 2 000 файлов, 1 МБ на файл, 12 МБ текста. Превышение лимита останавливает чтение без усечения результата.

Локальный экземпляр принимает путь на своём компьютере. Для удалённого сервера доступны только заранее разрешённые корни; материалы с компьютера браузера нужно загрузить.

## Импорт готовых материалов

Для прежнего импорта без помощника откройте ссылку «Импорт готовых материалов». Этот режим принимает уже оформленные Markdown-заметки; инструкции ниже относятся к нему.

Frontend Lab принимает Markdown-файлы, заметки Obsidian и ZIP-архивы с ними. Из заметок можно получать вопросы для подготовки или оставить их только для чтения.

## Загрузка

1. Откройте «Свои материалы» → «Импорт готовых материалов».
2. Введите название источника, например «Мои заметки по JavaScript».
3. Выберите Markdown-файлы или один ZIP и нажмите «Подготовить изменения».
4. Просмотрите результат и примите его.

Ограничения: до 200 Markdown-файлов, до 1 МБ на файл и 8 МБ суммарно. Для ZIP также действует предел в 2000 записей и 8 МБ распакованного содержимого. Нужна кодировка UTF-8. Служебные и скрытые файлы пропускаются; содержимое архива не запускается.

## Пример заметки с вопросом

```markdown
# Функции

## Что такое замыкание?

Объясните, какие переменные доступны функции после её создания.

> [!answer]- Ответ
> Замыкание позволяет функции обращаться к переменным из окружающей области видимости, даже когда внешний вызов уже завершён.
```

Название материала задаётся заголовком `#`, вопросы — заголовками `##`. Скрытый ответ записывается в блоке `> [!answer]- Ответ`; каждая строка внутри него начинается с `>`.

Обычные ссылки Markdown, Obsidian-ссылки `[[Название заметки]]` и скрытые блоки поддерживаются. Перед принятием приложение проверяет ссылки. Если целевого файла или раздела нет, исправьте ссылку либо добавьте нужную заметку.

Для заметки в другой папке укажите путь, например `[[JavaScript/Асинхронность]]`.

## Профиль и назначение

При необходимости добавьте метаданные в начало файла:

```yaml
---
title: Моя заметка
aliases: [Другое название]
frontendLab:
  profile: shared
  kind: theory
  category: JavaScript
---
```

- `profile`: `shared`, `vue` или `react`.
- `kind`: `theory`, `practice`, `design`, `behavioral` или `reference`.
- `reference` оставляет заметку для чтения без извлечения вопросов.

В интерфейсе можно исключить весь источник из интервью и практики, сохранив его материалы для чтения.

## Обновление и личные правки

Нажмите «Обновить» у источника и загрузите его **полный новый снимок**. Отсутствующий файл станет предложением удаления; поэтому не загружайте только изменившуюся часть папки.

В просмотре доступны прежний внешний текст, текущая личная версия и новое содержимое. При конфликте выберите, что сохранить, либо отредактируйте итог. «Сохранить правки просмотра» позволяет продолжить позднее. Активная база изменится только после принятия.

Переименование файла с тем же содержимым распознаётся автоматически. Если одновременно изменился текст, укажите прежний материал через «Это переименованный файл». Для переименованного заголовка можно задать соответствие, чтобы сохранить старые ссылки.

Внешние файлы не переписываются. Пустая загрузка и ошибка чтения не удаляют уже принятую базу.

## Папка на сервере

Вместо загрузки можно подключить папку, доступную серверу Frontend Lab. Её сначала разрешает владелец установки, затем название папки появляется в интерфейсе. Папка на компьютере браузера не считается папкой удалённого сервера.

Команды подключения описаны в [инструкции установки](self-hosted.md#папки-источников).

## Общая и личная база

Репозиторий содержит общие технические материалы. Свои заметки, проекты, настройки и прогресс хранятся в данных вашего экземпляра и не передаются другим установкам. Для переноса личной базы используйте закрытую резервную копию данных, описанную в [инструкции установки](self-hosted.md#резервная-копия-и-обновление).
